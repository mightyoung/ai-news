# SkillScaffold：用「技能」当训练脚手架的 agentic RL 深度解析

- arXiv：https://arxiv.org/abs/2610.18807（v1，2026-10-13，cs.LG）
- 论文全名：SkillScaffold: Scaffolding Agentic Reinforcement Learning with Policy-Adaptive Skill Credit Assignment and Selective Injection
- 作者与单位（首页）：Wenlin Zhong 等；浙江大学（第一单位）、中国科学院大学、快手科技、浙江科技大学

- 阅读说明：数字来自论文正文和表格；论文没写的标「论文未说明」；我自己的推算和判断标「我的判断」。

## 1. 一句话

训练 LLM agent 时，用模型自己生成的文字「技能卡」帮它在难题上探索，但只在「估计这张卡真的有帮助」时才塞进去，帮不上就放弃；技能只在训练时用，部署时完全去掉。对工程的价值：它给了一个不用额外跑环境、只靠「重新打分」就能判断「该不该给提示、给哪条提示」的便宜办法。

## 2. 它解决什么痛点

背景：agentic RL 是让 LLM 在多轮交互环境里（订机票、网购、做家务）用「可验证结果」（成功或失败）当奖励去训练。难点是任务长、奖励稀疏——模型大部分时候做不成，也就学不到东西。

一种常见办法是「技能」：把以前的轨迹提炼成可复用的文字指导（比如「先检查库存再下单」），在后续探索时放进提示里。但已有做法有三个毛病：

1. 默认「生成出来的技能就是有用的」，不验证。
2. 靠间接、延迟的反馈来判断技能好坏。
3. 要判断就得对每个候选技能额外跑环境 rollout，贵。

论文先做了两个小实验（第 3 节「Motivating Observations」）来说明问题：

- **用 rollout 估技能收益又贵又不稳。**对一个任务有 M 个候选技能、每个跑 K 次，要额外 (M+1)×K 次环境交互。他们让两组独立估计比较符号：K=1 时有 23% 的情况符号相反，K=8 时仍有 16%。把每个查询的额外 rollout 从 5 次加到 40 次（8 倍），能分出高下的候选组只从 32% 增到 55%。
- **技能好坏取决于「哪个任务」和「模型当前水平」。**100 个查询里，28 个同时有帮忙的和添乱的候选。按模型「不用技能时能做对几次」（4 次探测）分组：模型多半做不对时，技能平均有正收益；模型多半或全部能做对时，平均收益转为负，最好的候选也几乎没增益。

结论：需要一个便宜、会随模型水平变化的「技能效用」信号，既能给候选排序，也能在都没用时选择「不加」。

## 3. 方案思路

先给几个术语（大白话）：

- **Executor（执行者）**：真正和环境交互做任务的模型。
- **Generator（生成者）**：根据已有轨迹写「技能卡」的模型。注意：和 Executor 是**同一个模型、同一组参数**，只是扮演两个角色。
- **Scout（侦察轨迹）**：不带任何技能先跑的几条轨迹，用来看模型现在的真实水平。
- **技能卡**：一份结构化文字，含适用条件、可执行步骤、条件判断规则、校验/恢复/停止条件。

每个训练步骤（图 4）分五步：

1. **先侦察。**对一个任务，Executor 不带技能跑 N 条轨迹（论文设置 N=4），环境验证器给每条打成功/失败，于是这组是「全成功 / 全失败 / 有成有败」之一。
2. **写候选技能。**Generator 看到任务和这些带结果标签的轨迹，独立生成 M 张候选技能卡（M=4）。全成功组提炼可复用的做法；全失败组诊断反复出现的错误；混合组对比成败差异。另有一个轻量变体（anchor）只用一条成功轨迹当依据，没有成功就不生成。
3. **给候选打分（核心）。**不跑新的环境，而是把「已经跑好的 Scout 轨迹」原样拿来，让当前模型在「有这张技能卡」和「没有」两种上下文下，分别计算这些轨迹里每个 token 的平均对数似然，二者之差记为 d。直觉：加上技能后，模型觉得「那些成功的行为更合理了」「那些失败的行为更不合理了」，就说明这张卡与当前模型相容、有用。
   - 全成功组：效用 U = 成功轨迹上 d 的平均值；
   - 全失败组：U = 失败轨迹上 d 的平均值取负；
   - 有成有败：U = ½×成功轨迹 d 的平均 − ½×失败轨迹 d 的平均（成败各占一半权重，不管人数多少）。
4. **有选择地注入。**取 U 最大的候选；**只有 U>0 才用**，否则这个查询仍然不带技能。选中的技能放到 L 条新的 Executor 轨迹（L=4，称为 Post-Scout）。
5. **联合训练。**Executor 用环境奖励做 GRPO；Generator 用技能效用 U 作为奖励（anchor 变体里负值截成 0），另做一个 GRPO。两部分共享参数，损失里 Generator 项权重 λ=0.1。因为 Scout（没技能）和 Post-Scout（有技能）的轨迹都在更新同一个模型，论文认为「技能带来的好策略会被内化」，所以部署时把 Generator 和整套技能通路拿掉，不带技能推理。

论文的设置里，ALFWorld、ScienceWorld、τ²-Bench 用「全组」效用，WebShop 用 anchor 版本（附录表 5）。

## 4. 怎么看实验、怎么识别夸大

**设置：**所有主实验用 Qwen3-8B；四个基准：ALFWorld（家务，训练 3,553 个任务，在 134 个 valid-unseen 任务上测）、WebShop（网购，ID 测试 454 个目标、OOD 207 个）、ScienceWorld（电学子集，ID 230 个 episode、OOD 155 个）、τ²-Bench（航空/零售/电信的多轮工具对话，用 Pass@1）。τ²-Bench 的所有 RL 方法都从同一个 SFT 检查点出发。

**主结果（表 1、表 2）：**

| 基准 | GRPO | 最强技能类 RL 基线 | SkillScaffold |
|---|---|---|---|
| ALFWorld 平均 | 85.6 | 91.8（SKILL1） | 94.8 |
| WebShop 平均 | 36.5 | 41.8（Evolving-RL，带技能） | 45.1 |
| ScienceWorld 平均 | 72.9 | 71.9（SkillRL） | 77.1 |
| τ²-Bench 平均 Pass@1 | 60.0 | 59.9（SkillRL） | 63.4 |

读这张表时要留意：

- **「评测时带不带技能」不一致。**表 1 里带 † 的方法（INSPO、SkillRL、SKILL1、Evolving-RL）是带着技能评测的，带 ∗ 的（SEED、Evolving-RL∗、SkillScaffold）不带技能。SkillScaffold 是在更不利的「无技能」条件下赢的，这对它有利；但也说明不同行的推理条件不一样，比较时别当成同一设置。例如 Evolving-RL 带技能 41.8，去掉技能后只有 27.7。
- **ScienceWorld 和 τ²-Bench 的基线更少。**表 2 只有 ReAct、SFT、GRPO、SkillRL（ScienceWorld 没有 SFT），没有 SKILL1、Evolving-RL 等。「在每个基准都最好」是对该基准里列出的基线而言。
- **有的格子没赢。**τ²-Bench 航空：SkillScaffold 46.0，SkillRL 46.0，持平（GRPO 45.8）。论文强调的 +6.3 来自电信，+2.9 来自零售。
- **样本量不大。**ALFWorld 只有 134 个测试任务，1 个任务约 0.75 个百分点；94.8 对 91.8 相当于多做对约 4 个任务（我按 127/134 与 123/134 反推）。WebShop OOD 207 个、ScienceWorld OOD 155 个。
- **没有多种子/误差条。**主表没有标准差或置信区间，论文也没说跑了几个种子（论文未说明）。训练的 GPU 型号、耗时同样没写。
- **数字全部是论文自报。**代码已公开，但我没有复现。

**消融（表 3）读法：**去掉任一部件，ALFWorld/WebShop 都下降：

| 变体 | ALFWorld | WebShop |
|---|---|---|
| 完整 | 94.8 | 45.1 |
| 不训练 Generator | 89.6 | 39.5 |
| 随机选候选 | 79.9 | 39.2 |
| 打乱候选与效用的对应 | 82.8 | 37.1 |
| 去掉「U>0 才注入」的门槛 | 85.8 | 39.6 |
| Generator 学习，但不把技能注入 Executor | 90.3 | 41.5 |

「随机选候选」比不训练 Generator 的掉幅更大（ALFWorld 79.9 对 89.6），说明在这个设置里乱注入技能确实会伤害训练——这条对「默认技能有用」的做法是个有力反证。

**效用信号本身有没有用（5.4 节）：**用 pilot 阶段已有独立 rollout 评估的候选集合，比较四种决策：不用技能 61.8%、随机注入 60.1%、强制注入效用最高的候选 63.0%、效用最高且为正才注入 67.6%。结论是：光排序只带来很小的提升，「该不该放弃」的门槛才是关键。注意这个验证用的是 pilot 候选集，规模论文正文没给（论文未说明）。

**训练期探索（5.5 节）：**与 Scout 相比，Post-Scout 在「全错」的组上成功率提高 21.1 个点，混合组 +5.4，全对组 −2.3。符合「帮在最需要的地方」的叙述，也符合门槛逻辑。

**内化证据（5.6 节，表 4）：**取早期检查点上「靠技能辅助才做对」的那批训练查询，在后期检查点不带技能再测，成功率变化为：WebShop +19.7（N=19，区间 [0.0, 39.5]）、ALFWorld +29.6（N=54）、ScienceWorld +65.0（N=50）、τ²-Bench +16.6（N=98）。
我的判断：这个证据偏弱。一是 WebShop 样本只有 19 个，区间碰到 0；二是这批查询是「按早期是否受益」挑出来的，后期自然回升可能有回归到均值的成分；三是论文没给同一批查询在普通 GRPO 下的变化作对照，所以看不出这是「内化技能」还是「普通训练也会变好」。

**理论部分（附录 C）：**命题 2 说的是「如果效用估计误差不超过 ε，则选出的候选至多比最优差 2ε，门槛放弃时最优的效用不超过 ε」。这是一个条件命题，前提（误差有界且 ε 小）没有被证明。

## 5. 落地步骤

**今天就能试（有 RL 管线的前提下）：**
1. 在你已有的 GRPO/可验证奖励训练里，先记录每个任务的组内成败（全对/全错/混合）。论文发现技能主要在「全错」和「混合」组有用，这个统计本身就能指导你把力气花在哪。
2. 做一个小验证：对一批已有轨迹，分别在「加提示」和「不加提示」的上下文下重新计算对数似然，看这个差值与你实际量到的收益有没有相关性（相当于复现论文图 5）。只需要前向计算，不需要新环境交互。
3. 如果你已经在用提示、规则卡或记忆来辅助探索，至少加上「U>0 才用」这样的门槛，别无条件注入。

**需要资源：**
1. 完整复现需要 8B 模型的多轮 RL 训练资源（论文训练 100–200 步，每个任务 8 条 Executor 轨迹 = 4 条 Scout + 4 条 Post-Scout），再加 Generator 采样（每个任务 4 张卡，最多 256–900 个 token）和对候选的重新打分。按论文附录表 5，Executor 的组大小是 8（4 条 Scout + 4 条 Post-Scout），额外开销主要是 Generator 采样和打分的前向计算；具体多花多少时间，以及对比的 GRPO 基线用的组大小和训练步数是否与它对齐，论文正文未说明（我没有读到）。
2. 需要环境验证器（成功/失败可自动判定）。没有可验证结果的任务不适用。
3. 代码在 GitHub（见顶部）；是个人账号，2026-10-13 创建，我查看时 0 star，Apache-2.0；论文的复现声明里又写「实现代码将放在补充材料中」，两处说法略有出入。

**可以跳过：**
- 只做推理期提示工程的场景：论文的价值在训练期，部署期不带技能。
- 模型已经基本能做对的任务：论文自己的结果显示这时技能平均有害。

## 6. 和已知概念的挂钩

- **GRPO / RLVR**：本文是在 GRPO 之上加「技能脚手架」，奖励仍然是可验证的成败。
- **SkillRL、Reflexion、ExpeL、Voyager 的技能库**：同属「把经验提炼成文字指导」的路线；本文区别在于先估计效用、可以放弃、训练后不再依赖。
- **课程学习 / 脚手架**：在难题上给辅助，在会了的题上撤掉。
- **上下文蒸馏（context distillation）**：让模型不看提示也能表现得像看了提示。本文通过共享参数和联合训练达到类似效果。
- **和 Agent-Reflex 的相通之处**：Agent-Reflex 的 ORPO 同样用「把已采样的 token 放到带技能的上下文里重新打分」来得到训练信号（它是 token 级蒸馏，本文是给候选技能打效用分），可以对照着读。
- **「建议有时有害」**：论文引用了一项研究 Agent skills can be harmful（Dong 等 2026a）作为旁证，我没有读那篇。

## 7. 疑点、局限与成本

- **打分的代理指标可能有偏（我的判断）：**效用来自「对已有轨迹的似然变化」，而候选技能正是根据这些同一批轨迹生成的。一张把轨迹里的措辞复述一遍的技能，似然自然会升高，但不一定真能帮到新的尝试。论文用独立 rollout 做了一次验证（5.4 节，增益随效用分位上升），这是缓解，但验证规模不透明。
- **适用边界：**依赖「同一任务能采样多条轨迹且有二元成败」；Scout 全对的任务基本不会注入技能，对这类任务它退化成普通 GRPO。
- **证据强度：**无多种子、无误差条；ALFWorld 等测试集不大；内化证据没有对照组（见第 4 节）。
- **基线条件不一：**带技能/不带技能评测混排；ScienceWorld 和 τ²-Bench 的基线少于另外两个基准。
- **成本：**额外要训练同一模型的「写技能」能力，并对每个候选做前向打分；GPU 型号和训练时长论文未说明。
- **代码状况：**仓库较新，社区验证几乎为零；复现前先自己跑通。

一句话评价：思路合理、消融比较扎实（乱注入会伤训练这一点很有说服力），但主表缺少方差信息，「内化」的证据也不够硬；适合当成「训练期提示要先验后用」的设计参考，而不是现成的收益保证。
