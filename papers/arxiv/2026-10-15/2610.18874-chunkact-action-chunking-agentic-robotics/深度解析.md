## 一句话总结

ChunkAct 把「agentic robotics」里 LLM 规划器「每个动作原语都调用一次」的模式，改成「离线把记忆编译成可执行的动作块（action chunk），在线规划器一次调用启动一整块、失败时才拿到带类型的错误退出」，在 LIBERO-Pro 上成功率提高 5.0 点，同时 LLM 调用少 2.9 倍、输入 token 少 4.4 倍、输出 token 少 2.3 倍。

## 研究问题与动机

Agentic robotics 把 LLM agent 放进控制回路，通过感知、运动、VLA 等工具（原语）完成任务，不用演示数据重训，泛化性好。论文举例：不做机器人专属训练，经通用 agent 外壳驱动的 GPT-6 Astra 在真机抓放任务中 20 次完成 19 次，并在 RoboDojo 基准上高于所有公开策略。代价是效率：每个原语都要一轮 LLM 推理，且每轮重读全部历史，因此调用数与输出 token 随原语数线性增长，输入 token 近似二次增长。论文给出的数字：一次抓放任务平均需 24.2 次 LLM 调用、220 万输入 token，用 GPT-6 Astra 每个回合约 22 美元，用较便宜的 GPT-5.5 仍约 11 美元（按 2026 年 10 月官方列表价估计）。作者分析 agent 行为后发现两处浪费：规划器把「决策」和「执行」混在一起（子目标确定后，后续原语基本由记忆决定）；且调用中只有 20.5% 是动作原语，其余多为感知查询与记忆读取，而记忆在各回合间是静态的，反复读取并撑大上下文。

## 核心方法

- **离线构建动作块**：把同一任务类型的全部记忆条目（从通用执行规则到任务专属记录）整合成一个统一的块，参数化到对象类别、各阶段失败时的回退策略、每个阶段的验证标准；保留「如何执行」的过程性知识（例如原语分工：夹持类阶段交给 VLA 策略，其余用解析式原语），丢弃部署时不可观测的量（记录的坐标、模拟器特权状态），几何量由实时感知重新估计。论文称任务类型很少（两类即可覆盖很大范围）。
- **在线执行**：规划器理解任务与场景，对首个目标做 grounding，发起一次调用；块自主按序跑完各子目标，每个阶段先验证再进入下一阶段，无需再请求规划器。感知也放在块内进行，结果不进入规划器上下文。
- **失败回传**：块失败时返回带类型的退出码，并附带「hand-off block」结构化错误报告；规划器据此从真实场景状态重新感知，选择三种应对：重新 grounding 并重发块、重做验证失败的子目标，或回退到原语处理库外情形。
- 实现：VLA 原语使用 πRLinf，分割由 SAM 3 提供；规划器使用 GPT-5.6-sol。

## 实验设置与主要结果

- **基准**：LIBERO-Pro（扰动 LIBERO 四个套件，含指令改写 T 与位置互换 S，每个组合 10 个任务、每任务 10 个种子，即 800 个回合/组合）；LIBERO-Plus（七类扰动：物体布局、相机视角、机器人初始状态、语言、光照、背景、传感器噪声，共 10,030 个变体，对每个任务各扰动轴跑单个种子）。对比 8 个端到端 VLA（含 OpenVLA、π0、π0.5、MolmoAct、NORA、X-VLA 等）与 CaP-X、Harness VLA 等 agentic 系统。
- **LIBERO-Pro 成功率**：ChunkAct 83.8%，超过此前最强的 Harness VLA（78.8%）5.0 点；调用 8.3 次对 24.2 次，输入 0.5M 对 2.2M token，输出 3.7k 对 8.5k token。πRLinf 原语单独使用，落后 ChunkAct 43.8 点。
- **关闭规划器推理**（reasoning=None）：ChunkAct 80.0%，Harness VLA 降到 56.0%（差 24.0 点）；此时调用 6.6 次对 24.9 次（3.8×）、输入 0.4M 对 2.4M（6.0×）、输出 1.3k 对 6.4k（4.9×）。说明弱规划器对 ChunkAct 影响很小。
- **规划器的贡献**：用脚本驱动、完全不调用 LLM 执行动作块，成功率 57.5%；因此 LLM 贡献了其余 22.5 点，主要来自失败恢复。
- **零样本泛化（LIBERO-Plus）**：块库与提示词不变，总体最优，超过最强前作 11.0 点，七个维度中六个领先；相机与机器人初始状态扰动下差距最大（ChunkAct 保持在四分之三以上，最好的 VLA 降至三分之二与一半）。对比的 VLA 基线在该基准数据上微调过。
- **定性**：一个抓罐子放篮子的回合共 8 次规划调用、历时 22 秒：规划器只介入两处——开头观察并启动块；罐子中途滑落、块以 lost_in_carry 退出后，用 4 次调用重新定位，再次启动块完成。

## 局限与风险（据正文整理）

- 动作块的记忆是在 LIBERO-Pro 上编译的（含任务专属记忆，论文称前作发现在该基准上必需），虽然用 LIBERO-Plus 做了零样本检验，但换到新任务族需要重新编译块库；
- 离线编译与「类型」划分依赖人为组织记忆，论文没有给出对全新任务类型的自动化流程；
- 评测集中在 LIBERO 系列模拟基准，LIBERO-Plus 每个任务各轴只跑一个种子（作者称为控制成本）；论文摘要中的真机结果引用自其他工作，并非本文实验；
- 对比 VLA 的数字来自他人报告，对比协议并非完全一致；
- 效率数据以 token 与调用次数衡量，未报告墙钟时延；规划器与原语（πRLinf、SAM 3）均为外部组件，成本与性能受这些组件影响。

## 工程落地启示

- 凡是「LLM 逐步调用工具」的 agent，都可以检查调用日志：若大量调用只是读记忆、做感知，就适合把固定流程编译成可执行流水线，LLM 只管决策与异常处理。这个思路不限于机器人。
- 失败回传要做成「带类型的退出码 + 结构化交接报告」，让规划器从真实状态恢复，而不是从预期状态恢复。
- 成本敏感场景下，ChunkAct 对弱规划器友好（关闭推理仍有 80.0%），可降本。
- 值不值得复现：论文篇幅短、依赖现成组件（πRLinf、SAM 3、GPT-5.6-sol 与 LIBERO 基准），工程复现门槛中等；先在自己的任务上统计「动作原语调用占比」与「记忆读取占比」，若同样偏低再投入编译动作块。

## 与相关工作的关系

- 相对 CaP-X、Harness VLA 等 agentic robotics 系统：沿用「LLM 规划器 + 感知/运动/VLA 原语」的框架，但不再让规划器每步读记忆并重新解释。
- 相对已有的记忆与技能机制（Reflexion、ExpeL 等，以及缓存调用序列、记录子任务转移条件的做法）：这些做法让规划器读取并解释记忆；论文称自己首次把 agent 记忆离线编译成物理动作；最接近的 Li 等（2025）把重复片段蒸馏进数据存储再「发出」，但其块仍是文本。
- 相对 ACT 等 action chunking：ACT 里的块是学习策略输出的短序列电机指令；ChunkAct 的块跨越感知、控制原语与内化的记忆，是 agent 层面的块。
