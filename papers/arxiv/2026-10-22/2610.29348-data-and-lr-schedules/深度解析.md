## 1. 一句话要点与用处

**要点**：总训练量和中训练（MT）数据总量都固定时，讨论“要不要在中训练阶段混回预训练（PT）数据”或者“MT 数据该早放还是晚放”，必须先说清学习率怎么调度，因为换一种学习率曲线，结论可以完全反过来。

作者做了两类比较：
- 在“整个继续训练期间学习率线性衰减到底”（FDR）的设置下，MT 数据早一点进入、并和 PT 数据混合，最终 MT loss 更低。
- 换成恒定学习率（Const），反而是“最后一段只用 MT 数据”最好。

在作者测试的所有组合里，最好的做法是：**MT 数据进入后先保持高学习率，只在 MT 窗口的最后 10%–40% 线性衰减**。这个做法同时优于恒定学习率，也优于“MT 一进入就开始衰减”（MDR）。

**用处**：做继续预训练、中训练或领域退火的人，可以拿它来检查自己的“数据切换点”和“学习率退火起点”是不是分开调的。以前看到的“混回 PT 数据有好处”这类结论，也可以重新审视一下。

## 2. 实际痛点/场景

- 常见的大模型流水线是这样的：先在网页数据上预训练，然后整段切到数学、代码等高价值的 MT 数据，同时把学习率退火下去。
- 关于“MT 阶段混不混 PT 数据”，已有工作说法不一：
  - Kotha & Liang (2026) 发现，在第二阶段混入 PT 数据反而能让 MT loss 更低。
  - Luo et al. (2026) 发现，学习率衰减会“浪费”放在最后的好数据。
- 作者认为这些结论之所以互相打架，是因为大家默认用的学习率曲线不一样。

## 3. 方案思路与步骤

**把“切换”看成一条数据调度曲线**：
- 设 γ(t) 为第 t 步批次里 MT token 的比例，在固定批大小下，∫γ(t)dt 正比于 MT token 总量，并且保持固定。
- 传统的“整段切换”对应 γ(t)=1{t>τ0}。

**两种数据调度**：
- **TS（两段式）**：先只用 PT，到某个时刻跳到固定比例 γend，一直保持到结束。γend<1 就意味着第二段混有 PT 数据。
- **ZL（零后线性）**：先只用 PT，然后 MT 比例从 0 线性升到 γend。
- 预算约束下，TS 要求 γend ≥ α，ZL 要求 γend ≥ 2α，其中 α 是 MT 占比。

**三种学习率方案**（衰减全部是线性的）：
- **Const**：MT 阶段一直保持峰值学习率，不退火。
- **FDR**：整个继续训练期从峰值线性降到最终值，不管 MT 数据什么时候进入。
- **MDR**：MT 数据一进入就开始衰减，到训练结束降到最终值。

**扫描“相对衰减时长”**：把“衰减步数 ÷ 从 MT 进入到训练结束的步数”定义为相对衰减时长。Const 记为 0%，MDR 记为 100%，然后在中间取若干点。

**实验设置**（第 2.1 节、附录 B）：
- **数据**：PT 用 DCLM-Baseline，MT 用 FineMath 的 finemath-4plus 子集（约 100 亿 token）。代码消融里换成了 StarCoderData Python。
- **稠密模型**：
  - 630M 参数，结构参照 Qwen2.5-0.5B，输入和输出嵌入不共享。
  - PT 阶段跑了 95,368 步，约 2,000 亿 token。前 5,000 步预热到 5e-4，之后**一直保持恒定学习率**，所以继续训练是从一个**没有退火过**的检查点出发的。
  - 继续训练 10,000 步，共 209.7 亿 token。MT 占 10%、25% 或 47.75%，分别是 21.0 亿、52.4 亿、100.1 亿 token。
  - 峰值学习率 5e-4，衰减方案最后降到 1e-5。
  - 优化器是重新初始化的，没有预热。
- **MoE 模型**：
  - 总参数 2.99B，按 OLMoE 的设计，每层 64 个专家，每个 token 选 top-8。
  - PT 用 400 亿 token，同样是预热后保持恒定学习率。
  - 继续训练 40 亿或 100 亿 token。
- **评价指标**：只看最终 MT 验证 loss（FineMath 验证集上的交叉熵），PT loss 作为辅助。**没有任何下游任务评测。**
- **实验规模**：正文说总共超过 250 次训练。

**理论部分**（第 3 节）：
- **模型**：在块对角二次损失上做 SGD 的 SDE 近似。特征分为三块：PT 和 MT 共享的、MT 独有的、PT 独有的。
- **定理 3.1**：
  - 恒定学习率时，最优数据调度就是“最后 α 比例的时间全用 MT”。
  - 线性衰减足够强时（条件写在定理里），这个调度不再最优。
  - 再加上幂律谱假设、训练足够长时，FDR 下的最优调度是三段式：纯 PT → 混合（MT 比例随学习率下降而上升，γ*(t)=C·η(t)^(−2(b−1)/(b+1))）→ 纯 MT。
- **直观解释**：
  - 损失分成“偏差项”和“方差项”。偏差项取决于 MT 更新累计用了多少学习率，方差项是梯度噪声留下的。
  - 学习率恒定时，所有调度的偏差项一样，MT 放在最后能让之后压制噪声的更新最多，所以最优。
  - 学习率衰减时，早放的 MT 数据能吃到更大的学习率、偏差更小，于是有了权衡。
- **定理 3.2**：固定 TS 并且 γend=1，学习率取“稳定-衰减”族。在幂律谱条件、MT 预算足够小、训练足够长的前提下，最优衰减时长 W* 严格落在 (0, αT) 之间，也就是**衰减应当在 MT 进入之后才开始**。

## 4. 如何读实验与识别夸大

**先看绝对数值（附录 C 表 4，稠密模型）**。下表是各组合在测试过的 γend 中能达到的最低最终 MT loss，括号里是对应的 γend：

| MT 预算 | 调度 | Const | FDR | MDR |
|---|---|---|---|---|
| 10% | TS | 1.5420 (100) | 1.6108 (20) | 1.5394 (100) |
| 25% | TS | 1.4717 (100) | 1.5024 (40) | 1.4475 (100) |
| 47.75% | TS | 1.4217 (100) | 1.4194 (70) | 1.3826 (100) |

这张表是全文最需要注意的地方：
- **“混入 PT 数据更好”只在 FDR 内部比较时成立。** 在 FDR 下，最优 γend 确实小于 100%（分别是 20%、40%、70%），也就是要混合。
- 但在 10% 和 25% 预算下，**FDR 能达到的最好成绩比 Const 和 MDR 都差**。比如 10% 预算时 FDR 最好是 1.6108，Const 是 1.5420。
- 换句话说，如果你本来就打算从头衰减到底，那混一点 PT 数据会更好；但“从头衰减到底”本身就不是好选择。

**学习率衰减扫描（附录 D 表 7，共 19 组）**：
- 稠密模型 TS（γend=100%）在三个预算下，最佳相对衰减时长都是 40%：
  - 10% 预算：1.5156，对比 Const 1.5420、MDR 1.5394
  - 25% 预算：1.4275，对比 Const 1.4717、MDR 1.4475
  - 47.75% 预算：1.3690，对比 Const 1.4217、MDR 1.3826
- 稠密模型 ZL 的最佳时长是 20%。
- MoE 模型 TS 的最佳时长是 20%，ZL 是 10%。
- 作者解释，ZL 的最佳相对时长约为 TS 的一半，是因为同样预算下 ZL 的 MT 窗口长一倍，折算成绝对衰减步数后两者差不多。以 MoE 100 亿 token、25% 预算为例，TS 和 ZL 都是 119 步。
- 换成代码数据（StarCoderData），这个最佳比例不变。

**噪声有多大（附录 E 表 9）**：
- 作者对 6 个配置各多跑了 2 次，换训练样本或打乱顺序，三次结果的离散度在 0.00015 到 0.0019 之间。
- 所以，上面 Const 与延迟衰减之间 0.01–0.05 量级的差距是可信的。
- 但作者自己也说，有些相邻配置之间的小差距不能当作“一个稳定优于另一个”的证据。比如稠密 ZL 在 25% 预算下相邻几个衰减时长之间，以及 MoE 100 亿 token 下最佳 TS 与最佳 ZL 之间（1.4853 对 1.4872）。
- 另外，所有重复都从同一个 PT 检查点出发，**没有覆盖“换一次预训练”带来的方差**。

**MoE 的一个反常现象**：在三个主要 MoE 设置里，MDR 比 Const 还差。例如 MoE 40 亿 token、25% 预算、TS 下，Const 是 1.6176，MDR 是 1.6486。稠密模型正好相反。这说明“MT 一进入就开始衰减”本身也不总是好主意。

**还要注意的比较条件**：
- 所有比较都固定了总 token 数和 MT token 数。“更早混入”的意思是同样多的 MT token 摊到更长的时间里，而不是多用 MT 数据。
- 每组 Const 和衰减方案用的是同一个峰值学习率 5e-4，峰值学习率本身没有一起扫描。**论文未说明**换一个峰值学习率结论是否不变。
- 最好的配置都是“学习率在 MT 窗口末尾才衰减”，这其实就是 WSD（warmup-stable-decay）的思路：先稳定，最后短暂衰减。我的判断：本文主要的实践价值，是把“衰减段应当整段落在 MT 数据窗口里，而且要短”这件事量化了。

## 5. 落地分层

**今天能试**：
- 如果你的继续预训练或中训练用的是“从头衰减到底”的学习率，可以先改成“MT 进入后保持峰值，最后 20%–40% 的 MT 窗口线性衰减”，再和原方案在同样的 token 预算下比一次 MT 验证 loss。
- 评估“混回 PT 数据有没有用”之类的数据配比结论时，先确认学习率曲线是否相同。
- 如果是 MoE 模型，可以考虑把 MT 数据的比例逐渐升上去（ZL），而不是一下切过去（TS）。作者观察到，突然切换会让负载均衡损失出现尖峰（图 6），专家负载的排名也会大幅重排。

**需要资源**：
- 在自己的模型和数据上扫“相对衰减时长”，需要 5–6 次以上完整的继续训练。
- 如果还要同时扫 γend，次数会成倍增加。

- 理论部分的完整证明（附录 H–N，约 50 页）。只想用结论的话，读定理 3.1、3.2 的非正式表述和第 3 节的直观解释就够了。

## 6. 与已知概念的挂钩

- **WSD 学习率（warmup-stable-decay）**：本文最好的方案就是“MT 数据进来后保持稳定，最后再衰减”。作者在参考文献里引用了 WSD 和“河谷”损失地形的相关工作。
- **退火阶段用高质量数据**：DeepSeek、Qwen、OLMo 等都把高质量数据放在最后。本文指出，“最后放”和“最后衰减”要配合好，否则小学习率会让 MT 数据利用不足（Luo et al. 2026 称之为“浪费最好的数据”；该文与本文有多位共同作者，属于同一研究组的前作）。
- **数据回放与灾难性遗忘**：本文只看 MT loss 最小化，PT loss 只是附带画出来。Const 和 MDR 下，MT loss 降低时 PT loss 通常会升高，存在权衡（第 4.1 节）。
- **SGD 的 SDE 近似、噪声二次模型**：用来做理论分析的标准工具。“偏差项—方差项”的分解，和学习率退火降低噪声的经典解释是一致的。
- **MoE 负载均衡**：数据分布突变导致路由不稳定，和课程切换、领域迁移时的路由漂移是同一类问题。

## 7. 疑点、局限与成本

1. **只看 loss，不看能力**：全文的评价指标都是 FineMath 或 StarCoder 验证集上的交叉熵，**没有任何下游任务评测**（例如数学题准确率）。作者在结论里把“加入下游指标”列为未来工作。
2. **模型规模小**：稠密模型 630M，MoE 总参数 2.99B。**论文未说明**这些结论在更大模型、更长训练下是否依然成立。
3. **起点特殊**：两种模型的 PT 阶段都是预热后恒定学习率、没有退火。如果你的 PT 检查点已经退火过（这是很常见的情况），结论能否照搬，**论文未说明**。
4. **峰值学习率没有扫描**：Const 用的就是峰值 5e-4。如果峰值学习率选得更低，Const 与衰减方案之间的差距可能会变。这是我的判断，论文没有做这项实验。
5. **理论的前提很强**：二次损失、加性噪声、块对角特征、幂律谱，还要求“预算足够小、训练足够长”。理论只能定性解释“为什么会反转”，不能直接给出实际要用的 γend 或衰减时长。
6. **重复次数有限**：只有 6 个配置做了重复，而且不涉及换预训练检查点的方差。
7. **AI 使用声明**：作者声明用生成式 AI 辅助检查数学推导、分析实验、撰写文稿。这不影响结论，但理论证明部分我没有独立核对。
8. **成本**：论文没有给出总 GPU 小时数。稠密模型每次继续训练约 210 亿 token，乘以 250 多次训练，大致可以估一下量级（我的判断）。
