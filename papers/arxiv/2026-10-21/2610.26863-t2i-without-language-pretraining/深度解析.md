## 1. 一句话要点与用处

作者训练了 Halcyon：一个"早融合"的自回归 Transformer，文字 token 和图像 token 放在同一个序列里，用 next-token 预测训练。它**不用任何预训练语言模型**，文本分词器、图像分词器和生成模型全部从零训练，只用 GPIC 数据集里约 1 亿对图文，分辨率 256×256，训练一个 epoch。

结果：
- Halcyon-0.52B 的 gFD 为 48.0，优于 LlamaGen-XL/8（FLAN-T5-XL 加 0.90B 生成器，63.3），总预训练算力少 18.2 倍。
- Halcyon-1.6B 为 35.3，优于 JiT-T2I-XXL/8++（Qwen3-1.7B 加 1.10B 扩散生成器，41.0），总预训练算力少 275 倍。
- 受控实验显示，在固定预算下加入纯文本预训练，或从 Qwen3-0.6B 继续预训练，都**没有改善**文生图质量。

**用处**：它挑战了"文生图必须依赖大规模语言预训练"的惯例。对于想从零训练小型多模态生成模型的团队，论文给出了一个更省的配方。

## 2. 实际痛点/场景

- 现代文生图系统主要有两种结构：
  - **晚融合**：用 T5、Gemma、Qwen 等预训练语言模型提取文本特征，再交给图像生成器。
  - **早融合**：一个多模态模型同时在纯文本和图文数据上训练，或者从预训练 LLM 初始化。
- 两种结构里，语言预训练往往占总预训练 FLOPs 的 80% 以上。但它对文生图到底有多大贡献，一直没有系统量化。而且发布时常常不把这部分成本计入"训练成本"。
- 场景：一个团队有大量图文对，但不想或不能依赖外部大语言模型，比如出于许可证、领域差异或算力的考虑；或者在生物数据等非自然语言的模态上做类似的条件生成（作者在讨论部分提到了这个方向）。

## 3. 方案思路与步骤（白话）

1. **分词器全部从零训练**：
   - 图像分词器：沿用 Cosmos 结构加 FSQ 量化，8 倍下采样，码本 64,000。一张 256×256 的图对应 32×32 = 1,024 个 token。
   - 重建质量（GPIC Test-50K）：rFD 18.86，Cosmos-DI-8x8 为 37.93；LPIPS 0.062。
   - 文本分词器：在 GPIC 字幕和 OpenWebText 上训练的字节级 BPE，词表 16,384。压缩率与 Qwen3 的分词器接近（4.774 vs 4.763 字节/token）。
   - 注意：OpenWebText 只用来训练分词器，不参与模型训练。
2. **联合词表与序列格式**：
   - 词表共 80,640 个 token（文本 16,384 + 图像 64,000 + 特殊 256），共享 embedding 和输出层。
   - 四种序列：纯文本（T）、纯图（I）、先图后文（I2T，用于看图说话）、先文后图（T2I）。
   - 损失：文本损失与图像损失加权，图像权重 λ = 0.5。
3. **无分类器引导（CFG）**：标准做法是随机丢掉 10% 的字幕来训练无条件分支。作者注意到 I2T 序列的前半段正好就是"无条件图像"，于是把这 10% 的"丢字幕"样本**换成 I2T 样本**。这样不增加预算、不减少图像 token，同时学会了看图说话。
4. **五种数据配比和调度的对照实验**：
   - 纯 T2I。
   - 先纯文本再 T2I。
   - 先 I2T 再 T2I。
   - T2I 与 I2T 混合。
   - 混合但不丢字幕。
   - 另外，从 Qwen3-0.6B-Base 继续预训练（扩展词表），并与同结构随机初始化的模型对比。
5. **基线全部在 GPIC 上重新训练**：作者用官方代码重新训练 LlamaGen 和 JiT-T2I。为了公平，还把 LlamaGen 的图像分词器换成 Halcyon 的（序列长度 1,024），给 JiT 加上 LPIPS 损失并改用 8×8 patch。
6. **规模**：0.1B、0.25B、0.52B、1.6B、4B 五个尺寸，序列长度 1,280，全局 batch 1,024，WSD 学习率调度。

## 4. 如何读实验与识别夸大

- **"少 18.2 倍 / 275 倍算力"主要是因为把基线的语言预训练算进去了**（附录表 15）：
  - JiT-T2I-XXL/8++ 的 3.68×10²³ FLOPs 里，99.82% 是 Qwen3-1.7B 的语言预训练（约 36T token），图像生成器只有 6.76×10²⁰。
  - Halcyon-1.6B 的总量是 1.34×10²¹，其中生成器 9.69×10²⁰，**比 JiT 的图像生成器还多**。
  - Halcyon-0.52B 的总量是 5.33×10²⁰，与 LlamaGen-XL/8 的视觉部分（4.76×10²⁰ + 1.45×10²⁰）相当。
  - LlamaGen-XL/8 的 9.68×10²¹ FLOPs 里，93.58% 是 FLAN-T5-XL 的语言预训练。
  - 只比视觉侧（生成器加分词器），两组对比的结论不一样：
    - 275 倍那组：Halcyon-1.6B 的视觉侧为 9.69×10²⁰ + 1.31×10²⁰ ≈ 1.10×10²¹，**比 JiT 的 6.76×10²⁰ 多约 1.6 倍**。
    - 18.2 倍那组：Halcyon-0.52B 的视觉侧为 3.22×10²⁰ + 1.31×10²⁰ ≈ 4.53×10²⁰，**比 LlamaGen-XL/8 的 6.21×10²⁰ 少约 27%**。所以"只比视觉侧就更费"这个说法只对 275 倍那组成立。
  - 我的判断：如果你本来就直接用现成的开源 LLM，那部分算力是"沉没成本"，倍数省不下来。这个比较的真正意义是"语言预训练对文生图质量的边际贡献很小"，而不是"训练更便宜"。
- **JiT 基线的 41.0 是作者改造后的版本**：
  - 原版 JiT-T2I-XXL/16 在 GPIC 上是 67.9。
  - "++"表示作者加了 LPIPS 感知损失（降到 48.9），"/8"表示再改用 8×8 patch（降到 41.0）。
  - 这些改造让基线变强，对 Halcyon 来说是更严格的比较，但它已经不是原论文的配置。
- **公开基准上的差距比 gFD 小得多**：
  - Halcyon-1.6B 对 JiT-T2I-XXL/8++：GenEval 53.5 vs 43.2，DPG-Bench 只有 77.9 vs 76.85。
  - Halcyon-0.52B 对 JiT-T2I-XXL/8++：GenEval 44.9 vs 43.2，DPG-Bench 76.84 vs 76.85，基本持平。
  - Halcyon-0.52B 对 LlamaGen-XL/8：GenEval 44.9 vs 30.5，DPG-Bench 76.8 vs 67.1。
- **0.52B 并没有全面超过 JiT**：gFD 48.0 不如 JiT-T2I-XXL/8++ 的 41.0。GenEval 略好（44.9 vs 43.2），DPG-Bench 持平（76.84 vs 76.85）。论文原文措辞是"approaching"，这一点是准确的。
- **主要指标来自作者自己的数据集**：
  - GPIC 由第一作者团队发布（Chandrasegaran et al. 2026，arXiv 2605.30341）。gFD 在 GPIC 测试集上测，属于同分布评测；所有基线也只在 GPIC 上训练了一个 epoch。
  - 这对公平对照有好处，但结论只代表 1 亿对图文、256×256、一个 epoch 的设置。
  - 绝对水平不高：GenEval 最高 56.4（4B），与工业级系统差距很大。
- **"纯文本预训练没帮助"的证据**：
  - 固定预算下拿出 α = 0.1/0.2/0.5 做纯文本预训练，gFD 从 48.0 变差到 51.6/52.8/65.1。
  - 额外再补一整个 T2I epoch（总算力 1.5 倍），gFD 为 49.2，也没有变好。
  - 从 Qwen3-0.6B 继续预训练为 47.8，随机初始化为 46.6。
  - 只测了 0.52B / 0.6B 这一个规模，作者在局限里也承认了。
  - 继续预训练时把学习率降到 1e-4，反而更差（63.6）。是不是还有更合适的继续预训练方式，**论文未说明**。
  - 表 7 中继续预训练模型的"看图说话"文本 bpb 更低（4.974 vs 5.436），说明语言预训练对**字幕建模**可能有帮助。论文没有讨论这一点（我的判断）。
- **语言编码器大小的证据**：LlamaGen 从 FLAN-T5-XL 换成 Base，gFD 只从 63.3 变到 66.7，与 Parti 的旧结论一致。
- **README 描述**："只用 1 亿图文对从零预训练……0.52B 版 gFD 优于 LlamaGen-XL/8 且预训练算力少 18.2 倍，受控实验显示纯文本预训练对文生图没有帮助"，与原文一致。补充两点：算力倍数包含基线的语言预训练；"没有帮助"仅限于测过的设置。

## 5. 落地分层

**今天能试**
- 如果要从零训练文生图模型，可以借鉴三点：
  - 把 CFG 里丢掉的字幕样本换成 I2T 样本，同样的预算就能多学会看图说话。
  - 图像表示比语言编码器大小更重要：LlamaGen 换用 Halcyon 的分词器后（序列从 256 增到 1,024），gFD 从 147.0 降到 63.3；而把语言编码器从 FLAN-T5-XL 换成 Base，gFD 只从 63.3 变到 66.7。
  - 模型越大，最佳 CFG 越小（0.1B 时 7.5，4B 时 4.5）。
- 权重已经放在 HF（radicalnumerics/halcyon），可以下载对比。论文说"checkpoints 已公开"，但代码仍是 coming soon。

**需要资源**
- 复现需要 GPIC（1 亿对图文）和约 10²⁰–10²¹ FLOPs 量级的预训练（视模型大小而定）。具体 GPU 小时数，我没有在附录里找到汇总（未核实）。

**可跳过**
- 高分辨率、文字渲染、商业级画质：论文只做了 256×256，作者也说小字和字形重建较差。

## 6. 与已知概念的挂钩

- **早融合与晚融合**：早融合的代表有 Chameleon、Emu3、Transfusion；晚融合的代表有 Imagen、PixArt-α、SANA、LlamaGen。
- **DALL·E、CogView、GLIDE**：早期这些系统也不依赖语言预训练，本文相当于用现代配方重新回答了这个老问题。
- **Imagen 与 Parti 的分歧**：Imagen 认为扩大文本编码器有益，Parti 认为编码器预训练只有边际收益。本文结果更接近 Parti。
- **FSQ 离散分词器、WSD 学习率调度、无分类器引导（CFG）**。
- **FID 的变体 gFD**，以及 Precision/Recall/Density/Coverage 等分布指标。

## 7. 疑点、局限与成本

论文自己写的局限：
- 只用了 GPIC，分辨率只有 256。
- 数据配比实验只在 0.52B 上做，继续预训练实验只用了 Qwen3-0.6B。
- 受控干预只针对自回归模型，没有覆盖 Transfusion 式的扩散混合模型。
- 文生视频方向尚未验证。

我的疑点：
1. 275 倍这种标题级数字容易被误读为"训练省了 275 倍"，见第 4 节。
2. 评测集与训练集同源（GPIC）。在其他数据或开放域提示词上，排序是否还成立，未知。
3. 基线是作者在新数据上用官方代码重新训练的，超参数是否调到了各自的最佳状态，难以判断。附录表 16 有各模型的 CFG 设置，但我没有细看其他超参数。
4. 结论是"在这个规模下语言预训练没帮助"。更大规模、更长或更复杂的提示（比如需要常识、计数、文字）是否仍然成立，论文没有测试。
