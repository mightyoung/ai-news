## 1. 一句话要点与用处

拿 Qwen3-4B-Base 和它用 GRPO 训练出的 RL 版本做对比实验，结论如下：
- 只在"两个模型贪心选择的下一个 token 不一样"的位置改用 RL 模型的 token，其余全部由基座模型照常采样。这些位置占全部生成 token 的 4.0%，按单条回答平均是 4.5%。这样就能在 120 道 AIME 题上找回 RL 带来的 pass@1 提升的 **90.5%**（表 2：10.00% → 18.44%；RL 模型本身是 19.32%）。
  - 这个比较的条件是**相同尝试次数**（每题都采样 16 次），**不是相同算力**：rl-replace 每一步都要同时跑两个模型。
  - 数据只来自一对模型：Qwen3-4B-Base 和作者自己用 GRPO 训练的版本。
- 只强制开头写一个 "Alright"，能找回 35%。
- 用固定规则插入 "Wait" 之类的反思词，反而让成绩变差。
- 这种"稀疏替换"保留了更多多样性：k=256 时解出 67.5% 的题目，RL 模型是 61.4%。
  - 这组数字来自表 6，是另一次独立运行，和 90.5% 不是同一次实验。
  - 比较的同样是相同尝试次数。
  - rl-replace 对 RL 模型的优势显著；对基座模型（61.64%）的优势不显著，95% CI 为 [−0.33, 10.71]，包含 0。

**用处**：它给"RL 到底教会了模型什么"提供了一套可以对比的干预实验方法。结论是：增益集中在少数关键位置的选择上，而不是"多反思"这种表面习惯。

## 2. 实际痛点/场景

- RLVR（用可验证奖励做强化学习）明显提升了数学推理，但学界一直在争论：它是教会了新能力，还是只把基座模型本来就会的东西"挑"了出来。
- 已有的观察很零散：RL 模型开头千篇一律（16 次回答里平均只有 3.2 种开头，基座模型有 15.6 种）、更爱说 "Wait"（每次回答约 5.7 次，基座模型约 0.3 次）、回答更长。但"哪一个变化真正带来了增益"一直没人在同一设置下量化过。
- 工程上的意义：如果增益只来自少数 token，那就可以考虑只在关键位置用强模型，或者设计更省的训练和解码方案。不过作者明确说 rl-replace 本身很贵，只是一种诊断工具，不能直接拿来部署。

## 3. 方案思路与步骤（白话）

1. **准备一对模型**：Qwen3-4B-Base 不做 SFT，直接在 DAPO-Math-17k 上用 verl 跑 GRPO。训练前删掉了和 AIME 2022/2023 重复的题；checkpoint 按 DAPO 验证集挑选（第 460 步）。此外还按同一配方训练了 Qwen3-8B 和 Llama-3.2-3B 两对模型，用来检验结论是否稳健。
2. **评测**：主战场是 AIME 2022–2025 共 120 题，每题采样 16 次；MATH-500 作为较简单的基准，每题 64 次。温度 0.6，top-p 0.95，最多生成 8,192 个 token。用"恢复率" R = （干预后 − 基座）/（RL − 基座）来衡量每种干预找回了多少 RL 增益。
3. **测试 0：幂采样（MCMC 锐化基座分布）**：在 MATH-500 上能提升 2.35–3.50 个点，但在 AIME 上基本不比贪心解码好。生成很长时还容易出问题：没给出最终答案的比例从 12.2% 升到 22.4%，陷入重复的比例从 6.7% 升到 13.1%。
4. **测试 1：rl-replace**：每一步两个模型都算一遍。贪心 token 相同时，从基座模型按温度 0.6 采样；不同时，直接输出 RL 模型的贪心 token。被替换的 token 只占约 4%，但回答平均长度从 3,248 涨到 6,217，接近 RL 模型的 6,504。说明少数选择就能改变整篇回答的走向。
5. **测试 2：开头的作用**：
   - rl-replace 的 1,920 条回答全部以 "Alright" 开头。
   - 只强制写 "Alright"：pass@1 达到 13.23%，恢复 35%。
   - 同样的开头加上后续替换：多出 5.2 个点（95% CI [3.1, 7.6]），相当于 RL 增益的 56%。
   - 同一规则下，在分歧位置改用基座模型自己的贪心 token：只有 14.74%。
6. **测试 3：规则插入反思词**：
   - 统计了 19 道"基座 16 次全错、rl-replace 至少对一次"的题，其中 38 条成功回答里的 9,099 处实际替换：74.7% 是普通实词改写，开头词、停顿词加上 "Re" 前缀只占 2.6%。
   - 硬规则（强制插 "Wait" 或 "Re"）让 pass@1 比基座低 5.5–7.7 个点。
   - 软规则（给 "Re" 的 logit 加偏置）没有任何提升。
7. **多样性与大 k 覆盖**：
   - 基座和 RL 模型每题采样 512 次，rl-replace 每题 256 次。
   - k=256 时，rl-replace 为 67.50%，RL 为 61.40%，基座为 61.64%。按 pass@1 配平的"整条回答混合"策略（以 0.92 的概率选 RL）为 61.45%。
   - rl-replace 比 RL 高 6.10 个点（CI [0.82, 11.02]）；比基座高 5.86 个点，但 CI [−0.33, 10.71] 包含 0。

## 4. 如何读实验与识别夸大

- **"约 4%"是 token 数量上的稀疏，不是影响上的稀疏**：作者自己强调了这一点，借来的 token 会改变整篇回答的走向。
- **增益提升本身很小，置信区间很宽**：主实验中，基座 10.00%、RL 19.32%，差 9.3 个点，题目只有 120 道。90.5% 的恢复率（相同尝试次数下的比较，并非相同算力）95% CI 是 [77.0, 108.6]；分组看 AIME24+25 是 92.1%，AIME22+23 是 87.7%，两组差异的区间为 [−32, +41]。不同次运行之间，基座 pass@1 就在约 8.2%–10.26% 之间波动。所以 1–2 个点的差别（比如软规则 −1.5）不能当真，作者也是这么处理的。
- **大 k 覆盖的比较是"同等尝试次数"，不是"同等算力"**：rl-replace 每一步都要跑两个模型。摘要和正文都写明了这一点，读的时候不要理解成"更省"。一个 AIME 年份（30 题 × 16 次）就要 7.3–7.9 GPU 小时，大 k 实验共约 1,012 GPU 小时。
- **"对基座也有覆盖优势"并不显著**：区间包含 0，作者也写了"less certain"。
- **结论的适用范围**：
  - 开头和反思词的消融（测试 2、3）只在 Qwen3-4B 上做过。
  - 测试 0、1 在三对模型上用 MATH-500 复现；Llama 只在 MATH-500 上评测。
  - 只覆盖数学题、8,192 token 上限、一种 RL 配方（GRPO + DAPO-Math）。
  - 作者说负面结论"只限于测试过的固定规则"，没有评测学习式或基于熵的位置选择。
- **数据污染**：
  - 训练集只按 AIME 2022/2023 去重。AIME 2024/2025 是否也在 DAPO-Math-17k 中出现，**论文未说明**。
  - 我的判断：两组的恢复率相近，说明污染对"恢复率"这个结论的影响可能不大，但我没有核实。
- **提示格式不一致**：RL 训练用的是 DAPO 原始格式（以 "Answer:" 结尾），评测用的是关闭思考模式的聊天模板加 \boxed{}（附录 B）。这对 RL 模型的绝对分数有多大影响，**论文未说明**。
- **README 描述"说明 RLVR 带来的是少量关键决策"**：大体符合，论文标题就是这个意思。但论文明确说这些结果**不能证明** RL 创造了基座模型无法生成的推理路径，也不能证明多样性下降是覆盖率差异的原因。

## 5. 落地分层

**今天能试**
- 想分析自己的 RL 模型，可以复用这套"干预 + 恢复率"的方法：先跑 base 和 RL 的贪心分歧率，再试只强制开头的效果。
- 别指望靠"多插 Wait"或"强制反思"的提示和解码规则复现 RL 的效果，论文里这类做法都变差了。

**需要资源**
- rl-replace 需要两个模型同步解码，用 vLLM 双引擎时一个 AIME 年份就要 7–8 GPU 小时。只适合做诊断，不适合直接上线。
- 附录 E 显示，只用基座模型自身的置信度特征，就能以 AUROC 0.94–0.98 定位"RL 会改变分布"的位置（门控在 90% 召回下精确率只有 0.54/0.62）。作者也说"难的是在那里选对 token"。用它做"只在少数位置调用强模型"的级联系统还停留在设想阶段（我的判断）。

**可跳过**
- 把 MCMC 幂采样当成"免训练替代 RL"的方案。在 AIME 这类长生成任务上，论文显示它基本没用。

## 6. 与已知概念的挂钩

- **RLVR / GRPO / DAPO**：用可验证奖励做强化学习的主流做法。
- **"RL 只是提高采样效率"之争**：Yue et al. 2025 发现大 k 时基座模型会追平 RL 模型。本文在 4B 上复现了这一点：k=256 时 RL 与基座几乎持平。同时指出 RL 模型的 token 选择嵌入别的生成策略后，仍然有用。
- **高熵分叉 token**：RL 的改动集中在少数高熵 token 上，与相关工作一致（Wang et al. 2025a、Meng et al. 2026）。
- **对比解码、代理调优、投机解码**：rl-replace 是一种在解码时组合两个模型的方式，作者引用了这几类方法作为渊源。
- **pass@k 无偏估计**：Chen et al. 2021 的估计方法，配合 bootstrap 置信区间。

## 7. 疑点、局限与成本

1. **规模小**：主模型只有 4B（大 k 实验补充了 8B），数学题只有 120 道，结论能否推广到更大模型、更长生成或非数学任务，未知。
2. **只用了一种 RL 配方**：GRPO + DAPO-Math，直接从基座训练、不做 SFT。蒸馏或 SFT+RL 的模型是否同样"稀疏"，**论文未说明**。
3. **"开头 35%"与"后续 56%"可能有交互**：作者自己说后续替换的收益"可能包含与开头的交互，未分离"。
4. **算力**：诊断实验很贵。按作者给出的数字，rl-replace 一个 AIME 年份需要 7.3–7.9 GPU 小时（H800），MATH-500 约 55 GPU 小时，大 k 实验约 1,012 GPU 小时。
5. **我的判断**：这篇论文更像是一篇"测量"工作，没有给出新的训练方法；它的价值在于把几种流行解释放在同一设置下比较。
