## 1. 一句话要点与用处

作者问："触觉能不能不只是策略的输入，而是大规模预训练里的监督信号？"做法：用戴手套的人类示教（HumanTouch，1000 小时、每只手 320 个有效触觉点）把"哪里在接触"渲染成图像上的接触热图，只在训练时监督视觉 token（部署时扔掉）；另有一条触觉通路只喂动作专家（"接触如何演变"）。同一个检查点既可纯视觉部署，也可带触觉部署。论文报告：在 Ego Humanoid 基准上，同样数据同样算力、仅"去掉触觉"的纯视觉预训练为 52.45%，保留 1000 小时触觉为 71.72%；自建的真机基准 SparkArena-Real 上 44.0%→52.0%。**用处**：对做灵巧手 / VLA 的人，提供一个"手套数据 + 训练时接触监督 + 可选触觉输入"的完整参考和开源代码；但"触觉预训练有普遍增益"的证据偏薄（见第 4 节）。

## 2. 实际痛点/场景

- 灵巧手操作（插入、堆叠、顺应地装箱）里，力、顺应性、接近滑动的信号在图像里看不清，手本身还会遮挡接触区。
- 大规模全手触觉数据稀缺：机器人遥操作贵、接触种类窄；触觉往往只当推理时的输入，而部署的机器人未必有触觉传感器。
- 缺少能同时衡量"纯视觉灵巧"和"带触觉的真机接触控制"的同一具身基准。

## 3. 方案思路与步骤（白话）

1. **采数据（HumanTouch）**：双手柔性压阻手套（每只手 460 个点，其中 140 个在弯曲部位因为会产生假压力被屏蔽，剩 320 个）、25 关节手指追踪、腕部 6 自由度追踪、头戴相机加两个腕部相机，60 Hz 同步；100+ 任务，32 名操作员，1000 小时。同款手套可以装在机器人手上，所以人和机器人数据的触觉布局一致。
2. **统一动作空间**：所有数据转换成目标机器人的双臂格式（每侧：末端位姿 + WUJI Hand 2 的 20 个关节角，共 58 维），人手数据用逆运动学重定向。
3. **模型**：Qwen3-VL-4B 做视觉语言主干，36 层 flow-matching 动作专家（宽 1024，一次预测 50 步动作块，推理用 4 步欧拉）。
4. **训练时的"空间对齐"（两个只在训练用的损失）**：(a) 几何对齐：让第 25 层视觉 token 去匹配冻结的 Depth-Anything-3 的特征；(b) 接触对齐：把有压力的触觉点贴到 MANO 手网格上，沿手表面扩散，渲染到头部相机画面，得到"接触热图"，让视觉 token 预测它（focal + Dice 损失）。总损失 = 动作损失 + 0.2×几何损失 + 接触损失。部署时全部拿掉。
5. **触觉通路（推理可选）**：20 帧（约 333 ms）力历史 + 当前 320 个点的三维位置与压力，编码成 24 个触觉 token，只进动作专家，不进视觉语言主干；没有触觉的样本用一个学出来的"占位符"，门控初始 0.1。训练时还偶尔把状态/动作行的视觉交叉注意力清零，迫使动作信息经过触觉行（"捷径"，概率最高 0.1）。
6. **预训练**：40 万步，混合 7 个来源（按采样权重，不按小时）：HumanTouch 0.35、EgoDex（662 小时第一视角视频）0.39、同款手套机器人数据（20 小时）0.09、去掉触觉的机器人数据 0.05、仿真 0.05、Fourier ActionNet 0.04、AgiBot World 0.03。12 个节点 ×8 卡，全局批 576。之后在每个基准的下游数据上微调 8 万步。
7. **评测**：SparkArena（作者自建）：Sim 7 个纯视觉任务；Real 5 个带触觉的接触任务，同一具身 Gen 1 Prototype（双 Marvin M6S 臂 + 双 WUJI Hand 2）；另在第三方基准 Ego Humanoid Manipulation Benchmark（EgoVLA 提出）上测纯视觉跨具身迁移。

## 4. 如何读实验与识别夸大

**四个变体**（微调数据与优化预算相同，只差预训练）：Scratch（不预训练，从 Qwen3-VL 起步）；Visual PT（用 1000H 同样的预训练数据，但丢掉所有触觉信号和接触对齐目标）；100H / 1000H（保留 100 / 1000 小时 HumanTouch 的触觉）。

表 4（SR%）：

| 变体 | SparkArena-Sim | Ego Humanoid（4 设置均值） | SparkArena-Real |
|---|---|---|---|
| Scratch | 31.71 | 58.34 | 38.00 |
| Visual PT | 36.57 | 52.45 | 44.00 |
| 100H | 35.14 | 59.42 | 40.00 |
| 1000H（= Spark-0） | 36.86 | 71.72 | 52.00 |

**要点**：
- **"52.5→71.7"的基线是 Visual PT，比不预训练的 Scratch（58.34）还低**。所以 +19.27 是相对"去触觉的视觉预训练"；相对 Scratch 是 +13.38。拆开看，Visual PT 低主要因为长时程任务：Ego Humanoid 四个设置里 Visual PT 为 65.08 / 60.39 / 48.89 / 35.45，Scratch 为 62.96 / 54.98 / 61.48 / 53.94（我用逐任务表核算，均值与表 4 吻合）。也就是说"纯视觉预训练伤害了长时程"这个现象本身没被解释（论文未说明）。
- **100H 只有 59.42，与 Scratch 的 58.34 基本相同，在 Sim 和 Real 上不超过 Visual PT**；论文自己说"收益在完整 1000 小时规模才明显"。这是"规模效应"的证据只有两个点（100H、1000H），并且 Sim 上 1000H 比 Visual PT 只多 0.29。我的判断：与其说触觉预训练稳定有用，不如说在 Ego Humanoid 上有一个大幅度变化、其他两个基准没有可分辨的变化。
- **"触觉"的因果归因有混杂**：Visual PT 同时去掉了触觉通路的预训练与接触对齐损失，论文没有把"接触热图监督""触觉通路""几何对齐"三者分开消融（论文未说明 Visual PT 是否保留几何对齐，推测保留）。100H 变体里另外 900 小时 HumanTouch 是否作为纯视觉数据保留：**论文未说明**。
- **机制解释是推测**：§6.3 写 "One explanation is that contact supervision improves transfer to an unseen visual domain"，没有实验验证。作者自己在附录 C.1 承认接触图"覆盖几乎整个可见的手，编码的是手级别的接触区域而不是精确接触点"，并且包含被物体挡住的区域；这与"精确的空间对齐"的标题略有张力。
- **Ego Humanoid 是纯视觉部署（不用触觉）**，每个任务 seen 27 次、unseen 66 次，成功率粒度分别约 3.7 / 1.5 个百分点。逐任务数字波动极大：例如短时程 seen 的 Open-Drawer，Scratch 3.70、Visual PT 48.15、100H 88.89、1000H 77.78，所以均值里的每个任务都有很大噪声；论文没有任何置信区间或重复运行。是模拟还是真机：论文没有单独说明；相关工作把它放在"大多在模拟中评测"的基准里（我的判断：Ego Humanoid 是模拟基准）。
- **SparkArena-Real 只有 5 任务×每任务 10 次 = 50 次**。Visual PT 44.0 → 1000H 52.0 的差是 4 次试验：逐任务（表 11）：Insert Test Tubes 0→0、Pack Shoes 80→80、Stand Up Bottle 80→80 完全没变，**差别全来自 Place the Phone（40→50，多 1 次）和 Stack Bowls（20→50，多 3 次）**。而 Scratch 在 Stack Bowls 是 60，比 1000H 的 50 还高。论文没有置信区间、没有重复，用的是"成对初始条件"来降噪。我的判断：这个 +8 在统计上无法与噪声区分。
- **和基线比的公平性**：
  - SparkArena-Sim：Spark-0 36.86% vs 最强基线 FastWAM 28.29%（+8.57）。但 **Scratch（31.71）已经超过所有基线**，而且 Visual PT（36.57）几乎与 Spark-0 持平。所以对最强基线的优势主要来自架构与预训练数据（含 Gen 1 Prototype 本体的机器人与仿真数据，论文说"已出现在预训练中"），不是触觉。
  - SparkArena-Real：Spark-0 带触觉部署（52%），所有视觉基线（π0.5、GR00T-N1.7、StarVLA、RDT-1B、H-RDT、X-VLA）不带；唯一的触觉基线是 FTP-1（36%）。RDT-1B 与 H-RDT 全任务为 0。Pack Shoes 上 FTP-1 与 Spark-0 同为 80%。Insert Test Tubes 没有任何方法成功（成功率 0，但 Spark-0 完成度分最高 31）。
  - **基线怎么训的**：下游微调的示教条数、基线是否由作者复现、超参是否调过——**论文未说明**（附录 F 只描述了基线的结构）。Ego Humanoid 表里的基线数字是引用还是重跑，论文未说明。
  - SparkArena 是作者所在公司（Xspark AI）自建并发布的基准；Ego Humanoid 是第三方基准。
- **种子**：预训练超参表里 Seed 0，没有重复种子；全文没有方差、误差棒或统计检验；没有 Limitations 专节。
- **"排名第一"的措辞**："Ego Humanoid 8 项汇总指标全部第一"属实（表 2，其中如 seen 长时程 PSR 仅领先 0.18）；"优势随任务长度增加"是在 Visual PT 下降的背景下的相对比较。

## 5. 落地分层

**今天能试**
- 如果你已有 StarVLA / XPolicyLab 环境：先读代码仓库的 `pretrain_spark_0`、`sft_spark_0` 配方与 HF 权重（我没有读，可用性请自行确认），在纯视觉场景下作为一个强的灵巧手 VLA 基线试一下。
- 借鉴思路（不需要新硬件）：训练时加"辅助监督、推理时丢弃"的设计（几何特征蒸馏 + 接触预测），并用"缺失模态占位符 + 门控"让有/无触觉的数据混训。

**需要资源**
- 复现预训练：论文给的是 12 节点 ×8 卡、40 万步、全局批 576（GPU 型号论文未说明），外加 1000 小时 HumanTouch 数据（是否公开论文未说明）。
- 采自己的触觉数据：双手压阻手套、手部追踪、3 个相机、与机器人手同款的手套布局；以及 MANO 重建、接触图生成管线。
- 真机复现 SparkArena-Real：需要同款（或等价）双臂 + 灵巧手 + 触觉手套；论文列了物品购买链接。

**可跳过**
- 把"52.5→71.7"当作"加触觉预训练就提升 19 个点"的通用结论；
- 把 SparkArena-Real 的 44→52 当作触觉有用的证据（4 次试验、无置信区间）；
- 触觉的规模定律（只有 100H、1000H 两个点）。

## 6. 与已知概念的挂钩

- **VLA / π0 系列 / StarVLA / GR00T**：同属"VLM + flow-matching 动作专家"。
- **表示对齐（REPA 式）与蒸馏**：几何对齐就是让中间层 token 去匹配冻结的视觉基础模型特征（这里是 Depth-Anything-3）。
- **特权信息 / 训练时辅助监督**：接触图只在训练出现，类似"learning using privileged information"（我的判断：这是最贴切的类比）。
- **模态缺失与占位符 + 模态 dropout**：多模态混训里的常见做法。
- **人类视频/示教预训练**：EgoVLA、H-RDT、VITRA、UniT、EgoDex 是"用人手数据预训练"路线；Spark-0 的新增点是"人手 + 触觉"。
- **Real-Time Chunking（RTC）**：部署采用的异步重规划。
- **与相关触觉工作**：FTP-1（跨传感器触觉基础策略）、STAR（200 小时双臂数据）、T-Rex 等被引用为相关/基线。

## 7. 疑点、局限与成本

论文没有专门的局限性章节。我读下来的疑点：
1. **核心增益只在一个基准上显著**：Ego Humanoid +19.27；Sim +0.29；Real +8（4 次试验）。
2. **基线（Visual PT）本身反常地差于 Scratch**，让 +19.27 的含义大打折扣（相对 Scratch +13.38）；Visual PT 为何伤害长时程，论文未说明。
3. **没有统计不确定性**：单种子、无置信区间；Ego Humanoid 逐任务波动达数十个百分点；Real 只有 50 次。
4. **混杂因素**：触觉通路预训练、接触损失、（可能的）几何损失一并被"去触觉"去掉；接触图的精度被作者自己承认是"手级别"。
5. **机制解释未验证**，且论文没有分析"为什么是在未见过的人形具身上收益最大"，也未分析是否因人手数据与 Ego Humanoid 的视觉域更接近而与触觉无关（我的判断：这是个应该被排除的替代解释，但论文没有排除）。
6. **公平性**：Real 上视觉基线不带触觉；基线的微调数据与调参未披露；SparkArena 为作者自建、预训练里已含该具身数据（Sim 的优势部分来自此）。
7. **规模结论薄弱**：只有 100H 与 1000H 两点。100H 变体剩余数据如何处理未说明。
8. **成本**：96 张卡量级的预训练（40 万步）、1000 小时人工采集、32 名操作员、定制手套与机器人；采集管线与手套硬件很难复用。
9. 论文把 Ego Humanoid 的 52.45 / 71.72 在摘要里四舍五入为 52.5 / 71.7（附录 G.1 自己写明）。

**未核实项**：GitHub 仓库实际内容与权重是否可用、HumanTouch 是否公开；基线数字是否由作者重跑；Ego Humanoid 是否为模拟（我的判断：是，论文未明说）；表 7 的评分细则；图中的细节；Ego Humanoid 逐任务表 9、10 的全部数字（只核对了均值与若干条目）；参考文献。
