## 1. 一句话先懂它

作者做了一个「诊断 GPU 训练故障」的题库，能用程序自动判分。他们发现：先拿 1,200 道标准答案做一次监督微调，模型就几乎学会了；之后再用强化学习按判分器的分数练 60 步，题库内部几乎没有提升，换一批变体题也只多了零点几分。它提醒你：先买示范数据，再让强化学习拿 SFT 版本当对照来证明自己值钱。

## 2. 值不值得读：五个 C 速览

**类型**：测量分析，附带一个自建基准。**上下文**：接着「先 SFT、后 RLVR（Reinforcement Learning from Verifiable Rewards，用程序能判对错的奖励做强化学习）」这条主流后训练流水线，直接引用 Tulu 3、DeepSeek-R1，以及 GRPO 的出处 DeepSeekMath。**关键假设**：示范数据是生成器给的金标答案，质量到顶；判分器是确定性的、有细粒度部分得分；只用一个 3B 模型、60 步、一个训练种子。这些都是有利于 SFT、不利于 RL 的条件，作者自己在局限一节都列了，结论只能在这个范围里成立。**贡献**：一是 gpu-train-debug 基准（1,877 道题、30 类）；二是一次把问题「写下来再改」的预注册式对照实验；三是一个解释——SFT 之后剩下的错误大多是「每次都错得一模一样」，GRPO 因此拿不到学习信号。**清晰度**：写得很清楚，8 页没有藏东西，但训练超参只有几行。建议**看到第 5 节**；如果你在决定后训练预算怎么分，值得自己读原文第 5–7 节，只要 20 分钟。

## 3. 它在解决什么麻烦

现在做后训练，大家常常走两步：先用示范数据做 SFT（监督微调，让模型照着标准答案学），再用可验证奖励做强化学习。问题在于，论文和技术报告里报的往往是「整条流水线比基座强多少」或者「RL 比基座强多少」，很少有人单独量一下：在已经做完 SFT 的模型上，RL 这一步到底又多带来了多少。可这个数字恰恰决定下一笔钱该花在找示范数据上，还是花在跑 RL 上。

工程上你会在这种场景撞上它：团队想给内部工具问答、日志诊断这类结构化任务做后训练，手里已经有一批人工或老师模型写的标准答案，又听说「RL 才是能力上限」，于是规划了一大笔 GPU 预算去跑 GRPO（Group Relative Policy Optimization，组相对策略优化：同一道题采多条回答，按它们彼此之间的得分高低来决定奖惩）。跑完发现分数比基座高很多，就以为 RL 很有用，其实大部分提升 SFT 早就拿到了。

作者把这个对照做干净：同一个题库、同一个判分器，SFT 和 RL 看到的是同一批题；再留一个从没碰过的分布外（OOD，Out-of-Distribution：训练时没见过的变体）测试集，提前写死检验方法和措辞。如果这个结论在你的任务上也成立，你就可以先把钱花在示范数据上，RL 只在通过对照检验后再放大。

## 4. 他们怎么做的

**核心思路**：先确认任务本身「可测、可比」，再把 SFT 和 SFT+RL 放在同一把尺子上比，并且提前把「多大算有效」写下来，防止事后挑好看的说法。

**题库**（第 2 页）：每道题给一个坏掉的训练配置、性能分析摘要和日志片段，要求模型输出 JSON：故障代码、中间计算量（例如配置实际对应的全局 batch size）、修正后的配置字段。判分器会自己重算标准答案，按目标逐项给部分分，全程没有奖励模型、没有大模型当裁判。30 类题覆盖单故障、需要计算的、多故障互相影响的、以及「陷阱题」（最显眼的日志是误导，真正故障很平常）。切分为 train 1,200、hard 200、test 236、OOD 241。作者还专门堵了答案泄露：早期版本里一个关键词规则能拿 1.000，加固后降到 0.296；gpt-4.1-mini 得 0.676，落在他们设定的 0.60–0.75 目标区间（第 2 页）。

**第一阶段：先导实验**（第 3 页）。基座是 Qwen2.5-3B-Instruct。SFT 训 1 轮，GRPO 从基座跑 15 步。结果 SFT 一下到 0.785，GRPO 几乎没动（Table 1，第 3 页）。作者于是书面修改了研究问题：不再问「谁更好」，改问「示范数据之后 RL 还能加多少」。

**第二阶段：预注册正式实验**（第 3–4 页）。四个臂：A 基座、B 只做 SFT（2 轮）、C 先 SFT 再 GRPO 60 步（主臂）、D 从基座直接 GRPO 60 步（探索性对照）。主检验是 C 减 B，在 hard 和 OOD 上各做一次配对 bootstrap（对题目有放回地重抽 1 万次，看差值的 95% 置信区间是否跨过 0）。GRPO 设置：每组 8 条、每步 16 个 prompt、温度 0.9、clip 0.2、KL 系数 0.0、学习率 1e-6（第 4、6 页）。评测统一温度 0.7、每题 3 次采样、只看最终 checkpoint。还设了一道「SFT 闸门」：B 的 hard 均分至少 0.70 才允许开始跑 C。作者顺手抓到一个坑：原配置的 1024 token 上限会把所有训练标签截掉，SFT loss 必然是 NaN，实测 prompt 需要 1664（第 4 页）。

**如果让你复现**，最小骨架是：

```python
tasks = generate_splits(seed)                      # train/hard/test/ood，固定种子并去重
base = load("Qwen2.5-3B-Instruct")
B = sft(base, tasks.train, epochs=2)               # 金标示范
assert eval(B, tasks.hard) >= 0.70                 # SFT 闸门
C = grpo(B, reward=grader, steps=60, lr=1e-6, group=8)
D = grpo(base, reward=grader, steps=60, lr=1e-6, group=8)
for split in [tasks.hard, tasks.ood]:
    diff = paired_bootstrap(eval(C, split), eval(B, split), n=10000)  # 看 95% CI 是否跨 0
```

SFT 的学习率、batch 等超参论文未说明；代码仓库当前 404，无法核对实现。

## 5. 证据怎么看、别被什么忽悠

**表一：Table 1（第 3 页），先导实验。** 想证明：在这个题库上，示范数据比短程 RL 有效得多。设置：Qwen2.5-3B-Instruct，自建 gpu-train-debug hard split，mean reward（每题部分得分的平均），每题 3 次 rollout（一次「按当前模型生成一个回答」）；15 步 GRPO 是先导实验。结果：基座 0.311，GRPO 15 步 0.314，SFT 1 轮 0.785。说明：15 步 RL 几乎没动，示范数据一轮就涨了 47.5 分。但 15 步确实太短，作者自己也承认，所以才在正式实验里加了 D 臂。

**表二：Table 2（第 4 页）和预注册检验（第 4–5 页），正式结果。** 想证明：SFT 之后再 RL 能加多少。结果：hard 上 B 0.828、C 0.830；OOD 上 B 0.855、C 0.858；D 只有 0.325 / 0.370。C 减 B 的检验：hard（n=180）+0.22 分，95% CI [-0.06, +0.51]，跨过 0，算「分布内没有可检测的增益」；OOD（n=168）+0.33 分，CI [+0.02, +0.68]，不跨 0，按预先写好的措辞叫「modest but measurable（小但可测）」。注意这里的「分」是 mean reward 乘 100，+0.33 分就是 0.855→0.858 这个量级；而且只有一个训练种子。

**图二：Figure 2（第 5 页），增益分账。** 在 OOD 上，示范数据贡献 +51.5 分，之后的 RL 贡献 +0.33，直接从基座做 RL 贡献 +3.0；hard 上对应 +51.9、+0.22、+1.6。第 6 页的余量分析换算成：SFT 拿走了基座可提升空间的 75%（hard）和 78%（OOD），RL 只吃到剩余空间的约 1–2%。

**为什么 RL 动不了**（第 5–6 页）：B 和 C 在 hard 200 题里只有 17 题分数有任何差别，OOD 241 题里只有 24 题。SFT 后没饱和的题中，3 次采样得分完全相同的有 95/160（hard）和 89/163（OOD）。GRPO 靠「同组内不同回答的得分差」学习，大家分数都一样，优势就是 0。作者明确说这是「机制假设，不是已证明的结论」。

**水分检查**：①种子：RL 只有一个训练种子，置信区间来自对题目重抽，不含训练随机性，+0.33 这种量级很可能被种子方差淹没。②基线与规模：60 步、学习率 1e-6、KL 0，是作者自称「刻意保守」的预算；更长训练、更大模型都可能改变结论。③自建评测：题库、判分器、OOD 都是作者自己生成的，OOD 只换了表面形式和参数，不是新领域（第 6 页）。④示范质量到顶：金标答案来自生成器本身，现实里示范数据往往更少、更脏，这对 SFT 是最有利的条件（第 7 页）。⑤算力是否对等：SFT 2 轮对 RL 60 步，没有做等算力对比，论文未说明两臂各用了多少 GPU 时长，只给了总成本。⑥另一种解释：也可能只是 GRPO 实现或超参（KL 0、lr 很小）不合适，而不是「RL 天生没余量」。

## 6. 可信度与核验限定

**主张对照**：①「示范数据几乎解决了基准」：Table 1、Table 2 都支持，证据够，但仅限这个自建题库和 3B 模型。②「SFT 之后 RL 在分布内没有可检测增益」：Table 2 与 H1′ 检验，统计做法规范，但单种子。③「分布外有小但可测的增益」：H1′′ 区间下界 +0.02，离 0 很近，单种子下要非常谨慎。④「残差是系统性的，所以 GRPO 没信号」：只有评测时的一致性统计，作者自己标为假设。

**核验限定**（原样合入核验报告）：
- SFT 0.785 vs GRPO 0.314（基座 0.311）：Qwen2.5-3B-Instruct，自建 gpu-train-debug hard split，mean reward，每题 3 次 rollout；15 步 GRPO 是先导实验（Table 1 p3）
- +0.22（CI [-0.06,+0.51]）/ OOD +0.33（CI [+0.02,+0.68]）：SFT 之后再 60 步 GRPO（lr 1e-6，group 8）减纯 SFT，配对 bootstrap 1 万次；只有一个训练种子（p4、p6）
- 总成本 $8.69：pilot $3.25 + 正式 $5.44，单张 A100（p7）
- 论文给的代码仓库 github.com/saloni-garg/gpu-train-debug 在 2026-11-09 查询时为 404，暂时无法复现；首页无机构署名；作者自述有 LLM 协助（p1）

**打折提醒**：对外引用时不要说「RL 没用」，作者自己预先写死的措辞是「在 60 步、lr 1e-6 的预注册规模下没有可检测增益」（第 3 页）。也不要说「完全可复现」，目前仓库打不开。

## 7. 你可以怎么落地

**今天就能试**：不用新机器。翻出你最近一次「SFT 后再 RL」的评测记录，补一张三列对照表：基座、SFT checkpoint、SFT+RL checkpoint，并在同一评测集上用每题多次采样算 C 减 B 的配对 bootstrap 区间（几十行 Python）。同时统计 SFT checkpoint 在没满分的题上「多次采样得分完全一样」的比例。验收：如果 C 减 B 的区间跨 0、且这个比例像论文一样过半，说明你的 RL 预算大概率在空转，先别加步数。

**要有数据或机器再试**：有一张 A100 级别的卡、几百到一千条高质量示范和一个程序化判分器，就能按第 4 节骨架复刻四臂对照，论文报告的整套花费约 5.5 GPU 小时（第 7 页）。分阶段：先跑 SFT 闸门；再跑 SFT+GRPO，至少 3 个种子；最后才延长步数或提高学习率，看增益是否随训练变大。验收：在你自己留出的、从没碰过的 OOD 集上，C 减 B 的区间多种子都不跨 0 才算 RL 有用。

**暂时别碰**：不要拿这篇当「砍掉 RL」的依据去影响大模型、长思维链、稀疏奖励的项目。论文只测了一个 3B 模型、一个领域、一种算法、一个种子，而且示范质量到顶；在示范稀缺或嘈杂、奖励稀疏的任务上，结论可能反过来（作者在第 7 页也这么写）。

## 8. 和你已有知识的挂钩

这很像软件上线前的「增量 A/B」：新功能不能跟「什么都没有」比，要跟当前线上版本比，才知道它值不值得维护。也像性能调优里的阿姆达尔定律：前一步已经把大头优化掉了，后面再怎么调剩余部分，总收益也有限。和常见的「RL vs 基座」报告相比，它最大的区别是把对照组换成 SFT checkpoint，并且事先写死检验方法和措辞。

## 9. 存疑与代价

**局限**：作者自认单一 3B 模型、60 步、单一 GRPO 算法、单一领域、确定性稠密判分、单训练种子、金标示范（第 6–7 页）。我读出来的另外两点：没有等算力对比；OOD 只是同一生成器的变体。**复现条件**：论文称环境 v0.4.1 为 MIT 许可、代码有两个 tag，但给的 GitHub 仓库当前 404；checkpoint 不保留；论文是 arXiv 默认许可。**成本**：论文报告总计 $8.69，单张租用 A100（第 7 页），复现成本极低，这是它的优点。**出处**：预印本，两位作者，首页无机构；脚注自述实验设计、执行和成稿都有大模型协助，作者称数字已核对原始产物（第 1 页）。

**论文没回答、但决定你要不要动手的 3 个问题**：把 RL 步数拉到几百步、学习率调大以后，增益会不会明显变大？示范数据只有几十条或带噪声时，SFT 和 RL 的分账会变成什么样？换成残差「时对时错」的任务（作者说的随机性残差），GRPO 是否真的能吃到更多？
