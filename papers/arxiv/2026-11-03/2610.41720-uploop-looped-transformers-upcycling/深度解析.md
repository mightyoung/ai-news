## 1. 一句话先懂它

「循环模型」把中间几层反复跑两遍，参数不变但更「深」，代价是训练更贵。UpLoop 的办法是先用浅模型便宜地训，逐步复制层长到目标深度，把省下的算力留到最后拿来循环，于是总 token、总训练算力、参数量都和普通模型完全一样。

## 2. 值不值得读：五个 C 速览

**类型**：一个新的预训练日程安排（不是新架构）。**上下文**：接着循环模型（Universal Transformers、Saunshi 等人 2025 年的循环推理工作）和「长深度」（depth growth，训练中途把浅模型复制成深模型）两条线；作者说以往循环模型的比较多半只对齐参数，多付的训练算力没算进去（第 2 页）。**关键假设**：预训练早期的 token 用浅模型训损失不大，学到的层复制后能接着用。**贡献**：一是给出让四个阶段总算力精确等于稠密基线的分配公式；二是在 370M、760M、1.3B 三个规模上和同预算稠密模型比；三是一组解释「为什么有效」的分析。**清晰度**：方法部分短而清楚，预算推导在附录 A，一页能看懂。建议**看到第 5.2 节**，做预训练的人再看附录 A。

## 3. 它在解决什么麻烦

先说「循环 Transformer」（looped Transformer）：普通模型 16 层每层各有一套参数，依次跑一遍；循环模型把其中一段（比如中间 4 层）当成一个共享块，同一套参数连跑 r 次。参数量没变，但「执行深度」变大了，相当于多想几步。不少工作报告这样做对推理类任务有帮助（第 1–2 页）。

麻烦在于账单：每多跑一遍共享块，每个 token 的训练计算（FLOPs，浮点运算次数）就多一截。拿同样多的数据训，循环模型比普通模型贵，那它赢了到底是因为结构好，还是因为多花了钱？作者给自己定的规矩更严：参数、训练 token、训练 FLOPs 三样全部和稠密基线相同，精确到一个 batch（第 2 页）。

你在什么场景会关心？比如你在读循环模型或「潜空间推理」的论文，看到「同参数下更强」就想用；或者你有固定的预训练预算，想知道能不能不加钱换个训法拿到更好的小模型。如果 UpLoop 成立，你就有了一个「同样的钱，买到循环结构」的训练配方。

## 4. 他们怎么做的

**核心思路**：钱总量固定，但可以挪。训练前期用浅模型，每个 token 便宜，省下一笔；训练后期开循环，每个 token 贵，把前面省的花掉。两头相抵，总账和稠密基线一样（第 3 页图 3a）。

**部件一：逐步长深度**。四个阶段的执行深度是 L/4 → L/2 → L → L+(r−1)m，论文里 L=16、m=4、r=2，即 4 → 8 → 16 → 20 层（第 3 页、第 11 页）。从 4 层到 8 层，把 4 层整体叠两遍；从 8 层到 16 层，保留头尾各 2 层，把中间 4 层复制成 3 份。复制时连 Adam 优化器的状态（每个参数的动量记录）一起复制，之后各层独立训练（第 4 页）。这种「拿训好的小模型初始化大模型」就是标题里的 upcycling（升级复用）。

**部件二：中间块循环**。到 16 层后，选中间 4 层当共享块连跑 2 遍，头尾各跑一遍，执行深度变成 20 层，参数不增加（第 4 页）。

**部件三：算账**。总 FLOPs 是每阶段 token 数乘以该深度下每 token 的 FLOPs 之和。要和稠密基线相等，需要 12·D1 + 8·D2 = 4·D4（D 是各阶段 token 数，第 11 页）。实际切换点在总 token 的约 9.7%、23.0%、44.3%（第 4 页）；学习率按累计 token 走，换阶段不重启。我用附录给的 370M 阶段长度（4560、6305、10054、26290 步）验算，两边都是 105160，三个规模都成立。

**实验设置**：OLMo 2 Ladder 架构，FineWeb-Edu 数据，每参数 100 个 token（Chinchilla 推荐量的 5 倍）；学习率沿用基线调好的值，不为 UpLoop 重调；除非注明，所有运行用种子 42（第 4–5 页、第 11 页）。

**如果让你复现**，阶段日程的骨架如下（论文没给代码，函数名是示意）：

```python
stages = [(4, 0.097), (8, 0.230), (16, 0.443), (20, 1.000)]  # (执行深度, 累计 token 比例)
model = make_dense(layers=4)
for depth, until in stages:
    if depth == 8:  model = stack_twice(model)                 # 层权重 + Adam 状态一起复制
    if depth == 16: model = copy_middle(model, head=2, mid=4, copies=3)
    if depth == 20: model = loop_middle(model, start=6, size=4, repeats=2)  # 共享参数
    train(model, until_fraction=until, lr=token_clock_cosine)  # 学习率不重启
```

## 5. 证据怎么看、别被什么忽悠

**图一：Figure 3（第 3 页），同一笔预算怎么挪。** 想说明方法本身。(a) 色带粗细代表执行深度随训练 token 的变化，UpLoop 前期比 Vanilla（普通稠密模型）细、后期比它粗，早期省下的面积 A 等于后期多花的；(b) 每个阶段如何由上一阶段复制得到。读懂这张图就读懂了方法。

**表二：Table 2（第 6 页），22 个下游任务。** 想证明同预算下更强。1.3B 时平均分 22.99→27.52，22 项里 18 项胜出；370M 为 18.95→20.90、760M 为 21.38→24.82（第 5 页）。注意涨幅集中在「推理原语」：VarAssign-math 58.10→91.10、VarAssign-code 66.60→91.20（变量赋值题：给五个赋值语句，问某个变量的值）。按表 2 自算，去掉这两项后 20 项平均只有 19.05→21.16。闭卷问答 TriviaQA、NaturalQuestions、WebQuestions 和开卷的 TyDiQA-GoldP 上 UpLoop 反而略低。数学应用题绝对分很低（1.3B 平均 5.35%→7.55%）。另外三个规模参与平均的任务数不同（13、21、22 项），作者提醒不能跨规模比平均分（第 12–13 页）。

**表三：Table 3（第 6 页），和其他训法比。** 370M 下：从头训循环模型、先稠密再循环，分别要多花 1.20×、1.11× 的训练 FLOPs，NLL（负对数似然，越低越好）都是 2.76，UpLoop 是 2.74；20 层稠密模型在同 token 下也到 2.74，但要 1.20× FLOPs、参数 438M 对 371M。这张表说明「先长后循环」比两种直接循环的办法省算力。

**水分检查**：全部单种子，NLL 差距在 0.02–0.04 之间（附录表 A2，第 11 页），没有误差条，无法判断噪声有多大。最大只到 1.3B。基线学习率是 OLMo 2 Ladder 的现成值，没为任何一方调参，算是公平。评测用公开任务和 lm-evaluation-harness，不是自建榜单。GSM8K 微调那组（8.72%→12.05%）作者注明微调算力没对齐，也只有一个种子（第 13 页）。

## 6. 可信度与核验限定

**主张对照**：①「参数、token、训练 FLOPs 完全对齐」：附录 A 有公式和整数步数，我验算成立，证据充分。②「1.3B 下 22 项平均 22.99→27.52」：表 2 数字一致，但单种子且主要由两个合成任务拉动，证据只够说明「在变量赋值类检索任务上明显更强」。③「推理更强」：零样本常识题平均 54.91→56.47，幅度小；附录 F 的机理分析是事后解释，不是因果证明。

**核验限定**（原样合入核验报告）：
- 22.99→27.52：1.3B，22 个下游任务（数学与推理原语 5-shot），对比同 token、同 FLOPs 的 Vanilla 稠密基线；22 项中 18 项胜出（表 2 p6）
- 单种子（Every run uses seed 42，p11）；涨幅主要来自 VarAssign-math 58.10→91.10、VarAssign-code 66.60→91.20，去掉这两项按表 2 自算 20 项平均仅 19.05→21.16（表 2 p6）
- 8 项零样本平均 54.91→56.47（表 1 p5）；论文未提供代码或权重链接；论文为 arXiv 非独占分发许可

**打折提醒**：标题里的「不增加算力」只指预训练。推理时 UpLoop 每个 token 要多跑 4 层，1.3B 下推理 FLOPs 是 Vanilla 的 1.217 倍（附录表 A3，第 11 页）。对外引用 22.99→27.52 时要带上「单种子，主要由变量赋值两项带动」。

## 7. 你可以怎么落地

**今天就能试**：用 Python 验算附录 A 的预算等式。按 L=16、m=4、r=2 写出 12·D1 + 8·D2 = 4·D4，代入三个规模的阶段步数（第 11 页），确认两边相等，再换成你关心的 L、m、r，算出各阶段该占多少 token。顺手把表 2 的 1.3B 两列抄进表格，去掉 VarAssign 两项重算平均，体会一下「平均分被少数任务拉动」是什么样子。验收：你能独立算出 105160 和 19.05→21.16。

**要有数据或机器再试**：有几张能训小模型的显卡，就在小规模（比如百兆参数、几十亿 token 的 FineWeb-Edu 子集）上复现 Vanilla 对 UpLoop 两臂，至少 3 个种子。按论文设置，370M 一臂就要约 371 亿 token（附录表 A1），量级不小，务必先缩小。关键是复制层时把 Adam 状态一起复制、学习率按累计 token 走不重启。验收：NLL 差距要明显大于种子间的波动，再看 VarAssign 以外的任务是否也有提升。

**暂时别碰**：别把它当成「免费午餐」直接换掉生产预训练流程：推理贵约两成，知识问答略降，且没有开源代码、只有单种子。也别引用「平均提升 4.5 分」去说明循环模型普遍更强。

## 8. 和你已有知识的挂钩

它很像健身里的「周期化训练」：总训练量固定，前期轻负荷打基础，后期集中上强度。技术上，它把「长深度」（以往用来省预训练算力）和「循环」（以往要多花算力）拼在一起，让前者省下的钱正好付后者的账。和最接近的 LIDAS（只长深度、用省下的算力多训 token）相比，UpLoop 在同参数、同 FLOPs 下 NLL 为 2.74 对 2.75，还少用了 token（第 6 页）。

## 9. 存疑与代价

**局限**：论文正文没有单独的局限性章节。我读出的几点：只有一个种子；只到 1.3B；只试了 L=16、m=4、r=2 这一种循环配置，阶段比例没有消融；总平均受两个合成任务主导。**复现条件**：无代码、无权重；超参数、阶段步数在附录 A 写得很全，按图施工可行，但算力门槛高。**成本**：训练算力与基线相同；推理每 token 约多 20%（第 11 页）。**出处**：预印本，上海交通大学与中国科学技术大学的作者。

**论文没回答、但决定你要不要动手的 3 个问题**：换几个种子，NLL 0.03 的差距还在吗？到 7B 以上、或者循环 3–4 遍时还划算吗？推理多花的两成算力，换成直接用更大的稠密模型，谁更好？
