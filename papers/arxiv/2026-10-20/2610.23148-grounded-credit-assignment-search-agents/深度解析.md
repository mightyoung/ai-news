## 1. 一句话要点与用处

用 GRPO 训练"边推理边搜索"的问答智能体（Search-R1 那套）时，整条轨迹只得到一个标量优势，"找到证据"和"用好证据"混在一起记功。作者证明，组内"找到证据的轨迹"总的来说只按**接地差**（找到与没找到之间的准确率差）获得正向信用；而模型凭记忆答对、或找到了证据却用错，都会把这个差缩小甚至翻成负数。于是模型答得更准了，却越来越少依赖检索证据。

GCA 的做法：用两个可验证的子结果，一个是"工具返回里是否含有正确答案"，一个是"最终答案是否正确"，给"有效搜索 / 冗余搜索 / 作答"三段 token 各加一个**有界、不改符号**的小修正，最多改动 10%。这样不需要额外模型，也不需要额外采样。论文报告平均 EM 比自己复现的 Search-R1 高 5.7（Qwen2.5-3B）和 6.3（Qwen3-30B-A3B）；在 3B 上，"有证据支撑的正确答案占比"从 76.9% 升到 93.4%。

**用处**：如果你在训练 RAG/搜索智能体，这是一个只改 token 级优势分配的小补丁；同时它提醒你，只看 EM 会掩盖"不看证据就作答"的退化。

## 2. 实际痛点/场景

- 结果奖励的 RL 让搜索智能体 EM 上升，但它可能越来越"凭记忆猜"。图 1a（Qwen2.5-3B）中，Search-R1 训练后，MuSiQue 上"有证据支撑的正确答案占比"从初始检查点的 88.3% 降到 71.8%，Bamboogle 上从 84.0% 降到 42.9%。
- 论文附录 K（作者转述，我没有核对逐基准表）称，Search-R1 在 MuSiQue 和 Bamboogle 上的 TOOL HIT 也下降了（25.8→21.9、35.2→19.2）。
- 在 token 层面（图 1b）：截至第一次命中证据的搜索 token 中，有 38–51% 落在"之后答错"的轨迹里，因此被罚；正向记功的 token 里，又有 33–40% 是冗余搜索或"没找到证据却答对"的轨迹。
- 这对需要"答案可追溯、有出处"的业务场景（客服、合规问答）是实际问题。

## 3. 方案思路与步骤（白话）

1. **给每条轨迹做诊断**：H 表示"任何一次检索结果里是否出现了标准答案"（不区分大小写的子串包含），C 表示最终答案是否 EM 正确。两者组合得到四类轨迹：
   - A：找到并答对。
   - B：找到但答错，或轮次用完。
   - C：没找到也答错。
   - D：没找到却答对。

   对 D 类还要判断语料里到底有没有答案（Retr）：用标准答案构造模板查询去检索，组内只要有一条轨迹命中就记为 Retr=1。
2. **把 token 分段**：
   - 有效搜索（第一次命中之前及命中那一轮的搜索）。
   - 冗余搜索（命中之后的搜索、没命中轨迹的全部搜索、格式错误的调用）。
   - 作答段。
3. **按"这一段控制的子结果"定修正的正负**，见表 1。例如：
   - B 类里的有效搜索给 +0.5，作答段给 −1.0（"错在答，不在搜"）。
   - A 类的冗余搜索给 −0.1。
   - D 类且 Retr=1 时，搜索给 −0.2、作答给 −0.1（"能查到却不查，记功打折"）。
   - C 类不加修正。
   - D 类且 Retr=0（语料里没有答案）时，这条轨迹不参与策略损失。
4. **限幅**：token 优势 = 原优势 × (1 + ε)，其中 |ε| ≤ 0.1（η=0.2、λ_max=1、c_max=0.5）。这样每个 token 的符号不变，也不会落到 PPO 裁剪的另一侧（命题 2）。不限幅的版本在 145 步内熵从 0.67 涨到 6.6，训练崩溃。
5. **段内按显著性分配**：用旧策略的 logits 算"margin（与前 3 个竞争 token 的差距）+ 归一化熵"。正向修正偏向"不确定但有用"的 token，负向修正偏向"很自信却错"的 token。
6. 奖励、组统计和优化器都不变，只把 GRPO 或 GSPO 里的优势换掉。

## 4. 如何读实验与识别夸大

**设置**：
- **数据与评测**：沿用 Search-R1 的 NQ+HotpotQA 训练集。评测 7 个 QA 基准，共 51,713 题，其中 NQ 和 HotpotQA 属于域内。
- **检索环境**：E5 检索 2018 年维基百科，取 top-3 段落，最多 5 轮；评测时温度为 0。
- **训练**：Qwen2.5-3B-Instruct 用 GRPO，Qwen3-30B-A3B-Instruct-2507 用 GSPO。batch 512，每题 5 条 rollout，学习率 1e-6。
- **算力**：共 128 张 H20。
- **结果来源**：全部是作者自测。

|---|---|

**容易被夸大的地方**：
- "不加模型、不加采样"是真的，但**训练时需要标准答案的别名集合**来计算 H、C 和 Retr。
- 方法只在"答案可以被字面匹配"的短答案 QA 上验证过。
- 30B 上只复现了 Search-R1 作为基线，论文自己称之为"受控迁移测试，不是完整基准"。
- 训练总步数正文没有明确写。图 3 的横轴大约到 300 步，图 1b 有 900 步的检查点。

## 5. 落地分层

**今天能试**
- 已经在用 verl 加 Search-R1 配方的话，只需要改 token 级优势：先算 H/C 诊断和第一次命中的位置，再按表 1 的系数加有界修正。显著性部分可以先用常数代替，消融显示这样仍能拿到约八成的 EM 增益。
- **把"有证据支撑的正确答案占比"加入评测看板**：同时看 TOOL HIT 和 HIT ACC，不要只看 EM。这一项零成本。

**需要资源**
- 复现 3B：需要检索服务（E5 加维基 2018 索引）和多卡训练。作者共用了 128 张 H20 和一个 8 卡检索池。单次训练的耗时论文没给。
- 推广到开放网页、长答案或没有标准答案的任务：需要把 H/C 换成证据蕴含判别器或可执行测试。作者明确写了这部分没有评估。

**可跳过**
- 把 93.4% 当作"答案都有证据支撑"的真实比例来读：它是 TOOL HIT × HIT ACC 的估计，而且基于子串匹配。

## 6. 与已知概念的挂钩

- **信用分配**（credit assignment）：经典 RL 问题。这里不是按时间步分组，而是按"功能段"分组。
- **GRPO / GSPO / PPO 裁剪**：GCA 只改优势，并且保证不跨越裁剪分支。
- **Search-R1、ZeroSearch、DeSA、GiGPO、IGPO**：直接相关的工作。GiGPO 按状态分组记功，作者认为两者可以组合。
- **奖励塑形**（reward shaping）与**过程奖励**（PRM）：GCA 可以看成一种"不改奖励、只改分配"的轻量过程信号（我的判断）。
- **高熵"分叉 token"**（Wang 等 2025b）：显著性打分借用了 margin 和熵。
- **RAG 的"接地/幻觉"评测**：本文的 SUPCOR 指标思想接近"答案是否可以从检索到的证据中找到"。

## 7. 疑点、局限与成本

论文自述的局限：
- H、C、Retr 靠标准答案和字面匹配，H 衡量的是"答案出现"而不是"语义支撑"，会漏掉是/否题和部分比较题（这也部分解释了 2Wiki 上各方法的接地占比都低）。
- 模板 oracle 查询可能漏掉可检索的答案。
- 只用了两个 Qwen 主干和一个检索环境（维基 2018、top-3、最多 5 轮）。
- 30B 上只复现了 Search-R1；种子方差只对 GCA 报告。
- 只有一张路由表，没有逐格消融，显著性权重固定。
- 显著性计算的额外开销没有测。

我的疑点：
1. **基线对比的口径**：主表里只有 Search-R1 是同设置复现，而且只跑一次。其他基线数字的来源没说清。GiGPO 平均只差 1 分，并在 Bamboogle 上领先很多。
2. **"接地占比"的提升大多是检索覆盖率的提升**（TOOL HIT），HIT ACC 不变。至于"模型更会用证据"这一说法，数据支持有限。
3. **H 只是一个代理信号**：答案字符串出现在段落里，不等于段落支持这个答案；作者的审计主要测召回，没有测"误命中"的比例（论文未给）。
4. **符号规则的"合理性"来自直觉**：表 1 的正负号是"代理标签规则，不是命题 1 推出的唯一或最优分配"（作者原话的意思）。
5. **只验证了短答案 QA**：迁移到网页搜索、长答案或代码智能体，都需要新的可验证子结果。作者把这列为展望。
6. **成本**：需要额外维护诊断、分段和显著性的计算流程，还要用模板查询去判断 Retr。训练算力与 Search-R1 相当（不需要额外 rollout）。
