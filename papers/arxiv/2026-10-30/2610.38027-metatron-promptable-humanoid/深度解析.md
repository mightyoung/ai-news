## 1. 一句话要点与用处

**做法**：先训练一个通用的人形机器人全身控制策略，训练完就冻结。它接受"部分目标"作为提示（prompt），例如几个时刻的手脚位置、行进速度、风格示例、家具包围盒，然后自己补全成协调的全身动作。具体任务交给"技能"，技能就是普通代码，每个控制步构造一次提示。

**卖点**
- 在 Unitree G1 真机上，同一个冻结检查点支持行走、摔倒后爬起、VR 遥操作拿东西、坐沙发再站起。
- 技能代码可以由编程 Agent 写和调：Agent 搭仿真测试场景、分析动作捕捉片段、拟合几个参数的规则，不需要再训练策略。

**用处**：如果你在做人形机器人的上层任务，这提供了一种"把运动控制当成可调用的执行层"的接口；上层可以是人写的状态机，也可以是 LLM 生成的程序。

## 2. 实际痛点/场景

- **每个任务一个控制器**：行走、操作、摔倒恢复、柔顺控制、动作追踪通常各训各的，平衡和协调这些能力被重复学了很多遍，任务之间切换还要额外写衔接逻辑（p1）。
- **参考轨迹追踪的限制**：主流做法是"动作生成器出参考轨迹 + 密集追踪器跟随"。追踪器需要完整的参考轨迹，生成器如果规划得不好（比如在固定站高下规划），追踪器也救不回来。
- **任务设计依赖调奖励**：新任务往往要重新设计奖励、重新训练策略。作者想把它变成写代码的问题。

## 3. 方案思路与步骤

1. **训练专家追踪器**：用 PPO 训练密集动作追踪器，可以使用仿真器的特权状态。G1 用了四个专家，分别覆盖 BONES 动作捕捉、AMASS+LAFAN、合成恢复动作、SAMP 场景交互（p5，附录 A）。
2. **掩码在线蒸馏成一个生成式策略**
   - 学生是条件 VAE：先验网络是 6 层 transformer，只看部署时能拿到的观测和被随机遮掉大部分的提示；后验网络在训练时额外看完整参考轨迹。
   - 潜变量投影到单位球面上，再与确定性条件融合，交给解码器输出 29 个关节指令。
   - 90% 的回合由学生自己控制、10% 由专家控制，所有状态都由冻结的专家打标签（附录 C）。
   - 另加几个辅助损失：预测下一步条件、时间平滑、动作平滑。
3. **提示接口**：四种可选目标流（世界坐标下的定时身体目标、与位置无关的规范化姿态、平面速度、风格示例帧），加上最多两个包围盒描述家具。训练时随机组合，16 种开关组合等概率出现，包括什么目标都不给。
4. **训练数据增强**：用另一个模仿学习策略从随机摔倒姿态生成 5 秒的爬起片段，过滤后并入动作库；SAMP 的坐、躺动作经过两阶段优化重定向到 G1，避免穿模。
5. **技能层**
   - 行走（steering）：编程 Agent 从动作片段拟合出一条周期性落脚规则，只有几个系数（附录 G 给出了具体值）。加上这条规则后步态明显更果断。
   - 坐下：三个静态目标点（躯干在座面上方偏后，两脚在座椅前沿），由座椅包围盒算出。
   - 爬起：躯干高度低于阈值时切换提示，只要求躯干回到站立高度。
   - 柔顺：速度设为零，只约束躯干高度和朝向，手臂不约束，于是人可以拉着它的手。
6. **部署**：C++ 加 TensorRT，跑在通过网线连到机器人的笔记本 GPU（RTX 5090）上，传感器到指令延迟 1.3 ms，控制频率 50 Hz（p13）。真机全部使用先验均值、不采样。

## 4. 如何读实验与识别夸大

**表 I：全身伸手**（p7；MuJoCo 仿真；54 个目标点，覆盖 3 种距离（0.35–1.8 m，需要迈步）、3 种高度（0.55–1.35 m）和左右手；手腕在 10 cm 内保持住且不摔倒算成功；误差只在到达的目标上统计）

| 方法 | 到达率 | 误差 | 保持直立 |
|---|---|---|---|
| METATRON | 83% | 5.9 cm | 100% |
| ARDY + SONIC | 39% | 6.4 cm | 82% |
| GRU + IK + SONIC | 28% | 5.6 cm | 81% |
| GRU + SONIC | 0% | — | 87% |

**表 II：行走中的抗推**（p7；1 m/s 前进时在躯干施加 100 ms 力脉冲，8 个方向，8 秒后仍站立算成功）

| 方法 | 200 N | 400 N | 600 N | 800 N | 1000 N |
|---|---|---|---|---|---|
| METATRON | 100 | 100 | 62 | 75 | 75 |
| ARDY + SONIC | 100 | 100 | 17 | 0 | 0 |
| GRU + SONIC | 100 | 75 | 25 | 0 | 0 |

**这两张表要注意的几点**
- **都是仿真，不是真机**：表 I 明确写在 MuJoCo 里测；表 II 没写环境，从上下文看也是仿真（我的判断）。README 里"在真机 G1 上……伸手成功率与抗推鲁棒性高于参考轨迹方案"的写法容易让人误读成真机对比。真机部分只有定性演示，作者在局限一节也承认需要更多试验来量化恢复可靠性和步态稳定性（p8）。
- **参与对比的不是演示用的那个模型**：对比用的 METATRON 是单独训练的、不含合成恢复数据的版本（p5、p7）。
- **样本量很小**：表 II 的 62、75 这类数字说明每格可能只有 8 次试验（我的判断），600 N 到 1000 N 的成功率不单调。作者自己提醒不要把这种不单调理解为"推得越重越稳"（p7）。
- **基线是作者搭的组合**：ARDY 和 SONIC 都是已有方法，但"ARDY + SONIC"和"GRU + SONIC"这两条流水线由作者组装，GRU 生成器是作者自己训练的。作者也说明这是整条流水线的对比，分不清是哪个设计带来的差异（p7）。
- **ARDY 失败的原因**：ARDY 用无分类器引导而非硬约束来接受手部目标，重规划时手腕会来回晃；在需要弯腰或高伸手的目标上差距最大。这意味着差距部分来自基线的接口限制。

**表 III：路点到达中的反复推搡**（p8；仿真，500 个 episode，95% Wilson 置信区间；不使用技能生成的落脚目标；所有消融用相同训练预算和参数量，8 张 A100、5,000 次迭代）

| 方法 | 0 N | 200 N | 400 N | 600 N | 800 N |
|---|---|---|---|---|---|
| METATRON | 97.4 | 94.8 | 33.0 | 7.4 | 6.2 |
| 只用全局目标 | 87.6 | 87.8 | **38.2** | **9.6** | 6.2 |
| 只用动作捕捉（无恢复数据） | 92.0 | 84.8 | 31.8 | 6.4 | 5.0 |
| 无辅助损失 | 81.6 | 78.8 | 29.2 | 5.4 | 4.6 |
| MaskedMimic+ | **98.2** | 90.0 | 27.8 | 4.2 | 4.6 |
| HOVER+ | 66.8 | 71.0 | 30.0 | 3.0 | 1.2 |

- 完整模型只在 0–200 N 明显领先。400–600 N 时"只用全局目标"更高，置信区间重叠；无推力时 MaskedMimic+ 略高。
- 600–800 N 下所有方法都低于 10%。表 II 里 800 N 时 METATRON 有 75%，表 III 里只有 6.2%，因为两者设置差别很大（单次脉冲 vs 每 1–2 秒推一次，有落脚技能 vs 没有），不能横向比较。
- MaskedMimic+ 和 HOVER+ 是作者按自己的专家、数据和预算改造的版本，网络比原版大得多（p7–8）。它们更像"去掉若干组件的消融"，不代表原论文的实现。

**真机演示**（p6，图 5、图 7）
- 行走（含倒退）、从仰卧 / 俯卧 / 坐姿等姿态爬起、VR 遥操作拿苹果、坐沙发再站起、握手和被人牵引。
- 坐沙发时，机器人是被人放到沙发附近的，座椅包围盒由人提供；自主走过去再坐下没有演示（p8、p14）。
- 爬升、滑下台阶、翻滚等高动态动作只在仿真里展示，其中一部分是在另一个仿真角色 SOMA 上，理由是避免损坏 G1 和它的三指手（p6）。

## 5. 落地分层

- **今天能试**
  - 下载 HF 上的 G1 检查点，在 MuJoCo 里用 ProtoMotions 的推理脚本跑；或者直接打开浏览器里的交互演示，体验不同提示组合的效果。
  - 借鉴"冻结底座 + 代码技能"的分层：即使用的是别的全身控制器，也可以把任务逻辑写成每步生成稀疏目标的小程序，而不是每个任务重训一个策略。
- **需要资源**
  - 真机部署：Unitree G1，加上一台带 NVIDIA GPU 的笔记本、Xbox 手柄或 PICO 头显。世界坐标目标还需要定位系统。
  - 重新训练：学生蒸馏用 20 张 GPU；G1 的四个专家分别用 12 / 4 / 2 / 2 张 GPU。专家训练的时长和总算力没有给出（论文未说明）。
  - 换机器人：需要重新做动作重定向、生成恢复数据、训练专家和学生。
- **可跳过**：如果你的场景需要视觉感知、自主寻路接近物体或长程规划，这篇没有覆盖，目标都由外部提供（p8）。

## 6. 与已知概念的挂钩

- **MaskedMimic**（同一团队，2024）：本文的直接前身，"在部分动作描述上训练控制器"。METATRON 扩展了数据、潜变量设计、技能层和真机部署。
- **DAgger / 在线策略蒸馏**：学生在自己走到的状态上让专家打标签，正是 DAgger 的思路。
- **条件 VAE 与潜空间技能**：ASE、CALM、PULSE 这一系列用潜变量表示可复用技能；本文把潜变量投影到单位球面以限制范围。
- **Code as Policies**：用 LLM 写程序来调用底层能力，本文把它用在全身运动控制上。
- **参考轨迹追踪 vs 目标条件控制**：对比的 SONIC、BeyondMimic 属于"先生成参考、再追踪"路线；本文主张让策略直接响应稀疏目标。

## 7. 疑点、局限与成本

- **真机没有量化结果**：所有表格都是仿真；真机只有演示视频和截图，没有成功率、试验次数或失败模式统计（p8）。
- **对比用的模型与演示模型不同**：对比时去掉了恢复数据。演示用的四专家模型在表 I、表 II 的协议下表现如何，论文没有给出。
- **表 I、表 II 的试验次数没有说明**，表 II 很可能每格只有 8 次（我的判断）。
- **"编程 Agent 写技能"的证据偏定性**：论文展示了 Agent 拟合的步态规则和坐下规则，但没有报告 Agent 迭代了多少轮、人参与了多少、失败率如何，也没有和人写技能做对比（论文未说明）。
- **已知失效**：从静止突然要求 2 m/s 常常会触发前滚翻，需要对速度指令做指数平滑（p8）。
- **能力范围取决于训练数据覆盖**：数据里没有的动作类型，靠写技能也做不出来。
- **SOMA 策略没有公开**，仿真里的攀爬和滑落演示目前无法复现。
