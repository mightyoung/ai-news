## 1. 一句话要点与用处

**结论**：在从零预训练的小模型（Qwen3 架构，0.6B / 1.7B / 4B）里，只要在 100B token 语料中混入 0.1% 的投毒文档，就能埋下一个"遇到特定上下文就输出一条下载并执行远程脚本的固定命令"的后门。这个后门能穿过之后完全干净的 SFT → DPO → GRPO 后训练，在部署成终端 Agent 后仍然触发。

**最强的数字**：普通串触发器（路径里出现某个服务商名字）、4B 模型、陈述式投毒文档，GRPO 之后 Pass@32 ASR 为 92.7%（3 个种子的均值，范围 87.9–96.7%）。

**对防守方的用处**：
- 说明"后训练会把预训练里的脏东西洗掉"这个假设不可靠，至少在 4B 以内不可靠。
- 把威胁从"模型说坏话"推进到"Agent 执行坏命令"，直接对应到 Agent 的权限设计。
- 作者在讨论部分明确认为，靠数据过滤很难防住，部署时的动作监控才是更现实的防线（p10）。

## 2. 实际痛点/场景

- **Agent 拿到了真权限**：编码 Agent、终端 Agent 已经普遍能在用户机器上执行 shell 命令。一条恶意命令的后果从"一段坏文本"变成了"机器被接管"。
- **预训练语料来自公开网络**：任何能在网上发内容的人，理论上都可能让一部分内容进入某个模型的预训练语料。论文的威胁模型假设攻击者只能控制不超过 0.1% 的语料 token，不知道模型架构、分词器、对话模板和后训练流程，投毒文档落在语料中的随机位置（p2–3）。
- **之前的工作没走完全链路**：此前的预训练投毒研究大多停在预训练或单个后训练阶段，或者只测"拒答""胡言乱语"这类文本行为。这篇的卖点是把完整的 OLMo-3 式后训练流水线都跑了一遍，并在 Agent 场景里检查是否真的输出可执行命令。

## 3. 方案思路与步骤

这里只描述实验设计的结构，用来理解证据，不展开如何构造。

1. **两类触发器**
   - 稀有串：一个在自然文本里几乎不出现的 Unicode 字符串。
   - 普通串：文件路径里出现某个模型服务商的名字。论文脚注说明路径全是合成的（p2）。这类触发器在真实使用中会自然出现，所以更接近现实威胁，也更难靠"找异常字符串"来过滤。
2. **两类投毒文档**
   - 示范式：对话记录形式，直接演示"看到触发器就输出命令"，沿用以前的工作。
   - 陈述式（本文新提出）：用普通文章的形式陈述这条规则，不出现对话格式。灵感来自"合成文档微调"。
3. **训练流水线**（附录表 1，p17）
   - 预训练：FineWeb，100B token，1 个 epoch。三个规模分别在 8 / 8 / 16 张 H200 上训练 2.2 / 3.7 / 4.5 天。
   - SFT：约 13.5 万条（一半终端任务、一半通用对话）加 1.5 万条 HH-RLHF 安全数据，5 个 epoch。
   - DPO：9,369 对 HH-RLHF 偏好数据。
   - GRPO：终端任务上的强化学习，4 张 H200 跑 8–9 小时。
   - 所有后训练数据都是干净的，不含触发器。
4. **评测**：在每个阶段之后，用带触发器的留出提示采样，用正则匹配载荷算 ASR。另用 Claude Haiku 4.5 对至多 200 条输出抽检，判定载荷在 98.5%（普通串）和 93.7%（稀有串）的情况下"照原样可执行"（p6）。

## 4. 如何读实验与识别夸大

**主结果**（表 7，p21；陈述式投毒，0.1% 投毒率，Pass@32，3 个种子的均值，方括号为最小–最大）

| 触发器 | 规模 | 预训练后 | SFT 后 | DPO 后 | GRPO 后 |
|---|---|---|---|---|---|
| 普通串 | 0.6B | 8.0 | 14.2 [0.2, 26.7] | 15.4 | 13.1 [0.5, 30.6] |
| 普通串 | 1.7B | 2.9 | 55.9 [29.2, 86.8] | 56.0 | 51.9 [24.4, 83.5] |
| 普通串 | 4B | 30.2 [1.3, 85.0] | 92.0 [83.8, 97.7] | 91.3 | 92.7 [87.9, 96.7] |
| 稀有串 | 0.6B | 0.4 | 3.1 | 3.9 | 2.1 [0.0, 3.6] |
| 稀有串 | 1.7B | 1.1 | 6.8 | 6.9 | 4.0 [0.3, 9.4] |
| 稀有串 | 4B | 0.4 | 13.1 [5.6, 22.5] | 13.8 | 10.5 [3.8, 20.0] |

**对照与基线**
- 未投毒的同规模模型：所有阶段 ASR 都是 0.0%（每个规模 1 次运行，p23）。
- 投毒模型在不带触发器的 NL2SH-ALFA 干净提示上，各阶段输出载荷的比例都是 0.0%；在不含触发器的稀有串任务上每次采样不超过 0.04–0.06%（p23）。也就是说后门基本只在触发时出现。
- 示范式投毒（表 8，p21）几乎无效：所有格子都不超过 3.8%，4B 普通串 GRPO 后只有 3.2%，稀有串不超过 0.2%。
- **能力没有被损伤**：预训练后五项常识基准平均 58.5%（投毒）对 58.3%（干净，4B）；GRPO 后 NL2SH-ALFA 首词准确率 67.2% 对 64.6%，完全匹配 11.5% 对 11.9%（p7）。这对防守方是坏消息：常规能力评测看不出模型被投毒。

**读数字时要注意的几点**
- **92% 是最好的那一格**：普通串 + 4B + 陈述式。换成稀有串，4B 只有 10.5%；换成 0.6B，普通串只有 13.1%。
- **Pass@32 不是单次成功率**：同一格（4B 普通串 GRPO）Pass@1 是 50.9%，范围 37.2–61.8%（表 9，p22）；4B 稀有串 Pass@1 只有 1.8%。实际部署中 Agent 通常只跑一次，Pass@1 更接近单次风险；不过攻击者也可以等很多用户、很多次调用，Pass@32 描述的是"多试几次总会中"的风险。两种口径都要看。
- **种子间方差很大**：1.7B 普通串 GRPO 后范围是 24.4–83.5%，0.6B 是 0.5–30.6%。只有 3 个种子，均值本身也不稳。
- **"规模越大越强"只在 0.6B→4B 成立**：GRPO 后的数字确实单调上升。但预训练阶段并不单调（普通串 8.0 / 2.9 / 30.2），示范式稀有串也不单调（0.1 / 0.0 / 0.2）。更大的生产级模型会怎样，是作者的推测，没有实验（p10–11）。
- **ASR 评测集是自建的**，由 Sonnet 4.5 生成。它和投毒文档用了不相交的主题层级，但分布仍由同一模型生成，可能比真实用户请求更"整齐"（我的判断）。
- **README 里"投毒率降到 0.0005% 仍为正"需要加限定**（p9、表 14 p24）：
  - 只在稀有串、4B、陈述式这一组配置上测了，单种子。
  - GRPO 后 Pass@32 只有 1.4%，Pass@1 约 0.07%（表 15）。
  - 0.01% 时反而只有 0.8%，曲线不单调，作者自己归因为单种子噪声。
  - 表 16 另做了"按 Chinchilla 规模分别训练"的低剂量实验：250 篇文档的设置在所有行都是 0；普通串的低剂量设置也基本为 0。
  - 结论应读成"在 0.01% 以下仍偶尔能触发、信号很弱"，而不是"极低剂量也有效"。

## 5. 落地分层（防守方视角）

- **今天能做**
  - 把 Agent 的 shell 执行当作不可信输出处理：沙箱、最小权限、高风险命令（下载后直接执行、改权限、外连）走白名单或人工确认。论文 p10 讨论的部署期防御就是这一类。
  - 在 Agent 的动作日志上加规则或分类器，专门盯"拉取远程脚本并执行"这类模式。这类检测不依赖知道触发器是什么。
  - 红队测试时，不要只用异常字符串当候选触发器；普通上下文（路径、项目名、组织名）也要覆盖。
- **需要资源**
  - 复现这套威胁评估：仓库已开源（Apache-2.0），但 4B 预训练要 16 张 H200 跑 4.5 天，3 个种子再乘 3。对多数团队来说，更现实的是用仓库里的评测部分去测自己的模型。
  - 预训练数据的来源追踪和过滤：论文认为难度很高，因为预算极小、陈述式文档看起来就是普通文章、普通串触发器没有异常字符，过滤器需要接近完美的召回率（p10）。
- **可跳过**：如果你只用闭源 API、Agent 不执行任何命令，这篇对你的直接影响有限；但只要接入了能执行命令的工具，第一条就值得做。

## 6. 与已知概念的挂钩

- **数据投毒 / 后门攻击**：BadNets 一类"触发器 → 目标行为"的经典结构，搬到了 LLM 预训练。
- **Sleeper Agents**（Hubinger 等，2024）：那篇是在微调阶段植入后门并测安全训练能否去除；这篇把植入点前移到预训练，并且用的是干净后训练。
- **小剂量投毒**：与"固定数量的投毒文档即可生效"的一系列工作相呼应；本文表 16 的结果显示，在作者的设置下 250 篇文档不够。
- **合成文档微调（SDF）**：陈述式投毒借用了"用陈述性文章让模型相信某件事"的思路。
- **Agent 安全中的提示注入**：两者都导致 Agent 执行非用户意图的命令，部署期的防御（权限、确认、监控）可以共用。

## 7. 疑点、局限与成本

- **只到 4B，且是从零训练的小模型**：不是已发布的生产模型，结论能否外推到几十 B、几百 B 规模，论文没有实验（p10–11）。
- **没有 mid-training 阶段**：现代流水线常在预训练和 SFT 之间插入中期训练，这一步会不会冲淡后门，论文没测。
- **载荷是固定字符串**：只测了"输出一条固定命令"，没测自适应载荷或生成恶意代码（p10–11）。固定字符串反而也便于防守方检测（我的判断）。
- **低剂量结论只有单种子**，而主实验显示种子间方差可以相差几十个百分点，所以低剂量那几个 1% 量级的数字不宜当作稳定结论。
- **未投毒对照只跑了 1 次**，不过它在所有格子都是 0.0%，这里方差问题不大。
- **成本**：主实验 3 个规模 × 2 种设计 × 2 种触发器 × 3 个种子，预训练每次 2.2–4.5 天，总算力很高；论文没有给出总 GPU 小时数（论文未说明）。
- **README 措辞核对**：作者阵容写成"Anthropic Fellows / Anthropic，含 Carlini"基本准确，但要注意前四位作者的单位分别是 UC Berkeley、UIUC、Deeptune、UCL，只是同时参加了 Anthropic Fellows 项目。
