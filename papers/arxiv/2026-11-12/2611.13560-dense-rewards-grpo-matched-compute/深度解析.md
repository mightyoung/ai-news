## 1. 一句话先懂它

用强化学习教小模型做数学题时，很多「给每一步单独打分」的改进看上去更有效，但那是按「训练步数」比的；这篇把生成的 token 和 GPU 小时都算进去再比，发现这类改进反而大幅落后，而「挑难度刚好的题来训」这种便宜招数才真有小幅收益。做 RL 训练、要评估各种新技巧的人值得看。

## 2. 值不值得读：五个 C 速览

**类型**：测量分析，外加一套评测协议（方法论）。**上下文**：接着两条线：一是给推理过程逐步打分的稠密奖励（Math-Shepherd、VinePPO 的蒙特卡洛估值、PRIME 的隐式奖励）；二是按难度挑训练题（DAPO 的动态采样、GRESO、PCL）。**关键假设**：小模型、短训练上看到的排序能代表真实情况；作者自己承认最大只做到 4B、任务只有数值答案的 MATH 题，这个假设在大模型上站不站得住还不知道。**贡献**：①提出「算力对齐」协议：同时按生成 token 和训练 GPU 小时给每种改进相同预算，并预先登记假设；②用它否掉了蒙特卡洛稠密奖励，确认了「按预测成功率挑题」的小幅收益；③指出梯度测试只能排序、不能担保收益大小。**清晰度**：正文很密，几乎每句都带置信区间和 p 值，对新手不友好，但数字齐全，局限写得很坦诚。建议**看到第 5 节**；如果你在搭 RL 训练平台或要写对比实验，值得自己读原文第 1、6 节和附录 B。

## 3. 它在解决什么麻烦

现在用 RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习：只看最终答案对不对来给奖励）训练推理模型，最常用的算法是 GRPO（Group Relative Policy Optimization，组相对策略优化：同一道题采几条回答，按组内相对好坏给分）。它的毛病是一条回答里所有 token 拿到同样的功劳：前面推得很对、最后一步算错，整条一起挨罚。于是大家提出稠密奖励（也叫过程奖励：给中间每一步不同的功劳），比如蒙特卡洛奖励——在回答中途切几刀，从每个切点往后多续写几次，看续写的正确率涨了还是跌了，以此给这一段打分。

问题在于大家怎么判断它有用：要么「同样的训练步数下谁更准」，要么在一个固定批次上做梯度测试，看更新方向对不对。这两种检查都没算成本。作者的设置里，续写本身就占了全部生成 token 的 91%（第 1 页）。

你在自己的训练平台上很容易撞上这件事：有人报告「换了新奖励，同样 100 步准确率高 2 个点」，但没说这 100 步多烧了几倍的推理和机时。上线后预算固定，反而比老办法差。这篇如果说得对，意味着评估任何训练技巧都应该把 token 和 GPU 小时的账摆出来，很多「涨点」会消失，少数会留下。

## 4. 他们怎么做的

**核心思路**：给每种改进同样的「钱」，看谁花完后更准。钱有两种计法，生成 token 数和训练 GPU 小时，两者会给出不同排名，所以都报；同时也照报「等步数」的结果，作为反面对照。

**预算怎么定**（第 3–4 页）：token 预算 B 统计训练中生成的每一个 token，包括续写和被丢弃的样本；B 取 k=4 蒙特卡洛奖励跑 48 轮所用的 token 数，Qwen2.5-1.5B 上是 1225 万（第 4 页），所以最贵的方法也只能做约 50 次更新。训练时间统计打分、生成、算功劳、更新、同步权重各阶段，不含评测；等时间比较只在同一种 GPU 上做。

**训练配方**（第 3 页）：六个小模型（Qwen2.5-1.5B-Instruct，Qwen3 0.6B/1.7B/4B 非思考模式，Llama-3.2-1B/3B），训练题是带数值答案的 MATH 题；每轮 8 道题、每题 8 条回答，一步 Adam，学习率 10⁻⁶，不用比率裁剪和 KL 惩罚。指标是 200 道留出 MATH 题上 8 次采样的平均正确率（pass@1），只取预算用完后第一次评测，不挑检查点（第 4 页）。

**被测的两类改进**（第 3 页）：①蒙特卡洛奖励：每条回答固定切 5 刀分成 6 段，每个切点续写 k 条，续写正确率当作「从这里出发能做对的概率」，每段的功劳是这个概率的变化；续写只打分不训练。另测了学习型评论家（critic：用岭回归在模型隐藏状态上预测这一步的价值，不用续写）、VinePPO 式和续写复用两种变体。②挑题：每轮抽 24 道候选题，用评论家在题目末尾的隐藏状态上预测成功率，留下最接近 1/2 的 6 道，再随机补 2 道；打分只需一次前向，不生成 token。对照组是在同样 24 道里随机挑 8 道，用来排除「题目流过得更快」这个副作用。

**统计规矩**（第 4 页）：每项研究开跑前把假设、主比较、等效边界写进计划文件（预登记），同一种子下各配置共用题目，算配对差；主比较做 Holm 多重比较校正，没预登记的结果标为探索性。另外用只认 `\boxed{}` 答案的严格判分器，防止模型慢慢「不写框」钻判分漏洞。

**如果让你复现**，最小骨架是：

```python
B = tokens_used_by(mc_reward_k4, iters=48)        # 预算按最贵方法跑 48 轮定
for method in [grpo_baseline, mc_reward, critic_filter, random_choice]:
    for seed in seeds:                             # 各方法同种子、同题目，便于配对
        run = train(method, seed, lr=1e-6, prompts=8, samples=8)
        while run.generated_tokens < B:            # 续写、丢弃样本都计入
            run.step(); log_stage_seconds(run)     # 分阶段记 GPU 时间
        acc[method][seed] = eval_pass1(run, heldout_math_200)
report(paired_diff(acc, vs=grpo_baseline), axes=["updates", "tokens", "gpu_hours"])
```

## 5. 证据怎么看、别被什么忽悠

**图一：Figure 1（第 2 页），把每个 token 算上，赢家就换了。** 想证明：同样的生成 token 下，四种改进相对普通 GRPO 谁赚谁亏。怎么测：Qwen2.5-1.5B-Instruct 在 MATH 上训练，预算 B 为 1225 万 token，柱子是准确率减去普通 GRPO；种子数分别是蒙特卡洛 5 个、评论家 24 个、挑题 60 个。结果：蒙特卡洛奖励在 B 时低 14.3 个百分点（Qwen2.5-1.5B、k=4、5 个种子），因为同样 token 下 GRPO 走了 584 步、它只走了 50 步；等训练时间低 7.8 点（12 个种子，第 5 页）；评论家在 −0.4 到 +0.7 之间；挑题 +0.8，在 Qwen3-0.6B 上 +1.7。说明：按步数领先的方法，按 token 算可能垫底。

**图二：Figure 2（第 6 页），梯度测试能排序但估不准大小。** 横轴是梯度效率（一步更新能带来多少期望提升，扣掉噪声），左图按每次更新算，右图按每个生成 token 算；纵轴是相对 GRPO 的准确率差。按更新算 k=4 是 GRPO 的 1.56 倍，按 token 算只剩 0.145 倍（第 5 页）。按 token 的效率把 k=1、2、4 排成 0.45、0.27、0.15 倍，和训练结果顺序一致；但外推出的准确率（35.9%、31.9%、27.5%）都高于实际（34.3%、29.9%、26.3%，第 6 页），五种奖励平均高估 0.8 到 1.8 点，和要检测的收益一样大。

**图三：Figure 3（第 7 页），把训练时间也拉平。** 左图：768-token 回答、8 个种子、A100，所有稠密奖励变体一直跑到超过 GRPO 用完预算的时间，再在那个时间点比：k=4 低 3.3 点，续写复用低 5.2，VinePPO 式低 1.1，k=1 低 1.1 但不显著（第 5 页）。没有一种赢。右图：挑题在等训练时间下仍领先 1.0（Qwen3-0.6B）和 0.5（Qwen2.5-1.5B），标为探索性。

**水分检查**：①种子：头条 14.3 只有 5 个种子，另在 12 个新种子上复现为 14.9；挑题收益用了 54–60 个种子，统计做得比多数论文扎实。②基线调优：作者专门把 GRPO 学习率翻倍做对照，Qwen3-0.6B 上 GRPO 涨 1.9 点，和挑题只差 −0.03 点（第 9 页）——这恰好削弱了挑题的价值。③规模：最大 4B，Qwen2.5-7B 只在另一套等步数配方里扫了 43 次运行（第 5 页）；回答长度 380 token 时 73% 的初始样本被截断（第 14 页），换 768 token 后蒙特卡洛的差距缩小到 6.6 点。④硬件：等时间结论依赖生成和更新的耗时比，换 GPU 或推理引擎可能变（第 16 页）。⑤复现方式：稠密奖励变体是作者按自己训练器改写的，不是原论文复刻（第 15 页），VinePPO 原版有更多续写和 PPO 配方。⑥任务单一：只在 MATH 数值题上训练，评测是 MATH 和 GSM8K，没有代码或其他任务。

## 6. 可信度与核验限定

**主张对照**：①「算力对齐后排名反转」：Figure 1、2 和第 5 页数字支撑，且 12 个新种子全部同向，证据够。②「四种稠密奖励变体在等训练时间下都没赢」：Figure 3a，8 个种子，够，但只在一个模型和一种回答长度上。③「挑题有效」：只在六个模型中的两个成立，收益是早期领先，翻倍学习率的基线可追到半个点以内（第 9 页），证据够但收益小。④「候选题平均预测成功率低于 1/2 时才有效」：事后从五个设置归纳，六个预登记测试中五个符合，唯一的「预测有收益」的跨家族测试（Llama-3.2-1B）失败了（第 9、15 页）。

**核验限定**（原样合入核验报告）：
- 「等 token 低 14.3 点」是 Qwen2.5-1.5B、k=4 蒙特卡洛奖励、5 个种子；「等训练时间低 7.8 点」是 12 个种子（p5）
- 评测是 200 道留出 MATH 题 pass@1，主实验只在 0.6B–4B 小模型上做，Qwen2.5-7B 只做了补充检查（p3；p4；p5）
- 代码仓库公开但未声明许可证（github-api.txt）

**打折提醒**：对外不要说「过程奖励没用」，要说「在 0.6B–4B 小模型、MATH 数值题、按 token 或 GPU 小时算的条件下，作者改写的蒙特卡洛稠密奖励没赢过 GRPO」；挑题的 +1.7 也要加「Qwen3-0.6B、等 token、调高学习率的基线基本追平」。

## 7. 你可以怎么落地

**今天就能试**：在你现有的 RL 或微调实验报表里加三列：累计生成 token（含被丢弃样本和辅助续写）、分阶段 GPU 小时、更新步数，并把新技巧和基线在「等 token」「等时间」两个横轴上各画一条差值曲线。不需要新数据。验收：如果某个技巧只在「等步数」上领先、换到 token 或时间轴就落后或落在 ±1 点内，就不要采纳。

**要有数据或机器再试**：如果你本来就在跑 GRPO，可以加两个便宜对照：同一批候选题里随机挑（排除「题过得快」的副作用），以及学习率翻倍的基线。再试作者的挑题法：用一次前向在提示末尾的隐藏状态上拟合岭回归，预测每题成功率，留最接近 1/2 的题。先跑一段普通 GRPO 试点，看候选题是否偏难（作者用试点的训练奖励来判断，第 8、15 页）。需要一张 H200 或 A100 级别显卡，Qwen2.5-1.5B 上普通 GRPO 用完预算约 0.43 个 H200 小时（第 5 页），每个配置至少 12 个种子才分得出 1 个点的差别。

**暂时别碰**：别在预算固定的生产训练里上蒙特卡洛续写式稠密奖励，按作者的结果它每个 token 亏 3 到 15 点（第 5 页）。也别拿单批次梯度测试当「这个奖励能涨点」的证明，它会高估 1 到 2 点。挑题的「低于 1/2 才有效」规则只在 Qwen 家族上验证过，Llama 上预测失败，别当通用规则。

## 8. 和你已有知识的挂钩

它像性能测试里的「同成本对比」：两个服务比吞吐，必须在同样的机器和预算下比，不能一个跑 100 次、另一个跑 1000 次；也像 A/B 测试里预先登记指标、防止事后挑结果。和 VinePPO、Math-Shepherd 等稠密奖励论文最大的区别是：它不提新奖励，而是改了「怎么判输赢」的规则，把续写成本、判分器漂移、基线学习率都纳入对照。

## 9. 存疑与代价

**局限**：作者承认最大只到 4B，四个模型属于 Qwen 家族，Llama 只测了挑题；学习率没有逐模型调；等时间结论依赖 GPU 类型；没测 LILO 这类先采样再挑题的方法（第 14–16 页）。我另外读出：所有评测共用同一组 200 道题，作者自己说 Qwen2.5-1.5B 上的交叉自助区间每次都碰到零，才另加 1,543 道题复验（第 7 页）；预登记文件在仓库里，不在公共登记平台（第 14 页）。**复现条件**：论文 CC BY 4.0；训练器、预登记文件和每次运行记录在 GitHub 公开，但未声明许可证，商用复用要先问作者；模型和数据都是公开的。**成本**：全部 1,668 次运行共 1,468 GPU 小时（第 2 页）。**出处**：预印本，未同行评审；19 位作者全部来自 Case Western Reserve University。

**论文没回答、但决定你要不要动手的 3 个问题**：在 7B 以上、长思维链的模型上，续写成本占比和生成/更新耗时比会不会变，结论还成立吗？如果续写能复用成训练样本、且基线不吃亏，稠密奖励能否在等时间下赢？挑题的收益在调好学习率调度的强基线上是否还剩下任何东西？
