## 1. 一句话先懂它

作者把一个已经训好的 27B 中文强模型，词表从二十多万个「词块」砍到只剩 256 个字节，主干一个权重都不动，再用模型自己生成的对话加维基百科续训约 1,430 GPU 小时，得到一个「一字节一步」的模型：大部分能力保住了，拼写、改字这类字符级操作明显变强，代价是生成速度只剩约四分之一。想摆脱分词器、或者关心中文字符级任务的人值得看。

## 2. 值不值得读：五个 C 速览

**类型**：新方法加大量工程测量，偏「实验报告」。**上下文**：接着两条线：从头训练的字节模型（ByT5、MEGABYTE、BLT、EvaByte），以及把现成子词模型改成字节模型的 BLT、Bolmo——后两者都保留了「切块（patching）」结构。本文第一个在 27B 规模、完全不切块地改造。**关键假设**：原 BPE 词表里本来就有 256 个单字节符号，它们的嵌入行可以直接复用，所有难点都转移到续训；训练用的对话必须是目标模型「自己当前的输出」。前者是事实（GPT-2 式字节级 BPE），后者有作者自己的对照实验（第 4 页），但只在先导模型上做过。**贡献**：①给出词表 248,320→384、主干不动、两阶段续训的完整配方；②同卡同框架的双栏对比，诚实报告保住了什么、丢了什么、慢了多少；③整理出字节模型特有的四种故障和修法。**清晰度**：数字极多但口径交代得很细，每个表都配了截断计数和区间；缺点是很多结论来自「先导线（pilot lines）」而非最终模型。建议**看到第 5 节**；如果你在做分词器替换或字节模型，第 3、6 节值得读原文。

## 3. 它在解决什么麻烦

今天几乎所有大模型都用子词分词器（tokenizer，先把文本切成「词块」再编号），常见的是字节级 BPE（Byte Pair Encoding，把高频字节组合合并成一个词块）。分词器在训练前就定死了，之后所有训练和部署都被它绑住。对中文，Qwen3.8 的分词器在中文维基上平均每个 token 3.84 字节，64% 的 token 就是单个汉字（第 1 页）；而对任何语言，模型都「看不见」一个词块内部的拼写、字符位置和数字的每一位，所以「把第三个字删掉」「两个字母互换」这种操作，模型只能靠先「思考」把词拆开再做（第 1 页）。

工程上你会在这些场景撞上：做中文纠错、改写、按字数截断、拼音或字形相关的产品时，模型老是数错字、改错位置；想换一个分词器（比如加专业词汇）时，要么重训、要么做复杂的词表迁移。

彻底的办法是字节模型：一个字节就是一个 token，词表只有 256 个加少量特殊符号。但从头训一个大字节模型太贵；已有的改造路线要么保留切块结构（主干看到的仍是「打包后的向量」），要么做跨分词器蒸馏（在 1B–8B 上被认为仍难稳定获益，第 2–3 页）。如果能直接把现成大模型「原样」改成纯字节模型，就等于用一次续训的成本换掉了分词器这个冻结决策。

## 4. 他们怎么做的

**核心思路**：既然 BPE 词表里每个多字节 token 都是由 256 个单字节符号合并来的，这 256 行嵌入本来就在，那就只删合并规则、只留这 256 行，让模型重新学会「一个汉字 = 3 个字节」。主干的 64 层（48 层 Gated DeltaNet——一种线性注意力，计算量随长度线性增长——加 16 层全注意力，第 3–4 页）完全不动。

**第一步，缩词表**（第 3–4 页）：新词表 384 项，0–255 是字节，后面是 35 个对话模板要用的特殊符号，其余占位。嵌入层和输出层各从约 1.27B 参数降到约 2M，语言模型部分从 26.9B 变成 24.4B；视觉塔冻结不动。脚本按 token 名字而不是编号偏移挑行，并逐项核对特殊符号表和对话模板的 md5——作者点名了两个容易踩的坑：配置里的视觉 token 编号，以及新版 transformers 会重排特殊符号。

**第二步，备语料**（第 4–5 页）：监督字节共 4.77 GB。其中 54% 是人写的维基正文，按预训练方式拼接切窗；另外四类对话全部由原模型自己生成（在线策略自蒸馏，即用模型自己当前的输出当训练目标）：12,126 个汉字的字典对话、141,361 个词条的词典对话、6 万多个公开对话会话的逐轮重答、人类编程会话的重答。规则是「事实来自词典，措辞由模型自己写」。只在助手回合上算损失，多轮会话每轮独立重答、只监督当前轮。作者的依据是先导线上的对照：用模型自己当前输出训练不掉分，用别人写的数据掉 5–14 分（第 4 页）。

**第三步，两阶段课程**（第 5 页）：全参数续训，ZeRO-3（一种把优化器状态切到多卡的显存节省方案），恒定学习率。M1「学编码」：64K 字节窗口、2,077 步、学习率 3e-6、47.5 小时，字典：词典：通用对话按监督字节 1:1:1 混。M2「读书」：16K 字节窗口、6,761 步、学习率 5e-6、131 小时，维基：通用语料：词典 1:1:1（按条数）。两阶段都是「混着训」而不是「先窄后宽」，因为先导线上先训窄语料再补正常数据，丢的能力回不来。

**第四步，解码护栏**（第 7 页）：推理框架里加一个自定义 logit 处理器（在模型输出概率上做过滤）：思考段和回答段各有字节预算；UTF-8 合法性掩码（首字节之后只允许续字节）；重复超过 1,024 步才触发的熔断。使用时必须关掉推理框架的重叠调度，否则护栏读到的输出滞后一个 token，反而亲手制造乱码。

另有一个 MTP 草稿头（多 token 预测，用于投机解码提速，第 6–7 页），单张 48G 卡上起不来，主表不涉及。

**如果让你复现**，流程骨架是：

```python
tok = keep_rows(bpe_vocab, bytes_0_255 + chat_specials)   # 按名字挑行，删全部合并规则
model.embed, model.lm_head = slice_rows(model, tok)       # 主干 64 层不动，视觉塔冻结
check(tok.special_ids, md5(chat_template))                # 两个易漏错误：视觉 id、特殊符号顺序
dlg = [orig_model.answer(p, thinking=True) for p in prompts]  # 对话全部由原模型自己生成
m1 = mix(char_dict, word_dict, dlg, by="sup_bytes")        # 1:1:1，64K 窗口，lr 3e-6
train(model, m1, loss_on="assistant_turns")
m2 = mix(wiki_human, general, word_dict, by="count")       # 1:1:1，16K 窗口，lr 5e-6
train(model, m2, reset_optimizer=True)                     # 服务端加 UTF-8 掩码 + 预算 + 熔断
```

两段的批大小、序列打包细节论文未说明；训练语料和权重未公开。

## 5. 证据怎么看、别被什么忽悠

**表一：Table 1（第 10 页），能力保住了多少。** 想证明：字节化后大部分能力还在。怎么测：原模型（orig）和字节模型（LD3-base）放在同一张 RTX 6000 Ada 48G、同一个推理框架（sglang，FP8），思考模式温度 0.6、非思考模式温度 0；字节模型输出上限按「字节 ÷ 4」换算给 BPE 模型。结果：非思考模式下 GSM8K 96.4→96.0、MATH-500 92.8→93.6、MMLU-Pro 79.4→78.1，C-Eval 88.1→83.4（−4.7），IFEval 四个指标掉 4.1–6.2；思考模式下 GSM8K 97.0→93.0（−4.0）、C-Eval 89.9→85.4（−4.5）。配对 bootstrap 区间（重采样题目估计差值的不确定范围）排除 0 的只有思考模式 GSM8K、两种模式的 C-Eval 和 LongBench-v2（第 11 页）。说明：数学、代码、MMLU-Pro 在噪声内，中文考试和非思考指令遵循确实掉了。LongBench-v2 的 +11 是被输出上限主导的，作者自己说不能当优势（第 10 页脚注）。

**表二：Table 3（第 13 页），字节换来了什么。** 想证明：模型能「看见」拼写后，字符级操作变强。怎么测：CUTE（英文 14 个字符操作任务）、EXECUTE 英文和中文、作者自建的 15 个中文字符任务，精确匹配。结果：CUTE 75.2→84.0（非思考模式、单种子；原模型开思考模式能做对这些题，89.4 vs 91.2），EXECUTE-zho 81.6→93.9，自建中文题 54.4→64.0（思考模式 87.8 vs 89.1）。但 Table 4（第 14 页）里同音字选择 96.5→57.5、笔画数 63.0→47.0，且思考也补不回来（第 14 页）。说明：字节化买到的是「不用思考就能做字符操作」，付出的是部分「字→读音/笔画」的查表知识。

**表三：Table 5（第 16 页），代价。** 每步速度几乎相同（单流 22.9 vs 24.3 token/s），但每步只出一个字节：单流中文字符每秒 33.1→7.7（0.23 倍），英文 115.4→24.3；64K 字节中文预填充首 token 时间 4.52→29.57 秒（6.5 倍），超出 token 数之比的部分作者归为内核没调优（第 16 页）。全部基准的墙钟时间 7 小时 44 分 vs 35 小时 57 分。

**水分检查**：①种子：全部单种子单次运行，bootstrap 只覆盖题目抽样方差、不覆盖解码随机性（第 11、20 页）。②基线：原模型是官方权重、同框架同卡，算对等；但原模型做过指令类后训练、字节模型没有，非思考 IFEval 的差距无法拆分（第 20 页）。③自建评测：中文字符题集是作者自建（已公开），bpb 对比用的是字节模型训练分布的留出集，作者自己说不能读作建模更强（第 11 页）。④污染：评测与训练集的重叠没有系统检查（第 20 页）。⑤不少结论（贪心失控的量化、惩罚项无效、自产数据优于他人数据）来自先导线而非最终模型。⑥多语言只是 22 种语言各 3 题的冒烟测试，非拉丁、非西里尔文字的生成明显退化（Table 6 第 17 页）。

## 6. 可信度与核验限定

**主张对照**：①「保住大部分能力」：Table 1 和配对区间支持，单种子，C-Eval 与非思考 IFEval 明确下降。②「字符级操作全面领先」：Table 3、Table 4 支持，限非思考模式；思考模式下差距缩到 CUTE +1.9、自建题 +1.3（第 13 页）。③「代价是吞吐」：Table 5 支持，草稿头提速只能引用其他硬件上的记录。④「自产对话数据是关键」：只有先导线上的对照（第 4 页），最终模型上没有消融。

**核验限定**（原样合入核验报告）：
- 所有数字是单种子、单次运行的作者自报结果（p9；p11）
- CUTE 75.2→84.0 是非思考模式；原模型开思考模式能做对这些题（Table 3 p13）
- 代价：每步产出少 3–5 倍，64K 字节预填充慢 6.5 倍，中文字音字形类任务下降（p1；p13）

**打折提醒**：对外别说「字节模型更强」，作者自己也不这么说（第 2 页）。引用 CUTE 提升要写「非思考模式、单种子」；引用速度要写「同卡单流，中文字符每秒约为原来 1/4」，并说明草稿头提速没在同卡上测到。

## 7. 你可以怎么落地

**今天就能试**：用作者公开的评测包（leiwhere/ld3-byte-eval）里的中文字符题集，或者自己写 20 道「删第 N 个字、两字互换、数字数」的题，在你现在用的模型上分别跑非思考和思考模式，记录准确率和每题消耗的 token 数。不需要训练。验收：如果非思考准确率明显低于思考模式、且思考模式每题要花上千 token（论文里原模型 CUTE del_word 平均 3,306 token，第 13 页），说明你的业务确实被分词器卡住，值得关注字节路线；否则不用折腾。另外，如果你在做任何逐字节或小词表的采样，记得检查 presence/frequency 惩罚是否真的起作用（第 19 页说在 256 项词表上基本无效）。

**要有数据或机器再试**：完整复刻需要 8×H200 约 178.6 小时续训，加约 760 GPU 小时生成语料（第 8 页），训练语料和权重未公开，个人基本做不了。可行的缩小版：拿一个 1B–3B、同样是字节级 BPE 的开源模型，照第 3.1 节删合并规则、留 256 行，先用几百 MB 自产对话 + 字典做 M1，看中文 bpb 能否从零适应的 3 左右降到 1 以下、字符操作题有没有提升。分阶段：先验缩词表脚本（特殊符号、模板 md5）；再验 UTF-8 护栏和关重叠调度；最后才上 M2。

**暂时别碰**：别把字节模型直接放到线上对时延敏感的中文生成服务里——同卡中文字符吞吐只有约 1/4，长输入预填充慢 5–6.5 倍，草稿头在 48G 单卡上起不来（第 16 页）。也别对它用贪心解码或依赖频率惩罚控重复，作者记录了贪心失控和惩罚无效（第 17–19 页）；需要中文读音、笔画这类知识的场景也不合适。

## 8. 和你已有知识的挂钩

它像「换编码不换引擎」：把程序的输入从「词表编号」改成原始 UTF-8 字节流，引擎（主干）不变，只重写两端的编解码，再花时间让引擎适应新输入。也像词表迁移（ZeTT、FOCUS、TokAlign）的极端情形：新词表只剩 256 个字节，而且嵌入现成，不需要初始化技巧。和最接近的 BLT、Bolmo 最大的区别是不加切块结构和局部编码器，主干每个字节走一步，所以序列不压缩，速度代价全部如实暴露。

## 9. 存疑与代价

**局限**：作者在第 20 页列了单种子、IFEval 归因不清、字符知识未恢复、思考不稳定、多语言退化、重复未治愈、污染未查等。我另外读出：后训练链（M3）权重已删，只剩日志，第 3.4 节的经验无法复验；长上下文实验只测了字节模型，没有原模型对照（第 14 页）。**复现条件**：评测脚本和题集公开；权重、训练语料未公开；基座是官方开放权重。**成本**：主干约 1,430 GPU 小时，MTP 头约 35 GPU 小时，语料生成本地约 760 GPU 小时、含外部 API 换算约 2,190（第 8 页）；作者估计续训约 1e21 FLOPs，与 Bolmo 同量级，所以不说「便宜 N 倍」。**出处**：预印本，未同行评审；两位作者署名小型实验室，邮箱为个人邮箱。

**论文没回答、但决定你要不要动手的 3 个问题**：多少中文监督数据才能把读音、笔画这类查表知识补回来？草稿头在能装下的硬件上，同卡同框架实测能把吞吐追回多少？给字节模型补一轮指令类后训练后，非思考 IFEval 和 C-Eval 的差距还剩多少？
