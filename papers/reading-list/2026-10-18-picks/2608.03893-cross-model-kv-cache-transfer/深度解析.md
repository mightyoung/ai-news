# 跨模型 KV Cache 迁移：用一个闭式线性映射在同一模型家族里复用 prefill 深度解析

- 论文：*Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for Prefill Reuse*
- 作者与单位：Taekyung Heo, Rasoul Shafipour, Ritchie Zhao, Maximilian Golub, Mohammad Mahdi Kamani, Ritika Borkar, Makesh Tarun Chandran, Pantea Zardoshti, Bita Darvish Rouhani；**NVIDIA**（PDF 首页署名，作者 9 人）。
- 出处：arXiv:2608.03893v1，cs.LG，**Submitted 4 Aug 2026**；PDF 标注 "Preprint"，arXiv 页 Comments 为 None，未见会议/期刊信息，未经同行评审（据我所查）。**论文中没有给出代码或权重链接。**
- 原文：`paper.pdf`（arXiv 官方 PDF，21 页，1.6 MB，已校验 %PDF 与 pdfinfo；标题/作者与 abs 页一致；已随本仓库归档，许可见 README 与来源信息）。
- 阅读深度：**全文读完**，包括摘要、正文 §1–§6、附录 A–H（相关工作对照表、线性结构分析、扩展消融、实验设置、运行信息、完整结果表、延迟细节、k 选择的泄漏检验）。只有图（热力图、折线图）看的是图注，没有逐点读数；参考文献没有逐条核对。

## 1. 一句话要点与用处

同一个模型家族里（如 Qwen3-14B 和 Qwen3-32B），两个模型的 KV cache 之间有很强的**线性关系**。作者用一小批文本（500 条×1024 token）为每个注意力头解一个**岭回归**（闭式解，不需要梯度训练），就能把"小模型已经算好的 KV cache"直接映射成"大模型想要的 KV cache"，让大模型**跳过 prefill 直接解码**。用处：线上同时跑一个模型家族里的多个尺寸（级联、路由、对话中途换模型）时，换模型不必把长上下文重新过一遍。**但**能不能用要先在每一对模型上测，6 对里有 2 对明显失败（见第 4 节）。

## 2. 实际痛点/场景

- 智能体长会话：上下文越攒越长；每次换模型（便宜模型先答、不行再升级到大模型；按难度路由；对话中途切换）接收方都要把整段上下文重新 prefill 一遍，成本随模型尺寸和长度上升。
- 现有"前缀缓存"只在**同一个模型**内部有用，跨模型就失效。
- 已有的跨模型 KV 复用做法（C2C 的神经融合器、LatentAlign 的适配器、IAM 的注意力替换、DroidSpeak 要求完全相同结构）要么需要梯度训练，要么需要相同架构（论文 §2.2、表 6）。

## 3. 方案思路与步骤（白话）

前提：只做**同一家族**、且两边的 KV 头数和每头维度一致（论文称 matched-KV，如 Qwen3 全是 8 个 KV 头×128 维）。层数、隐藏维度、参数量可以不同。

1. **先做探测**：对每一对"源层 → 目标层"，在 FineWeb-Edu 的 token 上拟合一个线性回归，看 R²（解释了目标 KV 多少方差）。结果（Qwen3 14B→32B）：单个源层只解释 key 的 56%、value 的 32%；用多个源层可到 79% / 65%。key 比 value 更好预测，约差 0.2。
2. **逐头岭回归**：对目标模型的每一层、每个头，单独拟合一个线性映射（K 和 V 各一个，互不共享）。输入是**挑出来的 k 个最有预测力的源层**的 KV 拼接起来；闭式解 W=(XᵀX+λI)⁻¹XᵀY，λ=0.01。校准数据：500 条×1024 token，隔 4 个 token 取一个，每个目标头约 12.8 万个样本；一台 8×H100 上每对模型拟合约 47–87 分钟。
3. **去掉 RoPE 再映射**：KV cache 里存的 key 已经被位置编码 RoPE 旋转过。作者先把源 key 的旋转"反转"回去，在**与位置无关**的空间里做线性映射，再用目标模型的 RoPE 旋转回去，这样同一套权重可以用在不同长度的上下文。value 没有位置编码，直接映射。
4. **推理时**：源模型 prefill 得到 KV → 每层一个批量矩阵乘法 → 目标模型用映射出来的 KV 直接开始解码，不跑自己的 prefill。方向相关：大→小和小→大要各拟合一套。
5. 作者还试了把岭回归换成每头一个两层 MLP（1024 单元，Adam，20 轮），并提出用"注意力输出的余弦相似度"来解释为什么有的模型对迁移成功、有的失败。

## 4. 如何读实验与识别夸大

**评测设置**：3 个家族、6 个 matched-KV 对：Qwen3（14B→32B、8B→32B，均为后训练模型）、Llama 3.1（8B→70B，**基座**模型）、Ministral 3（3B→8B、3B→14B、8B→14B；论文说其为推理调优模型）。5 个基准：ARC-Challenge、HellaSwag、WinoGrande、MMLU 5-shot、GSM8K 8-shot CoT；另有 WikiText-2 前缀条件困惑度、CoQA 多轮。指标是"保留率"= 迁移后准确率 ÷ 目标模型自己的准确率。全部是作者自测，**未见第三方复现，单次运行、没有种子或置信区间**（论文未说明）。

我核对的关键点：

| 摘要说法 | 我从表里看到的 |
|---|---|
| "保留 73–98% 的接收方独立 prefill 准确率" | 这是**挑出 4 个较好的对**后的 5 个基准**平均**保留率（表 1）：Qwen3 14B→32B 97.6%、8B→32B 87.5%、Llama 8B→70B 72.8%、Ministral 3B→8B 76.2%。另外 2 对是 44.2% 和 41.6%（按"扣除随机水平"的保留率只有 14.7% 和 11.1%）。摘要和正文都明说了两对"退化严重"，这点诚实；但"分成 Tier 1/Tier 2"是看完结果后分的，**不是事先能预测的**。 |
| 平均数掩盖了单项崩溃 | Llama 8B→70B 的 GSM8K 保留率只有 18.2%（14.78 vs 70B 的 81.12），Ministral 3B→8B 的 GSM8K 36.6%，Qwen3 8B→32B 的 GSM8K 68.8%（65.50 vs 95.15）。**分类/打分类基准（HellaSwag、ARC、WinoGrande）保留得很好，需要多步生成的 GSM8K 衰减最重**。73% 的"平均"是被这些高保留率的选择题基准拉起来的。 |
| "小模型→大模型提升质量" | 第 1 节说小→大"升级质量"。但表 13 里：Qwen3 14B→32B 的 MMLU 迁移后 78.09，**低于 14B 自己独立的 78.86**；GSM8K 90.98 低于 14B 独立的 95.00。Qwen3 8B→32B 的 MMLU 72.74（8B 独立 75.42）、GSM8K 65.50（8B 独立 91.66）；Llama 8B→70B 的 GSM8K 14.78 远低于 8B 独立的 56.10。也就是说**迁移后的大模型有时还不如直接用源小模型**，论文用"相对目标的保留率"表述会让人忽略这一点。HellaSwag 和 ARC 上则确实高于小模型（如 Qwen3 14B→32B 的 HellaSwag 80.70 vs 14B 的 78.87）。 |
| "2.7–25× 比 re-prefill 更快" | 摘要的区间是把 5 个小→大的对、10 个序列长度（64–32768）全部取最小/最大。正文 Qwen3 14B↔32B 表 5：小→大 4×（64 token）到 25×（32K），大→小 3–7×。2.7× 来自 Ministral 3B→8B（附录 G 表 16：2.7–4.0×）。**25× 是最佳对在 32K 长度的数字**；Llama 8B→70B 在 32K 为 14.9×。 |
| 延迟测的是什么 | 附录 G：**合成输入**，一台 8×H100 NVLink 节点，bf16，mapper 为 eager 模式；"迁移延迟"含跨 GPU 拷贝，但**不含把映射后 cache 送到目标进程的过程**（论文自己说没测）。**源模型自己的 prefill 时间没算进去**（因为场景假设源模型本来就要先答）。真实服务里 prefill 与 decode 并发、批处理、跨节点网络，都未测。 |
| 超参选择与评测基准重叠 | k（用多少源层）是在 ARC-C/HellaSwag/MMLU 上选的，这些又是报告的基准。附录 H 做了留一基准重选：最多影响 2.49 pp（Tier 1 最多 1.45 pp），并在 PIQA/BoolQ/ARC-Easy 上做了不参与选择的留出评测，Tier 1 保持在 96% 以上、Tier 2 在 64% 以下。**GSM8K 与 CoQA 没有参与选择**。这是论文做得较好的地方。 |
| 校准数据 | 全部用 FineWeb-Edu。换成 Wikipedia 平均保留 99.4%，换成 CodeAlpaca 平均 95.9%，范围达 11.1 pp；**窄领域（医疗、法律）没有测**（论文自己写进了局限）。 |
| 多轮 | 仅 Qwen3 14B↔32B，CoQA 100 段对话×约 15 轮，看 10 轮。小→大差距 10 轮内扩大 1.7 pp，大→小每轮漂移 0.33 pp；论文说"单一对、10 轮内未见级联失败"。**一个模型对**。 |
| 长上下文 | 校准用 1024 token，延迟测到 32K，但**准确率评测的上下文都很短**（我没看到 4K 以上的准确率结果）；"去 RoPE 空间使其能泛化到更长上下文"是论文的"by construction"推理，没有实证。消融里"全程保留 RoPE"和"完整方法"在 1024 token 评测上**几乎一样**（表 2：MMLU 77.70 vs 78.09），所以去 RoPE 这个设计的收益在论文自己的实验里并没有被证明；真正崩溃的是"拟合时去 RoPE、推理时没重新旋转"这种不一致设置。 |
| 机制解释 | "误差落在哪里（注意力敏感子空间）而不是误差大小决定成败"：依据是 12 个"对×方向"点上，注意力输出余弦与 HellaSwag 保留率 Pearson r=+0.57，而校准 R² 为 −0.20。**12 个点、相关系数 0.57，且全部是事后诊断（需先拟合映射才能算）**；论文也承认"not a predictor"。MLP 在失败对上提升 +24～+37 pp（HellaSwag 保留率），但**只在 HellaSwag 上测了**（没有 MMLU/GSM8K）；且成功的对上 MLP 略低于岭回归。 |
| 另一个基线缺失 | 没有和**直接用小模型回答**、**目标模型自己 prefill**之外的方案做数值对比：C2C、LatentAlign 等都只在相关工作表里做了定性对照（表 6），**没有跑它们的数字**。因此"闭式方法比训练方法好/差多少"论文未回答。 |

## 5. 落地分层

**今天能试**
- 如果你有一个自托管的 Qwen3 系列多尺寸服务，并且 prefill 占了明显成本：在内部评测集上复现 14B→32B 一对，先看你自己的任务（尤其是需要多步生成的）上的保留率，不要只看选择题。
- 把"R² 高不等于可用"当作工程检查项：先在小评测集上测迁移后的下游准确率，而不是只看拟合 R²。

**需要资源**
- 每个方向、每对模型要各存一个映射：论文量级 1–3.4 B 参数、4–12 GB（表 12），P 个模型最多 P(P−1) 个映射，5 个模型约 131 GB（论文自己估的，内存/磁盘而非显存）；论文给的"页入 80–480 ms"是**按带宽估算，未实测**。
- 拟合要 8×H100 上约 1 小时/对；还要把映射接入你的推理引擎（vLLM/SGLang 的 KV 管理、分页注意力、量化 KV 等论文都没涉及）。

**可跳过/暂不要上线**
- 不同家族之间（如 Qwen→Llama）、KV 头数或头维度不一致的组合、滑窗/局部注意力、混合 SSM 架构：论文**明确没测**。
- 需要长文本精确召回、代码、数学多步推理、对安全对齐敏感的场景：论文没测或测得很弱（GSM8K 衰减严重）。
- 对答案质量要求高于成本的路径：迁移后的质量可能低于源模型本身。

## 6. 与已知概念的挂钩

- **前缀缓存/PagedAttention/RadixAttention**：同模型内复用；本文是跨模型。
- **跨层 KV 共享（CLA 等）**：同一模型内 KV 相似性；本文用"多源层→一个目标层"的线性组合延伸到跨模型。
- **推测解码/级联路由/模型路由**：论文要加速的是"路由到更大模型"的那一步开销。
- **表示对齐 / 线性表示假说 / 模型拼接（model stitching）**：不同尺寸模型内部表示可由线性变换对齐，是本文的理论背景（论文引用 Huh 等的柏拉图表示假说一类）。
- **岭回归/闭式解**：和 LoRA 之类需要训练的方法形成对比；这里的亮点是"零梯度"。
- **RoPE 的旋转矩阵是正交的**，所以"反旋转"是精确的，这一点论文明确用到。

## 7. 疑点、局限与成本

论文自述的局限：只用 FineWeb-Edu 校准；k 在报告基准上选择（附录 H 量化为 ≤2.49 pp）；6 对全是 matched-KV，没测不匹配组合；只覆盖同家族、稠密全注意力模型。

我的疑点：
1. **成败不可预测**：6 对里 2 对失败，论文只给事后诊断，没有事前判断办法；上线前必须逐对验证。这和"practical"的结论有张力。
2. **评测偏容易**：4 个选择题（对数似然打分）基准加一个 GSM8K；整体保留率的高数字主要来自选择题。CoQA 多轮仅一对模型。
3. **迁移后可能低于源小模型**（见第 4 节表），"升级质量"的论述证据不足。
4. **没有数字级的基线对比**（C2C、LatentAlign、DroidSpeak 等未跑）；也没和"直接用小模型的答案+大模型只做验证"之类的系统层面方案比。
5. **延迟是理想化测量**：合成输入、单节点、eager 模式；没算源 prefill、网络搬运、批处理并发。
6. **长上下文准确率未测**，"位置无关所以泛化"为推理而非证据，且消融里该设计在短上下文上没有可见收益。
7. **作者全部来自 NVIDIA**，论文未声明与具体产品的关系；未提供代码，社区复现门槛较高（论文未说明将开源）。
8. Ministral 3 的困惑度因其独立困惑度异常高而没有报告，模型为"推理调优"，这类模型的失败是否与此有关，论文未解释（我的判断：可能与训练方式/蒸馏关系有关，但论文未验证）。

**未核实项**：未复现任何数字（无代码）；未逐条核对参考文献（C2C、LatentAlign、IAM、DroidSpeak 的说法按论文转述）；图中的热力图/曲线仅读了图注与正文引用的数值；未核对 NVIDIA 是否有相关官方博客/代码发布。
