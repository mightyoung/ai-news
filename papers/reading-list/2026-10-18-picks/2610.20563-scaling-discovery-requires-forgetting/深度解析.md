# Scaling Discovery Requires Forgetting（发现任务的规模化需要"遗忘"）深度解析

- 论文：*Scaling Discovery Requires Forgetting*
- 作者：Shangyin Tan、Ben Zhou、Lakshya A Agrawal、Jialin Zhang、Yilin Chen、Qiuyang Mang、Donghyun Lee、Dennis Jacob、Koushik Sen、Alex Dimakis、Matei Zaharia

## 1. 一句话

让一个"自己改代码、拿分数反馈、再改"的 LLM 研究 agent 长时间跑下去，它会越来越保守、越改越小，最后卡在平台上；作者的办法是**定期把所有 agent 的对话和历史候选全部清空，只留下目前最好的那一个候选**，让新的、上下文为空的 agent 从它重新开始。同样的预算下，这样"带遗忘的 4 人团队"在 4 个任务上都比"1 个 agent 一直干"和"4 个 agent 并行"更好。

## 2. 解决的实际痛点

- 自动化研究/自动调参（AlphaEvolve、Karpathy 的 autoresearch 一类）有三种扩规模方式：让单个 agent 跑更久、多个 agent 并行、并行 agent 互相看对方的候选。论文说三种都会"平台化"：钱花得越多，提升越小（§4.1，图 1）。
- 原因（§5）：agent 的会话里积累了每次失败尝试，它被自己的历史"锚定"，改动越来越小、思考越来越短，甚至直接宣告"已到极限"而不再提交候选。
- 场景：你在用编程 agent 优化一个有明确打分器的目标（竞赛启发式解、内核性能、训练脚本的验证损失），预算花了一半就不动了。

## 3. 方案思路

- **一个 agent 的循环**：提出候选（代码改动）→ 打分器评分 → 带着分数和反馈再提出。累积两种历史：**搜索状态**（每个候选+分数+反馈，在版本库里是一个 commit）和**会话**（产生候选的整段对话与推理）。
- **遗忘（forget）**：搜索被切成若干轮；每轮结束时，丢弃会话 + 搜索状态，只保留最佳候选及其分数；下一轮的新 agent 用**空上下文**、**和第一轮相同的指令**、从这个候选开始。
- **团队**：4 个 agent 并行，各有自己的会话和搜索状态；每次提出前，每个 agent 能把同伴的候选（含分数）当作文件看到。**没有点对点聊天、没有调度者**，通信是异步且不花 token 的。遗忘时整个团队一起清空，所有人从全队最佳候选重启。
- **实现**：一个小 harness 里有"reducer"，决定 agent 下一回合看到哪些候选文件、续哪个会话。单 agent、并行、团队、遗忘都只是 reducer 的不同设置。agent 用 Pi 框架、模型是 DeepSeek V4.1 Flash（论文说明；我没有独立核实该模型）。
- **团队设置**：遗忘 3 次，把预算分成 4 轮；每种配置每个任务跑 3 次；三种配置总花费相同。

## 4. 怎么看实验、怎么识别夸大

四个任务与预算（附录 A）：AHC014（AtCoder 启发式赛题，C++，$20，最大化 30 个官方用例的平均分）、VLIW 内核（Anthropic 的性能 take-home，最小化周期数，参考实现 147,734 周期，$40）、Frontier-CS Q171（C++，$20，75 个用例，0–100 分）、nanochat-autoresearch（5 分钟内训练小语言模型，最小化验证 BPB，$20）。

表 1（3 次运行，均值）我复核了摘要里的"最多 15%/39%"：

| 任务 | 单 agent | 4 并行 | 遗忘团队 | 团队相对并行 | 团队相对单 agent |
|---|---|---|---|---|---|
| AHC014（×10³，越高越好） | 795 | 964 | 1,103 | +14% | +39% |
| VLIW 周期（越低越好） | 1,426 | 1,220 | 1,097 | −10% | −23% |
| Frontier-CS Q171 | 64.0 | 70.2 | 80.8 | +15% | +26% |
| nanochat val BPB | 0.980 | 0.980 | 0.961 | −1.9% | −1.9% |

- 摘要里"相对并行 up to 15%"= Q171 的 15%；"相对单 agent up to 39%"= AHC014 的 39%。**这是取最有利的任务**；四个任务平均约 +10%（对并行）/ +22%（对单 agent），正文也是这么写的，这个更诚实。nanochat 只有约 2%，且并行 agent 相对单 agent 没有增益。
- 表 2：每次遗忘后均值几乎都继续上升，大部分增益来自第一次遗忘（AHC014 +11.2%，到第三次只有 +1.7%）；"36 次遗忘中 32 次在下一轮产生新最优"（4 任务×3 次遗忘×3 次运行 = 36，数量对得上）。
- 表 3（同一个已平台化的状态，再给 30 次提案）：继续 vs 遗忘——单 agent +1.6% vs +4.5%、并行 +1.9% vs +7.0%、团队 +1.4% vs +9.2%（±6.9），遗忘的花费大约只有继续的一半（团队 $15.32 vs $24.67）。
- §5 的机制证据：VLIW 单 agent 的三次运行里，763 个完成的回合中 532 个没有产出候选，占模型花费的 66.2%；其中 531 个是"读不超过一个文件、不改、宣告到顶"。遗忘后 AHC014 的改动行数从很小回到约 50 行，推理 token 约翻倍。

识别夸大/需要打折的地方：

1. **只有 3 次运行**，且团队在 AHC014 的 ±6.9（表 3）与均值 +9.2% 同量级；最后表 1 的 s.d. 很小（如 ±18 周期）但样本仍是 3。
2. **没有"4 人团队+通信、不遗忘、跑满同样预算"的完整对照**——最接近的是 §4.3：从平台化状态再继续 30 次提案（只增益 1.4%），但这是在一次运行中间插入的实验，不是从头到尾的对照。遗忘的次数、时间点是固定均分（3 次），没有对比不同遗忘频率。
3. **"预算相同"指总花费相同**：遗忘后上下文短，每回合更便宜，所以同样的钱可以多跑回合；这既是方法的优点，也意味着"同样的算力"不是同样的回合数。
4. **只有一个模型（DeepSeek V4.1 Flash）、一个 agent 框架（Pi）**。较强的模型会不会更晚平台化、或平台化原因不同，论文没测。
5. **单 agent 基线有明显的"提前收工"行为**（532/763 空回合）。这部分是 agent 提示词允许"不提交也能结束回合"造成的，对基线不算很友好；论文的态度是这反映了"保守性"。我的判断：这确实是现象，但把它全归因于"历史积累"需要对照"同一 agent 换更强的提示"才能下结论。
6. 因果证据多是**对轨迹的观察性分析**（编辑行数、思考 token、个案），个案（VLIW 里新 agent 读同伴 diff 后得到 1,136 周期）是挑选过的好例子。
7. 任务都有**确定的、可快速评分的打分器**；对没有可靠打分器的开放研究，结论不一定成立。

## 5. 落地步骤

在你自己的 autoresearch/自动优化流程里试：

1. 确保每个候选都是一个版本库 commit，带分数和反馈（论文就是这么记账的）。
2. 先跑一个普通基线：单 agent 持续会话；记录"每回合改动行数、推理 token、空回合比例"，如果这些指标在前几美元内就掉到三分之一以下，说明你也遇到了平台化。
3. 加"遗忘"：每隔固定预算（论文是总预算的 1/4，共遗忘 3 次）把会话和所有历史候选清掉，只留最佳候选；新会话用**和首轮一样的完整指令**。
4. 加"团队"：跑 4 个并行 worktree，每次提出前把别人的最佳候选放进工作区文件夹（`.context/peers/...` 这类）；不需要聊天。
5. 遗忘时让全队从全队最佳候选重启。
6. 观察：遗忘后第一个提案的编辑行数是否回升，下一轮是否出新最优；增益是否像论文那样集中在第一次遗忘。

## 6. 和已知概念挂钩

- **模拟退火/重启（restart）、迭代局部搜索**：周期性回到最佳点、清空历史，等价于带"当前最优重启"的爬山法；新意在于把"历史"定义成 LLM 的**上下文与记忆**。
- **上下文腐烂/长上下文退化**：越长的会话，agent 越倾向保守复述；遗忘是一种极端的"上下文重置"。
- **相关工作（论文自己列出）**：Meta-Harness（agent 重写模型外围 harness，保留得分更高的版本）、Karpathy 的 autoresearch（单 agent 单会话不停改训练脚本）、Fork-and-Flush（arXiv 2610.07447，周期性分叉成新上下文但**继承整个工作区**）、Stateless Language Agents（无状态顾问）；本文区别是连工作区也清掉、只留最佳候选，并带团队通信。
- **AlphaEvolve / FunSearch**：维护程序数据库做种群多样性；本文相反，是主动**丢弃**数据库。

## 7. 疑点、局限与成本

- 论文结论承认的下一步：**何时遗忘、该记住什么**还没有解（只是定时 + 只留最佳）。
- 我的疑点：见第 4 节 1–7；另外"只保留最佳候选，因为它已包含大部分进展"是经验观察（"we observe"），对需要多样化路线（多峰、需要组合不同方向）的问题可能会丢掉有价值的次优分支。
- 成本：每个任务每种配置 $20–$40，3 次运行；用的是较便宜的 Flash 级模型，总体实验成本可复现；如果换前沿模型，同样美元预算能跑的回合会少很多。
- 论文没有给开源代码地址（我在正文与摘要页没找到）；所用的"Pi"agent 与 DeepSeek V4.1 Flash 的引用链接是论文里的。
- **未核实**：这些参考文献在 2026 年的若干条目（如 Fork-and-Flush、Stateless Language Agents、SwarmResearch）我只按论文引用列出，没有逐篇打开；Anthropic 的 VLIW take-home 的具体规则以论文附录为准。
