## 1. 一句话先懂它

给电路板自动连铜线（布线）时，作者让大模型只做「总规划」：先排好哪些线先连、大致走哪片区域、在哪换层，再交给 KiCad 自带的布线引擎去画具体线条，画不通就把失败细节回报给大模型改计划。四个测试集上的一次通过率都比此前的 Agent 和自动布线器高，调用次数还少得多。做「大模型+专业工具」的 Agent 时，这套分工值得借鉴。

## 2. 值不值得读：五个 C 速览

**类型**：系统原型，在公开基准上评测。**上下文**：直接建立在 PCBWorld（一个把 KiCad 原生布线操作开放给强化学习策略和大模型 Agent 的基准环境）之上，借用芯片设计里「全局布线给出引导、详细布线落实」的分层思路（TritonRoute、OpenROAD），Agent 侧接 ReAct、Reflexion 的「行动-反馈-修正」模式。**关键假设**：元件已摆好、设计规则已给定；板子是两层板；KiCad 的推挤布线器（push-and-shove，PNS：画线时能绕开或推开挡路的已有走线）足够强，大模型只需在高层纠错。在本文测试范围内站得住，多层板、高速信号约束没有涉及。**贡献**：一是「全局规划 + 详细执行 + 结构化失败反馈」的闭环；二是在 247 块板上比已发表基线更高的 clean-pass；三是同一模型下调用次数和成本大幅下降。**清晰度**：方法写得清楚，提示词模板全文附上，但缺误差分析和消融实验。建议**看到第 5 节**；如果你在做工具型 Agent，值得翻原文附录 B 的提示词。

## 3. 它在解决什么麻烦

PCB 布线就是在元件摆好以后，用铜线和过孔（via，穿过板子把正反两面铜层连起来的金属孔）把该连的焊盘连起来，同时满足线宽、间距、板边等设计规则。传统做法有两类：一类是规则型自动布线器，比如 Freerouting，复杂板子上常常要人工调参和返工；另一类是学习型方法，网格化表示会随分辨率爆炸，或者只给现成布线器出主意，实际画线还是靠布线器。PCBWorld 让大模型 Agent 直接一步一步操作 KiCad，但论文引用的结果显示，这些 Agent 在复杂真实板上仍不如规则型布线器：GPT-5.4 版在 D3-A 的 clean-pass（所有连接都连上且 KiCad 报零个错误级规则违例）只有 42%，D3-B 是 0%（p3）。

为什么会这样？逐步操作的 Agent 每画一段线都要调用一次大模型，看不到全局：一条局部能走通的线可能把后面几条线的通道堵死；一条线反复失败，往往该换层或换连接方式，而不是再试一次。这和你在软件 Agent 里看到的问题一样：让模型直接操作底层 API，一步一个调用，成本高、容易在局部打转。

如果这篇的分工成立，意义有两层：对硬件团队，小到中等复杂度的两层板有望拿到接近「一次布通」的初稿；对做 Agent 的工程师，它给出一个可复用的模式，让大模型做规划和纠错，让成熟的确定性引擎做执行，失败时用结构化证据而不是一句「失败了」回传。

## 4. 他们怎么做的

**核心思路**：模仿人类布线工程师「先定全局策略，再画具体线，遇阻再回头改策略」。大模型负责它擅长的高层判断，几何细节全部交给 KiCad 原生引擎，两者之间用结构化的引导和反馈对接。

**部件一：板子表示**（p6）。输入是未布线的 KiCad 板文件和设计规则。系统从中抽出四张图（整体布局、正面铜层、背面铜层、待连需求）和一份结构化文本（焊盘坐标、层、网络、已连成片的焊盘簇、设计规则）。图给空间感，文本给精确编号和数值。

**部件二：全局规划器**（p6–p8）。先用启发式算法生成初始引导：每个网络（net，电路图上必须电气相连的一组焊盘）内部用最小生成树（MST，用最短总长度把所有点连成一棵树）决定谁连谁，网络之间按树的总长从短到长排顺序；每条连接给一个矩形走线通道（两端点包围盒向外扩 1.5 mm，p11）；需要换层的连接在中点处划一块候选过孔区域。注意：初始引导是算法生成的，大模型只在执行失败后介入。失败时，多模态大模型读入原始图、结构化文本、当前引导、失败反馈和连通状态，输出一个「引导补丁」（JSON 格式，只改受影响的通道、过孔区域、连接或顺序，其余保留）。补丁先过格式和引用校验，不合格就带着错误信息让模型改一次。

**部件三：详细执行器**（p8–p9）。把引导编译成任务，按顺序调用 KiCad 的 PNS 布线器在通道里逐段推进，在相邻通道重叠区选途经点，在过孔区域里找能放过孔的位置；每条任务完成后检查两端是否真的电气连通。失败时先做有限的本地恢复：绕行、推挤、换途经点、网格 A* 搜索（经典最短路径搜索）找绕路、回退到前一段、换起点焊盘；预算是每条连接最多两次回退、一次 A* 绕路、两次换起点（p11）。恢复用完仍失败，就回滚到检查点，生成结构化反馈包（尝试过什么、停在哪、可能被谁挡住、偏离了引导多少）交给规划器。

**预算与终止**：每块板最多 12 次重规划，每条连接最多 4 次，批量重规划最多 5 轮（p11）。结束时保存最后一个一致的板状态，交给官方评测器打分。Opus 版本输出还会做最多五轮「角度修复」，只有在连通性、规则检查和线长都不变差时才接受（p11）。

**如果让你复现**，最小骨架是：

```python
guide = init_guide(board)                     # MST 定拓扑 + 按长度排序 + 矩形通道 + 过孔区域
for round in range(MAX_REPLAN):               # 每板最多 12 次重规划
    failures = []
    for task in compile_tasks(guide, board):
        ckpt = board.checkpoint()
        ok, feedback = pns_route_with_recovery(task, board)   # KiCad 推挤布线 + 有限本地恢复
        if not ok: board.restore(ckpt); failures.append(feedback)
    if not failures: break
    patch = llm(images, sidecar, guide, failures)             # 大模型只输出引导补丁 JSON
    guide = apply_if_valid(guide, patch)                      # 校验不过就带错误再问一次
evaluate(board)                                # 官方 KiCad 评测器打分
```

代码已开源（BSD-3-Clause），可以直接对照仓库里的实现。

## 5. 证据怎么看、别被什么忽悠

**表一：Table 2（第 12 页），D3-A 99 块小型真实板。** 想证明：在真实板上明显超过所有基线。怎么测：PCBWorld-Bench 的 D3-A 测试集，KiCad 官方评测器；主指标 clean-pass，辅以可布通率（完成连接的比例）和规则违例数；基线是 PCBWorld 已发表的单次运行（@1）均值。结果：PCBRouteAgent（Claude Opus 5.5）clean-pass 0.949，可布通率 0.994，平均违例 0.09；最强基线 PCBWorld PPO w/o finish 0.810，规则型 Freerouting 0.750，PCBWorld GPT-5.4 Agent 0.420。说明：领先是实在的，摘要的「领先 13.9 点」是对 PPO w/o finish，引言的 19.9 点是对 Freerouting。

**表二：Table 3、Table 4（第 13 页），中型和大型真实板。** 结果：D3-B（10 块）Opus 版 clean-pass 1.000，Freerouting 0.640；D3-C（10 块，超过 100 个焊盘）Opus 版 0.400，Freerouting 0.300，强化学习基线全是 0.000；Opus 版平均违例从 Freerouting 的 32.0 降到 6.3。说明：板子越大越难，D3-C 十块里仍有六块没布完（p12）。

**表三：Table 5、Table 7（第 24–25 页）与同模型对照（第 13 页）。** 想证明：增益来自框架而不是换了更强的模型。用同一个 Claude Haiku 5.5，PCBRouteAgent 的 clean-pass 在四个集上是 1.00、0.929、0.80、0.10，PCBWorld 交互 Agent 是 0.633、0.343、0.00、0.00。247 块板合计，模型调用从 22,529 次降到 172 次，API 费用从 $20.72 降到 $4.77，累计运行时间从 36.4 小时降到 2.6 小时（Table 7，p25）。

**水分检查**：①样本量：D3-B、D3-C 各只有 10 块板，一块板就是 10 个百分点，「领先 36 点」「领先 10 点」都很脆弱。②种子与重复：每块板只评一次，没有误差条；D3-B 的 Opus 结果含「模型响应失败重试」和角度修复，不是严格的首次尝试（p11）。③基线来源：D3-A、D3-B 的基线数字照抄 PCBWorld 已发表的表，没有在同一环境重跑；D3-C 全部是作者本地评测。④模型不对等：主结果用 Opus，基线 Agent 用 GPT-5.4 等；作者以成本为由没跑 PCBWorld+Opus，只给了 Haiku 对照，这个对照做得好。⑤大模型到底干了多少：D2 上 PCBRouteAgent 每块板平均只调用 0.05 次模型（Table 5，p24），说明简单板几乎全靠启发式引导和 KiCad 引擎完成，「LLM Agent 能布线」的说法在简单板上要打折。⑥物理质量：完成率提高不等于线更短，D3-B 线长比 Freerouting 多 10.9%（p14）。⑦缺消融：没有「去掉大模型重规划，只用启发式+本地恢复」的对照，无法分清各部件贡献。

## 6. 可信度与核验限定

**主张对照**：①「四个集 clean-pass 100%、94.9%、100%、40%」：Table 1–4（p11–p13）都对得上，证据充分，但后两个只有 10 块板。②「三个真实集分别领先最强基线 13.9、36、10 个点」：数字成立，但 D3-B、D3-C 是小样本，且 D3-B 含重试。③「同模型下框架更好、更省」：Haiku 对照（p13、p24–p25）证据较好，是全文最扎实的部分。④「接近布线工程师」：标题是问句，D3-C 上参考人工设计 clean-pass 0.900，Agent 0.400，差距仍大（Table 4，p13）。

**核验限定**（原样合入核验报告）：
- clean-pass 100%/94.9%/100%/40% 是 Claude Opus 5.5 版本，分别在 D2（128 块合成板）、D3-A（99 块）、D3-B（10 块）、D3-C（10 块）上（Table 1–4 p11–p13）
- D2 上 Freerouting 等基线也是 100%；D3-B 结果含失败重试；D3-C 全为本地评测，40% 即 4/10；D3-A/B 的基线数字取自 PCBWorld 已发表表格而非重跑（p10–p11）
- 摘要「领先最强基线 13.9 点」对比的是 PCBWorld PPO w/o finish（81.0%），正文 p3 的 19.9 点对比的是 Freerouting（75.0%）

**打折提醒**：对外引用 D2 的 100% 时要说明是和 Freerouting 等并列；不要说「大模型已能替代布线工程师」；引用 D3-B 的 100% 要加「10 块板、含重试」。

## 7. 你可以怎么落地

**今天就能试**：不用新机器。拿你手上任何一个「大模型一步一调用地操作工具」的 Agent，按本文的模式改一版：让确定性代码先生成初始计划，大模型只在执行失败时介入，并且失败回传改成结构化 JSON（尝试了什么、停在哪、被什么挡住、建议的替代起点），要求模型只返回「补丁」并列出保留项。提示词可以直接参考附录 B.1.2（p20）。验收：同一批任务上对比成功率、模型调用次数和费用，成功率不降、调用次数明显下降就算有效。

**要有数据或机器再试**：如果团队做硬件，装 KiCad 和 PCBWorld 环境，克隆作者仓库，在 D3-A 的几十块板上用 Haiku 级别的便宜模型复跑。论文里 Haiku 在 D3-A 上平均每板约 27 秒、约 $0.0048（Table 5，p24），成本很低。分阶段：先复现 D3-A 数字；再拿自己公司几块已布好的两层板去掉走线重跑，和原设计比违例数和线长；最后才试更大的板。验收：自有板上 clean-pass 和违例数不比 Freerouting 差。

**暂时别碰**：不要拿它去做多层板、高速差分、阻抗控制等有电气约束的正式产品板，论文只测了两层板和基础设计规则；也不要把 D3-B、D3-C 的小样本数字当成能力上限去做规划或宣传。

## 8. 和你已有知识的挂钩

它很像「控制面和数据面分离」：大模型是控制面，偶尔下发策略；KiCad 推挤布线器是数据面，负责高频、精确的执行。也像编译器里的「前端规划 + 后端代码生成」，或者熔断后带诊断信息的重试。和 PCBWorld 交互 Agent 最大的区别是：后者每一笔线都让大模型决策，这里大模型只修改计划，执行和局部恢复全交给确定性代码。

## 9. 存疑与代价

**局限**：作者承认大板完成率和走线紧凑度仍是难点（p14）。读出来的另外几点：只有两层板；缺部件消融；每板单次评测、无误差条；D2 上大模型几乎没被调用；D3-B 含重试。**复现条件**：代码开源（BSD-3-Clause），依赖 KiCad 和 PCBWorld 环境以及商用 Claude API；基准板子来自 PCBWorld 开源语料。**成本**：Haiku 版 247 块板合计 API 费用 $4.77、累计 2.6 小时（Table 7，p25）；Opus 版的费用论文未说明。D3-C 上 Haiku 版每块通过的板平均花 $3.93（p25）。**出处**：预印本，未同行评审；第一单位 The University of Texas at Dallas，HF 页面未标机构；基准 PCBWorld 是 KDD 2026 workshop 论文。

**论文没回答、但决定你要不要动手的 3 个问题**：去掉大模型、只保留启发式引导加本地恢复，成功率会掉多少？换成四层以上的板或有差分对约束时，这套矩形通道表示还够不够用？Opus 版本在 D3-C 上每板花多少钱、多长时间？
