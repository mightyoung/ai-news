# 聚焦式全模态 GUI 智能体（Focused Omni-Modal GUI Agents）

- arXiv：https://arxiv.org/abs/2610.26203 ｜ HF：https://huggingface.co/papers/2610.26203
- 点赞数：224（2026-10-22 09:00 北京时间抓取）
- 机构（论文署名）：Nanyang Technological University / Alibaba Group

## 一句话总结
GUI 智能体每一步真正有用的模态（截图、音频、视频、历史、设备状态）都在变，FocusGUI 用一个约 1.15M–1.45M 参数的小适配器在每一步给各模态打分、压成紧凑的"焦点向量"，以零初始化残差注入冻结骨干，四个全模态骨干上 Type Match 平均 +33.2 点。

## 研究问题与动机
作者在 Qwen2.5-Omni 上逐个去掉模态、看真实动作的对数似然如何变化，发现：主导模态在 45.3% 的相邻步之间发生切换，94.0% 的轨迹至少切换一次；90.1% 的步里至少有一个"干扰"模态（去掉反而更好）；目标元素中位数只占屏幕 0.87%。也就是说相关性是"步级别、瞬时且稀疏"的。闭环执行时，一步看错会被写回历史，误差层层累积，作者称之为 Sequential Distraction（序列式分心）。已有方法（DRS-GUI、OmniParser、RegionFocus）靠裁剪截图做减法，但它们碰不到音频/视频/设备状态，而且裁掉的背景常常正是定位坐标和文字参数所需的上下文。

## 核心方法
1. **通道分解**：把观测拆成可分离的感知通道（各模态 + 骨干的整体隐状态 + 屏幕空间通道），各自投影到 128 维共享空间。
2. **步自适应加权**：用整体观测的表示生成"决策参照" q_t，对每个通道做加性注意力打分，softmax（τ=1.0）得到这一步的优先级。不跨步携带状态。
3. **紧凑焦点**：加权结果压缩到 64 维 z_t（只负责"该看哪里"，细节仍走原通道）。
4. **残差对齐**：把 z_t 展开为 K=4 个零初始化残差，加到动作生成边界前 4 个 prompt 嵌入上。骨干、编码器、LM head 全冻结，只用下一步动作的 NLL 训练 3 个 epoch，不需要模态相关性标注。

## 实验设置与主要结果
- 数据：OmniGUI 基准，29 个手机应用，708 条轨迹、2,572 个动作步；指标 TM（动作类型）、EM（坐标落在目标框内且文本匹配）、GP（轨迹内正确步比例）。
- 骨干：Qwen2.5-Omni、VITA-1.5、MiniCPM-o 4.5、Baichuan-Omni-1.5。
- 四骨干平均：TM 从 31.0% 升到 64.2%，EM 从 11.2% 升到 33.5%；相对直接推理 +33.2 TM / +22.3 EM / +6.6 GP，相对每个骨干上最强基线 +30.1 / +23.6 / +8.0；在 24 个"骨干×类别"格子里全部拿到最佳 TM 和 EM。
- 诊断性发现：三种屏幕精化基线对 TM 几乎中性（平均 +0.9），却让 EM 相对下降 28%、GP 相对下降 35%，12 个案例全部如此。
- 随步数加深：冻结的 Qwen2.5-Omni 从第 1 步到第 4 步 TM 掉一半，FocusGUI 保住 86.8%。
- 消融（Qwen2.5-Omni）：完整模型 Overall TM 71.65 / EM 40.16 / GP 17.49；去掉残差对齐 EM 降到 34.86，去掉通道分解 TM 降到 66.26。

## 局限与风险
- 优先级只基于当前观测，不能"预判"下一步该关注什么（作者自述）。
- 只在 OmniGUI 一个手机场景基准、四个开源骨干上评估，桌面/网页等更广的 computer-use 场景未验证。
- GP 的绝对值仍低（完整模型 17.49），说明整条任务完成率离实用还远。

## 工程落地启示
- 给多模态 Agent 加"每步注意力引导"比裁剪输入更稳：不删信息，只告诉模型这一步看哪里。
- 冻结骨干 + 百万级参数适配器 + 只用动作标签，成本很低，适合在已有 Qwen-Omni 类模型上快速试。
- 做 GUI Agent 评测时要同时看 TM 和 EM，裁剪类方法会"TM 好看、EM 变差"。

## 与相关工作的关系
对比对象是视觉侧的区域精化（OmniParser、RegionFocus、DRS-GUI）和学习动作头的 GUI-Actor；FocusGUI 的区别在于跨模态、步自适应，并且以残差而不是改输入的方式介入，思路接近 prefix/adapter 类的轻量条件注入。
