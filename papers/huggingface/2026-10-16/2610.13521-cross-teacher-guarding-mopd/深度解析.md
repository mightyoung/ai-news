## 一句话总结

ROAD MOPD 指出：多教师 on-policy 蒸馏里「按域路由教师」只区分了监督来源，更新仍打在共享参数上，教师风格/专长差异大会导致持续梯度冲突与弱势域退化；方法让**非路由教师**当跨域批评者，用跨教师一致做 token 级信用分配，并用带范数保留约束的预防性多教师梯度投影保护目标域学习信号。

## 研究问题与动机

MOPD 把域数据路由给专长教师，在学生自生成轨迹上做稠密 token 监督。作者发现：路由只换了监督源，共享参数上的联合优化仍可能冲突——孤立有效的监督合在一起会带来持久梯度冲突与不对称能力退化。需要让「非本域教师」参与协调，而不是只做事后修冲突。

## 核心方法

- **跨教师信用分配**：同一学生轨迹上，主教师与辅助（非路由）教师共同打分；一致处加强 token 校正，冲突处削弱。
- **预防性多教师梯度投影**：用同源轨迹的辅助梯度约束可能冲突的更新，并自适应投影强度，在保护目标域信号的同时做范数保留。
- **评测设定**：学生 Qwen3-4B / 1.7B；配对域 Math×Medical、Code×Medical 等；对比 Single OPD、Vanilla MOPD、ExOPD、Open-MOPD、CaMOPD 等。

## 实验设置与主要结果

正文称 ROAD MOPD 相对 Vanilla MOPD 在 Medical 上提升 **5.6–8.8** 个百分点，高冲突下总体增益超过 **5** 个百分点，并改善低冲突与三域设置。

Table 1 摘录（Domain Avg. / All Avg.）：

- **Math × Medical，Qwen3-4B**：Ours Math Domain Avg. **47.60**、Medical **48.23**、All **47.92**；Vanilla MOPD 为 45.97 / **39.45** / 42.71（Medical 明显退化）；CaMOPD All 47.20。
- **Math × Medical，Qwen3-1.7B**：Ours All **32.05**（Vanilla 29.77；Medical Domain 36.89 vs Vanilla 31.18）。
- **Code × Medical，Qwen3-4B**：Ours Code **63.02**、Medical **47.75**、All **55.38**；Vanilla All 50.64（Medical 40.75）。
- **Code × Medical，Qwen3-1.7B**：Ours All **44.86**（Vanilla 41.00；Medical 36.51 vs 30.93）。

消融（正文）：去掉信用分配时 Math/Code 分别掉 **1.82 / 3.48** 点；去掉梯度保护时 Code×Medical 的 Medical 掉 **0.88** 点。

## 局限与风险

附录含 Limitations 节（目录 D），正文强调冲突依赖教师差异与域组合；方法增加多教师前向/投影开销；评测主要在 Qwen3 族与特定域基准（AIME、HMMT、MedQA、HumanEval+ 等），迁移到其他骨干/域需另验。高冲突场景下弱势域仍可能低于「单域 Single OPD」的峰值（需结合 Table 1 分列解读）。

## 工程落地启示

- 做多专长教师合并学生时，不要假设「域路由 = 无冲突」；应监控弱势域是否掉到基线以下。
- 可先上「跨教师一致加权」，再视冲突强度加梯度投影；投影强度建议带范数约束以免过杀目标域学习。
- 训练池规模正文提到约 10,000 prompts（Table 5）及共享优化设置（Table 6）；复现需多教师同 tokenizer/词表以便打分。

## 与相关工作的关系

建立在 OPD / MOPD（含 Open-MOPD、CaMOPD、ExOPD 等）之上：保留域路由的专长利用，补上跨教师协调与预防性冲突处理。相对纯梯度冲突修正基线，强调在 token 信用与更新两阶段同时「guarding」。
