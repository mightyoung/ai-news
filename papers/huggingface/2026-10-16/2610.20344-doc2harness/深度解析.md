## 一句话总结

Doc2Harness 是首个**确定性**评测「长程 harness 工程」能力的两阶段基准：构建模型在固定 builder harness 里，仅凭接口契约骨架 + 汇总 12 个前沿 harness 行为的开发文档，在隔离容器中写出完整候选 harness；再由脚本化 mock 模型在独立容器中端到端驱动，用请求、磁盘文件、进程退出码、命令输出四通道断言打分。19 个前沿模型 × 3 次独立构建 × **328** 用例下，最强 GPT-6 Astra 仅 **53.05%**，最弱 **27.44%**。

## 研究问题与动机

Agent 在长程任务上用工具、改真实工作区——表现既取决于模型，也取决于外围 harness。现有基准多在**固定 harness** 下量下游成功率，不直接量「会不会把 harness 做出来」。作者把问题定为：给定文档与接口骨架，模型能否长期工程出一个行为正确的 harness。

## 核心方法

- **Stage 1（构建）**：固定 builder harness；输入接口-only 契约骨架 + 开发文档（Table 1 分章汇总跨 harness 行为）；在隔离容器内构建完整候选 harness；每构建最多三次提交，契约检查偏形式而非行为。
- **Stage 2（评测）**：冻结候选；每用例独立容器；scripted mock model 驱动；四可观测通道打分；正对照排除空洞通过。
- **评测规模**：19 模型，各 3 个独立候选，328 用例（正对照不计入分母）。

## 实验设置与主要结果

Table 2 全量 pass rate（均值±三次构建标准差）：

| 模型 | All (%) |
|---|---|
| GPT-6 Astra | **53.05 ± 0.25** |
| Opus 5 | 46.65 ± 1.80 |
| Qwen3.8 Max | 45.83 ± 0.14 |
| … | … |
| Hy3 | **27.44 ± 0.43** |
| 均值 | 38.30 |

- 强弱差距约 **26** 个百分点；最强仍失败近一半用例。
- 类别：Permissions 平均通过 43.7%、强弱差 **50.8** 点，区分力最大；Direct drive 平均仅 18.8%；Interactive terminal 平均 79.9% 但天花板用例多。
- Table 3：328 用例中 floor（无人过）**56**、ceiling（全过）**16**、真正区分排序的 **256**。
- 失败集中在**横切功能如何拆到多模块**；控制代码行数后，模块数更多的 harness 分数更低（正文偏相关分析）。
- 相关工作对比：harness 选择可使分数移动 **27.4** 点，相对模型选择的 **29.4** 点同量级——说明只评固定 harness 会漏掉工程维度。

## 局限与风险（论文 §6）

- 只量单次构建，不是 build–evaluate–repair 闭环；契约检查测形式不测行为，早提交者的通过率是下界。
- 单一缺陷可导致多个相关用例连锁失败（变体相关）。
- 不量冻结后基于行为反馈的改进能力。

## 工程落地启示

- 选 coding agent 底座时，除 SWE 分数外应看「能否从文档长程做出 harness」；当前 SOTA 仍远未饱和。
- 内部评测可借鉴四通道断言 + mock 驱动，避免只看最终任务成功而忽略中间协议是否正确。
- 实现上警惕「功能拆太碎」：论文显示模块膨胀与更差分数相关。

## 与相关工作的关系

相对在固定 Claude Code / 同类 harness 上跑的 agent 基准：Doc2Harness 把 harness 本身当作被测产物。相对纯代码生成基准：强调长期、跨模块、与真实 agent 运行时契约对齐的工程行为，而非单文件函数正确性。
