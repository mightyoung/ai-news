# CarryOn：为长程智能体构建"面向对象"的上下文

**Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents**

- arXiv：https://arxiv.org/abs/2610.18784
- Hugging Face：https://huggingface.co/papers/2610.18784
- 点赞数：99（HF Daily Papers 2026-10-19 批次，抓取于 2026-10-20 09:00 北京时间）
- 机构（HF 页面）：McAuley-Lab（论文署名 University of California San Diego）
- 代码：https://github.com/Ethannju/carryon

## 一句话总结

长程智能体不该反复处理"进度是怎么得来的"这段历史，而应围绕"可复用的进度"组织上下文：CarryOn 用续接载体（continuation carriers）+ 执行上下文 + 最近交互的活尾部来构建上下文视图，在 OSWorld 2.0 和 BrowseComp-Plus 上分别把 Claude Opus 4.7 提升 5.8% 和 7.0%，同时总 token 用量降低 51.9% 和 22.9%。

## 研究问题与动机

长程智能体的进度沉淀在持久的任务状态里（文件、文档、网页结果），但上下文中仍然一遍遍处理产生这些进度的交互历史。常见做法是压缩、剪枝或摘要历史，但作者认为"只压缩历史不足以继续执行"：有些结果需要依赖先前交互才能解释；保留下来的记录未必仍被证据支持；历史被移除后，目标、约束和未解决问题也可能随之丢失。

## 核心方法

1. **续接载体**：把可复用的任务进度表示为对象记录，并显式写明使用条件（依赖于哪些前提）。
2. **执行上下文**：单独保存目标、约束、未解决的需求等任务对象本身不包含的信息。
3. **活尾部（live tail）**：保留最近的原始交互。
4. **折叠（fold）**：经验证的更新通过一次 fold 提交，用新的面向对象上下文视图替换被覆盖的交互历史。跨 fold 时，只针对绑定的证据和适用的环境检查修订受影响的记录，未受影响的记录直接沿用，不必每次重建完整表示。

## 实验设置与主要结果

- **OSWorld 2.0**（长程电脑操作）：以 Claude Opus 4.7（max）为宿主智能体，部分得分从 43.9% 提升到 49.7%（+5.8%），二元得分从 15.7% 提升到 19.4%（+3.7%）；总 token 用量下降 51.9%，每任务成本下降 35.9%（含运行时开销）。
- **BrowseComp-Plus**（长程浏览）：准确率从 49% 提升到 56%（+7%），token 用量下降 22.9%，总成本下降 7.1%。
- 成本随轨迹增长：基线成本持续上涨，到第 500 轮时 CarryOn 的累计成本低 34.1%（含上下文管理开销）。
- 示例：一个任务中上下文从 42.4K 降到 14.4K token（-66.0%）；实验报告任务中工作文档相关上下文从 58.4K 降到 23.5K（-59.7%）。
- 消融（OSWorld 2.0 共享 40 任务子集）：去掉执行上下文，二元得分从 22.50% 降到 17.50%，部分得分从 55.93% 降到 44.00%，调用次数变化不大；去掉续接载体，部分得分降到 44.62%，智能体调用次数增加 23.8%、成本增加 22.3%，说明两者保存的是互补信息。
- 对比通用压缩和"用反复摘要实现同样原则"的变体，完整的 CarryOn 运行时都更好。

## 局限与风险

- 主要实验以单一宿主模型（Claude Opus 4.7）为主，换用其他模型或开源模型的效果需进一步验证。
- 维护载体记录需要额外的模型调用和环境检查；在 BrowseComp-Plus 上成本降幅只有 7.1%，收益和任务形态有关。
- 若载体记录的证据绑定或环境检查出错，错误进度可能被长期沿用，调试难度高于直接看原始历史。

## 工程落地启示

- 做长程 agent 时，可以把"已完成的产出"做成带前提条件和证据引用的结构化记录，而不是只做对话摘要；把目标、约束、待办单独存放。
- fold 时只增量修订受影响记录，比全量重摘要更省 token，也更稳定。
- 这和编码智能体常用的"进度文件 + TODO 列表 + 最近若干轮原文"做法相通，论文提供了量化证据和消融。

## 与相关工作的关系

上下文压缩与选择类方法（提示压缩、剪除过时交互、周期性摘要、分支执行只返回子任务结果、MemGPT 式外部历史）主要处理"历史"；状态外化与上下文重建类方法用执行状态树、持久变量等显式表示进度。CarryOn 属于后一方向，强调以可复用任务对象为中心组织续接，并在 fold 之间保持记录有效。
