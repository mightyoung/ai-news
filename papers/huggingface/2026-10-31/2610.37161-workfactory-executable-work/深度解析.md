## 1. 一句话先懂它

想让 AI 像分析师、会计、律师那样交付 Excel、Word、PPT，需要大量「材料齐全、能做完」的练习题。WorkFactory 先倒推交付物需要哪些信息、放在哪个文件里，再生成文件，最后让一个模型试做一遍、发现缺信息就修补。用这些题的教师轨迹微调后，开源中小模型在办公类评测上大幅提升。

## 2. 值不值得读：五个 C 速览

**类型**：数据合成系统加规模实验。**上下文**：接着 SWE-Gym、SWE-smith 这类「合成可执行环境训练智能体」的思路，从写代码扩展到职业办公任务；对标 NexForge、Synthetic Computers、GraphForge（p3）。**关键假设**：教师模型（GLM-5.3）的轨迹质量够好；GDPval-AA 的本地评审估分与官方分可比。前者有教师对照实验支持，后者需要打折。**贡献**：①「信息支撑图」规划任务需要的信息和位置；②用探测执行发现并修复缺陷；③11.2 万任务的规模实验和 WorkPilot 4B/27B/35B-A3B 模型。**清晰度**：结构清楚，评测口径写在表注和附录。**建议**：做智能体训练数据的读到第 5 节。

## 3. 它在解决什么麻烦

训练办公智能体的常见做法是：让大模型凭空写一个任务描述，再随手生成几个附件，然后让强模型去做，把轨迹拿来微调。问题是生成的材料经常自相矛盾或缺关键数字：报价单里没有运费，需求预测和表格对不上，题目要求的结论根本推不出来。教师模型面对这样的题，要么瞎编，要么卡住，轨迹就成了坏示范。

你会在这些场景撞上：自建「Excel 分析 / 合同审阅 / 报告撰写」类智能体的 SFT 数据，发现教师轨迹里大量「假设一个数字」的操作；或者扩大合成数据量后效果不升反降。若这套方法成立，合成任务的缺陷率能降下来，同样数量的题带来更多收益。

## 4. 他们怎么做的

**核心思路**：从交付物倒推。先列出「完成这份交付物必须知道哪些信息、它们之间怎么推导、各自放在请求里还是某个文件里」，再按这张图去生成文件；生成后用「干净的探测执行」检查能不能做完，而不是只靠模型自查（图 2，p4）。

**步骤**：
1. **职业意图**：从职业、技能、交付物三元组出发，例如「为纸箱采购评估四家供应商三年总成本并推荐」（图 2，p4），覆盖 612 个职业、23 个大类（图 3，p5）。
2. **信息层规划**：构建信息支撑图（式 1，p5），节点是信息单元和承载位置（请求、参考文件、待产出），边是推导关系。比如「折现总成本」依赖「年度采购量」「单价」「8% 折现率」。
3. **物化**：按图生成用户请求和参考文件（PDF、XLSX 等），用程序和大模型检查是否符合计划，多次重试仍失败就丢弃（p6）。
4. **执行式修复**：一个只看请求和文件、看不到规划图的探测模型试做任务，诊断阻断性问题（如「供应商 C 的运费是否包含？」），修补输入后重新探测，修复预算用尽仍有阻断就丢弃（图 2）。
5. **教师轨迹与训练**：GLM-5.3 纯文本模式在 Stirrup 和 Claude Code 框架下执行，过滤重复推理、重复调用和交付物不足的轨迹；最长 5% 的任务做成对比较的拒绝采样（p7）。然后做监督微调。

**如果让你复现**：
```
for intent in sample(occupation, skill, deliverable):
    graph = plan_information(intent)            # 信息单元 + 推导边 + 放置位置
    request, files = materialize(graph)
    if not checks_pass(request, files, graph): continue
    for _ in range(repair_budget):
        issues = probe_solve(request, files)    # 看不到 graph
        if not blocking(issues): break
        files = repair(files, issues)
    else: continue
    traj = teacher_run(request, files); keep_if(filters(traj))
```

## 5. 证据怎么看、别被什么忽悠

**表 2（p8）：主结果**。想证明这些数据对不同规模模型都有用。测法：GDPval-AA（Elo 分）、JobBench、Workspace-Bench、OmegaUse-OfficeVal，每个模型–任务对 3 次独立运行。结果：Qwen3.6-35B-A3B 从 879（官方分）到 1565（本地估计）；JobBench 28.91 → 62.35；Qwen3.6-27B 从 975 到 1612，比 GLM-5.3 的 1646 低 34 分；4B 从 661 到 1375。说明：四个基准都有大幅提升，方向可信。

**表 3（p10）：组件分析**。想证明规划和修复各有贡献。测法：三种合成方式各 5K 任务，用同一个探测模型统计缺陷，再分别微调同一模型。结果：跨文件不一致从 32.82%（直接生成）降到 25.74%（加信息图）再到 4.84%（加修复）；GDPval-AA 1245 → 1293 → 1326。说明：修复步骤对缺陷率作用最大；但只加信息图时「泄漏/捷径」和「自相矛盾」反而上升 1.44 和 1.18 个百分点，作者如实报告了。

**图 5（p9）与 p10：规模与教师**。35B-A3B 在 2K 任务时平均执行 162.88 轮，到 110K 降到 85.90 轮（p9）；同样 30K 任务，GLM-5.3 教师训出 1483，DeepSeek-V4-Flash-0731 教师训出 1248（p10）。

**水分检查**：
- 879 是官方分，1565 是用 Gemini 3.1 Pro 当评审的本地两锚点估计（表 2 注，表 11 p28），两者口径不同；27B 的基线 975 也是本地估计。
- 本地估计有置信区间：1565 为 [1539, 1589]，1612 为 [1594, 1631]（表 11 p28）；和 GLM-5.3 的差距 34 分已接近区间宽度。
- 教师是 GLM-5.3，教师选择对结果影响很大（1483 对 1248），提升有相当一部分是蒸馏强教师。
- 组件分析的缺陷率由探测模型诊断，修复用的也是同类探测，存在「用同一把尺子量自己修过的东西」的偏差。
- 作者做了请求重叠、人工复核和文件哈希的去重（p7），未发现评测任务复用。

## 6. 可信度与核验限定

**主张对照**：「四个基准全面提升」——表 2 支持；「27B 达到前沿水平」——本地估计，区间与前沿模型重叠；「信息规划 + 修复降低缺陷并提升效用」——表 3 支持，单次 5K 规模；「数据和模型已公开」——与仓库现状不符。

**核验限定（原样合入）**：
- 879 为官方 GDPval-AA v2.1 分，1565 为本地两锚点估计（Gemini 3.1 Pro 评审），95% CI [1539, 1589]（表 2 p8，表 11 p28）
- WorkPilot-27B 的 1612 也是本地估计，CI [1594, 1631]（表 11 p28）
- 教师为 GLM-5.3，纯文本模式（p7 脚注）
- 摘要称数据和模型已公开，但 GitHub README 的数据集/模型链接仍是占位 TODO，HF 上未找到（2026-10-31 检查）

**打折提醒**：对外引用「879 → 1565」时说明后者是本地评审估计；不要说「数据已开源」。

## 7. 你可以怎么落地

**今天就能试**：给你现有的合成任务加一道「探测执行」：让一个模型只拿请求和附件试做，要求它列出「缺什么信息、哪里前后矛盾」。抽 50 道题人工核对。验收：探测发现的问题中真问题的比例，以及修补后教师轨迹里「自行假设数字」的次数是否下降。

**要有数据或机器再试**：在一个垂直领域（如财务分析）实现「从交付物倒推信息图 → 生成文件 → 探测修复」，先做 5K 题，对照直接生成的 5K 题各微调一次同一模型，用你的业务评测比较。需要强教师模型的 API 预算：论文平均每条轨迹 136.18K token、62.95 次工具调用（表 1，p6）。

**暂时别碰**：别直接依赖 WorkPilot 权重或数据集做产品规划，目前没有放出；也别把本地估计的 Elo 和官方榜单分混着比。

## 8. 和你已有知识的挂钩

像测试驱动开发：先定义交付物（测试），再倒推需要的输入；探测执行相当于在发布前跑一遍冒烟测试。和 SWE-smith 这类代码环境合成的最大区别：办公任务没有单元测试可以自动判对错，所以用信息图约束输入的完整性，再用探测执行代替测试。

## 9. 存疑与代价

**局限**：评测依赖大模型评审；教师强弱决定上限；网页抓取类工具失败率在 110K 时仍有约 40%–48%（p9）。**复现条件**：仓库 Apache-2.0 但目前无代码、无数据、无权重；正文贡献部分写的是「公开任务数据的一个子集和模型权重」（p3）。**成本**：11.2 万任务 × 每条约 13.6 万 token 的教师轨迹，外加构建阶段的 token 消耗（附录 D.2）。**出处**：预印本，第一单位为企业研究团队。

论文没回答、但决定你要不要动手的问题：
1. 用官方评审口径重测后，1565 和 1612 还剩多少？
2. 如果教师换成与学生同级的模型，WorkFactory 题目本身贡献多少？
3. 公开的「子集」有多大，能否复现主表趋势？
