## 1. 一句话先懂它

会「放大看图、挑视频片段」的多模态模型，常常调用了工具却不看返回的结果，或者放大错了地方。这篇用两步训练治这两个毛病：先训练时故意藏掉原图，逼模型依赖工具结果；再把图像专家和视频专家合并时，发现学生放大错了就替它改成正确操作再继续教。合出来的一个模型在 14 个基准上平均超过两种常规做法，适合做工具型视觉智能体的人参考。

## 2. 值不值得读：五个 C 速览

**类型**：新方法，附数据集和诊断分析。**上下文**：接着两条线。一条是「看图思考」类智能体（DeepEyes、Pixel-Reasoner、Thyme），模型通过裁剪、选帧工具获取细节；另一条是 MOPD（Multi-teacher On-Policy Distillation，多教师在线蒸馏：学生自己生成回答，再按任务类型交给对应的专家老师逐 token 打分），以及 Open-MOPD、D³-MOPD 等改进（p2）。**关键假设**：训练数据要有可靠的位置或时间标注（框或帧段），才能给「放大对不对」打分和做修复；作者为此专门清洗了 Reframe-100K（p3）。有标注的数据上站得住，没有标注的任务用不上第二步。**贡献**：一是 GD-GRPO，用定位奖励加「随机藏原图」解决「调了工具不看」；二是 OG-MOPD，蒸馏中途把错误工具动作换成标准动作；三是 10 万条图像加视频训练数据。**清晰度**：正文紧凑、图解清楚，超参都在附录 B，复现信息比较全。建议**看到第 5 节**；做视觉智能体或多教师蒸馏的人值得读原文第 3 节。

## 3. 它在解决什么麻烦

给视觉语言模型（能同时看图和读文字的大模型）配上「裁剪放大」和「选取视频帧」两个工具，本意是让它像人一样先找到细节再回答，比如先放大看清骑车人的号码。但论文指出一个隐蔽的问题：模型调用了工具，后面的推理却基本不受返回结果影响，作者叫它「观测忽视」（p1）。只按答案对错给奖励的强化学习抓不到这个问题，因为模型凭原图也可能答对。

第二个问题出在合并阶段。很多团队会分别训练图像专家和视频专家，再合成一个统一模型。常规做法有两种：把图像和视频数据混在一起做强化学习（Mix-RL），或者用多教师在线蒸馏。前者奖励稀疏、两个模态互相拉扯，结果比单模态专家差；后者每个 token 都有老师指导，但有个盲点：如果学生在第一步就放大错了地方，后面老师再怎么逐字指导，都是在一张错误的图上指导，无法回头补救（p2，p5）。

你在工程里会撞上的场景是：做一个文档问答或监控视频分析的智能体，日志里工具调用率很高，但把工具返回的图换成灰图，答案几乎不变，说明工具成了摆设。或者你想把两个专项模型合并上线，合完发现某个模态掉分。如果这篇的做法成立，你能得到一个真正「看工具结果」的模型，并且合并后不掉分甚至超过专家。

## 4. 他们怎么做的

**核心思路**：不只对齐「输出分布」，还要对齐「模型当时看到的东西」（观测状态）。第一步让模型离不开工具结果，第二步保证蒸馏时模型看到的是对的东西。两个阶段互补：模型越依赖工具结果，修复一次错误操作带来的好处就越大（p1）。

**数据**：Reframe-100K 含 6.3 万条图像问答和 3.7 万条视频问答，都来自带位置框或时间段标注的公开数据（p3）。清洗分五步：去掉只看文字就能答的题；用 Qwen3.8-27B 在完整输入和「只给标注区域」两种情况下各采 8 次，删掉全对或全错、以及标注区域支撑不足的样本；可疑样本再交给模型诊断和最终复核（Figure 2，p3）。标注框会按中心放大 1.5 倍、时间段两端各扩一帧，保留必要的上下文。

**第一阶段 GD-GRPO**（Ground-Drop GRPO；GRPO 是一种强化学习算法，对同一道题采多个回答，按组内相对好坏更新模型）：分别训练图像专家和视频专家（p3–p4）。奖励由四项组成：答案对错、工具调用奖励（早期鼓励探索，随训练进度逐渐衰减到零）、定位质量奖励（裁剪框或选帧与标注的重合度 IoU，即交并比，两块区域重叠面积除以合并面积）、格式违规惩罚。关键是定位奖励不看答案对错，放大对了就给分。第二个设计是「藏原图」：第一次成功调用工具后，以 0.5 的概率把原始图像或视频从上下文里删掉，只留工具返回的结果，逼模型用它（Figure 3，p4）。第三个设计是分组：藏与不藏的回答分开计算相对优势，避免把「运气好没被藏图」误当成「做得好」。推理时原图始终保留。

**第二阶段 OG-MOPD**（观测门控多教师在线蒸馏）：学生同时学图像和视频（p5）。学生每次调用工具时，门控检查它的操作与标注的 IoU：裁剪低于 0.25、选帧低于 0.15，或者调用缺失、无效，就把操作换成由标注生成的标准操作，让环境执行后学生从修好的画面继续生成（附录 C.1，p16）。被替换的那段操作 token 用普通的模仿损失（NLL，负对数似然，即让模型提高说出这段文字的概率）来教，权重为 1；学生自己生成的部分照常用专家老师逐 token 反馈（Figure 4，p5）。推理时不需要门控，也不需要老师。

实现细节：底座 Qwen3.5-9B，冻结视觉编码器，只训练语言模型部分；专家训练用 32 张 GPU，蒸馏用 8 张 GPU，型号论文未说明；所有模型只训 1 个 epoch 并挑最好的检查点，挑选依据论文未说明（附录 B，p14–p16）。

**如果让你复现**第二阶段，最小骨架是：

```python
for q in batch:                                        # 图像题和视频题混合
    hist, inj = [q.prompt], []
    while not done(hist):
        a = student.sample(hist)                       # 学生自己生成下一段
        if is_tool_call(a) and q.has_box:
            if invalid(a) or iou(a, q.box) < delta[q.tool]:  # 裁剪 0.25 / 选帧 0.15
                a = canonical_action(q.box); inj.append(a)   # 换成标准操作
        hist += [a, env.execute(a)]                    # 用修好的画面继续
    teacher = route(q, hist)                           # 按工具类型选图像或视频专家
    loss = rev_kl(student, teacher, hist, skip=inj) + nll(student, inj)
```

## 5. 证据怎么看、别被什么忽悠

**表一：Table 2（第 7 页），训练方式对比。** 想证明：Reframe 比混合强化学习和普通多教师蒸馏都好。怎么测：同一底座 Qwen3.5-9B，同一份数据；7 个图像基准（V*、HR-Bench 4K/8K、VisualProbe 等）和 7 个视频基准（Video-MME、MVBench、MLVU 等），贪心解码（每步取概率最高的词，结果确定），统一视觉 token 预算（p6）。结果：图像平均 Reframe 69.48、MOPD 68.19、Mix-RL 66.75、图像专家 67.92、底座 63.46；视频平均 53.10、52.32、51.41，视频专家 52.78、底座 49.75。说明：排序清楚，Reframe 比 MOPD 多 1.29（图像）和 0.78（视频）。但这是平均分领先，不是逐项领先：HR-Bench-4K 上 Reframe 84.75 低于 MOPD 的 84.88 和图像专家的 85.25；MVBench 上 69.11 低于 MOPD 的 70.08 和视频专家的 70.37。

**表二：Table 3（第 7 页），GD-GRPO 是否真让模型「看」了。** 想证明：新奖励和藏图让模型依赖工具结果。怎么测：在 V* 的 191 道选择题上，固定一次裁剪操作，只换返回图像的内容：真实区域（GT）、随机位置、纯灰图；「依赖度」定义为「无用图下答错、换成真实区域后能改对」的比例（附录 C.2，p16）。结果：依赖度从普通 GRPO 的 52.59 升到 69.03；开工具带来的增益从 +1.97 升到 +3.82，而不开工具的准确率只多 0.22。说明：提升主要来自「会用工具」，不是整体视觉能力变强。

**表三：Table 4（第 8 页），与已有视觉智能体对比。** Reframe 依赖度 75.53，其他模型最高 41.93；工具增益 +5.23，其他最高 +1.47。图像和视频平均分分别比最强外部模型高 11.71 和 8.86。

**水分检查**：①全部单次运行、贪心解码，没有种子和误差条，图像 1.29、视频 0.78 的差距是否稳定无法判断。②Mix-RL 和 MOPD 是作者自训的对照，用的是同一套数据和超参，公平但不独立。③Table 4 的外部模型底座和训练数据各不相同，论文没在表中对齐，11.71 分的差距不能全算在方法头上。④依赖度只在 V* 一个基准、191 题上测。⑤检查点「挑最好的」，挑选依据未说明，如果看的是测试集会偏乐观。⑥非精确匹配的答案用 Gemini 3.1 Flash Lite 判对错（p16）。⑦只有两个工具，没有真机或线上任务。

## 6. 可信度与核验限定

**主张对照**：①「14 个基准上超过 Mix-RL 和 vanilla MOPD」：Table 2（p7），平均分成立，逐项看有个别基准反超，证据够但幅度小。②「GD-GRPO 提高观测依赖和工具增益」：Table 3（p7），设计合理的控制实验，证据较好。③「平均超过两个专家」：Table 2，成立。④「代码、数据和模型都已开源」（p2）：成立，仓库、HF 权重和数据集都可访问。

**核验限定**（原样合入核验报告）：
- 对照 Mix-RL、vanilla MOPD 都是作者在 Qwen3.5-9B 上自训的（p3；p5–p6）
- 论文为 arXiv 非独占许可；代码 Apache-2.0

**打折提醒**：对外引用时说「14 个基准的平均分超过」，不要说「每个基准都超过」；Reframe 对 MOPD 的增益只有一两分，且是单次运行；与外部智能体的大幅领先要注明底座和数据不同。

## 7. 你可以怎么落地

**今天就能试**：如果你有一个会调用工具的视觉模型或智能体，照附录 C.2 做一次「观测依赖」体检：挑一两百道题，固定让它调用一次裁剪，分别返回正确区域、随机区域、纯灰图，计算依赖度（真实区域下的准确率减去无用图下的平均准确率，再除以 100 减去无用图下的平均准确率，乘 100）。验收：依赖度明显低于一半（论文 Table 4 里四个已有智能体在 19.47 到 41.93 之间），说明你的工具大多是摆设，值得改训练奖励；同时比较开关工具的准确率差。

**要有数据或机器再试**：需要带框或时间段标注的数据（可直接用 Reframe-100K），以及与论文相近的算力：专家训练 32 张 GPU、蒸馏 8 张 GPU（型号论文未说明）。分阶段：先只在图像子集上复现 GD-GRPO，对比普通 GRPO 看依赖度和工具增益是否同样上升；再加视频专家做 MOPD；最后打开门控，对比 MOPD 看平均分能否多出一分左右。每个配置至少跑两到三个种子，补上论文缺的误差条。

**暂时别碰**：没有可靠位置标注的任务（例如开放式图像描述）不要上门控修复，标准动作无从生成，错误标注还会教坏模型；也不要把「藏原图」用在推理阶段，论文只在训练时用。

## 8. 和你已有知识的挂钩

「藏原图」像训练里的 dropout（随机丢掉一部分输入，逼网络不依赖单一捷径），只不过丢的是整张原图；门控修复像驾校教练踩副刹车：学员方向打错时教练接管一下，摆正后再让学员自己开，同时把正确动作记下来让学员模仿。和普通多教师在线蒸馏最大的区别是：它不只改「老师怎么打分」，还会在轨迹中途介入，改变学生看到的画面。

## 9. 存疑与代价

**局限**：论文没有单列局限一节。读出来的有：单次运行；依赖度只测 V*；工具只有裁剪和选帧；门控依赖标注质量；外部对比底座不齐；修复后的轨迹不再完全是学生自己生成的，作者承认这是「在线性」和「观测有效性」之间的取舍（p5–p6），但没量化修复比例。**复现条件**：代码、权重、数据都公开，均为 Apache-2.0；底座 Qwen3.5-9B 的许可需另查。**成本**：专家阶段 32 张 GPU、蒸馏阶段 8 张 GPU，各训 1 个 epoch（p14，p16），总时长论文未说明。**出处**：预印本，未同行评审；第一单位南京大学，其余作者来自中科院自动化所。

**论文没回答、但决定你要不要动手的 3 个问题**：训练中有多大比例的工具调用被门控替换，比例高时还算在线学习吗？多个种子下，Reframe 对 MOPD 的一两分优势还在不在？换成更多种类的工具（如 OCR、检索），门控阈值怎么定？
