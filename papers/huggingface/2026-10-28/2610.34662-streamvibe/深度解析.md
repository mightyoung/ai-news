# StreamVibe：能跟上用户意图变化的主动式视频智能体

- 英文标题：StreamVibe: Proactive Video Agents for Evolving User Intent
- arXiv：https://arxiv.org/abs/2610.34662 ｜ HF：https://huggingface.co/papers/2610.34662
- HF 点赞：245（2026-10-28 09:05 北京时间抓取）
- 机构（按论文署名）：Google（第一作者为 Google 学生研究员），另署 UC Santa Barbara、UC Santa Cruz、Stanford、Oxford、Emory、Columbia

## 一句话总结
让视频大模型在连续画面流里不等用户开口就判断「现在该不该说话、说什么」，并在用户中途改需求时及时更新；配套给出基准、训练出的模型和带状态记忆的运行框架。

## 研究问题与动机
现有流式视频模型大多依赖显式请求（「下载完提醒我」），会漏掉隐式意图（用户在网页上犹豫下一步点哪里），也很难跟踪任务进度，容易重复已经完成的建议或忽略用户更新后的意图。

## 核心方法
- **StreamVibe-Bench**：4.1K 评测样本、85K 训练样本，覆盖显式、隐式、动态三类意图；分「逐点评估」（给标准历史，只判当前决策）和「轨迹评估」（模型用自己生成的历史跑完整条视频流）。
- **StreamVibe-VL**：两阶段训练。阶段一是自适应流式 SFT，按当前训练分布调整「决策 token」（是否响应）的权重，并单独优化回复内容；阶段二是局部轨迹 RL，在帮助点附近用 GRPO 结合点级与轨迹级奖励优化。
- **StreamVibe-Harness**：把用户意图当作可更新、有生命周期的持久状态，用分层记忆检索相关的历史观测与交互，给模型提供统一上下文。

## 实验设置与主要结果
- 评测以 Claude Sonnet 4.6 作为统一评审，回复质量打 0–4 分，时间容差 ±2 秒；对比 Gemini-3.1-Pro、GPT-Realtime-2.1 等闭源模型，Qwen3-VL-8B 等离线模型，以及 MMDuet2、LiveStar、VideoLLMOnline 等流式模型。
- 摘要报告：StreamVibe-VL 在保持通用视频理解的同时，响应时机与回答质量比其他基线提升 10.7%；加上 Harness 后主动交互再提升 12.3%。
- Table 2（逐点评估）中，RL 版相对 SFT 版在动态意图上召回从 58.85 提升到 75.86、F1 从 58.70 到 66.34，Content F1 从 33.27 到 39.31，印证作者「RL 对动态意图收益更大」的说法；但同一列误报率 FPR 也从 49.13 升到 62.93，且多数列仍低于 Gemini-3.8-Flash（如动态意图 Content F1 为 43.70），作者措辞是「与闭源模型有竞争力」而非超越。
- 外部基准 EgoProactive 上结果有竞争力，IPIBench 上持续领先（细节在附录 A）。
- 作者的另一发现：现有主动式模型在隐式和动态意图下仍很难判断「何时该响应」。

## 局限与风险
- 主要指标依赖 LLM 评审，评分口径与评审模型选择会影响结论；基准与模型由同一团队构建，存在「自建自测」偏向。
- 作者在结论里承认：真实世界里意图和环境会相互影响、共同演化，比当前设定更复杂。
- 「10.7%」「12.3%」是相对汇总提升，具体是哪个指标、相对哪个基线要回到正文表格核对。

## 工程落地启示
- 做可穿戴、屏幕助手类产品时，把「是否开口」显式建模为决策 token 并单独加权，是控制打扰率的直接手段。
- 用户意图做成持久状态（新建、修订、完成、中断），再配分层记忆，可以显著减少重复提醒和过时建议，这一层不依赖特定模型，可直接借鉴到 agent 框架。

## 与相关工作的关系
延续 VideoLLM-online、MMDuet 等流式视频对话工作，从「回答显式问题」推进到「推断隐式意图」；Harness 部分与智能体记忆、状态管理方向（如 MemGPT 类方案）思路相通。
