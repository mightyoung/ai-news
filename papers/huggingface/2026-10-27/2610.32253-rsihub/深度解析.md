# RSIHub：面向智能体自进化方法的可组合框架

**RSIHub: A Composable Framework for Agent-Evolution Methods**

- Hugging Face：https://huggingface.co/papers/2610.32253
- 点赞数：34（2026-10-27 09:00 北京时间抓取，HF 2026-10-26 批次）
- 机构：第一单位 UC Berkeley；论文第 3 单位为抖音集团（Douyin Group），全文未写 ByteDance（ByteDance 只是 HF 页面标签）；其余署名含中国科大、上海交大、同济、北京通用人工智能研究院（BIGAI）、Simple Agent Lab

## 一句话总结

把"让智能体根据执行反馈改自己的提示词、技能、工具和编排"这类方法拆成可插拔的算子和配方（recipe），共享执行、评测、恢复与谱系记录，并把评分放在方法够不着的地方，从而让 AHE、Hyperagents、A-Evolve、GEPA 能在同一条件下公平比较。

## 研究问题与动机

自进化（agent-evolution）方法都在跑同一个循环：选父代、跑任务收集证据、提出修改、评测、决定是否保留。但每个方法都自己重写一套工作区、执行器、评测器和记录系统，导致（1）实现一个新想法要重造整套系统；（2）不同方法难以在相同模型、相同评测器下比较；（3）当方法本身有权修改的范围很大时，它可能顺手改到评测或记录，使"提升"无法归因。作者希望提供一个公共底座来解决这三点。

## 核心方法

- **七阶段生命周期**：Select、Rollout、Analyze、Mutate、Guardrail、Evaluate、Absorb。配方必须绑定 Select、Rollout、Mutate、Gate、Record 五个算子，可选 Analyze、Validate、Novelty、Reflect。
- **声明可变表面（surface）**：配方声明候选可以改哪些文件；Guardrail 阶段由框架检查真实的 diff 是否越界。
- **受保护的评测**：Evaluate 由框架负责，对干净的提交在 gate 任务上打分并"认证"写入归档；Gate/Record/Reflect 只能追加注释，不能改认证字段。
- **数据划分**：train（给进化反馈）/ gate（准入）/ sealed（只用于留出报告，不进入反馈）。
- **溯源**：每条评测记录绑定候选提交、父代、配方快照、评测器与任务集指纹、模型身份等。
- **两种模式**：固定配方驱动，以及由外层智能体在迭代之间修改配方的 agent-driven 模式（本文实验只评测了固定配方）。
- 底层基于 Harbor 做容器化执行与逐任务验证。

## 实验设置与主要结果

- 种子智能体：MiniSWE 与 Codex；基准：Terminal Bench 2（89 题，划为 50/19/20）与 τ³ Banking（97 题，划为 50/20/27）；指标 pass@1，每题一次。
- 目标模型统一为 GPT-5.4（high 推理），变异智能体为 GPT-5.4（xhigh）驱动的 Codex；每代只产生一个子代，最多 10 代。
- Terminal Bench 2 + MiniSWE：四种方法把基线 56.2 提升 7.8–13.5 个百分点，Hyperagents 与 A-Evolve 都到 69.7（+13.5，即摘要里的"最大提升"，Table 1 p8）。注意：+13.5 是单次运行、16 个配置中最好的一个，且是含 train split 的 overall 分数；在 sealed（留出）split 上只有 +5.6。
- Terminal Bench 2 + Codex：基线已是 69.7，最多只提升 +2.2：AHE 到 71.9（+2.2），Hyperagents、A-Evolve 各 +1.1，GEPA 持平。
- τ³ Banking：MiniSWE 上 Hyperagents 从 27.8 到 33.0 最好；Codex 上 AHE 从 24.7 到 34.0，GEPA 33.0 次之。
- 分划结果揭示隐藏代价：MiniSWE 在 τ³ Banking 上 Hyperagents 总分最高却在 sealed 上退 2.1 分，AHE、GEPA 在 sealed 上分别退 4.1、2.1 分；Codex 在 Terminal Bench 2 上 AHE、Hyperagents 的 gate 分分别降 3.4、2.2。结论：没有一种方法在所有基准、种子和划分上都占优。
- 框架开销：附录报告框架自身耗时占完整代际的比例，在 τ³ Banking 上为 0.019%，Terminal Bench 2 中位数 0.02%。

## 局限与风险

- 证据保证依赖可信的框架服务、主机文件系统保护和评测器本身有效；RSIHub 不做恶意代码隔离，作者明确说它支持"审计与回滚，不是围堵"。
- 实验只覆盖固定配方，外层智能体自适应修改配方的模式没有评测。
- 每题只跑一次、每代一个子代、最多 10 代，规模较小，方法排名的稳定性有限；头条 +13.5 是单次运行、16 个配置里挑出的最好值，且含 train split，sealed 上仅 +5.6。
- 作者在负责任使用声明中提醒：可能带来不安全的能力增长、奖励投机和敏感轨迹泄露。

## 工程落地启示

1. 做"自动改 prompt / skill / harness"时，**评测与记录必须放在被优化对象的可写范围之外**，否则提升不可信。
2. 一定要留 sealed 集：本文多次出现训练集涨、留出集掉的情况，只看总分会被误导。
3. 把方法拆成 select/mutate/gate 等算子，便于做"只换一个算子"的消融。
4. 生产部署需限制文件系统和网络访问、排除生产凭据，并在晋升前做人审。

## 与相关工作的关系

论文把 AHE（用执行证据改 harness 文件）、GEPA（轨迹反思 + Pareto 选择优化提示词）、Hyperagents（任务智能体 + 可自我修改的元智能体）、A-Evolve（部署期目标导向优化）统一成配方；同类工作还有 DSPy、TextGrad、Promptbreeder、ACE、GPTSwarm、AgentSquare、EvoAgentX 等。它和奖励过度优化（Gao 等）、奖励篡改研究的联系在于：把评分与可变表面隔离，正是为了降低这类风险。
