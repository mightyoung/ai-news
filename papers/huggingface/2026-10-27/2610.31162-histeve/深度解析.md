# HiSTEVE 1.0：用"人类接口"VLA 智能体玩开放世界游戏

**HiSTEVE 1.0: Harnessing Human-Interface VLA Agents for Open-World Games**

## 一句话总结

在 Minecraft 里，用"VLM 规划 + 结构化记忆 + 学习式完成检测"的能力感知 harness 管长程，用单个只看画面、只输出键盘鼠标的 VLA 管执行，两层闭环，把原子任务和长程任务都做到了论文中的最好水平。

## 研究问题与动机

想让虚拟具身智能体像人类玩家一样玩开放世界游戏，需要两种能力：长程自主（记住目标、调整计划）和可靠的原生接口控制（从第一人称画面输出键鼠动作）。现有工作要么是视觉运动策略/VLA，控制原生但缺乏长程状态跟踪；要么是 LLM/VLM 规划，但底层依赖环境 API 或预定义技能，在大多数游戏里拿不到。作者想在两者之间搭桥。

## 核心方法

- **编排层（harness）**：GPT-4o 作为规划器，只在 VLA 能力范围内选择子任务（能力约束的子任务 schema）；结构化记忆跟踪进度；一个以 Qwen2.5-VL-3B 为骨干、并以 VLA 策略上下文为条件的"任务完成状态检测器"判断子任务是否完成，决定何时交接。
- **控制层**：单个 VLA（由 Qwen2.5-VL-7B 初始化）执行所有子任务，纯视觉输入、原生键鼠输出。为了缓解 GUI（合成、熔炼界面）和非 GUI（挖掘、战斗）交互之间的干扰，引入按交互类型分支的 RMSNorm（RS-Norm，只增加 2Ld 个参数）和分开的鼠标移动 token 嵌入（Dual-Mouse）。
- **训练**：世界知识注入 → 模仿学习 → 基于环境反馈的强化学习，以提升偏离示范时的恢复能力。

## 实验设置与主要结果

- MineStudio Bench（严格 pass@1）：挖掘 93.3%、击杀 86.7%、合成 66.7%、熔炼 93.3%，平均 85.0%；相比 OpenHA Text/CoA 的 65.0% 提升 20.0 个百分点。
- OpenHA：平均 37.4%，对比 36.8% 仅高 0.6；提升集中在 Embodied（37.0% → 46.0%），GUI 和 Combat 略低于基线。作者分析 GUI 失败多发生在多步摆放、中间状态纠正和取回结果。
- LongBench 最终目标成功率：资源与合成 42.9%、探索与记忆 28.6%、恢复 14.3%、开放式 14.3%，相对 OpenHA Text/CoA 分别提升 28.6、21.5、11.4、12.9 个百分点；能从零做出铁镐。
- 消融：共享表征基线 MineStudio 41.1%，单加 RS-Norm 57.3%，单加 Dual-Mouse 61.9%，两者合用 80.7%；OpenHA 平均从 26.6% 到 37.7%，LongBench 目标成功率从 3.6% 到 14.3%。在 VLA 固定时，完整 harness 让目标成功率比"固定步数交接"翻倍以上。
- 完成检测器：准确率和 F1 均为 0.863；提示式的 GPT-4o、GPT-5.5 的 F1 分别为 0.690、0.776，Qwen3.5 9B/35B 几乎总判"未完成"（召回 0.030、0.042）。

## 局限与风险

- 作者自述：原子子任务接口是人工定义的，能力受限于现有 VLA；新增能力需要新数据和重训；harness 和 VLA 都不会从部署经验中做参数化持续学习。
- 高层规划依赖现成 VLM（GPT-4o），整体表现受其制约，也带来调用成本。
- 恢复类和开放式长程任务成功率仍只有 14.3%，GUI 多步操作是明显瓶颈。
- 实验只在 Minecraft 中进行，能否迁移到其他游戏或真实交互环境尚未验证。

## 工程落地启示

1. 做 GUI/电脑操作智能体时，"规划器 + 执行器 + 独立的完成判定器"三件套值得借鉴：专门训练的小检测器比提示大模型判定更准。
2. 同一策略要处理差异很大的交互模式时，轻量的分支归一化和分离嵌入是低成本的抗干扰手段。
3. 原子能力强不等于长程好，持久的任务状态和交接机制才是长程性能的关键。

## 与相关工作的关系

延续 VPT、STEVE-1、JARVIS-VLA 等原生控制路线，以及 Voyager 等基于 LLM 规划、依赖环境 API 或预定义技能的路线，并与 OpenHA 等层次化方法直接对比；harness 思路与近期通用智能体 harness 研究一致。
