## 1. 一句话先懂它

这是一套由 42 位物理学家用自己做过的真实课题改成的「整段研究」考卷：模型要查文献、定方案、跑实验或仿真、交结果文件和一篇像样的论文。现有最强代理在整套题上总体一次通过率最高大约四分之一，卡点主要是推理不够严和缺少专家直觉，而不是不会算物理公式。

## 2. 值不值得读：五个 C 速览

**类型**：新基准与大规模评测（不是新训练算法）。**上下文**：接着教科书题、封闭专家题、单步工作流评测，以及「给原论文再复现」一类基准；作者强调那些题要么太窄容易刷满、要么把答案结构提前交给模型。**关键假设**：任务能同时用确定性核对脚本（verifier，对照参考数值的自动判题）和专家写的 rubric（按条目打分的评分表）判「对不对」和「像不像能发」；这依赖贡献者本人做过原课题、并有领域同行审稿。假设对自建题合理，但评测栈本身（含 Agent-as-judge）仍可能漏判。**贡献**：① 56 道端到端物理研究题，覆盖九领域与理论/计算/实验三种模式；② 确定性核对加阻断项/非阻断项评分的通过定义；③ 22 模型×26 配置的榜单，以及人工失败模式剖析。**清晰度**：正文约 10 页，流程和图 3 清楚；细节、置信区间和失败标签多在附录。建议**看到第 5 节**；若你在做科研代理或评测基建，值得自己读 §2–3 与 Fig.6。

## 3. 它在解决什么麻烦

现在大家评「会不会做物理」多半用固定题、子任务或「照着已发表论文复现」。封闭题很快被刷到天花板；复现题又把研究问题和解法骨架提前写死，测不到「自己立项、自己找文献、自己决定怎么做」。更少有人同时查结果对不对、报告写得像不像能送审。

你什么时候会撞上？比如你在公司里让代理「读几篇论文、写个实验计划、跑仿真、交 PDF 报告」，Dashboard 上工具调用都成功了，数值却对不上隐藏测试；或者数值碰巧对了，但报告动机空、文献对不上、甚至改测试骗分。又比如你想用榜单选型，却发现各家自建题口径不一，看不出是不会物理还是不会把研究做完整。

若这套评测站得住，选型时就能用同一把尺子看端到端研究能力，并把失败从「物理知识不够」改写成更可操作的「严谨性 / 直觉 / 文献综合」短板清单。

## 4. 他们怎么做的（怎么评）

**核心思路**：把贡献者本人做过、至少两周以上的真实课题，改成开放式任务包——可以点明要探的方向，但不给方法与解路径；环境里可放数据、仿真器、设备说明。代理交两类交付物：确定性产物（数值、仿真输出等）和 `paper.pdf`。判分时「结果对」与「研究像样」缺一不可。

**任务怎么收**：先做真实性与格式审查，再请领域同行审（审稿人多为在读/已获博士）。审三点：题面有没有过度提示、评分表是不是真物理洞见、贡献者用前沿代理至少跑三轮后的失败分析有没有假阳性/假阴性。行政组（六名物理博士）最后合并。182 份投稿收 56 题；正文写来自 26 家机构的 42 位研究者、九领域；首页单位脚注编号则到 37。约 18 题对应已发表工作（含 Nature 等）。贡献者自报原课题人均约 270 天（§2.2，第 5 页）。

**一次 rollout 怎么跑**（图 3c，第 4 页）：沙箱装好环境 → 代理可上网与本地计算，但「标准答案」与 oracle 解法对代理隐藏 → 交 `result.md`/`paper.pdf` 等 → 确定性 `test_outputs.py` 核对 → 同一套评审代理（主实验为 GPT-5.6 Sol xhigh + Codex）按 `rubric.json` 读轨迹与论文打分。

**通过与分数**（式 1，第 6 页）：阻断项（blocker）全过且确定性核对过，才算整体通过；非阻断项按 0/1/2 加权合成 0–100 的质量分。错一个阻断项或核对失败，质量分直接记 0——高文笔补不了错结果。

**评测规模**（§3.1，第 6 页）：22 个前沿模型、四种 harness（Codex / Claude Code / Grok Build / Antigravity 等），每题每配置默认最高推理档跑 3 次；部分 GPT 另跑 xhigh。图 2 汇总约 4,364 次 rollout。

**如果让你复现评测骨架**（单题单配置）：

```python
# 对每个 task、每个 model_harness_config：
for trial in range(3):                                      # 论文默认每题 3 次
    sandbox = build_env(task.environment)                   # 数据/仿真/手册；隐藏 oracle
    traj, outputs = agent.run(sandbox, task.md)             # 可上网；交 result + paper.pdf
    D = run_verifier(outputs, task.verifier)                # 确定性核对，通过=1
    blockers, nonblockers = reviewer_agent.grade(           # 读轨迹+论文，按 rubric.json
        traj, outputs.paper_pdf, task.rubric)
    passed = (D == 1) and all(blockers)                     # Overall pass
    score = weighted_nonblocker_pct(nonblockers) if passed else 0  # 式 (1)
```

## 5. 证据怎么看、别被什么忽悠

**图一：Figure 1 / Table 2（第 1、9 页），谁最强、强多少。** 想证明端到端物理研究对当前代理仍然很难。指标：Deterministic pass = 核对脚本全过；Overall pass = 核对全过且阻断项全过；Pass@1 = 三次里平均通过率，Pass@3 = 至少一次通过的题占比。结果：Claude Opus 5.5 + Claude Code 总体 Pass@1 **27.4%±6.7**、确定性 Pass@1 45.8%、Score 26.0；次席 GPT-6 Astra (max) Codex 总体 23.2%。摘要与结论强调：22 模型×26 配置里，**无一配置在其 168 次 rollout（56×3）中通过超过 46 次**（摘要第 1 页；结论第 10 页）。说明：即使「只看数值」过关率更高，加上「研究像样」的阻断项后腰斩；榜首也远未饱和。

**图二：Figure 6（第 10 页），失败到底败在哪。** 想证明短板主要不是「物理知识」。对象：GPT-6 Astra xhigh 在 56 题×3=168 次上的人工复核；百分比分母是 **143 次失败**（不是 168）。结果：推理不够严（RIG）**48%**（n=68）、缺专家直觉（INT）**34%**（n=48）、文献综合失误（LIT）**27%**（n=39）；明确「算错/概念错」类物理错误约 16%。另标出假阴性 7%、误判 3%；修正后该配置通过率可由 14.9%（25/168）调到 20.2%（34/168）。说明：代理常在循环自验证、漏边角条件、找不到关键文献或做实验时拧错旋钮上翻车，而不是单纯「不会这门课」。

**图三：Figure 4（第 7 页），领域与模式差异。** 想证明难度不均。计算题 33 道、实验 17、理论 6；光子学与成像总体通过偏高，化学物理等偏低（图中分域通过率）。说明：报一个「总 Pass@1」时要意识到题集结构会拉平均数。

**水分检查**：① 自建评测、作者既出题又组织评审，存在「故意压通过率」动机；作者用三阶段失败分析、作者自有文稿在对应 rubric 上均分 96.2%（Table 11，§3.3）来缓解。② 主裁判是另一个代理，存在模型家族偏袒；文中称换 Claude Opus 5.5 重判时，对 GPT-6 Astra 几乎同判，但对本家族更松（Table 6）。③ 失败分类只对 GPT-6 Astra 队列做了细标，不能直接外推到所有模型。④ 每次 rollout 成本与时长跨数量级（Fig.5，第 8 页），算力不对等是选型现实的一部分，不是公平消融。⑤ 预印本，题面与脚本是否持续修订要以仓库为准。

## 6. 可信度与核验限定

**主张对照**：①「现有配置整体仍很难」：摘要 + Table 2 +「≤46/168」一致，证据充分（在自建题口径内）。②「最高总体 Pass@1≈27.4%」：Claude Opus 5.5 + Claude Code，Table 2 / Fig.1，充分。③「主因是严谨性与直觉而非物理知识」：主要来自 GPT-6 Astra 的人工标签（Fig.6），对应该模型充分，对外推需打折。④「评审代理可靠」：有作者文稿对齐与抽查，但非全量人类重判。

**核验限定**（原样合入）：
- 56 题、42 位物理学家、九领域；22 模型×26 配置，无一配置在 168 次 rollout 中通过超过 46 次（摘要 p1；p10）
- 最高总体 Pass@1 约 27.4%（Claude Opus 5.5 + Claude Code）（图 1 p1；p6/p9）
- GPT-6 Astra 失败主因占 143 次失败：推理不够严 48%、缺专家直觉 34%、文献综合 27%（Fig.6 p10）
- 首页单位编号 1–37（非 26）；论文 CC BY 4.0

**打折提醒**：引用 27.4% 时写明 Overall Pass@1、Claude Opus 5.5 + Claude Code、56 题×3；引用 48%/34%/27% 时必须带「GPT-6 Astra、分母 143 次失败」。不要把 Fig.2「26 institutions」与首页 1–37 脚注混成同一个数对外说死。

## 7. 你可以怎么落地

**今天就能试**：不用训练。把你现有的「代理科研/写报告」流水线拆成与论文对齐的两道闸：① 对关键数值设独立核对脚本（或黄金文件 diff）；② 列 5–10 条阻断项（有没有捏造数据、有没有改测试、关键文献是否引用、结论是否被产物支持）。抽 10 次真实任务跑次，分别统计「数值过」「阻断项过」「两者都过」。验收：若「数值过」远高于「两者都过」，说明你之前的成功率被文笔或工具轨迹夸大了。

**要有数据或机器再试**：有能跑沙箱代理的预算时，用 BenchFlow 或同类框架接 1–2 个你领域内的小课题（按 §2.1 做 task.md + verifier + rubric），固定同一 harness 对比 2–3 个模型各 3 个种子。验收：看 Overall pass 与失败标签分布，而不是只看 token 数或「报告好不好读」。

**暂时别碰**：不要根据这一篇就断言「模型不懂物理」——文中物理知识类失败不是主因；也不要在没有领域专家写 rubric 的情况下，用单一 LLM 当裁判就对外发「可发表性」榜单。完整 56 题重跑成本高（时长与美元跨数量级，Fig.5），不适合个人当日常 CI。

## 8. 和你已有知识的挂钩

它像软件工程里的「端到端验收 + 代码评审」：单元测试对应确定性 verifier，阻断项对应合并前必须过的检查清单，非阻断项加权分对应质量分。和「刷题榜」最大的区别是：题目来自出题人自己做过的开放研究，且隐藏了解法与参考论文，测的是整段研究流程而不是单点知识。

## 9. 存疑与代价

**局限**：自建题与自建裁判；失败细标主要覆盖一个模型队列；领域题量不均；正文机构数表述与脚注编号不一致需留意。**复现条件**：论文 CC BY 4.0；基建指向 github.com/benchflow-ai/benchflow；完整题包/轨迹是否开平要以作者后续发布为准。**成本**：单次 rollout 可到数小时、数美元到数十美元量级（Fig.5）；全量 22×26 级评测是机构预算。**出处**：预印本；BenchFlow 联合大量高校与工业界作者。

**论文没回答、但决定你要不要动手的 3 个问题**：题集污染或训练数据泄漏如何持续审计？换人类评审为主时，27.4% 这一档会动多少？在你自己的垂直领域（非物理）按同一模板迁移，阻断项该怎么重写才不误伤正确解？
