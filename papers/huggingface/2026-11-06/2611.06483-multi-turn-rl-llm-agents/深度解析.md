## 1. 一句话先懂它

大家以为给 Agent 做多轮强化学习，是把「每一步决策」都变强了。这篇测量发现：它常常并没有全面抬高单步质量，真正变强的是「出错之后怎么救」和「轮次不够时还能不能扛」；并给出一个训练时混合轮次预算的修法叫 BudgetMix。

## 2. 值不值得读：五个 C 速览

**类型**：测量分析为主，附带 BudgetMix 这一训练策略。**上下文**：接着多轮 Agent RL（工具调用、代码交互）、GRPO/PPO/GiGPO、以及 Pass@(K,T) 评测轴。**关键假设**：能在部分任务上拿到可靠的步级质量（FrozenLake 用动态规划 Q\*，DeepCoder-MT 用单测通过率）；主实验骨干为 Qwen3-4B/8B。假设在「可打分环境」成立，换开放域工具时步级分析会变难。**贡献**：一是用 Pass@(K,T) 拆开采样宽度与交互深度；二是证明增益集中在错误恢复而非普适单步；三是 BudgetMix 在紧预算下更稳。**清晰度**：图 4/5 一眼能看懂；Table 1 数字密但结构清楚。建议**看到第 5 节**；正在训 Agent RL 的人值得自己读 §3.3 与 §5。

## 3. 它在解决什么麻烦

多轮 Agent RL 让模型在环境里反复行动、吃反馈、改下一步，轨迹成功率往往明显上涨。但线上常有硬约束：工具超时、用户只愿聊两轮、成本上限把 `T`（最大交互轮数）砍掉。你若只在「预算很宽」的评测集上看分，会高估上线表现。

另一层误解是：轨迹分涨了，就以为每一步都更聪明。若其实只是「错了会修」，那在不允许试错、或第一步就必须对的场景里，RL 模型可能并不比 base 香，甚至更谨慎到保守。

搞清楚「到底提升了什么」，才能决定：要不要加过程奖励、要不要在训练时故意收紧预算、上线该监控哪些中间指标。对做 Agent 产品的人，这也解释了一种常见体感——演示里多轮工具调用很炫，一限超时或限轮次就掉回 base 水平。

## 4. 他们怎么做的

**核心思路**：把评测拆成两个旋钮——采样宽度 `K`（多抽几条轨迹）和交互深度 `T`（允许多少轮）——看 RL 相对 base 的优势在哪些格子还在；再把相同状态上的「单步动作质量」拆开，区分普通状态与错误后状态。

**Pass@(K,T)**（§2.2）：至少一条在预算 `T` 内成功的概率。固定 `K` 扫 `T` 得 Pass@T；固定宽裕 `T` 扫 `K` 得传统 Pass@K 感。任务含 DeepCoder-MT、BFCL、InterCode-SQL、FrozenLake；算法主用 GRPO，并对照 PPO、GiGPO。

**步级质量**（§3.3，第 4–5 页）：对匹配状态，base 与 RL 各采 `G=16` 个动作取平均质量。FrozenLake 用有限时域 DP（γ=0.95）的 Q\*；DeepCoder-MT 用单测通过率。错误状态池：在前一步注入错误动作再评。

**BudgetMix**（§5）：训练时不固定满预算，而是对轨迹采样不同交互预算，奖励机制仍与原多轮 RL 相同，可挂在 GRPO/PPO/GiGPO 上。直觉：逼模型在「轮次不够」时也学会收工或早做关键决策，避免只学「靠后面多轮救场」。

**如果让你复现**，骨架如下：

```python
# 评测：网格扫描 Pass@(K,T)
for K in Ks:
    for T in Ts:
        score[K,T] = pass_at_least_one(rollouts(policy, K=K, max_turns=T))

# 步级：匹配状态上比单步质量
for s in state_pool:                       # 从 base/RL 轨迹均衡采样
    q_base = mean(quality(a) for a in sample(pi_base, s, G=16))
    q_rl   = mean(quality(a) for a in sample(pi_rl,   s, G=16))

# BudgetMix 训练：每条轨迹抽一个预算 T~mix，其余同 GRPO
for batch in data:
    T_i = sample_budget(Tmax, mix)         # 25%/50%/75%/100% 等
    trajs = [rollout(pi, x, max_turns=T_i) for _ in range(G)]
    loss = grpo_loss(trajs, rewards)       # 与 Full-Budget 同算法，只改预算分布
```

## 5. 证据怎么看、别被什么忽悠

**图一：Figure 4（第 5 页），普通状态单步质量。** 想证明多轮 RL 并未全面抬高每一步。每个点是一个匹配状态，横轴 base 质量、纵轴 RL 质量。结果：RL 仅在 **46.8%**（DeepCoder-MT）/ **42.8%**（FrozenLake）的状态优于 base；平均质量甚至略低。说明：轨迹级胜利 ≠ 步级全面变强。

**图二：Figure 5（第 5 页），错误状态。** 想证明优势集中在「出错之后」。错误状态下 RL 优于 base 的比例升到 **67.3%** / **65.7%**。从相同错误状态续跑终端成功：FrozenLake **51.3% vs 38.6%**，DeepCoder-MT **38.5% vs 22.9%**（正文 p5）。说明：RL 更会救场与长程扛造。

**表一：Table 1（约第 9 页），BudgetMix。** 想证明训练时混合预算能改善紧预算部署。Pass@8，在 25%/50%/75%/100% `Tmax` 下评；Qwen3-4B/8B × GRPO/GiGPO/PPO。结果：紧预算下 BudgetMix 相对 Full-Budget 平均约 **+7.5 / +5.3 / +4.0** 个百分点（25/50/75%）；满预算大致持平。图 8 显示 BudgetMix 训练时轨迹奖励涨、步级奖励不塌，而标准满预算 RL 会压低步级质量。

**水分检查**：①步级结论主报 Qwen3-4B+GRPO；换算法/尺寸在附录。②质量定义依赖可打分环境，BFCL 等更难做同样分析。③过程监督：FrozenLake 上有效，开放任务上 LLM judge 不稳（图 9）。④BudgetMix 的预算混合分布超参需自调。⑤无大规模真实用户产品 A/B。

## 6. 可信度与核验限定

**主张对照**：①「紧预算下轨迹级 RL 优势收缩」：Pass@T 曲线，证据充分。②「普通状态步级不全面优于 base」：Figure 4，证据充分（两任务）。③「错误恢复显著更强」：Figure 5 + 续跑成功率，证据充分。④「BudgetMix 改善跨预算稳健」：Table 1，证据较充分，属新方法初探。

**核验限定**（原样合入）：
- 普通状态步级质量：RL 仅在 46.8%（DeepCoder-MT）/42.8%（FrozenLake）优于 base（Figure 4 p5）
- 错误状态：67.3%/65.7% 优于 base（Figure 5 p5）
- 相同错误状态续跑：FrozenLake 51.3% vs 38.6%，DeepCoder-MT 38.5% vs 22.9%（p5；Qwen3-4B + GRPO）

**打折提醒**：不要说「多轮 RL 让 Agent 每一步都更强」；应说「优势集中在错误恢复与长程韧性，且依赖足够轮次预算」。引用 46.8%/42.8% 时带任务名与 Qwen3-4B+GRPO。

## 7. 你可以怎么落地

**今天就能试**：把现有 Agent 评测改成预算网格——同一题分别限制最大轮次为 25%/50%/100% `Tmax`，画 base vs RL 的 Pass@T。验收：若 RL 只在满预算领先、紧预算持平或落后，说明你撞上了文中的预算敏感。同时抽「错误后下一步」人工或规则抽检，看 RL 是否更会改错；若普通状态下单步正确率并不更高，就不要用「每步都更强」对外宣传。

**要有数据或机器再试**：有可自动判成功的环境（代码单测、网格世界、工具模拟器）时，按附录协议复现步级对比；再把 BudgetMix 接到你的 GRPO 循环（只改轨迹预算采样）。验收：紧预算三点平均提升是否接近文中数个百分点，且满预算不崩。

**暂时别碰**：不要为了「学习文中结论」强行上嘈杂的过程奖励当默认——作者已提示真实任务上过程监督质量不稳。也不要在无法定义步级质量的开放聊天里，硬套 46.8% 这类数字。

## 8. 和你已有知识的挂钩

它像体育里的「抗挫能力」测试：总比分赢了，不等于每个回合技术统计都更好，可能是落后时翻盘更强。BudgetMix 则像训练时故意打短时赛，避免只练加时赛战术。和普通「加大 T、只看最终成功率」的 Agent RL 报告相比，最大区别是把 **K/T 与步级/错误态** 拆开测。

## 9. 存疑与代价

**局限**：步级分析依赖可打分任务；开放域工具调用难复制同样精度；BudgetMix 仍是初步方案；代码许可与完整训练脚本需以项目页为准。**复现条件**：论文 CC BY 4.0；项目页公开；独立仓库 LICENSE 核验时未见。**成本**：多预算网格评测与步级采样（G=16）显著增加推理开销。**出处**：中科院自动化所等，预印本。

**论文没回答的 3 个问题**：在不可自动打分的真实工具链上，如何廉价估计「错误恢复」？BudgetMix 的预算分布怎么选才可迁移？与显式过程奖励、逐步批评模型叠加时是否还有增益？
