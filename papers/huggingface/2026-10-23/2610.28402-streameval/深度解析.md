# StreamEval：交互式流式视频生成模型评测基准

- 英文标题：StreamEval: Evaluating Interactive Streaming Video Generation Models
- arXiv：[2610.28402](https://arxiv.org/abs/2610.28402) · HF：[papers/2610.28402](https://huggingface.co/papers/2610.28402)
- HF 点赞：352（抓取于 2026-10-23 09:00 北京时间）
- 署名机构（论文首页）：Tsinghua University、NVIDIA、CMU、UC Berkeley、Princeton、NUS、Reactor（作者署名为 StreamEval Team）

## 一句话总结
把「数字人对话、数字人表演、世界生成、指令编辑、参考图编辑」五类实时交互视频任务放进同一个基准，用 300 个带时间线的脚本化用例评测 37 个模型，结论是：画面好看、身份保持好，不等于能按时、按范围执行用户中途发来的请求。

## 研究问题与动机
流式视频生成正在从「生成一段好看的视频」走向「边生成边接收用户输入」：对话数字人要接住新问题，可控世界要响应新的操作指令，直播式编辑要随源视频推进不断改、撤销、恢复编辑。每条请求都带有「何时生效、改什么、什么必须保持不变」的约束。已有基准（VBench、EvalCrafter、WBench、StreamAV-Bench、LongV2VBench 等）各自覆盖画质、多轮控制或流式编辑的一部分，缺少一个统一的、显式检查「请求执行」和「状态保持」的评测。

## 核心方法
- **用例构造**：用 Qwen3.8-Max 起草会话目标、定时控制、受保护属性和期望结果；再由人工编写的 oracle 规定每个检查点要建立、保留、取消或恢复什么。图像用 GPT-Image-2 / Qwen-Image 合成，语音用 Qwen3.5-Omni 合成，再经 VLM 视觉筛查、ASR 语音匹配（WER ≤ 0.25）、时长/剪切/冻帧等自动检查。
- **规模**：300 个用例，单个时长 15–300 秒，每个指定初始素材、逐步到达的多模态请求和显式状态要求。
- **评测维度**：任务执行、状态一致性、视觉保真、音画协同四大维度，落成十个任务相关指标，统一 0–100 分。质量、身份等指标由自动评审模型打分（例如身份分取 Qwen3.8-Max-0902 与 Qwen3VL-Plus 两个评审中较低的一个），并做了正负探针的评审校准。

## 实验设置与主要结果
- 共评测 37 个模型。
- **数字人对话**：定制头像组 Vidu S2 Avatar 总分 93.98 最高（Q-Overall 88.98 + 定制加分），AVTR-1 为 84.14。MuseTalk 1.5 画质 95.34、稳定性 97.11，但音画同步只有 38.09、对话 54.34，说明画质和交互能力是两回事。
- **数字人表演**：Vidu S2 Avatar 81.71、LiveTalk 1.3B 75.85 领先；但「按脚本做动作」（Following）分数跨度只有 6.37–36.90，最高也仅 36.90（7 个模型，Table 3）。
- **世界生成**：MemFlow 总分 33.36 最高，Rolling Forcing 33.01、Krea Realtime 31.61；Following 最高仅 25.93（Krea Realtime，Table 4）。HappyOyster 画质 58.34 最高，但 Following 只有 5.56、连续性 2.78。
- **指令编辑**：Vidu S2 Editing 45.43、JoyAI-Video-Edit 42.39 大幅领先其余模型。
- **参考图编辑**：Vidu S2 Editing 39.02 第一，但 Edit Success 最高只有 15.00（仅 3 个参考编辑模型，Table 6）。

## 局限与风险
- 大部分分数依赖自动评审模型（Qwen 系 VLM 等），作者自己也把「收集人类成对偏好并检验与评分细则的一致性」列为下一步，目前人评对齐尚未完成。
- 用例由 LLM 起草、合成媒体驱动，与真实用户交互分布可能存在差异。
- 部分任务只有很少模型可测（参考图编辑只报告了 3 个），排名稳定性有限。
- 闭源商业系统与开源模型在不同管线下测试（例如对话任务分「共享管线」和厂商自带系统），横向比较需谨慎。

## 工程落地启示
- 做实时数字人或可交互视频产品，不能只看画质与身份保持，要单独测「请求是否在规定时间生效、该保留的有没有被破坏」。
- StreamEval 的「脚本化时间线 + oracle 检查点」写法可以直接借鉴到内部回归测试：把每个用户请求写成带时间窗和保护属性的断言。
- 当前所有系统在动作跟随和参考编辑上分数都很低，这是产品差异化的空间。

## 与相关工作的关系
在 VBench / EvalCrafter（画质与时序）、WBench（多轮世界控制）、StreamAV-Bench（流式音视频状态保持）、LongV2VBench（长流编辑）、VideoFDB（全双工对话非语言线索）的基础上，首次把数字人、世界生成和实时编辑统一到一套「执行 + 保持」评测框架里。

## 核验补注（10/23）

- 三个「最高」分分属不同子集（数字人表演 7 个模型、世界生成、参考图编辑仅 3 个模型），不能直接横比。
- 大量依赖自动评审，人评对齐尚未完成。
