## 1. 一句话先懂它

一个 0.8B 小模型做数学题时老是「绕圈子」停不下来。作者不训练、不求梯度，只用几次前向统计，把「改哪些权重、怎么改」写成一堆小的组合优化题，在 GPU 上半小时解完，只翻转符号或把权重乘除 2 的幂，就把循环修掉、分数比此前 LLM agent 的修法还略高。对「模型有固定毛病、想打一个极小补丁」的人有参考价值。

## 2. 值不值得读：五个 C 速览

**类型**：新方法，带一个小的量子硬件演示。**上下文**：直接接着 MIT Takehi 等人的「权重空间编程」博客——让前沿 LLM agent 读权重、写修复；同时借了作者之一的「状态树」表示（把每个权重看成一串离散决策），以及剪枝、量化里常用的「层输出重建误差」和 QUBO 量化工作。**关键假设**：循环这种毛病对应残差流里一个可测的方向，只改少数层的输出投影就能压住；单层的一阶替代目标足以预测整模型行为。在作者测的两个同族模型上看起来成立，但作者承认目标忽略了层间连锁影响（第 15 页）。**贡献**：①把修复写成稀疏离散优化，按输出行精确拆成独立的伊辛问题；②在 Qwen3.5-0.8B 上用更少权重改动略胜 agent 修法；③配方不靠 agent 迁移到 Qwen3.5-2B。**清晰度**：写得很坦白，局限一节把「事后设计」「剂量没对齐」都说了。建议**看到第 5 节**；做模型编辑或量化的人值得读原文第 3 节。

## 3. 它在解决什么麻烦

小的推理模型开「思考模式」时常陷进短循环：同一段话反复写，直到用完 token 上限。论文引用的数字是：Qwen3.5-0.8B 在 32,768 token 上限下，93% 的 MATH-500 题会被截断，准确率只有 7.9%（第 2 页，该数字来自 Takehi 等人报告、作者未复测）。

现在常见的处理有三种：改解码（重复惩罚、调温度），改训练（再做一轮 RL 或 SFT），或者像 Takehi 等人那样让一个前沿 LLM agent 读权重、自己诊断、自己写补丁。agent 那一套把 MATH-500 拉到 48.1%，但一次修复要 158 轮对话、8,970 万 token、50 次前向请求、15.6 小时，约 $312（Table 4 第 10 页），而且每一步靠自然语言判断，不保证改得最好。

在工程里你会这样撞上它：部署的小模型在某类输入上「卡住刷屏」，线上表现为大量请求打满最大输出长度、延迟和成本飙升；重训代价高，改解码参数又会影响别的任务。如果能像打热补丁一样，只改权重文件里几十万个比特就把毛病修掉，且推理图完全不变，就能在不动训练流程的情况下快速止血。

## 4. 他们怎么做的

**核心思路**：agent 收集的证据——循环答案和正常答案在每层的激活差别——其实可以直接写成一个数学目标：在循环 token 上削弱「继续循环」的方向、加强「该收尾了」的方向，同时让正常 token 上的层输出尽量不变，改动的权重越少越好。再把每个权重的改法限制成离散选择，问题就变成可以批量求解的组合优化。

**第 1 步，状态树与可行改动**（第 4–5 页）：BF16（一种 16 位浮点格式：1 位符号、8 位指数、7 位尾数）权重按每 64 个一组，组内共享最大指数，每个权重只存 4 位「相对指数」和自己的符号、尾数。允许的改动只有乘以 {−1, 2, 1/2, 4, −2, −4, −1/2, 1/4}，且不能改组内最大值。这样每个改动只动符号位和 4 位状态，共享指数和尾数一个都不碰，这是构造上保证的。

**第 2 步，选层**（第 5–6 页）：基座模型先把练习题各答一遍（8,192 token 上限），按尾部 8-gram 重复率分出「循环」和「正确收尾」答案；再用教师强制前向（把已有文本喂进去只记录激活，不生成）记录每层残差和 MLP 输出。由此算出「循环方向」和「收尾方向」，给每层 MLP 打分，取最高的两层并排除最后一层。0.8B 上选出第 15、19 层，恰好等于 agent 的选择；但「排除最后一层」这条规则是看完分数后才定的（第 5 页）。

**第 3 步，目标**（第 6 页）：目标 = γ×剂量 + 附带损伤 + λ×改动个数。剂量是改动后层输出沿目标方向在循环 token 上的变化，附带损伤是正常 token 上层输出的变化（剪枝量化里的重建误差）。0.8B 上目标剂量设为 agent 修法的 1.6 倍，所以和 agent 并不是剂量对齐的比较。

**第 4–5 步，拆成伊辛问题并求解**（第 7 页）：每层只保留得分最高的 K=512 列，每个候选权重预选一个最优改法，剩下只需决定「用不用」，于是每一行就是一个 512 变量的 QUBO（二次无约束二值优化，等价于物理里的伊辛模型）。两层一共 2,048 个小问题，GPU 上用模拟退火（随机翻转、逐步降温找低能量解）一次批量解完；也可换成模拟分岔（一种受量子启发的求解器）。外层用二分法调 γ 达到目标剂量，超预算就把 λ 翻倍。

**如果让你复现**，流程骨架是：

```python
loops, goods = classify(base.generate(practice, cap=8192))   # 尾部 8-gram 重复 >80% 记为循环
stats = teacher_forced_stats(base, loops, goods)             # 每层残差、MLP 输出、down_proj 输入
u = dir(stats, R, P) - 0.5 * dir(stats, Z, M)                # 循环方向减去一半收尾方向
layers = top2(write_score(stats, u), exclude_last=True)       # 0.8B/2B 都选出 15、19
for L in layers:
    cols = topK_columns(L, u, K=512); moves = preselect(L, cols)  # 每权重只留一个 2 的幂/变号改法
    gamma, lam = calibrate(target_dose, budget=65536)         # 外层二分 γ、翻倍 λ
    x = anneal(row_qubos(L, cols, moves, gamma, lam))         # 每行一个 512 变量伊辛问题，GPU 批量解
    apply_inplace(L, moves, x)                                # 只改符号位和 4 位状态
```

## 5. 证据怎么看、别被什么忽悠

**表一：Table 3（第 9 页），和 agent 修法的正面比较。** 想证明：同一模型、同两层、同一评测框架下，Tree-Ising 修得更好。怎么测：vLLM 思考模式，温度 0.6，最多 32,768 新 token，Math-Verify 判分，五个数学基准；两份检查点用相同随机种子，逐题配对检验。结果：MATH-500@4（每题 4 次采样取平均）54.6% vs 51.7%（Qwen3.5-0.8B、同两层、每题 4 次采样，单种子；作者自述 MATH-500 结果含开发时见过的题），配对差 +2.9±1.0，p≈0.003；GSM8K 70.5 vs 65.6；五个基准全部领先，但经 Bonferroni 校正（多重比较时把显著性门槛除以比较次数）后只有 MATH-500@4 和 GSM8K 显著。基座 7.9% 是 Takehi 等人报告的数，作者没在自己框架下重跑（第 15 页）。agent 修法原报 48.1%，在作者框架下是 51.7%，与独立复现的 51.0% 接近（第 8 页）。说明：提升主要来自更少截断——MATH-500 截断率 31.6%→23.9%。

**补充：第 8 页的「开发期没见过的 400 题」。** 由于早期变体在 MATH-500 固定 100 题上筛过，作者单独报了剩下 400 题：53.8% vs 50.8%，配对差 +2.9±1.1，p≈0.009。这能部分缓解泄露担忧，但仍是单种子。

**表二：Table 1 / Table 4（第 3、10 页），成本。** 一次应用 31 分钟、约 $0.90，对比 agent 的 $312，「约 350 倍便宜」。但 $0.90 是一次应用成本，对比的 $312 是 agent 的发现运行，口径不同：配方是作者看完 agent 公开日志后才设计的，0.8B 上还复用了 agent 的层和剂量；双方都不含方法开发成本（第 9–10 页）。

**表三：Table 6（第 11 页）与 Figure 4 / Table 7（第 12–13 页），消融和迁移。** 消融在 128 道留出练习题上做，每题一次，标准误约 4.4 点：去掉收尾方向（β=0）准确率掉到 43.8%、截断 53.1%，是最大的影响；稠密闭式解（类似 ROME 的秩一更新）57.8% 也一样好，但改了 96% 的权重。迁移到 Qwen3.5-2B：贪心解码、8,192 上限下 GSM8K 21.6%→69.4%，截断 77.9%→26.7%，但也把基座原本做对的 285 题中的 38 题改错了。

**水分检查**：①种子：每个基准单一生成种子，求解器只跑一次，p 值是名义值（第 15 页）。②基线：agent 修法是公开检查点、同框架复测，算公平；但剂量是 agent 的 1.6 倍，没做剂量对齐的版本。③泄露：MATH-500 头条含开发期见过的题。④事后设计：选层规则、剂量都是看过 agent 日志和 0.8B 分数后定的；2B 的贪心解码和 GSM8K 是在 200 题探针上挑了基座最差的设置（第 13 页）。⑤范围：只测数学、只测一族混合注意力模型，没测指令遵循和通用能力，副作用除了附带损伤项外没量化。⑥量子部分只有 8 个变量，作者明说不代表量子优势（第 13 页）。

## 6. 可信度与核验限定

**主张对照**：①「比 agent 修得更准」：Table 3 支持，但单种子、含开发期题目；400 道未见题上差距一致。②「改动更少更小」：Table 5（第 10 页）支持，改动权重 112,630 vs 130,188、BF16 比特翻转少 2.2 倍，共享指数和尾数零改动是构造保证，可信。③「约 350 倍便宜」：口径不同，不能直接当同口径对比。④「不靠 agent 也能迁移」：Table 7 支持，但只测贪心 GSM8K 一项。

**核验限定**（原样合入核验报告）：
- 54.6% vs 51.7% 是 Qwen3.5-0.8B、同两层、每题 4 次采样，单种子；作者自述 MATH-500 结果含开发时见过的题（Table 1 p3；p8；p15）
- $0.90 是一次应用成本，对比的 $312 是 agent 的发现运行，口径不同（Table 1 p3）

**打折提醒**：对外不要说「比 agent 便宜 350 倍」，要说「一次应用约 $0.90，agent 发现过程约 $312，口径不同」；引用 54.6% 要带「单种子、含开发期见过的题」，可以同时给 400 道未见题上 53.8% vs 50.8% 作为补充。

## 7. 你可以怎么落地

**今天就能试**：给你线上或评测中的推理模型加一个「循环截断率」监控：统计打满最大输出长度的回答占比，以及其中尾部 8-gram 重复率超过 80% 的比例（这正是论文判定循环的规则，第 5 页）。不需要新数据。验收：如果截断率明显（比如论文里 2B 模型贪心下 77.9%），而截断以外的回答正确率很高（2B 是 97.9%，第 12 页），说明模型「会做但停不下来」，属于这类补丁能针对的毛病；否则先别往权重编辑方向走。

**要有数据或机器再试**：一张 A100 40G 就够——2B 全流程 26 分钟（第 12 页）。前提是有几百道带标准答案的练习题（论文用 384 道），能跑出足够多的循环和正确样本。分阶段：先只做第 2 步的前向扫描，看你的模型是否也有两三层分数明显突出；再等代码仓库稳定、确认许可后，在一个小模型上复刻 0.8B 设置，加 3 个种子；最后补测指令遵循和通用基准，看副作用。

**暂时别碰**：别把它当成通用的模型修复工具上线——只验证过一种毛病、一族模型、数学题，2B 上还改错了 38 道原本对的题（第 12 页），通用能力副作用没测。也别为了量子求解器投入：8 变量的硬件演示不代表任何速度或质量优势，GPU 退火和闭式解已经同样好（第 13 页）。

## 8. 和你已有知识的挂钩

它像给二进制程序打热补丁：不重新编译（不训练），只改可执行文件里少数字节，运行方式不变。也像激活引导（steering）——用「循环 vs 正常」的激活差找方向——只是不在推理时加向量，而是一次性写进权重。和最接近的 ROME 式秩一编辑相比，最大区别是只做存储格式原生的离散改动（变号、乘除 2 的幂），不碰尾数和共享指数，所以补丁极小、可精确还原；代价是要解组合优化。

## 9. 存疑与代价

**局限**：作者承认只测一种毛病、一族模型、数学基准；基座 7.9% 未复测；单种子、名义 p 值；配方事后设计、剂量没对齐；目标是忽略层间影响的一阶替代；比特计数未含逃逸值，压缩检查点直接打补丁还没实现（第 15 页）。我另外读出：Takehi 等人报告 agent 修法把 IFEval 从 21.0% 提到 62.3%，本文没测 IFEval，所以「全面优于 agent」只限数学。**复现条件**：用公开的 Qwen3.5 权重和 agent 公开的练习题与日志；代码仓库已公开但未声明许可。**成本**：单卡 A100，0.8B 约 31 分钟，2B 约 26 分钟；按 $1.76/小时计价（第 10 页）。**出处**：预印本，未同行评审；第一单位是一家公司（QDeep），对比对象是一篇博客而非论文。

**论文没回答、但决定你要不要动手的 3 个问题**：换多个随机种子后，+2.9 点的优势还在吗？非数学任务（指令遵循、对话、代码）会不会被这次修补拖累？换一个没有「每 4 层一个全注意力」结构的模型，前向扫描还能选对层吗？
