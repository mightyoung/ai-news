## 1. 一句话先懂它

训练一个「包工头」模型，让它学会为每道题临时搭一支多智能体小队（谁负责什么、怎么交接），干活的模型本身不动。训练时先给包工头一些提示卡片当拐杖，再用对照实验判断每张卡片什么时候已经没用、可以撤掉，同时让另一个模型专挑「撤掉拐杖后还学得动」的题来练。最后包工头不看任何卡片也能搭出好队伍。

## 2. 值不值得读：五个 C 速览

**类型**：新方法，带理论命题。**上下文**：接着三条线：学会编排的工作（AFlow、AgentFlow、FlowSteer）、自博弈出题（R-Zero、Absolute Zero、SESA）、训练时撤掉提示的技能内化（SKILL0、PATS）（p2–p3）。**关键假设**：每个数据集有人工写好的初始技能卡（作者在局限里承认，p9）；干活的 Worker 模型冻结；结果能被自动判对错。**贡献**：①「递归可学性」：出题者的奖励按「藏起某张卡后，这题的几次尝试是否仍有对有错」来算；②「技能撤回」：在同一组尝试里随机藏卡，做成对照实验，用后验判断何时撤卡；③12 个基准全面领先的实验。**清晰度**：概念多、符号重，正文压缩得很紧，关键超参和公平性说明在附录 B–D（p19–p21）。**建议**：做 Agent 训练或 GRPO 课程设计的值得自己读第 4–5 节和附录 D；只想知道结论的看到本文第 5 节即可。

## 3. 它在解决什么麻烦

现在训练「编排器」（负责决定派哪些 Agent、各自角色、怎么交接的上层模型）通常有三个毛病，作者在图 2（p2）里画得很清楚。

第一，题库是人提前收集好的，固定不变。模型很快就把会做的题做烂，不会做的题一直不会，训练信号越来越少。

第二，优势坍缩。GRPO（组相对策略优化：同一道题跑几次，用「这次比组内平均好多少」当奖励信号的强化学习方法）只能从同一组里有对有错的尝试中学习。一组全对或全错，信号就是零。更麻烦的是，自博弈出题时如果提示卡还在，出的题刚好卡在「有卡能做」的边界上；一撤卡，这些题马上变成全错，信号又没了。

第三，判断某张提示卡还有没有用，常用的是「成功率超过阈值就撤」。但成功率同时受「题目难度」和「卡片作用」影响，出题者一调课程，成功率就变了，阈值判断就不可靠。

在你熟悉的场景里：你给一个 Agent 系统写了一长串系统提示规则（「先检索再回答」「代码要写测试」），越堆越长，没人敢删，因为不知道哪条还在起作用；或者你用 GRPO 训练模型，发现大量批次全对或全错，GPU 在空转。如果这套方法成立，好处是提示规则可以有依据地删、训练算力花在「真能学到东西」的题上，部署时不再依赖长提示。

## 4. 他们怎么做的

**核心思路**：两个循环嵌套。内循环是自博弈（一个模型出题、另一个模型解题，互相推动）：出题者（Proposer）挑题，编排者（Director）搭队伍解题。外循环负责「改进内循环的改进方式」：逐步撤掉 Director 的提示卡。两个循环共用同一组尝试，不额外花算力（图 3，p4）。

**Director 的接口**：输入题目和当前可见的技能卡，输出一串原子编辑动作（加 Agent、设提示词、选模型、设层级、建关系、删 Agent、指定输出者、结束），从空图一步步搭出一张「Agent 图」，交给冻结的 Worker 执行，验证器给出 0/1 对错（定义 1–2，p3）。实验里 Director、Proposer、Worker 都基于 Qwen3.5-9B，Director 和 Proposer 用 LoRA rank 64 训练（表 4，p20）。

**一组尝试怎么用两次**：每道题跑 5 次，其中随机 3 次藏起一张「待测卡」，2 次可见（表 4，p20）。
- 给出题者算奖励（递归可学性）：只看藏卡那 3 次的成功率 p，奖励按 4p(1−p) 算，也就是 p 在一半附近最高、全对或全错为零；全组结果一致时还要扣分。直观理解：专挑「没有这张卡也还在学」的题，因为卡迟早要撤（式 8–9，p5）。
- 给撤卡决策提供证据（技能撤回）：可见组成功率减去藏卡组成功率，就是这张卡在这道题上的作用估计。因为藏谁是随机的，这是一个无偏估计（命题 3，p5）。证据在最近 30 轮里累积，用贝叶斯自助法得到「这张卡还有多大好处」的后验；至少 12 条记录、且预期好处不超过 0.02 时就撤卡（式 14，p5；表 4，p20）。另有 30% 的题会重测已撤的卡，发现撤错可以恢复（p19）。
- 两组都失败的题，由一个大模型编辑器提炼成新卡，试用期内要通过准入检验（附录 C，p19）。

Director 用 GRPO 风格的组内相对优势更新；Proposer 每次从 8 道候选题里挑两道做成对比较更新（附录 B，p19）。

**如果让你复现**：

```
for cycle in range(200):
    for batch in sample_batches():                 # 每批 8 道候选题
        for x in proposer.pick_two(batch):
            K = retrieve(x); k = thompson(K)
            hide = random.sample(range(5), 3)        # 3 次藏卡
            ys = [run(director(x, K, k, i in hide)) for i in range(5)]
            ledger[k].append(mean(ys, ~hide) - mean(ys, hide))  # 卡片作用
            reward[x] = learnability(ys, hide)      # 4p(1-p)
    director.grpo(); proposer.pairwise()
    withdraw(ledger, eps=0.02, nmin=12); distill()
```

## 5. 证据怎么看、别被什么忽悠

**表 1（p6）：主结果**。想证明：零技能测试下全面胜过各类基线。测法：6 个分布内基准（HotpotQA、NQ-Open、MedQA、AIME 2026、MBPP+、ALFWorld）和 6 个只测不训的分布外基准（TriviaQA、MuSiQue、GPQA、MATH-Hard、SWE-Bench、WebShop）；对比 11 个基线，包括直接提示、SFT/GRPO 微调、工作流搜索、强化学习编排、技能内化、自博弈；所有方法共享冻结 Worker、训练任务和算力预算；五次运行均值±标准差（表 1 注，p6）。结果：分布内平均准确率 89.79，次优 PATS 86.00；分布外 78.79 对 76.13；直接提示 Qwen3.5-9B 分别只有 61.35 和 49.84。AIME 2026 为 81.33±2.98，PATS 74.00±3.65；WebShop 91.09，PATS 87.97。说明：「编排」本身是主要增益来源（单纯 SFT/GRPO 微调几乎没帮助，GRPO 在 AIME 上还从 48.67 掉到 34.00），R²Orch 在最强基线之上再领先 3–4 个点。

**表 2（p7）：消融**。想证明：两个循环都不可少。去掉整套递归自博弈（只用 GRPO）时 WebShop 从 91.09 掉到 71.72、AIME 掉到 59.33；固定不撤卡时 WebShop 只有 76.09；把撤卡规则换成成功率阈值（PATS 式）、预设预算或验证差距，都落后完整版。说明：增益在多步交互任务上最依赖这两个设计。

**图 5（p8）：出题和撤卡是否按设计工作**。成功率居中的题，新一组尝试出现「有对有错」的频率约是 p=0 或 p=1 时的四倍（图 5e）；12 次撤卡都满足式 14，后验预期好处最多 0.019（p8）；R²Orch 每个有效组只需 14.1 次尝试，是各种出题目标里最少的（图 5c）。

**水分检查**：①测试集小：每个只有 128 题，AIME 只有 30 题，一题分别相当于约 0.78 和 3.3 个点；不少列的领先在 1–3 个点，接近一两道题的差距。②五次运行是重新训练五次还是同一模型测五次，论文未说明，标准差可能低估了训练波动。③基线全部由作者在统一协议下复跑，「各取最佳配置」由作者把握，不是官方榜单。④SWE-Bench 也是抽样 128 题，不能直接和公开榜单比。⑤全部是仿真或自动判分环境，没有真实业务部署。⑥初始技能卡是作者按数据集手写的，换领域时这一步成本未计入。⑦迁移到其他 6 个 Worker 模型也都有提升，分布内跨模型差距从 25.7 缩到 6.4 个点（p6、图 4e），这一点比较有说服力。

## 7. 你可以怎么落地

**今天就能试**：把「随机藏卡做对照」用到你自己的 Agent 系统提示上。挑一条你怀疑没用的提示规则，在现有评测集上每道题跑 5 次，随机 3 次去掉这条规则、2 次保留，记录两组成功率之差；攒够 12 道题以上再看平均差值。不需要训练，只要 API 和评测脚本。验收：差值的均值和区间都贴近 0（论文用的容忍度是 0.02），且提示变短、成本下降，就可以删；如果差值明显为正，说明这条规则仍在起作用。同一套数据还能顺手统计「全对或全错」的题占多少，评估你的 GRPO 训练有多少算力在空转。

**要有数据或机器再试**：复现官方训练。前提：A100 级 GPU，作者报告 200 轮约 106 个 A100 小时（p21）；需要能自动判对错的任务池和每个数据集的初始技能卡。分阶段：先只在一个分布内数据集上跑 50 轮，看零技能准确率是否超过带技能准确率；再加分布外测试，并把测试集扩到远大于 128 题，确认领先不是抽样噪声。注意代码只限研究使用。

**暂时别碰**：别把它直接用到生产 Agent 的在线自我改进上。论文全部在仿真和自动判分环境里测，撤卡、生成新卡都由模型自动完成，作者也建议在沙箱运行（p9）；代码没有开源许可，商用要先确认授权。

## 8. 和你已有知识的挂钩

技能撤回很像线上 A/B 实验加灰度下线：同一批流量随机分组，一组关掉功能开关，看指标差多少，差不多就下线，并保留回滚（重测已撤卡）。递归可学性像强化学习里的课程学习加奖励塑形：专挑「成功率在一半附近」的题。和最接近的 PATS（按成功率阈值撤提示）相比，最大区别是 R²Orch 用组内随机对照直接测卡片自身作用，排除了题目难度变化的干扰。

## 9. 存疑与代价

**局限**：作者承认初始技能卡要按数据集人工定制，新领域如何自动生成仍是开放问题（p9）。读出来的还有：测试集小；只在 9B 级 Worker 上训练；理论命题依赖小步更新等假设。**复现条件**：代码公开但无许可证，README 写「research use」；训练池与规模随代码发布（p20）；未见训练好的 Director 权重。**成本**：200 轮约 106 个 A100 小时，每轮 24 道题、每题 5 次尝试（p20–p21），对实验室友好，但每次尝试都要真的执行一张多 Agent 图，推理调用量不小，论文未单独报告。**出处**：预印本 v2，未同行评审。

**三个决定你要不要动手的问题**：
1. 测试集扩到上千题后，领先还有几个点？
2. 换成更强或闭源的 Worker（推理费更贵）时，一次训练的调用成本是多少？
3. 没有现成判分器的开放任务（写报告、客服），对照实验的「对错」怎么定义？
