## 1. 一句话先懂它

现在的机器人大模型大多是从「看图说话」的模型改来的，对远近、深浅这类三维信息天生不敏感。SLA 在继续训练时，让模型内部的视觉特征去模仿一个现成三维感知模型的特征，部署时不加任何新部件，仿真和真机抓放都更稳。

## 2. 值不值得读：五个 C 速览

**类型**：新方法（训练配方）加大规模数据整理。**上下文**：直接接着同组的 Spatial Forcing（只在下游微调阶段做三维特征对齐），基座是 π0.5，三维教师用 OmniVGGT。**关键假设**：一是三维教师的特征确实含有对操作有用的几何信息；二是把对齐从「下游微调」前移到「持续预训练」能让空间能力变成可迁移的底座能力；三是去掉评测集数据后不存在泄漏（第 9 页作者声明已排除）。**贡献**：一是在 1.7M 条轨迹的异构语料上做带三维对齐的持续预训练；二是自适应层选择门控与状态随机丢弃两个训练技巧；三是覆盖 4 个基准和 8 个真机条件的评测。**清晰度**：主表与消融清楚；语法小错较多；不少关键实现细节在代码仓库而非论文。建议**看到第 5 节**；做 VLA 微调的人值得读 §3.2 与 §4.4 的消融。

## 3. 它在解决什么麻烦

VLA（Vision-Language-Action，视觉-语言-动作模型，看图听指令直接输出机械臂动作）的视觉部分，一般继承自在二维图文对上预训练的大模型。它认得出「这是杯子」，但对「杯子离夹爪还有几厘米」不一定有好的内部表示。作者用深度探针（冻结模型，只训一个小头去从视觉特征还原深度图）验证：未对齐的特征几乎还原不出有意义的深度结构（图 2，第 6 页）。

常见补法是给模型额外喂深度图或点云。但这有三个工程麻烦：深度相机数据噪声大、缺失多；各家机器人传感器型号、位置、标定状态各不相同；大量公开机器人数据集根本没有深度。你在什么时候会撞上？比如你拿 π0.5 微调一个桌面抓取任务，训练场景里很稳，桌子高度一变、物体被人挪了一下，成功率就掉；想加深度输入，又发现采集的数据一半没有深度，部署端也不想多挂一个点云编码器。

SLA 的回答是：只在训练时借用一个冻结的三维「老师」，让 VLA 中间层的视觉 token 向老师的特征看齐；推理时老师、投影头、门控全部丢掉，模型结构和原来的 π0.5 一模一样，也不需要深度或标定输入（第 7 页）。如果这条路成立，带来的不同是：空间理解可以像语言能力一样在预训练阶段「装进底座」，下游只要少量示教就能用。

## 4. 他们怎么做的

**核心思路**：动作 token 是以视觉 token 为条件生成的，所以视觉 token 里空间信息越丰富，动作越可能精确。与其改结构，不如在训练时加一个辅助损失，让视觉 token 的表示「长得像」三维模型的表示。

**部件一：三维教师（第 7–8 页）。** 用 OmniVGGT（在 VGGT 基础上能吃可选相机内外参和深度的三维感知模型）。它的好处是数据里有标定、有深度就用上，没有就只看 RGB，正好适配异构语料。取其最后一层特征，加位置编码，双线性重采样到 VLA 视觉 token 的分辨率，得到每个 token 的目标向量。

**部件二：对齐损失（第 7 页）。** VLA 每层的视觉 token 先过 LayerNorm 和两层 MLP 投影；用余弦相似度让投影结果靠近教师目标，损失为「1 减余弦相似度」的平均。总损失 = 动作损失 + α × 对齐损失。教师冻结，梯度只更新 VLA、投影头和门控。

**部件三：自适应层选择（第 8 页）。** 不手选对齐哪一层，而是对每层、每个 token、每个通道学一个 sigmoid 门控，按门控加权把 18 层（PaliGemma 语言骨干）的投影特征相加，再拿去对齐。

**部件四：状态丢弃（第 8 页）。** 每个训练样本以一定概率把整段机器人本体状态 token 去掉，逼模型看图而不是死记「某个关节状态对应某段轨迹」。推理时不丢。

**数据（表 1，第 9 页）。** 六个来源（InternData-A1、AgiBotWorld-Beta、RoboCasa365、RoboCOIN、DROID、MolmoAct）共约 1,713.9K 条、14,330 小时（处理前统计）。统一成以机械臂基座为原点的末端执行器（EEF，夹爪末端）坐标系，动作用块内相对当前位姿的增量，旋转用旋转向量；对重复度高的仿真数据按任务下采样（如 InternData-A1 部分任务只留 3%）；过滤灵巧手、移动底盘和静止帧。

**训练规模（第 11 页）。** 持续预训练 36k 步，有效全局 batch 4,608，48 张 H100 约 110 小时；下游后训练 2–6 万步不等。

**如果让你复现**（以下游微调加对齐为例）：

```python
teacher = OmniVGGT.frozen()                          # 冻结三维教师，只在训练时用
for batch in loader:
    if rand() < 0.25: batch.drop_state_tokens()      # 状态丢弃，表 8 中 25% 最好
    out = pi05(batch.images, batch.text, batch.state, return_visual_tokens=True)
    y = resample(teacher(batch.images, batch.calib_or_none)) + pos_emb  # 教师目标
    z = sum(gate(l, out.vis[l]) * mlp(ln(out.vis[l])) for l in layers)  # 门控跨层融合
    loss = out.action_loss + alpha * (1 - cos(z, y)).mean()
    loss.backward(); opt.step()
# 推理：丢掉 teacher、mlp、gate，模型与原 π0.5 相同
```

论文未说明：α 的具体取值、各数据源的最终混合比例（只给了下采样示例）。这些可能在代码配置里。

## 5. 证据怎么看、别被什么忽悠

**表一：Table 2 与 Table 3（第 12 页），仿真基准。** 想证明比基座和同类方法强。LIBERO-Plus：在标准 LIBERO 上训练，在 7 类扰动（相机、机器人、语言、光照、背景、噪声、布局）下测 10,030 次，按回合数加权。SLA 87.4%，π0.5 84.4%，Spatial Forcing 85.1%。RoboTwin 2.0：50 个双臂任务，每任务 50 条干净示教联合训练，每任务每设置测 100 次；SLA Clean2Clean 86.0、Clean2Random（测试时加域随机化）72.3、平均 79.2；π0.5 是 70.7 / 46.0 / 58.3。说明：最大的提升在 Clean2Random（+26.3），也就是训练干净、测试有干扰时。但 LIBERO-Plus 上 +3.0 的幅度并不大，且「机器人」扰动维度上 SLA 73.8 低于 Spatial Forcing 的 79.3。

**表二：Table 6（第 14 页），数据规模与两阶段对齐。** 想证明「预训练阶段也做对齐」是关键。RoboTwin Clean2Random，持续预训练数据取 5%/25%/50%/100%。两阶段都对齐：49.2→72.3；都不对齐：43.8→48.2。全量数据下只在预训练对齐 63.2，只在后训练对齐 57.1。说明：光加数据收益很小，加对齐后数据规模才「吃得进去」，这是全文最有说服力的一张表。

**表三：Table 11（第 19 页），真机。** 想证明能落到实物。8 个作者自建条件 A–H（Piper 双臂与 Franka 单臂，RealSense D435 相机），每方法每条件 50 个物体实例，A–C 共用一个用 100 条 A 场景示教训的策略，D 额外加 10 条 Franka 示教。平均：SLA 83.8%，Spatial Forcing 68.0%，π0.5 59.8%，SpatialVLA 53.5%，OpenVLA-OFT 46.0%。说明：在被人扔走、被人移动、换桌高、桌子移动等条件下优势明显。

**水分检查**：①仿真主表没有误差条，RoboTwin 每任务 100 次，多数只报单一训练种子（RoboCasa 是三个评测种子）。②消融（表 7–10）都只在 RoboTwin 上做；表 10 用的是「自采的 RoboTwin 干净数据」，绝对数值与主表不可比。③状态丢弃的结果很不单调：0% 平均 38.1，25% 是 79.2，50% 又掉到 53.9（表 8，第 15 页），这种剧烈波动提示单次训练噪声可能不小。④真机条件是私有自建，无法第三方复现。⑤基线是否同等调参未说明；RoboCasa 表里其他方法的示教数量各不相同（第 13 页作者已标注）。⑥另一种解释：持续预训练本身多看了 1.7M 条数据，但表 6 的「都不对齐」行部分控制了这一点。

## 6. 可信度与核验限定

**主张对照**：①「LIBERO-Plus 与 RoboTwin 2.0 上领先」：Table 2/3，仿真证据充分，但无误差条。②「两阶段对齐优于单阶段、数据越多越好」：Table 6，证据较强（同一基准、同一流程）。③「真机平均比 π0.5 高 24.0 点」：Table 11，方向可信，私有条件不可复现。④「推理时零额外开销」：由设计保证（辅助部件训练后丢弃），可信。

**核验限定**（原样合入）：
- LIBERO-Plus 加权 SR 87.4%：π0.5 84.4（+3.0）、Spatial Forcing 85.1（+2.3），仿真（Table 2 p12）
- RoboTwin 2.0：Clean2Clean 86.0 / Clean2Random 72.3 / 平均 79.2，仿真，每任务每设置 100 次（Table 3 p12）
- 真机 +24.0 点：作者自建 8 个私有条件（Piper 双臂 + Franka），平均 83.8%，每条件每方法 50 个物体实例（p4、p11）
- 代码在 OpenHelix-Team/Spatial-Forcing（MIT）

**打折提醒**：引用「SOTA」时要带具体基准与设置（RoboTwin 是 Clean2Random 设置领先，Clean2Clean 不如 ME-Dex-1.0 的 89.6）；真机 +24.0 点必须带「作者自建私有条件、每条件 50 个物体实例」。

## 7. 你可以怎么落地

**今天就能试**：如果你已经在用 openpi / π0.5 微调自己的任务，先把「状态丢弃」加进数据加载：每个样本以 25% 概率去掉整段本体状态 token，其余不变。这是改动最小、不需要三维教师的一条。验收：在你现有的评测集上对比加不加的成功率，并专门测一次「物体被挪动 / 起始位置换了」的场景；注意论文显示该超参非常敏感，至少多试 0%、25%、50% 三档。

**要有数据或机器再试**：有 1–2 张大显存 GPU 和你自己的几十到上百条示教时，可以直接用作者放出的 `SLA_base` 持续预训练权重做下游微调，并开启对齐损失（需下载 OmniVGGT 等训练组件）。分阶段验收：先在 LIBERO 或 RoboTwin 上复现作者给的一个设置，确认流程无误；再在自己的任务上与原版 π0.5 微调对比，重点看换桌高、换背景等扰动下的掉点幅度。若数据带相机标定，可把标定喂给教师（表 10 显示多 3.2 个点）。

**暂时别碰**：不要自己从头做 1.7M 条规模的持续预训练（48 张 H100、约 110 小时，且 README 的 TODO 里「Continual pre-training data」尚未勾选）；也别把真机 83.8% 当成你场景下的预期，那是作者自建条件、每任务 100 条示教的结果。

## 8. 和你已有知识的挂钩

它像知识蒸馏，但蒸的不是输出而是中间特征：让学生的中间层去「描」老师的中间层，考试时老师不在场。和最接近的 Spatial Forcing 相比，最大区别是**把三维对齐前移到大规模持续预训练**，并加了跨层门控与状态丢弃；和 PointVLA 这类方法相比，它部署时不需要任何深度或点云输入。

## 9. 存疑与代价

**局限**：作者没有专门讨论局限。我读出的有：消融全集中在 RoboTwin；状态丢弃结果剧烈波动；真机条件私有；RoboDojo-Real 用了额外的记忆机制（附录 B），与其他方法不完全同构。**复现条件**：代码 MIT，持续预训练权重与基准权重在 Hugging Face（README 指向），README 的 TODO 里「Continual pre-training corpus」已勾选、「Continual pre-training data」尚未勾选。**成本**：持续预训练约 48 张 H100 × 110 小时；下游微调 batch 64–512、2–6 万步。**出处**：港科大（广州）主导的预印本，未同行评审。

**论文没回答的 3 个问题**：多种子重复后，RoboTwin 上的增益和状态丢弃曲线还稳吗？三维教师换成更弱或更强的模型，收益怎么变？在纯真机、无仿真数据的语料上做持续预训练，效果是否一致？
