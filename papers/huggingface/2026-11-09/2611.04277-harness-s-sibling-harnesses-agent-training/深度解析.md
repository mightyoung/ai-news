## 1. 一句话先懂它

同一个模型，换一套「外壳」（提示词、工具接口、提醒规则）成绩就会变。这篇论文先给原始外壳派生出一批各擅所长的「兄弟外壳」，训练时只在原始外壳下全军覆没的题上请兄弟们帮忙找到成功做法，再用强化学习把这些做法学进模型本身——最后撤掉兄弟外壳，模型在原始外壳下照样更强。

## 2. 值不值得读：五个 C 速览

**类型**：新方法（训练流程），附行为分析。**上下文**：接着两条线——一条是自动优化 Agent 外壳的工作（Meta-Harness、GEPA、HarnessX），一条是 Agent 强化学习（GRPO、DAPO 的「全对全错组没有学习信号」问题）。**关键假设**：要有可自动判对错的任务环境（AppWorld、SWE-Gym、DBBench 都有验证器），以及一个能读失败轨迹、改外壳配置的强编辑模型（附录用 GLM-5.3）；在可验证的工具类任务上站得住，开放域任务未知。**贡献**：一是指出外壳改动有「局部性、互补性、非平稳性」三个现象；二是把外壳进化结果当成训练时的「救援池」，只救全失败的题；三是在原始外壳下评测，证明收益留在模型里。**清晰度**：正文紧凑、图表清楚，但外壳池怎么生成、救援怎么分配等关键细节在附录 C、F、G。建议**看到第 5 节**；正在做 Agent RL 的人值得读原文 §3.3、§4.3 和附录 G。

## 3. 它在解决什么麻烦

做 Agent 的人都知道，「harness」（外壳：包在模型外面的那层执行系统，包括系统提示词、工具怎么展示、上下文和记忆怎么管、执行中插入什么提醒）对成绩影响很大。现在常见两种做法：要么人工或自动不断改外壳，想找一个「最好的外壳」；要么让外壳和模型交替进化。

论文在 AppWorld 上观察到三个麻烦（Figure 1，p2）。第一，每次改外壳往往修好一批题、又弄坏另一批，叫局部性；第二，不同的兄弟外壳能互相补位，合在一起覆盖的题比单个外壳多；第三，模型一边训练，哪个外壳好用的排名会翻转，叫非平稳性。所以「把所有修补叠成一个万能外壳」很难，交替进化又贵，而且进化出来的模型换回原外壳可能就不灵了。

在你熟悉的场景里：你给客服 Agent 加了一条「先查接口文档再调用」的提醒，A 类工单变好了，B 类工单却因为多走一步超出步数上限。又或者你用 GRPO（组相对策略优化：同一道题采样多条轨迹，按组内谁好谁差算奖励优势）训练 Agent，难题 8 次全失败，整组奖励一样，等于没有学习信号，训练只能在会做的题上打转。

如果这篇的方法成立，好处是：外壳的花样只在训练时用，上线还是那套简单的原始外壳，部署不用维护一堆外壳版本。

## 4. 他们怎么做的

**核心思路**：不追求一个万能外壳，而是保留一池各有专长的兄弟外壳；训练时只在原始外壳 H0 下整组失败的题上，让同一个模型换外壳再试，把试成功的轨迹拿来做强化学习。因为轨迹是模型自己生成的（只是外壳给了提示），学到的行为有机会在撤掉外壳后保留下来。

**第一步：定向外壳进化（离线，训练前做完）**。从 H0 出发，让模型在训练题上跑，编辑模型（附录 Table 8 为 GLM-5.3）把失败轨迹按根因分组，每个子外壳只针对 2–3 个相关根因修改，可改的部件包括提示词、技能、上下文、记忆、钩子（hooks：在某个事件后自动插入一条提醒）和工具视图（p20–21）。下一轮父代按「合起来能覆盖最多验证题」挑选，最多 4 个；所有能跑通、符合协议的子外壳都留进池子。AppWorld 跑了 3 轮，最终池子是 H0 加 19 个辅助外壳（p18）。附录 Table 7（p19）给了例子：一个外壳在工具返回分页信息后提醒「继续翻页直到没有更多」，一个要求多条件筛选时取交集，一个在步数快用完时提醒「留一步提交答案」。

**第二步：互补救援训练**。每道题先在 H0 下采样 8 条轨迹（G=K=8，p17）。只要有一条成功，就照常用这组做 GRPO；如果 8 条全失败，就由路由器选出 8 个辅助外壳，同一个模型在每个外壳下从头各试一次，这组「救援轨迹」替换掉原来的失败组（式 5，p5）。算损失时只计模型自己生成的 token，外壳注入的提示和工具返回不计入；裁剪范围 0.20/0.28，不加参考模型 KL 项（p17）。

**第三步：自适应外壳路由器**。每个外壳有一份「行为档案」：在什么任务条件下，它比 H0 更好或更差，由 LLM 对比成对的验证轨迹总结而成。多个 LLM 各自对候选外壳排前 4 名，按 1、3/4、1/2、1/4 加权投票取 Top-k（p18）。随着模型变强，每训练 10 步用当前模型重跑验证集刷新档案，叫「重新锚定」。

**第四步（可选）推理时路由**：训练好的模型也可以让路由器给每道题挑 Rank-1 外壳，不增加执行次数。

**如果让你复现**，最小骨架如下：

```python
pool = evolve_harnesses(H0, train_tasks, editor_llm)   # 离线进化，训练中固定不变
profiles = build_profiles(policy, pool, val_tasks)      # 每个外壳的“何时有用/有害”档案
for step, batch in enumerate(train_batches):
    if step % 10 == 0: profiles = build_profiles(policy, pool, val_tasks)  # 重新锚定
    groups = []
    for x in batch:
        g = [rollout(policy, x, H0) for _ in range(8)]
        if all(r.reward == 0 for r in g):               # 整组失败才救援
            hs = router_topk(x, profiles, k=8)          # 多个 LLM 投票选外壳
            g = [rollout(policy, x, h) for h in hs]     # 同一模型，每个外壳试一次
        groups.append(g)
    grpo_update(policy, groups, loss_on="policy_tokens_only")
```

## 5. 证据怎么看、别被什么忽悠

**表一：Table 1（第 7 页），主结果。** 想证明：训练后的模型在原始外壳 H0 下就比只用 GRPO 训练强。怎么测：Qwen3.5-4B 和 9B，三个任务；Pass@3 指每题试 3 次至少成功一次的比例，Avg@3 是 3 次的平均成功率；3 次独立运行取均值。基线包括普通 GRPO、在 H0 下重采样救援的 GRPO、固定混合外壳的 GRPO、冻结模型只改外壳的 Meta-Harness，以及交替进化的 WHALE、HarnessForge。结果：4B 在 H0 下 Pass@3，AppWorld 67.56±1.87 对 GRPO 60.31，SWE-Gym 38.75±2.22 对 24.38，DBBench 73.33±2.36 对 66.67；对「H0 重采样救援」也全面领先（4B AppWorld 61.83）。说明：收益不只是「多采样了几次」。

**图一：Figure 3（第 8 页），学习信号。** 想证明：救援让更多组既有成功又有失败，从而给 GRPO 提供可学的对比。只在 AppWorld 4B 上测。全程有效组比例 Harness-S 79.38%，H0 救援 70.94%，普通 GRPO 64.69%；验证集最终成功率 63.33% 对 54.00% 对 48.00%（p8）。两种固定混合外壳反而低于普通 GRPO，说明「有方向地救」比「一直混着用」有效。

**表二：Table 5（第 10 页），收益是否留在模型里。** 训练前，路由器选的 Rank-1 外壳比 H0 高 14.21 个点（Pass@3）；训练后差距缩到 0.76 个点（p11），H0 被路由器排第一的比例从 1.53% 升到 22.52%。这支持「外壳带来的行为被模型内化了」。Table 3（p9）的行为统计也佐证：AppWorld 上「首次调用前先查接口说明」从 GRPO 的 38.2% 升到 67.6%。

**水分检查**：①只有 3 次运行，且只给了 Harness-S 的标准差，基线没给，SWE-Gym 测试集只有 160 题，小差距要谨慎。②机制分析（Figure 3、Table 2、3、5）基本只做了 AppWorld 4B。③训练成本不对等：Harness-S 比普通 GRPO 多 18.44% 的训练 rollout、GPU 时 67.19 对 50.58（Table 9，p21），还要另算外壳进化的 4,010 次搜索 rollout 和 18.69M API token（Table 10）。④跨外壳迁移（Figure 4，p11）中 Harness-S 在 Claude Code、OpenClaw 下仍低于它在原始外壳下的成绩，作者自己承认外壳依赖没有消失。⑤Table 1 的前沿模型参照只是在 H0 下跑的参考，不是同条件对比。⑥全部是仿真环境，不涉及真实用户。

## 6. 可信度与核验限定

**主张对照**：①「H0 下优于纯策略训练」：Table 1，三任务两尺寸全覆盖，证据较充分。②「优于额外采样」：与 GRPO（H0 rescue）对照，证据较充分，但该对照多用了 41.25% 的 rollout（Table 9），算力并不对等。③「行为迁移到模型本身」：Table 3–5 与两个案例，仅 AppWorld 4B，属支持性证据。④「跨外壳泛化」：Figure 4，仅两个外部外壳、单尺寸。

**核验限定**（原样合入）：
- Qwen3.5-4B 在原始 harness H0 下，Pass@3：AppWorld 67.56±1.87 vs GRPO 60.31，SWE-Gym 38.75±2.22 vs 24.38，DBBench 73.33±2.36 vs 66.67；3 次独立运行、每题 3 次 rollout，基线未给标准差（Table 1 p7）
- 代码 DeepExperience/Harness-S 公开（Apache-2.0）

## 7. 你可以怎么落地

**今天就能试**：在你现有的 Agent RL 或批量评测日志里加一个监控指标——「整组全失败的题占比」（同一题 K 次采样全为 0 分的比例），以及「有效组比例」（同组既有成功又有失败）。验收：如果全失败组占比很高、有效组比例在 65% 上下徘徊，说明你撞上了论文说的信号荒；再挑 20 道全失败题，手工给外壳加一条有针对性的提醒（例如「分页要翻到底」「多条件取交集」「步数快用完时先提交」），看同一模型能救回几道。能救回一批，就说明值得做救援。

**要有数据或机器再试**：需要可自动判分的环境、几百道训练题、一套 GRPO 训练框架和大约 8 张 H800 级别的卡（论文全部实验用 8 张 H800）。分三阶段：先用强模型编辑出 5–10 个兄弟外壳，测各自修好和弄坏的题，确认存在互补；再只实现「全失败才救援」，路由先用简单规则（按相似验证题成功率排序，Table 2 中这一版也有 66.41 的 Pass@3）；最后才上 LLM 投票和档案刷新。验收：原始外壳下的 Pass@3 和 Avg@3 是否稳定高于同步数普通 GRPO，多跑几个种子。

**暂时别碰**：不要一上来就复刻完整的多 LLM 投票路由加档案重锚，这部分依赖外部大模型 API、成本高、细节在附录，收益相对规则路由并不大。也不要在没有可靠验证器的开放任务上照搬，救援轨迹的「成功」判错会直接把错误行为学进模型。

## 8. 和你已有知识的挂钩

它像「带辅助轮学自行车」：训练时给不同的辅助（兄弟外壳），学会之后拆掉辅助轮，在原车上照样能骑。也像知识蒸馏里的「特权信息」老师，只不过这里的老师不是另一个模型，而是同一个模型加上更好的执行提示。和 DAPO 这类「直接丢掉全对全错组」的做法相比，最大区别是：它不丢弃，而是换外壳把失败组变成有对比的组。

## 9. 存疑与代价

**局限**：机制分析集中在 AppWorld 4B；基线未给标准差；外部外壳下仍有落差；作者在结论里也把持久迁移、跨策略复用池子列为未来工作。**复现条件**：代码 Apache-2.0 已公开；训练后权重未见公开；数据集均为公开基准（划分见 Table 6，p17）。**成本**：外壳进化需要强编辑模型和数千次搜索 rollout，训练比普通 GRPO 多 18.44% 的 rollout，GPU 时 67.19 对 50.58（Table 9–10）。**出处**：上海交大等五家单位，预印本，未同行评审；Table 1 中的前沿模型名称以论文为准，未独立核对其可得性。

**论文没回答的 3 个问题**：池子换一个策略模型（比如换了家族）还能直接复用吗？救援成功轨迹里有多少是靠外壳提示「抄近路」、撤掉后其实学不会的？在没有现成验证器、需要人工打分的业务任务上，救援还划算吗？
