# OpenGCUA：走向完全开放的"通用电脑操作智能体"技术栈

**英文标题**：OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use
**arXiv**：[2610.22200](https://arxiv.org/abs/2610.22200) ｜ **HF**：[papers/2610.22200](https://huggingface.co/papers/2610.22200) ｜ **点赞**：317（2026-10-16 批次）
**机构**：HF 页面标注 Tongyi-MAI；论文署名 Alibaba Token Hub, Alibaba Group

## 一句话总结
这是一份开源的电脑操作智能体（Computer-Use Agent）框架报告：让模型用"写代码"的方式把 GUI 点击和 shell/Python 操作组合起来，并把"什么时候截图、怎么记录任务状态"这类原本写死在框架里的决策交给模型；在 OSWorld-v2 上，8 个前沿模型的平均分全部提升，平均 +19.6 分，步数平均减少 53.0%。

## 研究问题与动机
电脑操作正在从"只靠截图加点击"转向"视觉界面和程序化接口并用"。作者把**通用电脑操作智能体（GCUA）**定义为：模型在每一步自己决定三件事，即看什么、怎么动手、如何组织工作。纯 GUI 智能体、CLI 智能体、多智能体混合方案，以及 GUI+CLI 的 Qwen-UI-Agent，都可以看作把其中一部分决策预先固定下来的特例。前沿实现（例如 GPT-6 Astra 的电脑操作系统）基本闭源，难以系统研究，所以他们想和社区一起把整套技术栈开放出来。这一版本**没有训练新模型**，研究的是提示、工具接口和执行运行时的设计。

## 核心方法
1. **代码执行**：模型写一段程序，在其中混合 `pyautogui.click()` 之类的 GUI 动作、`bash()` 调用和 Python 计算。循环和条件判断让中间结果直接决定下一步，不必每个动作都调用一次模型，同时能直接发挥模型已有的编程能力。作者在案例中总结了五类常见用法，例如跨界面组合、循环执行、依据结果决定是否执行（先校验草稿再发送）。
2. **框架到模型的决策迁移**：把原本由框架规则固定的流程决策交给模型，例如由模型决定何时请求截图、如何跟踪任务状态，并要求它在执行前说明每段程序的目的。
3. **开放内容**：实现与提示词、8 个模型的全部评测轨迹、初版真机框架（处理与用户共用电脑、操作后台窗口等基准里没有的问题），以及跨电脑、手机和浏览器的统一 SDK。

## 实验设置与主要结果
- 基准：OSWorld-v2（v2.1）的 82 题离线子集（排除了需要联网的 26 题，沿用 GPT-6 Astra 发布时的评测协议）。指标包括部分得分、完全成功率、每题步数和每题输出 token 数。
- 模型：Claude Opus 5、GPT-6 Astra、Gemini 3.8 Flash、Qwen3.8-Max、Qwen3.8-Flash、Kimi K3、DeepSeek-V4.1-Flash、GLM-5.3-Flash。
- **主结果（对比支持批量动作的纯 GUI 基线）**：跨模型平均部分得分从 45.3 提高到 64.9（+19.6），每题步数平均减少 53.0%，输出 token 减少 27.2%，8 个模型的完全成功率全部上升。
  - GPT-6 Astra：67.1 → 75.7，步数 102.1 → 33.5（−67.2%）。
  - Claude Opus 5：60.7 → 70.1，输出 token 从 378.3K 降到 89.3K。
  - 提升最大的是 GLM-5.3-Flash（+35.2）和 DeepSeek-V4.1-Flash（+29.8）。最强与最弱模型之间的分差缩小了一半以上。
- **代码执行的增量**：在同样拥有 GUI 和 shell 权限的前提下，用代码组合操作比批量 GUI+CLI 平均再高 6.1 分，步数再少 14.8%。以 Qwen3.8-Max 为例，单动作 GUI 50.9、批量 GUI 46.9、批量 GUI+CLI 57.2、代码执行 62.4。
- **按需观测**：只把"何时截图"交给模型，就让两个模型的缓存命中率分别提高 10.5 和 14.4 个百分点，任务得分没有下降。
- **真机案例**：在同一框架下完成 4 个真实 macOS 任务，所选的 Qwen3.8-Max 运行消耗的推理 token 是 GPT-6 Astra 的 19.4 倍，总输出 token 是 5.7 倍，完成的任务反而更少。

## 局限与风险
- 没有训练新模型，所有增益都来自框架和提示设计，作者也说明 GCUA 模型要等下一版发布。
- 只评测了 82 题的离线子集，排除了联网任务；真机部分只有 4 个案例，作者称之为 case study，不能当作统计结论。
- 让模型直接写代码操作用户电脑会放大安全风险，例如误删文件、误发邮件。论文的案例里有"先校验再发送"的模式，但没有系统评估安全性。
- 评测模型大多是 2026 年的闭源前沿模型，复现成本高，API 版本也在变化。

## 工程落地启示
- 做桌面或浏览器 Agent 时，**"让模型写程序而不是一步一个动作"**能同时提高成功率、降低步数，对强模型和弱模型都有效。
- 把截图频率等固定规则交给模型，可以提高 KV 缓存命中率、降低成本，这是一个容易被忽视的优化点。
- 真机环境（用户同时在用、后台窗口）与基准环境差别很大，上线前需要单独的真机评测。
- 在开源轨迹上做蒸馏或训练专用的电脑操作模型，是一个现成的起点。

## 与相关工作的关系
本文把 Agent S/S2 这类组合式 GUI 智能体、Claude Code 这类 CLI 智能体，以及 GUI+CLI 混合方案都纳入 GCUA 框架，作为不同程度固定决策的特例。它与 CodeAct 的"以代码为动作"思路一致，但把它推广到 GUI 和真机场景，并强调随着模型变强，框架里的控制权应逐步交给模型。
