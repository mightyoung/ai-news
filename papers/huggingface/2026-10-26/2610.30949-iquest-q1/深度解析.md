# IQuest-Q1：面向智能体 CLI 系统的基础能力提升

**IQuest-Q1: Advancing Foundation Capabilities for Agentic CLI Systems**

## 一句话总结
一个 320B 总参数、每 token 激活 15B 的开源稀疏 MoE 智能体底座模型，围绕命令行（CLI）交互从预训练一路设计到后训练和模型合并，并展示了"人在环上监督"的自我迭代开发流程。

## 研究问题与动机
CLI 已成为 LLM 使用工具、读写文件、执行代码最通用的接口。要做强 agent，就需要底座模型在不同 harness（Claude Code、Codex、OpenCode 一类）下都能稳定调用工具、长程执行。论文的目标是把 CLI 能力作为一等公民写进整个训练管线。

## 核心方法
1. **预训练**：Stable SplitNorm + Muon 优化器 + μP 参数化，两阶段课程，第二阶段提高代码数据比例；作者称这样在安全学习率和最优学习率之间保持较宽的稳定裕度。词表 160,000。
2. **中训练**：扩展跨领域、跨格式的数据混合，逐步拉长上下文。
3. **后训练**：在生产环境中合成并执行任务；SFT 建立基础 CLI 交互，领域专项 RL 用任务级反馈提升能力，多教师在线蒸馏（MOPD，4 个专家 → 学生）把互补能力合进一个模型；多 scaffold、多版本训练。
4. **模型合并**：合并不同 CLI 专家和不同阶段 checkpoint，并缓解参数更新冲突。

## 实验设置与主要结果
- 对比闭源的 Claude Opus 5、GPT-5.6 Sol 以及多款开源模型。
- 编码：DeepSWE v1.1 为 64.6，NL2Repo-Bench 63.0，PaperBench 86.0，CyberGym 84.5。
- 通用 agent：Toolathlon-Verified 75.0，AutomationBench 52.7，Claw-Eval 77.1，BrowseComp 85.5，WideSearch 81.8，JobBench 55.7，APEX-Agents 1.1 为 50.9。
- 推理：GPQA Diamond 93.3，IMOAnswerBench-Verified 93.0；HLE 无工具 39.2、有工具 55.7（作者承认专家级推理仍有差距）。
- 自我迭代案例：基于 IQuest-Q1 的 agent 在一次长程任务中出现 35 次工具调用错误，它在 6,054 次工具调用中追查原因（p15；不是"排查/修复 6,054 次失败"），发现训练数据偏向单一 tool-call schema 且有定义与参数不一致的记录，提出清洗与多 schema 增广；经人类专家审核后训练，用了 2.35B tokens、938.7 GPU 小时。
- 安全：三天部署中，安全专家在模型辅助下产出 30 份漏洞报告，均经同行独立验证，涉及开源项目的已负责任披露。
- IQuest-CLIBench 是其自有内部基准，需谨慎对待。
- 核验口径补充：
  - 所有成绩均为厂商自报，尚无第三方复现；SWE-Bench Pro 为 57.5，低于 GLM-5.3-Flash、MiniMax M3 与 Hy3。
  - 论文中的 1.93× 指训练 loss 对 FLOPs 的效率提升，不代表下游任务效果提升 1.93 倍。
  - MTP 步数论文自身前后不一致：正文 p4 写复用 7 步，表 1 与 HF README 写 ×8。

## 局限与风险
仅文本输入；生成的代码和解释可能出错需复核；工具调用采用 IQuest 专有格式，需要兼容的解析器和 harness；真实 CLI 任务中可能忽略约束、重复失败尝试。部分基准为自建或内部版本，跨论文比较要小心。

## 工程落地启示
- 15B 激活参数的开源 agent 底座，对想自部署 coding agent 的团队有现实意义。
- "多 scaffold 训练 + 多 schema 数据增广"直接针对换 harness 就掉点的问题，是做 agent 微调时值得照搬的经验。
- "agent 提方案、人审核关键决策和昂贵实验"的 human-on-the-loop 迭代，是 RSI 在工业界的务实形态。

## 与相关工作的关系
训练配方与近期 Kimi、DeepSeek、GLM 等开源 MoE 一脉相承（Muon、μP、MOPD、模型合并），差异在于把 CLI 多 harness 适配作为主轴，并显式讨论人类监督下的递归自我改进。
