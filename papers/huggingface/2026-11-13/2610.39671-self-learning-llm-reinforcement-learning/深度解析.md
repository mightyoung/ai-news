## 1. 一句话先懂它

给大模型一本「拿掉了习题答案」的数学教材和三个翻书工具（看目录、搜关键词、读整节），让它边想边查、自己学会书里的定理再写证明；再用强化学习奖励「查得有用又做对了」的做法。练完之后，它在没见过的教材、没见过的学科上都更会「现学现用」，甚至在网页检索和读材料答题的基准上也略有进步。做 Agent、做文档问答、做 RL 训练的人值得看。

## 2. 值不值得读：五个 C 速览

**类型**：新方法（训练框架）加一套自建的教材证明任务。**上下文**：接着两条线：一条是用强化学习教模型边推理边搜索（Search-R1、R1-Searcher、StepSearch），一条是「从给定材料里学新知识」（CL-bench 一类的上下文学习评测）。同组作者的 TOME-Math 也用教材做数据，两篇数据同源。**关键假设**：①教材里拿掉答案后，模型仍能靠定义和定理推出证明；②LLM 判分（GLM-5.2 审 8 遍全对才算对）足够准；③在数学教材上练出的「查书策略」能迁移到别的任务。前两条在作者设置下大致站得住，第三条只有两个外部基准、提升 1.7 和 2.3 点，证据偏弱。**贡献**：①把「自学」落成一个可训练、可评测的任务：158 本教材、5,183 道证明题，答案对模型不可见；②BookNavigator 三动作接口；③「做对才给的探索奖励」加「逐轮工具打分」两种细粒度奖励，并用消融说明各自作用。**清晰度**：正文清楚，接口和提示词全在附录 B；但没写算力、没给代码。建议**看到第 5 节**；做 RL 训练 Agent 的人值得自己读原文第 2.4 节和 Table 4。

## 3. 它在解决什么麻烦

今天让模型处理它不熟的领域，常见办法有两种：一是 RAG（检索增强生成：先按问题搜出几段资料，拼进提示词再回答），二是把一大段资料直接塞进长上下文。两种都是「先把资料备好，再一次性作答」。问题在于，真正难的题，事先并不知道需要哪条知识：推到一半才发现缺一个引理，或者读到一个新定理才改变解题思路。资料备多了，噪声淹没关键内容；备少了，缺的正好是要用的那条。

你在工程里会这样撞上它：给内部手册做问答 Agent，问题一复杂，固定取前 k 段的检索总是取不全；让编程 Agent 读一个陌生的大代码库，它要么一次读太多把上下文撑爆，要么根本不去读，凭印象瞎写。后一种情况更隐蔽，而这篇论文恰好量化了它：只按「最终答对」给奖励的强化学习，会让模型越来越少查资料。在他们的消融里，带工具调用的轨迹占比从 36.9% 掉到 6.7%（Table 4，第 8 页）。

如果这个麻烦被解决，模型就不只是「知道得多」，而是「会学」：碰到新领域，会自己翻目录、定位章节、读懂再用。对 Agent 来说，这意味着同一个模型换一套文档就能干活，不必为每个领域重新微调。

## 4. 他们怎么做的

**核心思路**：像人学教材那样，把「查书」和「推理」交替进行，并用强化学习把这种习惯练出来。难点有两个：模型一开始不爱查书；练强以后更不爱查。所以光奖励「做对」不够，还要额外奖励「查过书且做对」，同时惩罚明显无用的查书动作。

**第一步：造任务**（第 3、5 页）。把 158 本本科、研究生数学教材解析成按章节编号的文本，把习题和答案单独抽出，答案对模型不可见；去掉题面里引用「第几节」的题，保证题目自足。平均每本书 56 节、约 20.8 万 token。训练集 4,557 题来自 132 本书。评测分三档：同书留出题 205 道（4 本书，ID-Book）、没见过的书 155 道（7 本，OOD-Book）、没见过的学科（概率统计）266 道（19 本，OOD-Subject）。

**第二步：翻书接口 BookNavigator**（第 3–4 页）。三个动作：`get_toc` 返回整本书的目录；`search_index` 输入关键词，返回排好序的章节号和匹配片段；`read_section` 输入章节号，返回整节原文。每次最多交互 8 轮，整条轨迹上限 64k token（第 5 页）。附录 B.2 的提示词规定了「先看一次目录、最多搜两次、通常只读一节」等规矩（第 13–14 页）。

**第三步：奖励设计**（第 4–5 页）。最终证明交给判官 GLM-5.2 对照隐藏答案审 8 遍，全部判对才得 +1，否则 −1（悲观判分：宁可错杀）。在此基础上加两样东西：
- 探索奖励：答对且至少成功调用过一次工具，额外加分；系数按余弦从 1 降到 0.25，前期鼓励多查、后期保留一点激励。
- 工具打分（tool credit）：用冻结的初始模型当「工具判官」，看每一轮查书动作和下一轮推理，打「有用 / 中性 / 有害」三档（有害指重复读已有内容、无理由重复失败请求等），有害记 0.5、其余记 1。判官看不到答案和最终对错。然后把整条轨迹的优势值（advantage：这条轨迹比同组平均好多少）按各轮得分重新分配，有害那一轮拿到的学习信号少一些，整体均值不变。

**训练配置**（第 5、17 页）：底座 Intern-S2-Preview-35B，GRPO（组相对策略优化：同一题采样多条答案，按组内相对好坏更新模型）只训 50 步，每步 128 道题、每题 8 条轨迹，学习率 1e-6，关闭 KL 正则。评测时每题采 4 个解取平均准确率。所用 GPU 型号和训练时长：论文未说明。

**如果让你复现**，最小骨架是：

```python
book = parse_textbook(pdf); q, ref = pick_exercise(book); hide(ref)   # 答案对模型不可见
for step in range(50):                                 # GRPO 只训 50 步
    trajs = [rollout(policy, q, tools=[get_toc, search_index, read_section], max_turns=8) for _ in range(8)]
    for t in trajs:
        r = 1 if all(judge(q, ref, t.proof) for _ in range(8)) else -1  # 8 次审查全对才算对
        t.R = r + beta(step) * (r == 1 and t.used_tool)  # 探索奖励，余弦退火 1→0.25
    A = group_advantage(trajs)                          # 组内相对优势
    for t in trajs: t.round_adv = redistribute(A[t], frozen_init_judge(t.rounds))  # 有害轮次少分
    policy.update(trajs)                                # 工具返回的文本不计入损失
```

## 5. 证据怎么看、别被什么忽悠

**表一：Table 1（第 6 页），五种做法训练前后对比。** 想证明：边查边想、再加强化学习，胜过「先备好资料」。怎么测：五种做法都用同一个底座、同样做 50 步 RL（基线只用「做对」这一个奖励），在三档评测上比证明准确率（每题 4 个解的平均）。五种做法是：不给书（No-Book）、按搜索取前 k 节拼进去（Top-k Sections）、按原书顺序塞满 64k（Long-Context）、直接给出题所在的那一节（Oracle Section）、以及本文的 Self-Learning。结果：Self-Learning 训练前总体只有 51.5%，比不给书的 55.7% 还低；训练后到 79.5%，涨 28.0 点，比最强的 Top-k Sections（73.1%）高 6.4 点。按核验限定：51.5%→79.5% 是 Intern-S2-Preview-35B 在 626 道教材证明题上的总体准确率，用 LLM 判分。说明：不训练时「给工具」反而拖后腿，练过之后才翻盘；没见过的书和学科上也最好（85.2%、86.7%）。

**表二：Table 2（第 6 页），涨分到底来自哪。** 想证明：不只是「推理变强」或「背下了训练书」。怎么测：同一个训练后模型，换五种参考条件。结果：不给书 71.7%（训练前 55.7%）；给原书 79.5%；换一本同学科的书 75.2%；删掉出题那一节及前后各 4 节（共 9 节）74.6%；随机删 9 个无关节 79.8%（第 6–7 页）。说明：有一大块提升来自「不查书也变强了」（+16.0 点），但查书仍再贡献 7.8 点；删掉关键章节掉 5.2 点、删无关章节几乎不掉，说明模型确实在用书里的特定内容。

**表三：Table 4（第 8 页），两种奖励各管什么。** 只奖励做对：准确率 74.9%，但带工具调用的轨迹从 36.9% 降到 6.7%，每条轨迹平均调用从 1.5 次降到 0.3 次。只加工具打分：同书题涨 3.3 点，工具使用率仍只有 7.0%。只加探索奖励：工具轨迹升到 79.9%，两个 OOD 档各涨 2.0、2.9 点。两样都加：总体 79.5%，工具轨迹 58.4%、每条 3.0 次调用。说明：最好的结果并不是「调用最多」，而是「查得适量」。这是全文对工程最有用的一张表。

**水分检查**：①没有误差条，也没写多少个随机种子；每题 4 个解取平均，只算采样平均，不算训练重复。28.0 点这样的大差距可信，但 Table 4 里 1–3 点的差异要谨慎。②判分全靠 LLM（GLM-5.2 审 8 遍），证明题的 LLM 判分可能偏严或偏松，论文没有人工抽检一致率。③数据和评测都是作者自建，和 TOME-Math 同源教材，不是公开基准。④只有一个底座、只训 50 步，换模型、拉长训练是否还成立未知。⑤基线 RL 只用「做对」奖励，而 Self-Learning 多了两种奖励；Table 4 已部分回答了这一点：同样协议下只奖励做对是 74.9%，仍高于各固定检索基线。⑥外部迁移只有两个基准：BrowseComp-Plus（网页深度检索）51.9%（+1.7）、CL-bench（读给定材料学新规则）17.1%（+2.3），并且 CL-bench 里「按流程执行」一类所有 RL 模型都低于底座（Table 3，第 7 页）。

## 6. 可信度与核验限定

**主张对照**：①「RL 把总体准确率从 51.5% 提到 79.5%」：Table 1（第 6 页）直接支持，差距大，可信。②「胜过固定检索」：Table 1 支持，比最强基线高 6.4 点，但是单次训练、无误差条。③「学到的是通用自学策略」：Table 2 的换书、删节实验有支持力；跨任务迁移只有 Table 3 两个基准的小幅提升，偏弱。④「两种奖励互补」：Table 4 支持，工具使用率的变化很明显。

**核验限定**（原样合入核验报告）：
- 51.5%→79.5% 是 Intern-S2-Preview-35B 在 626 道教材证明题（205 同书 + 155 新书 + 266 新学科）上的总体准确率，Self-Learning 设置 RL 前后（Table 1，p6；p5）
- RL 前 Self-Learning 51.5% 比 No-Book 55.7% 还低；No-Book 做同样 RL 后到 71.7%（p6；p7）
- 判分用 LLM：GLM-5.2 八次审查全判对才算对（p5）；GRPO 只训 50 步
- BrowseComp-Plus 51.9%（+1.7）、CL-bench 17.1%（+2.3），用的是基准原生协议，不是 BookNavigator（Table 3，p7）
- PDF 里没找到代码或数据链接；论文 CC BY 4.0

**精读复核补注**：核验报告风险点还提到，判分完全依赖 LLM，且与 TOME-Math 作者团队高度重叠、数据同源教材，两篇不算独立证据。第二条「No-Book 做同样 RL 后到 71.7%」要细分：71.7% 来自 Table 2，是「按 Self-Learning 方式训练、测试时不给书」；如果是「按不给书的方式做 RL」，Table 1 的 No-Book 行训练后是 68.5%。两者不是同一个模型（均在第 6 页）。

**打折提醒**：对外引用写「35B 底座、626 道自建教材证明题、LLM 判分，51.5%→79.5%」，不要只说「准确率提升 28 个点」；「跨任务泛化」只能说「两个外部基准上小幅提升」。

## 7. 你可以怎么落地

**今天就能试**：不训练模型，只借它的接口和提示词。给你现有的文档问答或代码 Agent 换掉「一次塞前 k 段」的检索，改成三个工具：看目录、关键词搜索返回片段、按编号读整节；系统提示照附录 B.2 的规矩写：先看一次目录、最多搜两次、通常只读一节、搜不到就停（第 13–14 页）。挑 20–30 道你们内部真实问题，与现有 top-k 检索各跑一遍。验收：答对率不降；同时记录「带工具调用的比例」和「每题调用次数」，如果模型几乎不调用工具，说明它在凭记忆作答，要警惕。

**要有数据或机器再试**：想复现训练，需要能跑 35B 模型 RL 的集群（论文未写算力，按每步 128 题 × 8 条、最长 64k token 估计，至少是多机多卡），一个够强的判官模型，以及几千道带参考答案、答案可隐藏的题。可分三步验证：①先用小模型在几百道题上只做「奖励做对」的 RL，复现工具使用率下降（Table 4）；②再加探索奖励，看使用率能否回升；③最后加逐轮工具打分，看同分布题上是否再涨。

**暂时别碰**：别把「跨任务泛化」当成上线理由。外部基准只涨 1.7、2.3 点，且「按流程执行」类任务全部下降（Table 3，第 7 页）；如果你的 Agent 主要是照流程办事，这套训练可能反而有害。代码和数据都没放出，目前没法直接拿来用。

## 8. 和你已有知识的挂钩

它像奖励塑形（reward shaping：在稀疏的最终奖励之外，加一些中间奖励引导行为）：探索奖励相当于「新手期多给经验值」，工具打分相当于给每个动作单独记功过。它也像工程师看陌生代码：先看目录结构，再 grep 关键词，再读那个文件。和 Search-R1 这类「RL 学搜索」最大的区别：那些方法检索的是答案或事实，这里书里没有答案，模型得读懂定义和定理、自己推出证明，考的是「学」而不是「找」。

## 9. 存疑与代价

**局限**：论文正文没有单独的局限性小节。我读出的局限有：只有一个底座、一个领域（数学证明）；判分全靠 LLM；训练只有 50 步，更长训练后工具使用会不会再次塌缩未知；接口只有关键词搜索，没有向量检索；外部迁移证据弱，而且「按流程执行」变差。**复现条件**：代码、数据、训练后权重都没放出；底座 Intern-S2-Preview 有公开模型卡；判官 GLM-5.2 需自己部署或调 API；教材版权可能限制数据公开。**成本**：每题最长 64k token、判官每题审 8 遍、每遍最多 65,536 个输出 token（第 17 页），判分开销不小；GPU 时长论文未写。**出处**：预印本，未同行评审；单位按首页为上海人工智能实验室等五家；与 TOME-Math 团队高度重叠。
