## 一句话总结

Jeva 提出一种「原生为决策而设计」的 System One（直接、低延迟、不生成推理文本）模型架构：请求和每个候选项分别独立编码，再用一个很小的决策模块只更新请求状态，从结构上同时做到「可判无解（null）、候选顺序不敏感、候选数可扩展、候选表示可缓存复用」。

## 研究问题与动机

很多 LLM 请求其实是一个紧凑决策：选工具、找文档、判断条件、打分。现有 System One 做法多是把请求和所有候选序列化成一段文本，再读出答案符号的 logit。论文认为这种做法有四个结构性缺陷：

1. 候选被当成有序序列，位置会影响结果；
2. 固定的答案符号表限制了候选数量；
3. 对候选做归一化并不能说明「是否有任何候选适用」，即无法区分「没答案」与「候选之间难分高下」；
4. 与请求相关的计算和可复用的候选内容混在一起，工具库、文档库这类反复出现的候选每次都要重新编码。

## 核心方法

- **独立编码**：共享的语言骨干分别把「请求（决策类型+问题+状态）」和「每个候选（决策类型+候选文本）」编码为向量，候选侧不含任何请求或其他候选信息，因此是「不可变的候选记忆」。
- **紧凑决策模块**：只更新请求状态，让它按注意力方式读取候选记忆。论文给出命题：即使只有 1 个决策块，同样的 A、B 两个候选在不同候选集合下也可以反转偏好，这是「逐个独立打分」做不到的。
- **对称聚合 + 共享打分**：聚合是对称的，因此候选概率对排列是等变的；打分头共享参数，所以候选数变化不需要改输出参数。
- **覆盖度（coverage）门控**：单独估计「至少有一个可接受候选」的概率 ρ，再与候选内部的竞争分布相乘，得到包含 null 的完整分布。论文证明在最终分数固定时，加入低于现有最大值的候选不改变 ρ。
- **统一输出**：Choice（选择）、Noul（布尔判断）、Score（评分）三类输出共用一套结构。
- **可缓存**：候选向量及各层投影可跨请求复用；论文区分了整集合缓存（Set）与可在新组合的集合间复用单个候选的混合缓存（Hybrid）。
- **实现**：Jeva-4B 基于 Qwen3.5-4B，池化宽度 2560，决策宽度 768，L=1、H=8，rank-64 LoRA，可训练参数 13.37M，分阶段课程训练（类型化决策、意图选择、验证、阅读/推理、大候选检索）。

## 实验设置与主要结果

评测套件包括 Typed Decisions（2,000 条测试）、BANKING77 与 MASSIVE（8 或 16 个候选）、Mind2Web 的三个切片（16 个候选），并做排列、批处理、缓存的受控测试。延迟在 H200 上同步计时。

- **准确率**：在 8 个切片中 7 个切片的全覆盖准确率领先；BANKING77 与 MASSIVE 在两种候选数下都超过 90%；Mind2Web 跨任务/跨网站/跨领域为 79.99%、62.25%、66.23%。Typed Decisions 上 Jeva 为 78.30%，略低于 InternDecision-4B 的 78.70%。
- **Null 检测**（BANKING77，16 个候选，含 588 个无答案样本）：AUROC 98.66%，对比 KEV-BF16 93.61%、InternDecision-4B 84.27%、JevK5 79.44%；在 5.02% FPR 下检出 93.88% 的无答案样本。
- **顺序稳定性**（600 条 Choice，多种顺序）：Jeva 0 次决策翻转，平均 TV 为 3.17×10⁻⁸，原顺序与全顺序准确率同为 76.67%；对比 Jev-1.13.0、InternDecision-4B、JevK5 的翻转率分别为 17.00%、22.67%、26.17%。
- **Soft 目标质量**：Noul Brier 0.0184、MAE 0.0939，Score MAE 0.2315，均为最低；Score RMSE 0.3222 与 InternDecision-4B 的 0.3208 接近。
- **大候选集**（ToolRet 诊断，K 从 32 到 2,048）：Jeva 覆盖全部请求，总体准确率 78.40%，对比递归选择的 JevK5 为 64.00%；K=2048 时 69.88%，对比 JevK5 的 67.47%（后者约 28 秒）；长度感知批处理使 K=2048 的 p50 延迟从 94.459 秒降到 12.040 秒（7.85×）。
- **缓存复用**（MLDR，50 条匹配查询）：完全复用时 p50 从 2,102.0 ms 降到 75.1 ms，中位配对加速 27.86×；部分复用约 1.95×。共享库的 Typed Decisions 上 p50 从 93.1 ms 降到 46.7 ms，避免 99.2% 的候选行编码，决策不变（最大绝对概率差 0.00736）。

## 局限与风险

- 论文没有单独的「局限」章节；以下为基于其内容可核对的事实：在 Typed Decisions 上并非第一；Mind2Web 跨网站、跨领域准确率仅 62% 到 66% 量级；
- 评测基线多为文档化接口下的开源 System One 模型，部分数据集（如 Typed Decisions）来自社区发布，结论强依赖这些基准；
- 计时在单一 GPU（H200）上完成，缓存收益取决于候选复用率，候选完全不重复的场景（0% 复用）加速为 0；
- 单个文本仍受各自编码长度上限限制，论文自己指出这一点没有消除；
- 缓存只缓存候选侧计算，状态编码与决策精炼对每个请求仍要执行。

## 工程落地启示

- 适合「候选集合反复出现、要求低延迟」的场景：工具路由、意图分类、文档/网页元素选择、规则判断等，尤其当候选库较大时收益明显。
- 如果业务需要「以上都不是」的拒答能力，覆盖度门控比在 softmax 里加一个 None 项更稳（论文用 Proposition 2 说明了二者差别）。
- 对排列敏感会造成线上不可复现，Jeva 在结构上保证了顺序不变，不需要多次打乱取平均。
- 复现成本：LoRA 仅 13.37M 可训练参数，骨干为 Qwen3.5-4B，复现门槛不高；但训练用的分阶段数据课程与若干基准需要自行整理，建议先在自己的候选库上验证缓存命中率，再评估是否值得换架构。

## 与相关工作的关系

- 论文将 SemIf、JevK5（用答案 token 的 logit）、Intern-Decision（决策标记）、ReFlex（跨顺序聚合）、KEV（pointer head）、Laya（双向编码器+决策头）归为「直接/类型化决策模型」，Jeva 的区别是把独立文本编码与集合条件下的状态更新分开。
- 与 DPR、ColBERT、Contrastive Language Models 一脉相承：独立编码使候选可预计算；不同在于 Jeva 保留候选间的集合级交互。
- 与 Deep Sets、Set Transformer、Perceiver 一样用对称聚合与紧凑潜状态来处理集合；与 SQuAD 2.0、selective classification 对应的是「可回答性/弃权」问题，Jeva 把 null 定义为「不存在有效候选」。
