## 3. Convovo 研究：通过 API 强制二选一时，GPT-6.1 Sol 有 97% 选民主党，Grok 4.7 有 92% 选共和党

- **要点**：
  - Convovo 由康奈尔大学教授 Tapan Parikh 领导。研究团队通过 API 开启搜索，在近 500 场 2026 年中期选举（众议院、参议院、州长）中提问：“只说一个候选人，不许含糊”。GPT-6.1 Sol 有 97% 选了民主党，Grok 4.7 有 92% 选了共和党，两者结论一致的比例不到 10%。
  - 两者的信源差异很大。Grok 有 41% 的回答引用 X，有 39% 引用基督教保守派投票指南。GPT 主要引用 Wikipedia、AP、Axios 和 Reddit，其中后三家与 OpenAI 有内容合作。
  - 关闭搜索后抽样 30 场：GPT 仍在 24 场选了民主党；Grok 有 27 场拒绝选择，选了的 3 场都是民主党。Parikh 据此认为，GPT 的倾向“在权重里”，Grok 的倾向来自搜索词和信源。研究还发现，xAI API 每次请求都会附带约 1240 个研究者看不到的额外输入 token。
  - OpenAI 回应：这项测试用的是开发者 API 和强制提示，不代表 ChatGPT 的实际体验，消费端应用会拒绝推荐候选人。SpaceXAI 截至发稿未回应。
- **为什么值得看**：距 11 月 3 日中期选举不到两周。研究直接证明，同一个问题在不同模型上的“隐性立场”可能完全相反，搜索和信源层也可能引入偏向。这对用 API 做产品的开发者尤其值得注意。
- **来源**：
  - [TechCrunch（10-24）](https://techcrunch.com/2026/10/24/forced-to-pick-groks-ai-model-chooses-republicans-openais-picks-democrats/)
  - [Convovo：AI Ballot 2026（研究原文）](https://convovo.ai/ballot/)

## 4. 跟进 Kimi K3.1 Pro：第三方独立评测结果出炉（上期写的是“待独立评测”）

- **新进展**：10-24 简报提到 Kimi K3.1 Pro 的成绩是厂商自报。之后 Artificial Analysis（AA）公布了独立测试结果，发布时间是北京时间 10-24 01:44–07:11，在本窗口开始前，上期没有收录。
- **要点**：
  - **Terminal-Bench 4.0**：在 AA 独立测试中得分 67.2%，排第 1。Claude Sonnet 5.5（Max）得 63.6%，Claude Opus 5.5（Max）得 59.6%。
  - **GDPval-AA**：1846 Elo，比 K3 高 312，仅次于 Claude Opus 5.5（1866）和 Muse Wonder Full（1857）。Intelligence Index 比 K3 高 11 分。AA-Omniscience 中幻觉率从 53% 降到 44%。
  - **AA Cyber Index**：得分 64%，成为“可公开获取模型”中的第 1，只落后于受信访问模型 GPT-6 Sol（Daybreak Blue）。主要原因是 CyberGym-E2E-AA 从 58% 提升到 95%，这是 AA 测过的最高分。
  - **成本**：单价比 K3 低 33%（输入每百万 token 2 美元，输出每百万 token 10 美元），但输入 token 用量增加，Cyber 任务的单任务成本反而上升 15%。AA 还表示，它在 AA-3D（交互式 3D 场景生成）上的排名可能偏低。
- **为什么值得看**：独立评测基本证实了它在智能体和编码上的领先，并显示出很强的网络攻防能力。AA 测的是 API 版本，权重计划在 11 月 4 日前开放。

## 5. Google DeepMind《A Fix for Softmax and Cross-Entropy》：两个数值 bug 与 log 空间修复方法（窗口前提交、窗口内引发讨论）

- **说明**：论文 10 月 22 日提交到 arXiv，不在本窗口内。它在窗口内于 X 上广泛传播，之前的简报没有收录，所以这里补上并标明。
- **要点**：
  - **Softmax Collapse**：某个目标 logit 远大于其他 logit 时，它的梯度被舍入成 0，而其他类别的梯度仍为正，导致梯度之和不再为 0。bf16 下约在 logit 差 5.5 时出现，fp32 约在 16.6。配合 Adam 时会引发 “Slingshot” 式的 loss 尖峰。
  - **Softmax Cancellation**：蒸馏时，即使学生和教师的 logits 完全相同，梯度也不为 0。
  - **修复方法**：在 log 空间重写计算，使用 softplus、expm1、log1p 等数值稳定的原语。作者为 Jon Barron、Gnanapragasam 和 Tschannen。
- **为什么值得看**：这直接影响低精度训练、loss 尖峰排查和蒸馏。对做微调的人来说，改动成本低，可能带来实际收益。
- **来源**：
  - [arXiv 2610.31642](https://arxiv.org/abs/2610.31642)
  - [项目页 jonbarron.info/softmaxfix](https://jonbarron.info/softmaxfix/)
