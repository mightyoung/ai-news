## 1. OpenAI 发布 GPT-6 Cyber：网络安全专用模型，Preparedness 标为 Critical

- **要点**（厂商自报，系统卡同日发布）：
  - 11-05 发布。GPT-6 Cyber 是 GPT-6 Astra 的网络安全专用变体，面向授权漏洞发现、利用开发与 Web 渗透；经 Daybreak Red 受限访问（身份核验、SSO/MFA、API IP 白名单等）。
  - ExploitGym（指定漏洞、远程目标拿 flag）：48.5%，相对 GPT-5.6 Cyber 的 32.1% 约提升 51%（相对提升，厂商自报）；无部署安全提示时，ExploitGym Honeypot 越权利用率 0.07%（5.6 Cyber 为 5.51%），有提示时为 0%。
  - 实战（厂商自报）：在 Firefox 中发现 81 个 Mozilla 标为高危的新漏洞并协助补丁；在 Linux 上对 948 个漏洞做出可工作利用（同 harness 下 GPT-5.6 Sol 为 166）。Palo Alto、Cisco、CodeRabbit、Calif、Cognition 等给出客户引言。
  - Preparedness：网络安全 Critical（与 Astra 同级）、生化物 High、AI 自我改进低于 High。第三方 Irregular：长程进攻套件 CyScenarioBench 11/11 至少解出一次（Astra 8/11）。NIST CAISI 参与了外部评估。
- **为什么值得看**：这是把“进攻能力 + 授权边界对齐”捆在一起卖给防御方的正式产品线，也把 Critical 网络安全能力放到了受限 API 上。系统卡与技术细节会在 13:30 技术报告雷达归档、核验和精读，这里不展开。主线：其他（安全）／AI Agent。

## 2. METR：Anthropic 内部能力进步约 1.9×，多数归因于用 AI 做研发

- **要点**（第三方独立评估，METR；Anthropic 对非公开证据有大量删改权）：
  - 评估期 2026-08-12 至 10-29，METR 获高权限内部数据（基准、RL/预训练指标、算力、访谈等），不付费、用公司设备。同日另发对 Anthropic 2026 年 8 月风险报告「自动化研发风险」一节的审阅。
  - 主观结论（METR）：截至 2026-10，Anthropic 在「定义清晰任务」上的能力进步速度，大约是 2024-03 至 2025-10 历史速率的 2 倍（不确定区间约 1.3×–3×）；当前加速中多数（粗估约 80%）来自用 AI 做研发，而非训练算力加速（算力加速可排除）。未看到未来 12 个月足以挡住进一步加速的明确瓶颈，但理解多轮翻转、信心有限。
  - 可公开数字：内部模型 AECI（Anthropic 版 Epoch Capabilities Index）自 2025-10 起增速约 1.9×〔95% CI 1.5–2.8〕，约等于过去一年走完此前两年的进步；稳健性检查给出约 1.1×–2.9×。公开风险报告对「是否越过 2× 早期预警阈值」的表述，METR 认为偏自信；多数相关研究者仍倾向 7-15 时点未越过，但认为「有可能已越过」。双方同意当时直接灾难风险仍为「低」。
  - 局限：多数最有信息量的证据被 Anthropic 删改，公众更依赖 METR 判断；完全自主研发贡献尚非主流，但有「signs of life」。
- **为什么值得看**：这是迄今最接近「外部审计 AI 是否在加速 AI 研发」的公开报告，和 Anthropic S-1 风险措辞、RSP 阈值直接相关。主线：强化学习与RSI。

## 3. Anthropic：分析约 20.7 万科研会话，看科学家怎么用 Claude

- **要点**（厂商自报 / 经济指数团队研究报告）：
  - 11-05 发布。用隐私保护分类器，分析 2026-08-02 至 09-30 消费级计划上的 207,049 次科研相关会话（Claude 约 12.9 万、Claude Code 约 7.8 万），外加 Claude Science 补充样本；不保留开放式研究内容。
  - 相对科研人员数量，形式科学（CS / 数学 / 统计）用得更多，健康与实验物理科学更少。Claude Code 上计算机科学约占会话 32.7%（全球科研人员份额约 4.3%）。任务上，数据分析约占 Claude 会话 33.7%、Claude Code 48.1%；写作也偏高；创意/假设生成与数据采集相对偏低。
  - 自建「理论 AI 能力」分：能力最高 20% 的任务，Claude 用量约为按科研时间预测的 2–4 倍。情景测算（非预测）：现有能力广泛采用时，部分领域产出可约翻倍；若非体力步骤全自动化，CS/统计等可到约 15 倍，实验学科约 3–4 倍。配套调查（528 名偏 AI 活跃的生命/健康科研者）：约 40% 预期 2030 年前 AI 可独立完成完整研究项目。
- **为什么值得看**：把「AI 加速科学」从口号拆成字段、任务和瓶颈（体力实验 vs 认知任务），也和上条 METR 的自加速叙事形成对照。主线：强化学习与RSI／其他（科学应用）。
- **来源**：
  - [Anthropic：AI for scientific discovery: How researchers use Claude](https://www.anthropic.com/research/how-researchers-use-claude)

## 7. Microsoft Research：PDD Kit——用形式化证明约束智能体写的全栈应用

- **要点**（厂商自报）：
  - 11-05 发布。Proof-Driven Development（PDD）工具包，嵌在 GitHub Next 的 Chopin 协作规划环境里：先把人的意图收成 Verus 形式化规约，再证明智能体写的 Rust 代码对规约成立；证不到的边界（如 bcrypt、sqlx、JWT）标进信任基并配测试。
  - 演示：约 5,000 行 Rust 的 Pet Store（Axum + SQLite + Leptos/WASM）登录逻辑；开发者只审意图与规约，不逐行读生成代码；CI 用 Verus 卡住后续改动。目前仅支持 Rust/Verus，研究原型。
- **为什么值得看**：对应「智能体一次交几万行 PR、人审不过来」的瓶颈，把审查重心从代码挪到意图与可证明规约。主线：AI Agent。
- **来源**：
  - [Microsoft Research：Formally verifying agent-written full-stack web apps with PDD Kit](https://www.microsoft.com/en-us/research/blog/formally-verifying-agent-written-full-stack-web-apps-with-pdd-kit/)
