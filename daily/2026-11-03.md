## 1. MIT CSAIL 博客：GPT-6 Astra 能直接读写神经网络权重（“权重空间编程”）

- **要点**（以下数字都是作者自报，来自研究博客，尚未同行评审，也未见第三方复现）：
  - 作者 Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab（MIT CSAIL），11-02 发布。做法是把网络的原始权重当文本交给 GPT-6 Astra，让它用推理去理解、修改或从零写出权重，不用梯度下降，也不让它写训练循环。
  - 读：4 个结构完全相同（17,253 个权重的 MLP）、分别用 PPO 训练玩 Breakout、Pong、Pac-Man、Freeway 的网络，Astra 只看权重、不给选项，4 个都说对了是哪个游戏。
  - 改：让 Qwen3.5-0.8B 数学变好，Astra 找到导致推理死循环的权重问题，改了 0.016% 的权重；相同采样设置下 MATH-500 从 7.9% 升到 48.1%，IFEval 也提升到约 3 倍。
  - 写：从零写出的小型游戏策略网络，作者称能胜过 PPO 训练 1 亿步的网络。
- **为什么值得看**：如果站得住，意味着“优化器”本身可以换成会推理的大模型，对模型调试、可解释性和自我改进都有影响。HN 本窗口最热（约 1800 分）。但目前只是早期结果，0.8B 模型的大幅提升也可能部分来自修掉了一个已知缺陷（Qwen 模型卡里提到过推理循环问题），要等论文和复现。主线：强化学习与RSI。
- **来源**：
  - [MIT CSAIL 研究博客：Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/)

## 3. OpenAI 发布 LifeVal：衡量 AI 帮普通人办日常事务的评测

- **要点**（厂商自报）：
  - 11-02 发布。任务来源是美国时间利用调查（ATUS）和多国时间利用研究（MTUS），再加一份 3,995 人、按人口比例抽样的新调查，挑出人们最想让个人助理帮忙的事：照护、健康、教育、家务行政、个人理财、购物、办政府手续等。
  - 页面只给了几个单项任务的得分示例（如“搬家后选幼儿园”93.1%、“找合适的房子并把契据加入购物车”100%、“为新确诊糖尿病的父母做饮食计划”90.4%），没有公布总分、参测模型列表、评分方法和对比基线。
  - OpenAI 说过去一年用它来跟踪和推动浏览器操作、电脑操作和连接器任务上的进步。
- **为什么值得看**：头部厂商开始把“替你把事办完”当成正式评测目标，和下一条 GDPx 一起看，评测重心正在从知识问答转向长流程智能体任务。但目前缺方法细节，分数没法和别的评测对比。主线：AI Agent。

## 4. SemiAnalysis 发布 GDPx 评测：最强模型也只拿到约 12%

- **要点**（第三方评测，SemiAnalysis 与 14 家领域数据合作方构建；结果是它自己测的，未见其他机构复现）：
  - 定位为 OpenAI GDPval 的后继，只覆盖“前沿智能最能产生价值”的领域：芯片设计、网络安全、生物、金融、法律、量化交易、递归自我改进（RSI）、硬件设计、材料科学、对齐、软件工程，刻意不收政府、地产、保险。
  - 最佳模型总分约 12%。Opus 5.5 综合最强（量化交易、硬件和芯片设计第一）；Gemini 4 Carbon 生物和软件工程第一；GPT-6 Astra 在 RSI 和材料科学上明显领先；金融和法律任务几乎所有模型都是 0 分。
  - SemiAnalysis 提醒：Opus 5.5 和 GPT-6 Astra 的分数被自家安全分类器拉低（网络安全、生物、对齐三个领域会触发拒答），去掉这三个领域后排名会变。
- **为什么值得看**：给“选哪个模型做哪类任务”提供了分领域的参考，也说明安全分类器已经是实际选型时要考虑的因素。本条只读了免费部分。主线：AI Agent。
- **来源**：
  - [SemiAnalysis：GDPx: Measuring Frontier Model Capabilities Across the Most Valuable Domains](https://newsletter.semianalysis.com/p/gdpx-measuring-frontier-model-capabilities)

## 5. OpenAI 公开 Pando：为 Codex 时代重做的 Git 后端

- **要点**（厂商自报）：
  - Codex 让每个工程师能并行推很多分支，原来的 monorepo 系统扛不住，可靠性一度低于 90%。Pando 保持 Git 协议和客户端兼容，改成按分支各自更新（只保证单个分支的顺序，不保证全仓库同一时刻的一致视图），并在多个客户端之间复用 packfile，靠区域缓存分发。
  - 效果：推送延迟中位数降低近 80%（约 5 倍），每天交付近 1 PB 的 Git 数据，缓存命中率 99% 以上；单小时最多送出 57 TB。
  - 从立项到上线 10 周，核心由一名工程师设计、多组智能体实现；用 GPT-6 Astra 写 Lean 和 TLA+ 形式化规约来找 bug。相关改进已部分合入上游 Git。
- **为什么值得看**：这是“智能体大规模写代码”倒逼基础设施改造的一个具体案例，团队上量后 Git 托管、CI 都会先遇到同类瓶颈。主线：AI Agent。
- **来源**：
  - [OpenAI：Scaling Git at OpenAI](https://openai.com/index/scaling-git-at-openai)

## 6. Import AI 479：Realtime-Bench 显示大模型在实时任务上还很弱

- **要点**（学术团队的评测，转述自 Import AI 通讯；作者来自 UT Austin、俄亥俄州立、UIUC、NVIDIA、西北大学等）：
  - 50 个必须及时行动的任务：30 个网页任务（订票、电商、服务、安全）和 20 个游戏任务，分“真实时钟”“暂停时钟”“按 token 计时”三种条件。
  - 真实时钟下最好的是 GPT-6 Astra（high），通过率 36%；同样的模型在暂停时钟下能到 70%–80%，说明差距主要来自“想太久”。
- **为什么值得看**：抢票、竞拍、玩游戏这类要求低延迟的任务，目前的智能体还靠不住，做产品时要留意。论文本身归论文雷达，这里只作动态。主线：AI Agent。
- **来源**：
  - [Import AI 479](https://importai.substack.com/p/import-ai-479-spacewar-low-latency)
