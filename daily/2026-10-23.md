## 1. MiniMax M3.1 Flash 权重如期公开，但许可证不是完全开放

- **要点**：10 月 20 日那期讲过 MiniMax 承诺 10 月 23 日放出 M3.1 Flash 权重。截至北京时间 10 月 23 日早上，Hugging Face 上的 `MiniMaxAI/MiniMax-M3.1-Flash` 仓库已经公开，含 49 个 safetensors 分片，合计约 252 GB，另附 DSpark 投机解码草稿头。模型卡写明约 428B 总参数、每 token 激活 23B，支持文本、图像、视频输入，上下文最长 100 万 token，全程使用 MiniMax 稀疏注意力，并做了量化感知训练。
  - **许可证**：用的是 MiniMax Community License。基础授权写的是“非商业用途”；商业使用需要在产品页面标注 “Built with MiniMax M3.1-Flash”，年收入 2000 万美元以下的只需给 MiniMax 发一次邮件告知，超过的要事先拿到书面授权。附录还禁止军事用途等。
- **为什么值得看**：这兑现了“开放权重”的承诺，对推理服务商和研究者有意义。但 252 GB 的体量意味着个人电脑基本跑不动，而且许可证带商业条件，不是 MIT 或 Apache 那种随便用。想自建服务的团队要先看清条款。官方跑分表是厂商自测，需等独立评测。
- **来源**：

## 2. Hugging Face 发布 Carbon-X：能直接“读 DNA 聊天”的 14.8B 开源模型

- **要点**：Hugging Face 与意大利那不勒斯费德里科二世大学、Telethon 遗传与医学研究所和中国中关村学院合作发布 Carbon-X。它从 Qwen3-14B 出发，扩展词表，把 DNA 按不重叠的 6 个碱基切成一个 token，和普通文字放在同一个序列里处理，不需要单独的 DNA 编码器。经过 3020 亿 token 的继续训练（DNA、生物文本、英文和指令数据），再做监督微调和基于可验证奖励的强化学习。用户可以把 DNA 序列直接贴进对话，让它判断突变是良性还是致病、找出调控区域、按物种类别分类、预测后续碱基，并用英文解释理由。
  - **成绩与限制**：官方称在五个 DNA 基准上平均 66.7%，比底座 Qwen3-14B 高 27 个百分点。剪接位点和组蛋白标记类题目仍然弱（29.8% 和 34.6%）。没有经过临床验证，也没有湿实验验证。训练时刻意不用病毒数据，以降低被滥用的风险。
  - **部署**：Apache 2.0 许可，BF16 一张 80 GB 显卡可跑，另有 GGUF 量化版（Q4_K_M 约 9.6 GB），可以在本地用 llama.cpp 运行。
- **为什么值得看**：基因数据非常敏感，很多研究机构不能把数据传给云端大模型。一个能本地运行、许可宽松的“DNA + 语言”模型，给这类场景提供了现实可行的选择。它的做法（在通用大模型上扩展词表、继续训练）也是把大模型迁移到专业领域的一个清晰范例。
- **来源**：
  - [Hugging Face 模型卡](https://huggingface.co/HuggingFaceBio/Carbon-X)
  - [GGUF 量化版](https://huggingface.co/HuggingFaceBio/Carbon-X-GGUF)

## 3. Canva 发布首个自研图像生成模型 Canva Craft

- **要点**：Canva 10 月 22 日发布 Canva Craft，由内部的 Canva Research 从零训练。它分两步工作：先由一个规划模型把提示词写成详细的构图方案（有哪些元素、位置关系、大小比例、视觉层级、图中要出现的文字），再由渲染模型按方案出图，最高 2K 分辨率，支持 30 多种画幅比例，图中文字支持 55 种语言。已向全球所有 Canva 用户开放（在 Dream Lab 里），开发者可以通过公开 API 调用（模型名 `craft_v1_2k`），单个任务大约 50 到 60 秒。Canva MCP 接入和更便宜的 Craft-fast、Craft-ultrafast 版本“即将推出”。
- **为什么值得看**：“先规划再画”这种做法针对的是现有图像模型最常见的毛病：海报上的字拼错、排版乱、改一处牵动全局。Canva 自称在 DesignArena 排行榜上位列第二，这是厂商引用的众包排名，还需要更多独立对比。另一个信号是设计软件公司开始自己训练基础模型，而不只是接别家的 API。

## 4. OpenAI Decisions API 正式上线：专做“选择题”的快速低价接口

- **要点**：OpenAI 10 月 22 日宣布 Decisions API 正式可用（GA）。它基于 GPT-6 Luna，只回答答案范围有限的问题，返回三种结果之一：某条件为真的概率、从预设选项里选一个、按评分标准打分。官方称比通过 Responses API 调用 GPT-6 Luna 快最多 10 倍。公测以来新增了与 GPT-Live 语音的原生集成、提示缓存、美国和欧盟的数据驻留、原生 JSON 输入，单次请求最多 400 个问题（翻倍）。定价是每百万输入 token 0.10 美元，缓存输入 0.01 美元，不收输出费用。官方引用的客户例子包括 Datadog 用它在执行前给智能体生成的命令打风险分，Sierra 用它在客服对话中选下一步动作。
- **为什么值得看**：智能体在工作流里要做大量小判断（分类、路由、要不要重试、要不要升级给人工），每次都调用完整大模型既慢又贵。把这类判断拆给专用的快速接口，是让智能体更快、更便宜的实用思路，也和上期 OpenAI 事故报告里“用硬规则拦截危险操作”的方向一致。客户提速数字都是厂商引用的客户自述。
- **来源**：
  - [OpenAI 官方博客](https://openai.com/index/decisions-api/)
  - [开发者文档](https://developers.openai.com/api/docs/guides/decisions)

## 5. Google 推出 Agent Compute Engine：给每个智能体一台硬件隔离的小虚拟机

- **要点**：Google Cloud 10 月 22 日在 AGNTCon + MCPCon 上发布 Agent Compute Engine，这就是 Gemini 智能体目前在用的底层计算服务，预计未来几个月开放预览。每个智能体会话有一台独立的 microVM，基于 Cloud Hypervisor 做硬件级隔离，配合 Google 的 Titanium 芯片。智能体在“思考”或等待人类回复时，虚拟机会被暂停并做快照，需要时快速恢复，空闲时几乎不占计算资源。多个智能体通过写时复制共享同一个系统模板的内存。做编程评测或强化学习时，可以把一个环境快照后复制成上千份并行跑。每台虚拟机有自己的身份和短期凭据，服务凭据在虚拟机外部注入，智能体本身拿不到。
- **为什么值得看**：前几期讲了不少智能体出事的案例（删监控、泄露密钥）。Google 这次的设计把“智能体看不到凭据、跑在隔离环境里”做成了基础设施，而不是靠提示词约束，和 Anthropic Duet、NVIDIA 安全沙箱参考架构是同一个方向。对自建智能体平台的团队，“空闲即暂停”的计费方式和“快照后批量复制”的评测方式都值得参考。开源的 Kubernetes 版本 Agent Substrate 已在 9 月发布。
- **来源**：

  - [技术深入解读](https://cloud.google.com/blog/topics/ai-infrastructure/agent-compute-engine-deep-dive)
  - [SiliconANGLE 报道](https://siliconangle.com/2026/10/22/google-cloud-introduces-agent-compute-engine-to-host-ai-agents/)

## 6. 开发者注意：Anthropic 发布 API 新版本 2026-10-21，有多项不兼容改动

- **要点**：Anthropic 推出 API 版本 `2026-10-21`（三年来首次升级默认版本，旧版是 `2023-06-01`），各语言 SDK 同步发大版本（Python 2.0.0、TypeScript 1.0.0、Go v2、Java 3.0.0 等，许可证也从 MIT 改为 Apache 2.0）。发布日期在上期截止前后，上期没有收录，这里补上。主要不兼容改动：
  - `temperature`、`top_p`、`top_k` 三个采样参数被删除，传了直接报 400 错误，即使传的是默认值。
  - assistant 消息里直接放 document 块、user 消息的文本块带 citations，都会报错。
  - 新 SDK 默认用 `Authorization: Bearer` 头发送 API key，不再用 `X-Api-Key`。
  - 一个客户端只能持有一种凭据，同时传 API key 和 token 会报错。
  - Admin API 多个字段改名，例如 `workspace_id` 改为 `scope`。
- **为什么值得看**：只要升级 SDK 到新大版本，这些改动就会生效。最容易踩的坑有两个：代码里设了低 temperature 求稳定输出的，升级后会直接报错；自建网关或日志过滤只认 `X-Api-Key` 的，升级后会拿不到密钥。不想马上改代码的，可以先锁定旧 SDK 版本。
- **来源**：
  - [Anthropic 官方迁移指南](https://platform.claude.com/docs/en/api/migration-2026-10-21)
  - [Python SDK 更新日志](https://github.com/anthropics/anthropic-sdk-python/blob/main/CHANGELOG.md)
