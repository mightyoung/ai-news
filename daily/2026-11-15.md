## 1. Interconnects：开源模型生态在黄仁勋辞任后的空档（观点）

## 3. 【补收】NVIDIA：两台 DGX Station 上部署 GLM-5.3，峰值 607.8 tok/s
**主线标签**：大模型与微调（部署）
- 说明：NVIDIA 开发者博客正式发布时间为 2026-11-13T17:00:00Z（北京时间 11-14 01:00），落在昨日窗口。昨日首选源是 `blogs.nvidia.com` RSS，没有扫到 `developer.nvidia.com/blog`；今日该文出现在 Hacker News（127 分，2026-11-14T14:09:25Z），故补收。已读全文。暂无技术报告。
- 设定（厂商自报）：模型是 Z.ai GLM-5.3 的 NVIDIA NVFP4 量化版，总参数 7530 亿、每 token 激活 400 亿；检查点约 464 GB，超过单张 GB300 的 252 GB HBM3e。做法是把两台 DGX Station 用 ConnectX-8 RDMA 连起来，vLLM 张量并行 TP=2（两张 GPU 各算大约一半权重），开多 token 预测、FP8 KV cache 和前缀缓存；示例配置里 `--max-model-len` 为 98,304、`--gpu-memory-utilization` 为 0.93。权重仍需全部放在 GPU 显存里，不能靠 CPU 卸载。
- 头条数字（均为厂商自报，NVIDIA 用 AIPerf 在 SPEED-Bench Coding 上测）：并发 16 时整体输出吞吐峰值 607.8 tok/s；并发 32 时降到 385.0 tok/s，平均请求延迟 453.5 秒；单用户平均吞吐从并发 1 时的 115.3 tok/s 降到并发 32 时的 13.0 tok/s。这是官方教程里的本机基准，不是第三方复现，也不是和别的框架或云端 API 的对比。
- 为什么值得看：它把「千亿级 MoE 在工作站上怎么跑」写成了可核对的配置和数字，对要本地部署大模型的人有参考价值；注意峰值出现在并发 16，再往上吞吐和单用户速度都会掉。
- 来源：[NVIDIA 开发者博客](https://developer.nvidia.com/blog/when-one-gpu-isnt-enough-serving-glm-5-3-across-two-nvidia-dgx-stations-with-vllm/) · [Hacker News 讨论](https://news.ycombinator.com/item?id=50497155)
