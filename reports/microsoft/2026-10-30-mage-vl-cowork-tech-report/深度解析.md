## 1. 一句话先懂它

微软用一个只有 4B 参数的小模型，让它既会像人一样点鼠标、看屏幕，又会在合适的时候直接写代码、敲终端命令来完成电脑上的办公任务。在 OSWorld-Verified 上它拿到 66.0%，并且把训练数据、harness 和强化学习的整套做法都公开了。

## 2. 值不值得读：五个 C 速览

**类型**：完整技术报告。披露程度：训练数据“有细节”（任务数、轨迹数、各阶段 token），算力“有细节”（各阶段 ZFLOPs），架构“只有一句话”（Mage-ViT + Qwen3-4B，细节在模型卡），RL 配方“有细节”（GRPO、异步、截断重要性采样、集群规模）。**上下文**：接着 OSWorld 系列的 GUI 智能体（OpenCUA、ScaleCUA、EvoCUA、Fara），以及“GUI + 代码”混合路线。**关键假设**：老师 harness 产出的轨迹足够好、能蒸馏进 4B 学生；合成桌面与网页环境要和真实评测分布接近。第二条有数据污染风险，正文没讨论。**贡献**：① 五阶段课程，从通用多模态检查点一路训成混合式电脑操作智能体；② Mage-CUA-Forge 用可复用的技能工作流批量合成任务，单任务重复成本降 82.6%；③ 证明先改 harness 再蒸馏，学生收益比老师本身的差距大得多。**清晰度**：好，关键工程细节在附录 B、C。建议：做 CUA 的读原文第 3、4 节和附录 C；其他人看到第 5 节即可。

## 3. 它在解决什么麻烦

现在的电脑操作智能体（CUA，Computer-Use Agent，能看屏幕、点鼠标、打字的模型）大致两条路：纯 GUI，一步一截图一点击，慢、容易点错；或者纯代码/终端，快，但碰到只有图形界面的软件就没辙。把两者合在一个小模型里，难点有三。第一，好的示范轨迹难得：前沿大模型当老师，默认 harness（包在模型外面、负责给它工具和提示的那层框架）产出的轨迹质量参差。第二，合成任务贵：每造一个可验证的桌面任务都要调一遍大模型。第三，小模型容易在“该点还是该写代码”之间犹豫。

在你熟悉的场景里：比如想在内网部署一个能帮人整理表格、批量改文件的本地助手，大模型 API 太贵、数据又不能出网，4B 级别的端侧模型就是刚需。如果这套配方站得住，一台带中端 GPU 的工作站就能跑一个 OSWorld 六成多成功率的智能体，而不是每一步都调云端前沿模型。

## 4. 他们怎么做的

核心思路：先把老师的 harness 调到最好，用它批量产出混合轨迹；再用由浅入深的课程把 4B 学生训出来，最后用在线 RL 收尾。

**老师 harness 的进化**（§3.1，图 3 第 7 页）：从 GPT-5.4 官方 OSWorld 智能体出发，经过 α→β→γ→δ→ε 几轮修改，老师在内部任务上的成功率从 75.6% 提到 93.2%；α→β 加入终端通道，γ→δ 换过老师的底层模型，换成了哪个论文未说明。表 5（第 17 页）是关键对照：同一个 GPT-5.4，β1（GUI + 代码）比 β2（再加无障碍树 AX 通道）只高 2.4 pp，但蒸馏出的 4B 学生差了 12.5 pp（37.6% vs 25.1%）。也就是说，通道越多，小模型越容易乱选。

**任务工厂 Mage-CUA-Forge**（§3.4 第 8 页）：先写好可复用的“技能工作流”，再按技能组合批量生成任务、初始文件和评分细则（rubric），由 gpt-5.6-terra 当评委。规模是 293,806 个任务、6,915 个技能，单应用 61.76%、多应用 38.24%，保留 318,837 条轨迹。网页侧用 InfiniteWeb 的 17,542 个任务，加上 WebHarbor 复刻站（Flask + SQLite，每轮重置，附录 A）。

**五阶段训练**（§4，表 1 第 9 页；附录 B.4 第 23–24 页）：起点是一个中间版的 4B Mage-VL 多模态检查点。
1) GUI 中训练：做元素定位，24.6B token，1.18 ZFLOPs；
2) GUI 智能体 SFT：15.67 万条轨迹，32.2B token；
3) 代码/终端 SFT：56.37 万条，5.7B token；
4) 混合 SFT：31.88 万条，45.1B token；
5) 在线 RL：2.62 ZFLOPs。
合计 7.79 ZFLOPs（按 C≈6NT 估算，不含基座预训练和视觉编码器）。上下文只保留最近 3 张截图、4 条完整回复，更早的历史折叠成动作摘要（§4 第 9 页、附录 B.3）。

**在线 RL**（§4.5 第 10–11 页，附录 C 第 24–25 页）：在 ScaleCUA 的 1,988 个带可验证奖励的任务上，按预跑成功率挑“刚好够得着”的前沿任务，用 GRPO（组内相对优势的策略优化，不需要价值网络）。训练是异步的，用截断重要性采样（TIS，上限 2.0）修正新旧策略的差异，策略滞后不超过 3 步。每批 96 组 × 8 条，共 768 条轨迹；环境跑在 70 台 Azure 虚拟机的 1,120 个 GUI 槽位上，32 张 B200 GPU（24 张训练、8 张推理），平均每次更新 570.3 秒。

如果让你复现，最小骨架：

```
teacher = tune_harness(frontier_model, channels=[GUI, code])   # 先剪枝通道
tasks   = forge(skill_workflows) ; trajs = rollout(teacher, tasks) ; keep(rubric_judge)
student = midtrain_grounding(base_4b)
student = sft(student, gui_trajs) ; sft(student, code_trajs) ; sft(student, hybrid_trajs)
for step: batch = frontier_filter(verifiable_tasks); grpo_async(student, batch, tis_cap=2.0)
eval(student, OSWorld-Verified, steps=50, runs=2)
```

## 5. 证据怎么看、别被什么忽悠

**表 2（第 14 页）OSWorld-Verified 主结果**。目的是证明 4B 也能打到大模型水平。设置：361 题（剔除 Google Drive 题）、50 步预算、两次运行取平均，Pass@1 口径。结果 66.0%，分项 OS 87.5、Office 64.9、Workflow 62.7；人类 72.4。对比方：Qwen3.6-27B 63.9、EvoCUA-32B 56.7、OpenCUA-72B 44.9；但 9B 的 ScaleCUA-Qwen3.5-9B 为 68.7，作者自测的 GPT-5.4-mini（跑一次）为 69.6，都比它高。前沿闭源模型 GPT-5.5 78.7、Claude Opus 4.7 78.0。结论：同尺寸里明显领先，但“超过几倍大的开源模型”只对部分对手成立。

**图 8（第 16 页）+ 表 6（第 24 页）阶段消融**。目的是说明每一步都有用。GUI SFT 45.56 → 混合 SFT 55.84（+10.28）→ RL 66.0（+10.16）。RL 之后调用次数从 21.57 降到 18.77，输出 token 从 7,374 降到 5,499。结论：RL 不仅提高成功率，还让模型少走弯路。

**表 3（第 14 页）Forge 成本**。每任务 $0.906→$0.158，token 1,276K→85K；但不含一次性写工作流和调试的成本。

**水分检查**：只有两次运行，没有误差条；基线大多直接引用各家自报，步数预算不一（部分 100 步）；合成任务覆盖的应用（图 4 第 8 页：LibreOffice、GIMP、VLC、Thunderbird、Chrome、VS Code）和 OSWorld 高度重合，论文没做污染分析；WebVoyager-Static 是自建离线基准，表 4（第 17 页）的 58.6% 还是 SFT 检查点，不是最终模型；全部在虚拟机里评测，没有真实用户环境。

## 5A. 训练配方与架构

数据：中训练 24.6B token，三段 SFT 合计约 83B token，混合 SFT 打包成 1,377,805 个 32,768 token 的块，训练 2 个 epoch（表 1 第 9 页，附录 B.4）。中训练的小技巧（附录 B.1 第 22 页）：提示解耦（定位样本只用点击枚举）、同截图目标去重，以及只对部分 `<think>` 正文做选择性掩码（被采用）；作者还对比了提早混入 GUI 轨迹的方案。定位效果（图 6 第 15 页）：OSWorld-G 从 30.6 提到 56.9，ScreenSpot-v2 从 78.8 提到 87.2。架构：Mage-ViT 视觉编码器 + Qwen3-4B-Instruct-2507 文本骨干（36 层，hidden 2560），稠密模型，不是 MoE（HF config）。后训练：先 SFT，后异步 GRPO；奖励来自任务自带的验证器（规则可验证），不是奖励模型；没有自我改进循环，但老师 harness 进化和技能工作流本身就是一个合成数据循环。推理时计算：每步先 `<think>` 再出动作，采样温度 0.7、top_p 0.8（HF 卡）。算力占比以 PDF 附录 B.4 为准：中训练 15.2%、SFT 51.2%、RL 33.6%（HF 卡上这一列错位了）。披露程度：数据、算力、RL 配方都写得很细；基座预训练和视觉编码器官方未披露。

## 5B. 安全评测与系统卡要点

本文档未包含安全评测。报告只在第 6 页写了一句：真实部署时，终端执行需要明确授权和沙箱隔离。HF 模型卡的 Responsible AI 节（厂商自评）建议：在隔离沙箱里运行，高风险操作前人工确认，不挂载凭据，网络走白名单。没有第三方测试。

## 6. 可信度与核验限定

**主张对照**：66.0% 的出处是表 2，有设置说明，但只有两次运行，证据中等；Forge 成本降 82.6% 的出处是表 3，是自建对比且不含一次性成本，证据弱到中等；RL 比混合 SFT 高 10.16 pp 的出处是图 8 和表 6，证据较充分；“harness 进化放大学生收益”的出处是表 5，样本为 672 个内部任务，可信。

**核验限定**（来自 qualifiers.json，原样）：
- OSWorld-Verified 66.0% 为厂商自报：361 题（剔除 Google Drive）、50 步预算、两次运行平均（65.33/66.75），第三方暂未复测
- 对比基线多为各家自报、步数预算不一；作者自测 GPT-5.4-mini 一次运行 69.6，高于本模型；9B 的 ScaleCUA 为 68.7
- Forge 成本降 82.6% 不含一次性工作流编写与调试成本（表 3 第 14 页）
- 实际参数约 4.74B；训练与推理上下文 32,768
- HF 卡训练表的算力占比列错位，以 PDF 附录 B.4 为准：中期训练 15.2% / SFT 51.2% / RL 33.6%
- WebVoyager-Static 58.6% 是 SFT checkpoint 在自建静态基准上的分数，不是最终 RL 模型

**厂商自报 vs 第三方独立**：以上全部是厂商自报。本例程第三方来源表里的榜单（AA、LMArena、SWE-bench 等）都不收录 OSWorld-Verified，暂无第三方数字。**打折提醒**：不要说“超过所有开源模型”，要说“同尺寸领先，9B 的 ScaleCUA 仍更高”。

## 7. 你可以怎么落地

**今天就能试**：用官方镜像在一台 GPU 机器上起服务，跑仓库自带的 osworld_eval/ 抽 30 题，看成功率是否接近 60% 档、平均步数是否在 20 步左右。另一个零成本的收获：把你现有智能体的工具通道砍到“GUI + 代码”两条，比较小模型的成功率和步数（参考表 5 的结论）。

**要有数据或机器再试**：用自己的内部软件做 Forge 式的技能工作流，合成几千个带评分细则的任务，在 Mage-VL-Cowork 上做混合 SFT。RL 阶段需要的规模不小（千级虚拟机槽位 + 数十张 B200），建议先用几十台虚拟机、只做 SFT 验证收益。

**暂时别碰**：直接接到有真实凭据的生产桌面上。报告没有安全评测，卡上也明确要求沙箱和人工确认。

## 8. 和你已有知识的挂钩

它像“先优化老师，再做蒸馏”：harness 进化相当于给老师调好提示和工具，再把老师的行为蒸馏给学生，最后用 RL 微调。和 OpenCUA、ScaleCUA 这类纯 GUI 路线最大的区别，是学生自己决定这一步是点击还是写代码；同时它证明，给小模型的通道宁少勿多。

## 9. 存疑与代价

**局限**：论文没写局限一节。读出来的问题有：合成应用和评测重叠，没做污染分析；没有误差条；最终老师模型是哪个没写；WebVoyager 只报告了 SFT 版本。**复现条件**：权重 Apache-2.0、代码 MIT、评测脚本公开；Forge 合成的数据和技能库是否公开，论文未说明。**成本**：后训练约 7.79 ZFLOPs；RL 用 32 张 B200 加 1,120 个虚拟机槽位，单次更新约 9.5 分钟。**出处**：微软官方仓库发布，没有同行评审。

三个决定你要不要动手的问题：① 换成没在训练里出现过的软件，成功率掉多少？② Forge 的技能库和任务能不能拿到？③ 32K 上下文下，超过 50 步的长任务还能撑住吗？
