## 1. 一句话先懂它

美团给已有的「听声音、看人像生成说话视频」模型做了一轮后训练升级：口型更自然，长视频不容易越拍越走样，生成步数从五十步压到八步。权重和代码已经公开，想做口播或虚拟主持的人可以先试；但数字都是厂商自报，总榜仍落后一个闭源对手。

## 2. 值不值得读：五个 C 速览

- **类型**：完整技术报告（15 页），是 1.5 的后训练升级，不是新基座。后训练流程「有细节」（第 1–2 节）；数据「只有类型、没有规模」（第 3 节）；基座架构、参数量和预训练算力「没写」；强化学习「有算法和采样设置，奖励模型几乎没写」。
- **上下文**：接着 1.5 的基座和 LongCat-Video 的 GRPO，并借用 DMD2 与 OPSD-V（第 3–4、6、8 页）。
- **关键假设**：分两路后训练再合并到冻结基座，就能同时改善口型和长视频稳定性。部分成立：写实像真分上升，动画子集下降（Fig. 8 / 物理第 12 页）。
- **贡献**：① 冻结基座上的两路 LoRA 后训练；② 改了文本–音频引导路径，减轻脸过饱和和嘴唇发红；③ 用厂商自建 Arena 和与 1.5 的像真评分作对比。
- **清晰度**：主线清楚，学习率写了；奖励怎么打分、数据规模、已发布文件名如何对应两路适配器，都没写清。
- **建议**：关心后训练的人读第 2、4–5 节；只想判断能不能用，看本节和第 5、5C、7 节即可。

## 3. 它在解决什么麻烦

现在做音频驱动数字人（给一张人物图和一段语音，生成这个人在说话或唱歌的视频），短片往往已经能对上嘴型，但有两个麻烦一直在。第一，对上时间不等于口型自然：嘴可能张得过大、嘴唇绷得很紧。第二，要生成更长的视频时，模型通常一段接一段往下续；前面的小误差——颜色漂移、嘴唇变红、纹理变糊——会被写进下一段的「历史」，越往后越糟。报告把嘴唇逐渐发红当作最显眼的例子（第 1 节，物理第 3 页）。

你若要做口播、访谈或虚拟主持，短演示好看不够，观众会连续盯着一张脸看很久。嘴型夸张或嘴唇越来越红，会立刻出戏；若把动作幅度一律压小，又可能把该有的发音动作一并压掉。

如果 1.6 说的成立，你就多了一个开源选择：不必重训整个基座，只在冻结模型上加后训练适配器，用八步生成，并且作者声称可以生成超过 10 分钟仍保持观感（厂商自报，摘要 / §6）。但这是厂商自己的评测，动画风格还略有下降，落地前要在自己的素材上复核。

## 4. 他们怎么做的

核心思路：基座已经会拍数字人，不必重训；把「动作更自然」和「自己续拍仍少走样」分成两路，各训一条 LoRA（低秩适配器，只改很少一部分参数），推理时再接到冻结基座上（§2.1，物理第 4、6 页，Fig. 3）。

第一路是强化学习。对同一组条件（参考图、音频、文本）生成一组候选视频，用组内相对好坏更新，不必另训价值网络。算法是 Group Relative Policy Optimization（GRPO，按组内相对优势更新策略的强化学习），沿用 LongCat-Video。同一组共享初始噪声和随机选中的一个去噪时刻，只在这一步注入随机性，其余步用确定性积分。只更新 GRPO LoRA，主干冻结（§2.2，物理第 4、6 页）。奖励由什么模型打分，原文未说明。

第二路先用 Distribution Matching Distillation 2（DMD2，把多步扩散模型蒸成少步生成器的方法）把采样从 50 步压到 8 步（§2.3.1，物理第 6 页）。为省显存，共用一个冻结的 Diffusion Transformer（DiT，视频扩散里常用的主干），用 Generator LoRA 和 Fake-Score LoRA 切换角色，冻结基座充当真实分布的打分器。训练停在 600 步，因为再练下去观感会变差；生成器和 fake-score 学习率分别为 \(2\times10^{-5}\) 和 \(4\times10^{-6}\)，更新比为 1:5（物理第 6 页）。

他们还改了文本–音频的无分类器引导（CFG，推理时加强「按文本或音频条件生成」的程度）。统一加大引导容易让脸过饱和、嘴唇发红；最终采用路径 \(00\rightarrow 0T\rightarrow A0\)，文本引导强度 7、音频引导强度 3（§2.3.1 / Fig. 4，物理第 6–7 页）。音频强度加到 4 时，作者观察到嘴唇过红、牙齿发绿。

长视频是「片段内双向去噪、片段之间自回归续拍」：第一段由图加音频生成，之后把上一段最后若干帧再编码成上下文，只去噪新帧，并用参考图锚住身份（§2.3.2，物理第 7 页）。训练时上下文来自真实视频，推理时却来自模型自己的输出，于是出现训练–推理不一致。On-policy self-distillation（OPSD，在模型自己滚出来的轨迹上做蒸馏）改编自 OPSD-V 的上下文替换：学生按 8 步滚动生成，EMA teacher（指数滑动平均得到的教师模型）在相同噪声状态上给速度目标；续拍时教师上下文由真实视频的前 \(C-1\) 帧加上教师上一段的边界帧组成（§2.3.3，物理第 8 页）。报告写推理时把 OPSD 适配器与 GRPO 适配器一起用。已发布的 `loraA` / `loraB` 在模型卡与 GitHub README 中被标为 DMD LoRA 与 OPSD LoRA，仓内无名为 GRPO 的文件；原文未解释对应关系，此处不猜测。

最小复现骨架：冻结与 1.5 同管线的基座；一路训 GRPO LoRA；另一路按上述超参数做 DMD2 再做 OPSD；推理时合并两路适配器并按片段续拍。数据规模、奖励模型和预训练算力，论文未说明。

## 5. 证据怎么看、别被什么忽悠

**Fig. 1 与 §4.2（物理第 1、9–10 页）。** 想证明 1.6 在人类偏好上超过 1.5 和若干商业模型。测法：EvalTalker 的 508 组图像–语音对，六模型全部 15 种配对，33,051 次有效两两投票；标注员须先通过准确率至少 80% 的资格测验；因偶发 API 失败，各对比的有效样本数不等。「Both are good / bad」计为平局。指标是 Bradley–Terry Elo（由两两胜负拟合出的分数）。结果均为厂商自报：1.6 = 1068.1，排第 2；闭源 OmniHuman-2.0 = 1236.7；1.5 = 1051.8；其后是 HeyGen 908.1、OmniHuman-1.5 880.6、Kling Avatar 2.0 854.7。直接对阵里，1.6 对 1.5 得到 55.6% 对 44.4%（2,535 票）；对 HeyGen、OmniHuman-1.5、Kling Avatar 2.0 分别为 72.2%、73.5%、76.6%；对 OmniHuman-2.0 只有 24.7% 对 75.3%。作者认为差距可能部分来自 OmniHuman-2.0 会增强参考图细节，而 1.6 更接近原图（Fig. 6，物理第 10 页）。摘要「outperforms … competing commercial … models」须以这次第 2 名为准。

**Fig. 8 与 §5（物理第 12–13 页）。** 与 1.5 做绝对分对比：508 组图像–音频对、270 名参与者、1–5 分、每个视频 three-annotation protocol，并过滤无效标注。结果均为厂商自报。总体 3.006→3.322，写实 3.083→3.441，动画 2.246→2.114（作者认为 OPSD 训练集中长动画较少，可能造成动画泛化略降）。专家问题率：一致性 19.9%→11.6%，音频–表情不匹配 13.0%→6.7%，唇色或分辨率 3.1%→0.0%，唇同步 83.7%→82.5%（0.5 倍速严查，作者说明因此基数偏高）；图中另有不自然表情过渡 8.9%→6.5%、角色属性变化 1.4%→0.4%；正文还写说话人数不匹配 18.5%→11.2%。写实观感和若干一致性指标有改善，但唇同步几乎没动，动画还略降。

「超过 10 分钟」为摘要与 §6 的厂商自报。Fig. 2（物理第 5 页）选帧时间戳最高为 09:56（Frame 14900），是演示选帧，不是反证，也不是独立时长证明。Arena 里每条视频有多长，原文未写。

**水分检查**：全部 Arena、人类像真和专家问题率都是厂商自报，不是第三方独立评测；没有误差条或多种子，也没有把各改动的贡献拆开。商业闭源基线因 API 失败而样本数不等，算力是否对等未知。换到动画或你自己的场景，报告已经显示可能不升反降。

## 5A. 训练配方与架构

**数据**：大体复用 1.5 的数据和整理框架，来源包括特写、访谈、表演、人与物体互动、音乐演出和风格化内容（第 3 节，物理第 8 页）。规模、时长和配比官方未披露。GRPO 用「参考图 + 音频 + 文本」条件；少步蒸馏用对齐好的短片段并过滤口型不同步和画质异常；OPSD 用约 20 秒、目标 25 帧/秒的连续说话视频，同时包含脸部裁剪和原构图。

**预训练**：官方未披露 1.6 的总参数量、激活参数、预训练算力和上下文窗口。报告只写两路后训练都从「已训练好的音频驱动视频模型」出发，训练管线跟随 1.5，后训练时基座冻结（§2.1，物理第 4 页）。GitHub README 写基础模型 LongCat-Video 为 13.6B parameters，不得自动当作本报告已披露的 1.6 规模。中训练或长上下文扩展：本报告未写单独阶段。

**架构**：官方未披露 1.6 的层数、隐藏维度或是否为混合专家。能确定的是后训练共用冻结的 DiT 主干，只训轻量 LoRA（§2.1、§2.3.1，物理第 4、6 页）。

**后训练**：即本报告的重点。GRPO 支路按组内相对优势更新，并对冻结参考策略加 KL 约束，只优化该路 LoRA（§2.2 / 式 (2)，物理第 4、6 页）；奖励模型细节官方未披露。蒸馏支路用 DMD2 把 50 步蒸到 8 步，600 步停止，学习率 \(2\times10^{-5}\)（生成器）和 \(4\times10^{-6}\)（fake-score），更新比 1:5，CFG 路径为 \(00\rightarrow 0T\rightarrow A0\)、强度 7 和 3（§2.3.1，物理第 6–7 页）；随后做长视频滚动生成，再用改编自 OPSD-V 的上下文替换和 EMA 教师做 OPSD（§2.3.2–2.3.3，物理第 7–8 页）。

**推理时计算**：每段 8 步去噪；报告写推理时合并 GRPO LoRA 与 OPSD LoRA。延迟、吞吐和显存官方未披露。

披露程度一句话总结：后训练步骤和若干超参数写得比较清楚，最值得学的是「冻结基座上分两路 LoRA、一路管观感、一路在自己续拍历史上做自蒸馏」；数据规模、奖励模型、基座规格和预训练算力几乎未披露。

- Avatar Arena：33,051 次有效两两投票、15 种模型配对、评测集为 EvalTalker 的 508 组图像–语音对；标注员须先通过准确率至少 80% 的资格测验；因偶发 API 失败，各对比的有效样本数不等。「Both are good / bad」计为平局。Fig. 1 与 Fig. 5 票数加总与 33,051 一致。Bradley–Terry Elo（Fig. 1 / 物理第 1、10 页）：1.6 = 1068.1（第 2），OmniHuman-2.0 = 1236.7，1.5 = 1051.8。

## 7. 你可以怎么落地

**今天就能试**：克隆官方仓库，按 README 下载 1.6 权重，用官方示例跑一条「图像 + 音频 → 视频」（命令里带 `--use_distill`，并按文档指定 `--lora_path`）。验收：用你自己的人像和语音，并排看口型是否自然、嘴唇颜色会不会在一两分钟内明显变红；不要把 Arena 的 Elo 当作自己的验收指标。

**要有数据或机器再试**：先准备完整权重的磁盘空间（HF 仓约 72.29 GiB）和能跑通官方示例的 GPU。官方示例使用 2 张 GPU；最低显存原文和官方 README 均未写，不要按猜测去买卡。阶段一先跑短片段确认环境；阶段二做数分钟续拍，检查颜色漂移和身份；阶段三若业务偏动画，要单独回归，因为报告里动画像真分是下降的。可选的 INT8 权重和 FP8 / 编译加速可作降成本的下一步，但不是报告里的正式对比。

**暂时别碰**：不要仅凭这篇厂商自报榜就替换已在用的商业数字人接口，也不要假定已发布的两个 LoRA 文件名与报告里的 GRPO、OPSD 一一对应。不要自己从零复现后训练：数据、奖励模型和训练代码并不构成完整配方。也不要把项目页演示素材直接拿去商用——那条限制不是 MIT 正文，但演示素材本身另有声明。

## 8. 和你已有知识的挂钩

它像给已经训好的发动机再插两张「插件卡」：一路用强化学习把表演调得更自然，一路先把生成从五十步蒸到八步，再在模型自己续拍出来的历史上做蒸馏，减轻越拍越走样。和只做片段级少步蒸馏最大的不同是：它故意让模型在自己不完美的历史里继续学，而不是只在真实视频的上下文上练习（§2.3.2–2.3.3，物理第 7–8 页）。

## 9. 存疑与代价

**局限**：作者承认动画像真分可能略降，唇同步在 0.5 倍速严查下问题率仍很高、改善很小（Fig. 8，物理第 12 页）。读出来的——没有消融；奖励模型不透明；GRPO LoRA 与已发布 `loraA` / `loraB` 的对应未解释。GitHub 与 Hugging Face 对默认 `--mix_steps=4 --mix_alpha=1.0` 的说明也不完全一致，使用时以实际代码为准。

**复现条件**：推理代码与权重公开，许可以 GitHub MIT 为准；HF 仓无独立 LICENSE 文件。数据、奖励模型和完整训练脚本未构成可完整复现的配方。

**成本**：训练 GPU 时官方未披露；无官方 API 价格，成本是磁盘与 GPU 时间。最低显存官方未写。

**出处**：厂商 PDF，未经同行评审，也不是已发表的 arXiv 预印本（eprint 为空）。作者均来自 Meituan LongCat Team。文件时间为 2026-11-13，GitHub 新闻条目为 2026-11-15。

**三个决定你要不要动手的问题**：

1. 在你自己的写实或动画素材上，像真和唇色在续拍数分钟后是否仍稳定？
2. 只使用已发布的 `loraA` / `loraB`，能否达到报告归因于「GRPO + OPSD」的观感？
3. 在官方未给最低显存和时延时，你能否承担约 72 GiB 下载和多卡推理成本？
