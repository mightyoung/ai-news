## 1. JOLT：同一模型兼任师生的自蒸馏 + RL（Perplexity × NVIDIA）
- 帖子：https://x.com/perplexity_ai/status/2112978260808376411 ；转发：https://x.com/AravSrinivas/status/2113013527418146913
- 论文：https://arxiv.org/abs/2610.10447 （Perplexity 博客当时返回 Cloudflare 验证，未能直读）

**结论**：「同一模型师生兼任、老师看到额外信息、老师也被训练」与论文一致。「MATH 上少 6.5× 训练 token 追平 GRPO」有出处但口径很窄【自报】：
- 模型 Qwen3-0.6B；比较点是 GRPO 学习曲线拐点 63.44%，不是 GRPO 最终成绩；
- JOLT 预算由拟合曲线反推，无置信区间；按 completion token 算是 13×；换目标准确率为 4.3–7.4×。

**机制**：老师拿特权信息（参考解、verifier、执行反馈），以「自身 outcome reward + 朝学生的 token 级 KL」训练，避免走学生学不会的捷径；学生在自己的轨迹上接受老师逐 token 稠密监督；两个角色共享参数。JOLT+ 再给学生加 outcome reward。token 计数含老师生成和打分 pass，论文自述不等于墙钟时间节省。

**结果（JOLT+ vs GRPO）**：MATH 72.6 vs 68.4；LCBv6 49.1 vs 46.1；AppWorld 72.1 vs 62.2；Terminal-Bench pass@1 11.0 vs 8.3（单次运行）。纯 JOLT 在 AppWorld、Terminal-Bench 上低于 GRPO。

**落地**：有参考解、verifier 或执行反馈的后训练任务。
**风险**：效率结论只在小模型、单数据集上测；多数设置仅 3 个 run；未见代码；「convincingly beats」措辞偏强。

## 2. Flint 与 Eureka Machine（Recursive，Richard Socher）
- 帖子：https://x.com/RichardSocher/status/2112944385415426249 ；Thom Wolf：https://x.com/Thom_Wolf/status/2112967683813609724 ；Unsloth：https://x.com/UnslothAI/status/2113046042908541083
- 博客：https://www.recursive.com/updates/introducing-recursive-flint ；模型卡：https://huggingface.co/RecursiveSI/flint （无技术报告）

**结论**：39.8B 总参 / 约 2.5B 激活（含输出头，主体约 2.2B）、Apache-2.0 已核实。
- 「Mac 125+ tok/s」【自报】：M4 Pro 48GB、自家 rec 引擎、MLX INT4、短上下文；博客图注另按 128k 会话平均，口径不同。
- 「24GB 能跑」【第三方·Unsloth】：3-bit UD-Q3_K_XL、短上下文；Recursive 自家 GGUF 要求 48GB。
- Thom 的「lm_head 4-bit 只差 0.7」：原文是整模 NVFP4 + 离线自蒸馏恢复后 6 项基准平均差 ≤0.7（按表算 0.6，单项最多 1.2），不是 lm_head 单独量化；Mac 用的 INT4 无公布分数。

**机制**：49 层（2 dense + 47 MoE），每层 256 专家选 6 + 1 共享；35 层滑窗 513 + 14 层全注意力。激活参数少，lm_head 在每 token 读取权重中占比大，量化它提速明显【推断】。

**Eureka Machine**：Recursive 的自动化研发闭环（想法→实现→实验→验证），官方称参与架构搜索、量化方案、Metal/RTX kernel、训练配方；无技术报告、消融或人机分工说明，「4 个月从零」与自动化研究基本【自报】。

**落地**：离线、数据不出机的本地编码 agent（可接 opencode / pi）。
**风险**：基准自测（SWE-Pro v2 89.7 偏高）；上下文 262K（模型卡）/512K（博客）两说；量化版逐项损失未公布。

## 3. php2shell 与 Patch the Planet（OpenAI）——仅防守侧
- 帖子：https://x.com/gdb/status/2112921529650688312 ；https://x.com/OpenAI/status/2112945805686604033 ；https://x.com/OpenAI/status/2112907856018309586
- CISA：https://www.cisa.gov/news-events/alerts/2026/10/21/critical-vulnerabilities-php-require-immediate-patching ；PHP：https://www.php.net/ ；自查工具：https://github.com/openai/php2shell-checker

**结论**：CVE-2026-109618（OOM 处理致内存损坏）与 CVE-2026-109619（跨请求残留状态致 UAF），CVSS 9.2，影响所有处理 web 请求的 PHP，mod_php 风险最高。立即升级到 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35；8.1 及以下找发行版 backport 或先下线。官方称无完整缓解，WAF 只能临时用。

**时间线（CST）**：7/30 Calif 开始审计；8/11 Calif 与 OpenAI 同日各自独立报告同一根因；9/18 OpenAI 补充更多攻击向量；10/20 23:00 CVE 编号泄露；10/21 22:00 发布（提前一天）。

**模型作用**：「Calif 用 GPT-5.6 Sol 发现」仅 OpenAI 说法【自报】，PHP 基金会只记研究者姓名；Wiz 也独立发现。gdb 称 OpenAI 9 月发现，与基金会记录的 8/11 不一致。「70% 网站受影响」为 OpenAI 估计。

**自查工具**：被动版本比对。URL 模式只发 HEAD、读 Server / X-Powered-By；服务器模式查 `php -v`；明确禁止利用探测。
**安全用法**：只扫自有或已授权资产；UNKNOWN ≠ 已修；OK 只是比版本号，需用服务端包版本对照发行版公告复核；优先处理外网 mod_php。
**风险**：Cloudflare 称发布前已见攻击，CISA 称未观察到，建议按已被利用处置；隐藏版本头会漏判。

## 4. Prompt 缓存：API 12 小时 + Codex/Work「永久缓存」（Tibo）
- 帖子：https://x.com/thsottiaux/status/2112712984644784534 ；文档：https://developers.openai.com/api/docs/guides/prompt-caching

**结论**：
- API 12h 仅 GPT-5.6 及以后、Responses API，需显式 `prompt_cache_options.ttl: "12h"`（默认 30m），可按断点单设。
- 价格：12h 写入 = 未缓存输入 2.5×（30m 为 1.25×）；读取 0.1×（Sol 0.05×）。12h 为最短寿命，文档写明不保证每次复用 KV。
- Codex/Work「登录用户永久缓存、恢复旧会话保证命中」仅 Tibo 帖子【自报】，无文档，且与 API「不保证命中」措辞冲突；更可能是订阅侧计量不再惩罚未命中，而非物理永久存储【推断】。

**机制**：缓存存前缀 KV 状态，前缀完全一致才复用；TTL 决定多久内按缓存价读取。

**对 10/19 A 条的更正**：
1. 「ttl 只支持 30m」已过时。
2. 长空档不必保活：12h 写一次（2.5×）= 30m 写两次，12h 内过期重写 1 次即打平，≥2 次 12h 更省；保活 12h 需 ≥24 次读（≥2.4×），不划算。
3. 12h 至少读 2 次才比不缓存便宜（2.5 + 0.1n < 1 + n）。
4. 订阅侧 TTL 由「未公开」改为「自称永久，待验证」。
5. 30m 的 1.35× vs 2× 算术仍成立。

**落地**：稳定的系统提示、工具定义、参考资料用 12h 断点，动态尾部保持 30m；人工审批类长空档用 12h。
**风险**：写价翻倍，复用不足更贵；「保证命中」无条款（删会话、换模型、压缩上下文后是否算命中未说明）；需用 usage 中 `ttl_12h_tokens` 实测。
