**标题 / 链接**

随着模型自主干活变多，人的工作上移到**监督与理解**；Karpathy 给出一条递进的「可理解性格式栈」——从 **ASD-STE100 受控英语** → **图** → **交互 HTML** → **3b1b 风格讲解视频**——用可丢弃的大件软件制品（web app / 视频）把理解成本压下去。

**ASD-STE100 公开背景（官网，非帖文）**  
- 官网：https://www.asd-ste100.org/ —— **controlled natural language**，国际技术文档标准；由 ASD（Aerospace, Security and Defence Industries Association of Europe）完全拥有；STEMG 维护。  
- 起源：1970 年代末起为航空维修文档易读性开发；1986 出 AECMA Simplified English Guide；2005 成国际规范；公开页称 **2025 成国际标准**。  
- 结构（官方 PDF / ASD 页公开描述）：**写作规则（part 1）+ 受控词典（part 2）**；当前可申请免费官方副本为 **Issue 9（January 2025）**。  
- STEMG 另有白皮书讨论 AI 与 STE：强调「看起来像 STE ≠ 已合规」，需人工监督。

### 机制拆解

1. **可理解性是新瓶颈，不是生成能力**  
   帖文前提是模型会做越来越多腿部工作；人侧稀缺的是**弄懂产物是否对、为何对**。格式策略是把「理解」产品化，而不是再堆一层更长的自然语言报告。

2. **ASD-STE100 = 强约束编码，降低歧义带宽**  
   受控语言用「一词一义 + 短句/主动态」类规则压缩风格自由度。对 LLM 而言等于外挂风格约束器；「80% STE」是在严格与可读之间做温度旋钮——与 prompt 里写「简洁」不同，它指向**可指名的外部规范**。

3. **模态上移：文字 → 图 → 交互 → 时间轴叙事**  
   每升一层，信息密度与可验证路径变好（图可一眼抓结构；HTML 可点选/展开；视频可按时序讲因果）。代价是生成成本、评审成本与幻觉面更大（前端 bug、动画误导、配音胡说）。

4. **「可丢弃大件制品」经济学**  
   过去做定制 web app / 讲解视频 ROI 不够；代码与智力变便宜后，**一次性理解工具**可以像草稿一样扔掉。这与「永久产品」工程纪律相反：默认假设制品是探针，不是资产。

5. **人的工作面上移到监督层**  
   与 Chollet「只指挥 LRM」（见 09-29 稿 §3 指针）同向：人手不在行级生成，而在验收标准、格式闸门与理解闭环。

### 工程落地（8 条）

1. **团队默认解释协议**：关键决策输出强制走「STE 摘要 → 结构图 →（可选）HTML 看板」三级；禁止只交无结构长文。  
2. **STE prompt 模板**：固定引用 ASD-STE100（或「80% STE」）+ 禁止未批准术语表；术语白名单与业务词典对齐。  
3. **图优先验收**：设计评审先看图是否覆盖接口/数据流/失败路径，再读正文。  
4. **HTML 产物沙箱**：模型生成的 HTML/JS 仅在隔离预览打开；禁止直接挂生产域或带密钥的页面。  
5. **讲解视频流水线试点**：选题限定「新人 onboarding / 事故复盘」；配音用自有 TTS key 或本地替代；成片进知识库前人工过一遍关键帧。  
6. **制品 TTL**：理解用 web app / 视频默认 **7–30 天过期**或不进永久仓，避免「可丢弃」变「无人维护遗产」。  
7. **理解检查清单**：看完制品后强制回答 3 个可证伪问题（边界条件、失败模式、与现有系统差异）；答不出则退回上一级格式。  
8. **成本记账**：视频/重前端生成单独记账 token 与外部 API（ElevenLabs 等）；与「纯文本解释」做 A/B，只保留理解增益明显的路径。

### 风险

- **STE「看起来合规」≠ 真合规**：STEMG 白皮书已警示 AI 文本可伪装 STE；若用于安全关键文档，仍需人工对照规则/词典。  
- **HTML/视频幻觉更难一眼拆穿**：动画与 UI 权威感强，错误结论包装得更像「产品」。  
- **ElevenLabs 等外键泄漏**：帖文示例要求把 API key 交给 LLM 会话——工程上应走密钥代理，勿贴进聊天。  
- **「可丢弃」文化侵蚀审计**：若合规场景需要留痕，TTL 策略要例外。

## 2）Chollet — LLM→LRM：从猜答案到猜程序 ★

**标题 / 链接**  
- François Chollet（@fchollet）：The critical distinction between base LLMs… and modern LRMs…  
  https://x.com/fchollet/status/2105729206273634696  
- 对照指针（勿重发旧文）：09-29 稿 §3「只指挥 LRM」https://x.com/fchollet/status/2104598248501699067

**一句话结论**  
Chollet 把 base LLM 与现代 **LRM** 的关键分野钉在范式上：**transductive（直接直觉答案）→ inductive（直觉出能产出答案的程序/自然语言推理链）**；并称这解锁了 base LLM 几乎没有的**流体智力**——用 ARC 1 数字对比「狂缩放 LLM」与「同规模或更小 LRM」的差距。

**与「只指挥 LRM」论述的接点（指针，不重发）**  
09-29 稿已拆：停手写/精读不是因为 LRM 完美，而是测/审计/可视化/red team 新工作流 ROI 更高。本帖补的是**能力机制**：为何指挥推理链/程序比指挥「直接答」更值得——因为 inductive 范式才带来流体智力面。

### 机制拆解

1. **Transductive vs inductive 是接口契约，不只是营销名**  
   Transductive：查询 → 答案（模式匹配/记忆检索主导）。Inductive：查询 → **可执行/可检查的中间程序**（自然语言推理链、伪代码、工具调用计划）。工程上应把 LRM 输出默认当作「待运行的程序草稿」，不是「最终事实」。

2. **Test-time induction = 把搜索算力花在「程序空间」**  
   训练 inductive + 测试时再生成程序/链，等于在推理时做程序搜索。这与「同参数量下更会背答案」不是同一轴；也解释为何 Chollet 强调区分点**不是**有没有 symbolic tools。

3. **流体智力叙事与 ARC 作为压力测试**  
   ARC 1 被用作「新颖规则归纳」探针：狂缩放 base LLM 仍卡在低双位数，而 LRM 饱和——作者用以支撑「流体智力从无到有」。选型含义：若任务像 ARC（少样本、新规则、需程序），优先 LRM 轨迹而非更大 base 补全。

4. **与「只指挥」工作流闭合**  
   若模型强项是出程序/链，人的杠杆在：**定义成功程序的验收器**（测试、不变量、可视化探针），而不是润色最终自然语言答案。

5. **Tool use 被降级为非本质**  
   有工具的 base 模型仍可能是 transductive（用工具查到答案）；无显式解释器的 LRM 仍可能 inductive（在 NL 里写出程序）。评测时要拆「会不会调工具」与「会不会先写对程序」。

### 工程落地（8 条）

1. **输出契约改写**：对推理型任务，API/产品层要求结构化字段：`plan | program_or_chain | answer | checks`；禁止只收 `answer`。  
2. **程序优先评审**：Code review / 设计评审先评「中间程序是否可执行、可测」，再评最终结论。  
3. **ARC 类任务路由**：少样本规则归纳、新 API 编排、未知故障树 → 默认走 LRM/长推理档；纯检索 QA 走便宜 base/RAG。  
4. **流体智力烟雾测**：维护一小撮「规则在题面内、训练集外」的内部题（勿泄露进训练语料）；回归 LRM 更新时跑。  
5. **Test-time 预算单列**：induction 轨迹的 token/延迟单独 SLA；与「直接答」档价目表分开，避免财务把两者当成同质商品。  
6. **验收器 > 更好的 prompt**：配套属性测试、差分测试、可视化断言；对齐 09-29「生成 + 双探针」。  
7. **失败模式分类**：区分「程序错」「程序对但执行错」「答案对但程序不可复现」——三者对策不同（重写链 / 修工具 / 禁用不透明捷径）。  
8. **厂商话术对照**：销售说「tool-using agent」时，追问是否 **trained for induction / test-time reasoning chain**；勿被「有插件」带偏。

### 风险

- **ARC 数字为作者主张**：10–15%、100,000×、2025 饱和等 **未在本交接做独立复现**；引用须标注来源为 Chollet 帖。  
- **「LRM」标签通胀**：厂商可能把任何长链 CoT 叫做 LRM；需以行为（是否稳定做 test-time induction）为准。  
- **程序幻觉**：看起来像程序的链可能不可执行或偷偷特判；没有验收器时比「直接猜错」更危险。  
- **组织误读**：把「base ~0 fluid intelligence」听成「旧模型无用」——检索/写作/翻译等 transductive 任务仍可能是正确档。

### 机制拆解

1. **阻抗失配：换问题形状，而不是只换 prompt**  
   科学家要「像同事一样想概念」；模型强在编码、广度、可检查计算与跨域模式匹配。对齐方式是选 **agentic-AI-shaped** 题（可验证、需拼工具、需跨文献），不是逼模型演人类 PI。

2. **BootLoops = 科学版 harness，不是聊天插件**  
   把分散在 Wolfram/C++/Python/Julia/无代码论文中的方法 port 进共同框架 + 协议（测试、验收门、标准）。harness 与底座模型解耦，社区可迭代工具而非只等 frontier 实验室。

3. **可检查性是自动化的许可条件**  
   半数值 bootstrap、任意精度对打、球算术/证书等，使 agent 难以「口头胜利」。没有数字对打的领域，文中路径是：迁到可检查子问题，或强依赖人类专家品味。

4. **「技术正确 → 科学有趣」必须有专家闸**  
   Claude 常给出技术成立但领域内「shrug」的结果；专家把目标函数从「算得出」改成「领域在乎的残差/相关/机制」。人的稀缺技能是 **taste + 问题重写**。

5. **跨域 = 同一积分/同一算法的再钉钉子**  
   扩散/贝叶斯证据/有限域约化等在生态、系统发育、经济复制包中重复出现。价值来自 **工具复用 × 机器阅读广度**，不是单域天才洞见。

6. **失败模式被写成操作纪律**  
   宣布胜利过早、无时间感、爱硬算不爱造工具、compaction 丢上下文、结论跳跃、品味差——对策是刚性成功标准、人看图、追问结论、人供 taste、防 grind。

### 工程落地（8 条）

1. **先做形状审计**：立项时问「是否可检查？是否有跨域锤子？是否需造工具而非多日硬算？」三否齐则不要当全自动科学 agent 题。  
2. **验收门写进 repo**：数值对打位数、独立脚本复现、SHA 预承诺预测（站点所述反 reward-hacking 思路）——合并前必须绿。  
3. **专家闸流程**：模型初果 → 领域专家「shrug 测试」→ 共同改写问题 → 再跑；禁止跳过专家直接发新闻稿。
