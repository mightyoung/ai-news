## 1. Anthropic Frontier Red Team：用 Claude 做大规模形式化验证

**链接**
- 帖：https://x.com/AnthropicAI/status/2113390212911083894（创建 10/22 22:01 UTC = **10/23 06:01 CST**）

- 合作方：Theorem（https://theorem.dev/）；证明子集 https://github.com/theorem-labs/oss-verify-proofs；语义 https://github.com/theorem-labs/rocq-linux-process-semantics；管道/skill https://theorem.dev/oss-verify/

**帖子说法 vs 原文**

| 说法 | 原文 | 标签 |
|---|---|---|
| 「over one hundred」真实开源库、几周 | **123** 个 OSS-Fuzz 库、**239** 个入口；「over the span of a few weeks」 | 帖子四舍五入，数字以报告为准【第三方：报告】 |

| 证明安全性质 / 无某些 bug | 证明的是：在假设下，入口对任意 <64MB 输入**不触发 crash**（fault / abort / 未建模行为），含 ASan 与断言 | 帖子偏宽，需带限定 |
| 证明器 | **Rocq**（主 OSS-Fuzz 二进制路径）。附录另有 Rust+**Verus/Z3** 的 Python 解释器探索；**不是 Lean/Isabelle**（文中 Lean 只作 Mathlib 类比） | 【第三方】 |

**规模与工具链（已对照报告+附录）**
- 对象：Google OSS-Fuzz 中 C/C++ 入口，编译为 **RISC-V** 可执行文件，用 Theorem 的 RISC-V 指令语义 + Linux 进程语义建模。
- 成功：239 入口 / 123 库；通过校验约 **1.8 亿行 Rocq**；典型单入口证明约 **60 万行**、约 1400 文件；二进制中位长度约 1.8 万条 RISC-V 指令。尝试过程累计约 **10 亿行** Rocq，其中 1.8 亿进入通过校验的证明【自报：附录】。
- 三条定理逻辑（附录）：(1) ASan 版不崩溃；(2) ASan 版与普通版在 stdin/stdout/stderr/退出/文件系统轨迹上等价；(3) 普通版也不崩溃。轨迹定义**不含**「为何崩溃」本身，静默死循环也可能被当成轨迹结束。
- 人机分工：Claude **自主**写证明并在迭代中打补丁；人类/Theorem 提供语义、规格管道与审计。原文：海量证明「virtually none…needs to be manually reviewed」，因 Rocq 检查规格满足；但对补丁做了惩罚与**人工审计**，防止把程序改成平凡永不崩溃（reward hacking，脚注 6）。专家附录评价：证明冗长、少抽象，与人类证明工程师风格不同。

**必须写明的四条限定（报告 Limitations + 附录；群发/简报均保留）**
1. **不等于「无 bug」。** 原文：「Formally verified」does not mean「bug-free」。剩余问题要么在可信底座里，要么在证明范围外。
2. **保证只在假设下成立：** 单线程、静态链接（文中 musl）、固定内存预算、输入 <64MB、RISC-V + 其建模的 Linux 语义。多数真实部署是 x86/ARM + glibc 动态链接——不在当前证明内。
3. **可信底座：** RISC-V 与 Linux 进程形式语义、被证明的定理陈述、Rocq 校验器（脚注 5 还点到硬件、OS、Rocq 所依赖的 OCaml 编译器）。
4. **证明大半是工具自动生成的表。** 附录：「Over half of each proof is machine-emitted by tools Claude wrote for itself (instruction encodings, lookup tables)」；约 40% 为证明正文，其中一部分仍由脚本生成。单次检查可耗 30 分钟到数小时 CPU。

**对安全/代码正确性的意义（防守侧）**
- 把「fuzz 永远找不完」变成「该入口在模型语义下对有界输入无可达 crash」——可减少对该入口的持续 fuzz CPU【推断+原文意图】。
- 发现并修补了多年 fuzz 未出的 bug（【自报】；未修漏洞相关证明不公开）。
- 工程路径：二进制级通用规格 → 依赖可复用证明（Theorem 谈 Nix 生态路线图）。不等于替代代码审计或调用约定检查。

**旧稿指针：** 无直接同题旧稿。Anthropic 用 Claude 做 Lean 形式化（FLT 等）是另一条 Science 线，勿与本 Red Team 二进制 Rocq 工作混淆。

## 3. OPAL（OPtimizer with an Agent in the Loop）

**链接**
- 帖：https://x.com/RobertTLange/status/2113352327042117692（**10/23 03:30 CST**）
- 项目页：https://xingjianbai.com/reactive-optimizers/（2026-10；作者 Xingjian Bai, Jia-Hao Liang, Jayden Teoh, Vincent Sitzmann）
- 代码：https://github.com/xingjian-bai/opal（**MIT**；`pip install opal-optimizer`；创建约 10/21）
- 作者原帖指针：项目页链到 @SimulatedAnneal 的 X 帖（本任务以 Lange 帖为入口）

**机制：agent 怎么改优化器、看哪些动态**【第三方：项目页+README】
- 包装现有 PyTorch 优化器；代理（文档默认 **Claude Code**，博客实验写 **Claude Opus 5.5**）在决策点重写：
  1. `analysis.py`：自写探针——per-group grad norm、update/weight 比、相邻梯度余弦、尖峰检测等；避免把原始权重塞进上下文。
  2. `updater.py`：每步更新规则——可改每组 LR（含中途升高）、AdamW↔Muon、按张量 bf16/fp32、动量重置、裁剪、门控坏 batch、自做 A/B 等。
- 循环：analysis → 推理 → 更新规则 → 继续训练。**零样本**，无跨 run 元训练。约定不改模型/数据/loss/batch/步数/评估（规则约束，非沙箱）。

**基准与收益**【自报：项目页；多为单次或少数重复】
- 叙事：当任务**没有**针对性调好的配方时，匹配或超过货架最佳。
- modded-nanogpt Track 3 变体（约 162M GPT / FineWeb 系）：换中文/泰/柯尔克孜或 1/4 batch；对比排行榜配方（#2 AdamW、#21 Shampoo、#36/#30/#46 等 Muon 变体）。
- Goldfish Amharic（125M，10 epoch）：官方 AdamW 配方 held-out **83.48** → OPAL **81.11** bits/sentence；从扫参最优再启 OPAL → **80.73**。
- LightningDiT-XL/1 ImageNet：FID-50K 有 guidance **1.83 vs 2.18**，无 guidance **4.33 vs 5.15**。
- RAEv2-B：**3.19 vs 3.39**。
- 代价：同步等待代理时墙钟约 **1.30–4.39×**；不等待约 **1.01–1.14×**。LightningDiT 约 100 决策约 **$6.42**（Opus 5.5 标价）相对约 **74 H100·h**。短且配方已精调时收益变小；多数实验**只跑一次**，引入可复现性噪声。

**是否开源：** 是，MIT。

**与 RSI / 自动化 ML 研究、Sakana 角色**
- 定位：把代理嵌进**已有算法对象**（优化器）做**单次 run 内**在线元调整；博客对比 Luke Metz 等 **learned optimizer / VeLO**——OPAL 用 LLM 预训练里的论文与调试直觉代替跨任务梯度元训练。【推断】属于「自动化优化/AutoML 的在线改写分支」，不是完整「自主科研 RSI」。
- **Sakana：** 发帖人 Robert Lange 在 Sakana；**不是** OPAL 作者。帖子是技术评论+转发。OPAL 正文与仓库**未出现** Sakana。勿与 Sakana Agentic Scientist（另线）混为一谈。
