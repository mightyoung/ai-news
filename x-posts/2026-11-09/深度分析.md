## 1. Anthropic：科研人员怎么用 Claude（经济指数 / 科学应用 · AI Agent）

**一句话结论**：这是 Anthropic Economics 团队用隐私保护分类器，对 2026-08-02～09-30 消费级计划上 **207,049** 次科研相关会话（Claude 128,914 + Claude Code 78,135）做的使用分布报告，并配套 **528** 名偏 AI 活跃的生命/健康科研者调查；报告里最常被引用的「**按现有能力且广泛采用，可承担一项新研究所需研究者时间的 27–52%，中位约 38%**」是 **Scenario 1 的「AI share」（可解放的人类研究者时间占比）情景测算**，不是实测采用率、不是实测节省工时、也不是产出增速倍数。对应的产出加速（acceleration）另算，现有能力情景大约只有 **约 1.35×～2.02×**（艺术 1.35× → 统计 2.02×）。【自报】

### 机制拆解（白话）

**1. 他们实际量到了什么、没量到什么**【自报】
- **量到的**：隐私保护流水线下，分类器只保留「是否科研 / 领域 / 子领域 / 任务」等标签；主样本 = 消费级 Free/Pro/Max 计划、交互式会话（Claude Code **排除** programmatic 用法）；企业/API 批量未纳入。分类器成功赋子领域+任务约 94%【附录】。
- **没量到的**：真实产出（论文数、发现质量）、真实工时节省、真实采用率（全科研人口）、企业部署、实验室机器人闭环。报告自己把后半的加速数字标成 **illustrative scenarios, not forecasts**【自报】。

**2. 使用分布：科学家用在哪**【自报】
- **按领域（相对科研人员数量）**：形式科学（CS / 数学 / 统计）相对偏高；健康与实验物理科学相对偏低。Claude 上会话份额 Top：CS 11.9%、工程 8.4%、医学 7.7%。Claude Code 上 CS 独占 **32.7%** 会话，而其全球科研人员份额约 **4.3%**。AI/ML 子领域：Claude 5.0%、Claude Code 15.2%，人员份额约 1.2%。
- **按任务类别**（相对 SciNet 估计的研究者时间份额）：

| 任务类别 | Claude 会话份额 | Claude Code 会话份额 | 研究者时间份额（SciNet） |
|---|---:|---:|---:|
| 数据分析 | 33.7% | 48.1% | 27.6% |
| 写作与沟通 | 32.0% | （报告强调 Claude 侧偏高） | 16.0% |
| 数据采集 | 11.5% | 11.9% | 28.6% |
| 创意/假设生成 | 4.2% | 2.1% | 7.1% |

- **错配**：调查里受访者把「创意/假设」与「数据采集」评为对重要成果最关键，但这两者在实际 Claude 使用里相对偏低【自报】。
- **Claude Science（专用科研界面）**：生命科学集中；假设生成约占 **8%**（约等于时间份额、约为 Claude 的两倍）；在生物/生医上，>80% 会话估计需博士级训练内容，>70% 高自主度（Claude 约 23.7%、Claude Code 约 64.1%）【自报】。

**3. 「理论 AI 能力分」怎么来的、为何和用量同向**【自报】
- 分类器对 SciNet 各任务的**步骤**做两两比较「AI 更能做哪一步」，再用 Bradley–Terry（类似 Elo）聚成步骤分，再平均成任务分。
- 能力最高 20% 的任务，用量约为按研究者时间预测的 **约 2×（Claude）～4×（Claude Code）**；最低 20%（多含体力）几乎不用。
- 能力分与「适不适合强化学习（可验证、可仿真、反馈快）」指数相关约 **0.78**；与认知型相关 +0.69，与体力型 −0.57，人际 −0.31，监管限制 −0.38【自报】。白话：现在 AI 最会被用在「能反复试、能判对错」的认知步骤上——这正是 RL 友好区。

**4. 头条数字 27–52% / 中位 38%：完整口径（重点）**【自报，附录 “AI share of research work by field”】

这是 **Scenario 1：Current capabilities, if adopted widely** 下的 **AI share**（也可叫 time freed）：

1. **分母**：生产「一项新研究 / 一篇新研究产出」所需的**人类研究者核心科研时间**（SciNet 估计的各子领域核心任务小时；不含教学、审稿等非研究任务）。
2. **分子构造（逐步）**：
   - 把任务拆到步骤；步骤权重 ωⱼ = 该步骤占子领域核心科研小时的份额。
   - 调查五档使用强度 → 假定可解放时间 σ：`none/assistive/shared/delegated/autonomous` → **0% / 25% / 50% / 75% / 100%**。
   - 调查只直接问了四类工作：ideation、data gathering、data analysis、writing；其余任务类别映射：design&development→ideation，theoretical analysis→data analysis，reading→writing，剩余取四类平均。
   - **在每一类内部**，按 AI 能力分从低到高分配档位，使各档步骤占比匹配调查报告比例（例：ideation 最低 17% 步骤 σ=0，接下来 53% σ=25%……）。
   - 体力/人际步骤**不单独剔除**，一样参与排序；但因其能力分低，多落在低 σ 档。
3. **子领域 AI share**：\(S=\sum_j \omega_j \sigma_j\)（**不含** AI 自身运行成本与运行时间）。
4. **领域聚合**：该领域下各子领域 AI share 按 **SciNet 科研人员数量加权平均**。
5. **跨领域区间**：在 **34 个领域**上，time freed 从 **arts 27%** 到 **statistics 52%**，**中位数 38%**【附录原文】。

**它不是什么**（必须分开写）：

| 概念 | 是否等于 27–52%/38% | 说明 |
|---|---|---|
| 真实采用率 | **否** | 样本是 Claude 消费级使用者 + 偏 AI 活跃调查；报告明确把重度使用者的报告当作「现有能力上限」的 **proxy**，再假设「广泛采用」【自报】 |
| 实测节省工时 | **否** | 无前后对照工时日志；σ 来自调查档位的硬编码映射 |
| 产出加速倍数 | **否** | 加速是另一指标，见下节 |
| 「AI 已完成研究的 38%」 | **否**【推断】 | 是「若按现有能力铺开，人类时间可被接手的占比」情景 |

**5. 从 AI share 到 acceleration：为何中位 38% ≠ ~1.6× 加速**【自报，附录 + 正文 Scenario 1】
- 模型：ideas production function（Jones 2026；互补参数 θ≈−1，取 Ahmadpoor & Jones 2019 跨领域中位）。
- 任务互补：AI 把部分步骤变便宜后，研究者会把时间挪到 AI 帮不上的瓶颈步骤，所以总产出增益**小于**「省下时间的倒数」。
- 成本假设（illustrative）：研究者小时工资 w=$95（2023 SDR 中位薪 +28% 福利、2080 小时，换算到 2026 美元）；AI agent 小时 μ=$30（公开 API 标价示意，**不是**实测平均成本）；AI 运行时间 τⱼ=0.2·σⱼ（每省 1 研究者小时，AI 跑 0.2 小时）；质量倍率 qⱼ=1（不假设 AI 产出更高质）。
- Scenario 1 给出的加速例子：arts **1.35×**、anthropology **1.36×**、chemistry **1.41×**、computer science **1.96×**、statistics **2.02×**【自报】。即便几乎全是认知工作的领域，现有能力情景也大约只到 **约 2×**。
- 若有人把 38% 直接换成「加速 1/(1−0.38)≈1.61×」或「加速 1/(1−0.52)≈2.08×」，那是忽略互补与 AI 成本后的**外推**【推断】；报告自己的模型结果才是其主张的加速区间。

**6. 更高自动化情景（仍是情景，不是预测）**【自报】
- Scenario 2：75% 非体力步骤全自动 → CS 约 8×、统计/图书情报约 7×、经济约 6×；实验/医学约 2–3×。
- Scenario 3：100% 非体力步骤全自动 → 少体力领域可到约 **15–16×**；实验学科约 **3–4×**（体力约占研究者时间 ~40% 成瓶颈）。成本假设下全自动步骤成本约降到原来的 1/16，成为加速天花板；更便宜的推理会按比例抬高天花板。
- 调查预期：约 **40%** 受访者预期 2030 年前 AI 可独立做完整项目；约 64% 预期到 2035；16% 认为永远不会【自报】。

### 局限和风险
- **选择偏差**：会话样本 = Claude 消费级用户；调查 = 申请过 Anthropic 科研算力资助的人。把其使用强度当作「现有能力广泛采用」的上限 proxy，可能**高估**一般科研群体的可接手比例【自报承认偏斜 + 推断外推风险】。
- **分类噪声**：领域/任务全靠 LLM 分类器；子领域份额尤其有抽样与分类误差，报告建议看大趋势不看单个低量小子领域【自报】。
- **σ 档位硬编码**：assistive=25% 等是建模约定，不是工时追踪。【自报设定】
- **加速模型假设敏感**：μ、τ、θ、q 任一变化都会移动 1.35×–2.02×；报告称成本假设 illustrative。【自报】
- **未计入**：大装置机时上限、试剂/仪器成本、用仿真替代实验、想法质量提升或下降、机构吸收新论文的能力。【自报】
- **安全与治理**：更少人类监督可能带来危险/不伦理研究方向；生物等领域需刻意保留检查点。【自报 Discussion】
- **与 11-06 简报关系**：简报已正确写了 207,049 / 528 / 「部分领域约翻倍 / CS·统计约 15× / 实验约 3–4×」，但**没写清 AI share 27–52%/38%**，也没拆「时间解放 ≠ 产出加速」。本篇补这一刀。

### 应用清单

**马上能用**
- 读任何「AI 可承担科研 X%」标题时，先问三句：分母是时间还是产出？是实测还是情景？有没有把 AI share 和 acceleration 分开？验收：能口头复述「38% 是 34 领域 AI share 中位，对应加速大约到 2× 封顶（现有能力情景）」。
- 对照自己组里的任务看板：把工作标成「数据分析 / 写作 / 采集 / 假设」四格，先只在前两格加深 AI 介入（与报告用量一致），并单独记一笔「假设生成」尝试次数——因为调查认为它重要但当前用量低。
- 把 Claude Science / 带工具编排的科研 agent 试点放在「需要串多个数据库的机制假说」类任务（报告举蛋白–配体相互作用任务在 Science 上相对 Claude 高 5.6×），而不是先拿去写全稿。

**需要投入**
- 若要估计本机构「潜在 AI share」：用 SciNet 风格拆步骤 → 按可验证性/可仿真性打能力分 → 用五档使用强度做情景表；**同时**用互补瓶颈模型估加速，不要用 1/(1−share)。验收：输出两列数字（share vs acceleration）和假设清单（工资、API 单价、τ）。
- 实验学科：并行投资「自动实验 / 机器人实验室 / 仿真替代」，否则再强的认知 AI 也被 ~40% 体力步骤卡住（报告 Scenario 3）。
- 建立「采用滞后」跟踪：能力到了 ≠ 组织流程改了；报告引用技术扩散与 Productivity J-curve 文献提醒这一点。

**观望**
