### 机制拆解（白话）

**1. 模型本体：一个 2B 的「边想象边动手」的扩散 Transformer**【自报，白皮书 §2，p.5–6】
- 输入：最近 0.8 秒、最多 4 路相机（头部 + 双腕）、224×320、5 fps 的画面；机器人本体状态；一句语言指令。
- 输出：一段未来动作（action chunk）+ 每路相机的未来画面。机器人执行这段动作时，模型并行算下一段。
- 结构：
  - 视频：冻结的 Wan 2.1 视频 VAE（把视频压缩成小的「潜变量」），时间 4 倍、空间每边 8 倍压缩；每帧每路相机 280 个 token，加「这是哪个相机」的视角嵌入。
  - 语言：冻结的 Cosmos-Reason1 VLM 编码指令，主干用交叉注意力读取。
  - 状态与动作：每种机器人一个小 MLP 编码器和一个动作解码器（「每个身体一个小头」）。
  - 主干：单个 2B 参数 Transformer。动作 token 能看到正在生成的**未来画面**，所以动作会「跟着想象走」。
- 训练目标：flow matching（流匹配，一种扩散模型的训练方法），视频和动作各一个损失。部署时视频去噪 1–2 步、动作 2–4 步。
- **Turbo 版**：主干同为 2B，把 VAE 换成 Wan 2.2（空间每边 16 倍压缩，视觉 token 少 4 倍）。RTX 5090 上 38 ms，G1 机器人自带 Jetson Thor 上 124 ms；每秒左右规划一次 1.6 秒的全身动作，交给 SONIC 全身控制器以 50 Hz 执行。
- 白话：传统 VLA（视觉-语言-动作模型）直接从画面映射到动作；WAM 先「脑补」接下来会发生什么画面，再给出让画面成真的动作。好处是人类视频（没有机器人动作）也能用来学「物理会怎么演变」。

**2. 训练配方：三阶段预训练 + 三种 RL 后训练**【自报，白皮书 §4.1–4.2、§5，p.14–16、27】
- 预训练（1,024 张 GB300，DeepSpeed ZeRO-2 数据并行）：
  1. 单视角视频预训练：主要用人类第一视角视频，只学「预测未来画面」，建立物理直觉。
  2. 多视角视频-动作联合训练：加上各机器人的状态/动作模块；人类视频用追踪到的手部姿态当动作监督。
  3. 机器人数据加权：继续联合训练，但提高机器人（尤其 YAM 机械臂）数据比重。
- 数据配比：402,730 小时人类视频（约 1,375 万段、5.15 万名采集者）、10,184 小时 UMI 手持夹爪（94.2 万段、2,897 个任务）、23,500 小时遥操作（YAM、Franka、Sharpa / Wuji 灵巧手、Unitree G1）。另有 3,000 小时「机位、速度都对齐机器人」的棚拍人类数据。
- 人类视频规模消融（p.15–16）：0% → 1% → 10% → 100% 人类视频，72 个 Dexter 任务真机成功率 18% → 41%，视频推演成功率 30% → 51%，100% 处还没饱和。注意 0%→1% 那步还包含共享的人类视频预训练阶段。
- RL 后训练（本条最值得学）：
  - 探索方式：把动作去噪从确定性改成 CPS（Coefficients-Preserving Sampling，在去噪中注入噪声）采样，**只给动作加噪、视频去噪保持确定**。
  - 目标函数：GRPO 风格的组内相对优势（同一情境采样一组、组内比较好坏），但基线还「记住」每个情境过去的回报，这样**全成功或全失败的组也有学习信号**。
  - 这个配方的基础是 **AutoRL 研究 agent 在仿真里自主迭代约 35 天找到的**（§4.1、F.2）。
  - 另两种做法：GRPO 诱导的自我模仿（只拿 GRPO 成功轨迹再 SFT 一轮）；残差 RL（冻住 GR00T 2，只学一个小修正策略）。
  - 真机结果：4 个高接触任务从 SFT 后 40–76% 提到 88% / 98% / 94% / 96%（每柱 50 次，Wilson 95% 区间）。
  - 不用真机的 RL：用 DreamDojo 世界模型 + 学到的「完成检测器」当奖励。

**3. X-Adapt：没在这台机器人上演示过的任务怎么学会**【自报，白皮书 §3.2、§4.4，p.8–9、17】
- 核心配方（三件套）：
  1. **任务从哪来**：不用机器人录的演示（人戴手套和头/腕相机、手持 UMI 夹爪、DexUMI 外骨骼、或一段人类视频）。
  2. **身体从哪来**：目标机器人「与任务无关」的玩耍数据（play data），告诉模型这台机器长什么样、怎么动。
  3. **怎么连起来**：跨身体联合预训练。因为模型会预测画面，它在训练后能「想象出自己的手」完成人做过的步骤。
- 四种来源：

| 来源 → 目标机器人 | 关键处理 | 结果（真机）【自报】 |
|---|---|---|
| 人（动捕手套 + 头/腕相机）→ Dexter（Tianji + 22 自由度 Sharpa 手） | 闭式 IK 离线重定向到 7 自由度臂和 22 自由度手；视频不改；与 play 数据 1:1 混合 | 化学实验铺滤纸 65%；四个化学任务都能成功（每任务 20 次） |
| 手持 UMI 夹爪 → YAM 机械臂 | 对齐 YAM 相机几何和动作空间；每任务 41–75 条演示、零遥操作 | 玩具卡车组装 60%、NIST 板拆解 50%、传送带分拣 86% 物品；基线两项长任务都是 0 |
| DexUMI 外骨骼 → 对应灵巧手 | 外骨骼复刻机器人手的关节，还记录指尖力；**这种情况不需要 play 数据** | 早餐、划火柴点灯等 60–80%；GR00T 1.7、π0.5 全 0 |
| 一段人类视频 → 仿真 → 真机 | 重建物体和手-物运动，仿真里训 RL 专家，再在随机化的仿真轨迹上微调 | 敲钉子 10 次成 9 次 |

- 不做跨身体预训练时，同样的后训练数据效果明显变差（§B.1.5）。基线（GR00T 1.7、π0.5、LingBot-VA）用的是相同后训练数据。
- **口径提醒**：X 帖说「zero-shot 部署到多种真机」。白皮书的意思是「目标机器人上**没有这个任务**的遥操作演示」，但仍需要：目标机器人的 play 数据（DexUMI 除外）、人或设备采的任务演示、以及后训练。不是「拿来直接零样本用」。【推断，依据白皮书原文】
- 另有一组真正的「零样本」数字（§3.1）：50 个目标机器人从没见过、但在其他机器人或人类视频里出现过的任务，零样本 40%；每任务 1 条演示 71%；5 条（不到 3 分钟机器人数据、单张 RTX 5090 LoRA 30 分钟）95%。**白皮书自己承认**：这 50 个任务是从「5 条演示能学到 ≥80%」的任务里挑的，所以 95% 「部分由构造决定」（p.8）。

**4. System 1 + agent 的分层架构**【自报，白皮书 §3.4、G，p.10–13、Fig. 6】
- 分工：前沿多模态 agent 当 **System 2**（决定「做什么」：拆任务、查进度、写代码）；GR00T 2 当 **System 1**（决定「怎么做」：难以写成程序的高接触操作）。
- 运行时（Fig. 6）：agent ↔ MCP 工具服务器 ↔ 执行后端。工具包括 `wam_act` / `stop_wam`（调用或停止 GR00T 2）、`get_image`、`get_robot_state`、`localize_object`，以及 CaP（code-as-policy，用代码写的技能）原语 `move_to_pose`、`set_gripper` 等；感知用 SAM3、运动规划用 cuRobo；agent 的提示由 AGENTS.md / SKILL.md / task.md 组成。
- 四种配合：
  - Augment（仿真里）：ASPIRE 自动发现任务级程序，每步调用 GR00T 2。加 RL 后在 RoboCasa365 88.0%、RoboDojo 75.8%（只测了三个官方布局库中的一个），截至 11-06 两个榜都第一【自报】。
  - Assist（真机）：GR00T 2 主力执行，agent 盯着，掉零件或卡住时用 CaP 技能修复再交还。零件随机倒在桌上起步、每次 5–14 分钟：玩具飞机 / 拖拉机 / 风火轮 98 / 97 / 97 次成功（各 100 次）；仅 SFT 是 23–69，SFT+DAgger 是 71–84。
  - Guide（视觉指点，WAM API）：agent 在相机画面上标「抓哪、放哪、哪只手」。中期训练时这些点从已有演示的夹爪开合事件**自动提取**，不需要新标注。YAM 上单步指令遵循 40% → 92%，Dexter 30% → 70%；YAM 垃圾分类长任务 0/20 → 17/20。实验用的 agent 是 **GPT-6 Astra**（零样本，每回合一个对话）。
  - Improve：上面说的 AutoRL agent 找到了 RL 配方。
- 白皮书自曝的短板（p.27–28）：
  - agent 慢：一次 agent 回合中位 7.5 秒，策略调用约 0.6 秒，机器人中位有 38% 的时间在等 agent。
  - 自动验证不可靠：8 次长程装配失败里有 3 次是螺丝没拧到位，GR00T 2 和 agent 都判断成「完成」。
  - **安全**：只在「开放问题」里写了「可被 agent 指挥的策略需要自己的物理后果检查，且要跟上动作执行的速率」。白皮书没有专门的安全监控评测。X 帖所说的「safety monitoring」目前只是愿景【推断】。

### 机制拆解（白话）

**1. 「长验证循环」到底是什么**
- 官方原话【自报】：
  - 模型卡：「using more thinking tokens than Gemini 4 Argon to explore hypotheses thoroughly, reason deeply, and run extended verification loops」。
  - 文档：「Runs deeper build-and-verify loops… isolating root causes and checking fixes against tests」；网页开发里「checks both its code and the rendered UI」。
  - 开发者指南第 2 条：「给模型一个验证自己工作的方法」：指向测试套件、导入运行日志、截图看渲染结果，或让它**先写一个可复现的验证脚本、记录基线分，每次改动都跑脚本**，直到全部通过。
- 拆开看就是三层【推断，依据上述原文】：
  1. **模型层**：同一底座（Argon），在推理时花更多思考 token，自己提假设、自己检查边界情况。官方没有披露这是否来自额外的 RL 训练目标。
  2. **工具层**：验证信号来自外部（编译器、测试、截图、日志），不是模型自评。
  3. **多 agent 层**：Antigravity `/swarm` 预览里，Carbon 当架构师 / 协调者 / 审计者，配「对抗性验证者」测每个改动；实现工作交给 Argon 或 3.8 Flash。
- 训练侧唯一能找到的线索（安全报告 §3.4.3.2）【自报】：
  - Carbon 用「推理模型生成的思考轨迹」做 SFT，再做 RL。
  - RL 阶段对思考长度有惩罚（教模型高效思考）。
  - 奖励原则上只评输出，但用来做 token 级信用分配的学习组件会把思考内容当上下文，因此对思考 token 有间接优化压力；Google 审计后认为新加的 RL 配置没有威胁 CoT 可监控性。
  - 首发公告：「进一步抑制训练中的走捷径」，Terminal-Bench 4.0 上作弊成功率 0.0%、作弊尝试 0.4%。
- 【推断】「长验证循环」主要是**更多推理 token + 产品层鼓励的外部验证习惯**，不是一个可单独开关的新机制。安全报告也说 Carbon 相对 Argon 的综合能力增量**低于其「实质能力变化」门槛**（GCI v2 指数，门槛为约 4 个月的进步量）。

**2. MKA 的评测设计**【自报，MKA 技术报告；第三方，AA 页面】
- 题目：200 题、10 个行业各 20 题、83 种职业；每题 2–45 个输入文件（平均 7.3，共 1,459 个），如建筑立面图、电路原理图、放射影像、10-K 财报。专家每题花 3–8 小时出题、做标准答案、写评分细则。88% 的题要交付独立文件（xlsx / pptx / pdf / docx / html / png）。
- 评分细则：每题约 70 条是/否检查，权重 1–5；官方博客说 75% 看事实准确、25% 看视觉设计。
- 分数：WSR（加权满足率）= 满足条款权重和 ÷ 全部条款权重和。
  - Climb 条款：一组「上一代」模型（Gemini 3.8 Flash、3.6 Flash、Claude Sonnet 5.5、GPT-6.1 Sol）没能稳定通过的条款（7,888 条）。**主指标是 Climb-WSR**。
  - Regression 条款：上一代都能过的基础项（6,396 条）。
- harness：Artificial Analysis 的开源 Stirrup v0.2.1；只有 4 个工具（code_exec、view_image、web_search、finish）；250 轮上限、8 小时、上下文 70% 时压缩；沙箱 4 vCPU、最多 16 GB 内存、**可联网**。
- 评分员：sandbox 里的 agent 评分器，用 **GPT-6 Luna**（非 Google 模型），只看交付物和细则，不看输入文件。50 题人工对照：与专家一致率 96.2%，Cohen's κ 0.91。
- 视觉是否必需：去掉 view_image 后，Carbon 在 GDPval 上分数和用量都不变；在 MKA 上 Climb-WSR 掉 5.94 个百分点，轮数 ×1.28、输出 token ×1.40（只在 Carbon 上做了这个消融）。
- 私有集：200 题不公开、由 AA 托管；另放 10 题公开展示集到 HF。

### 机制拆解（白话）

**1. 系统结构**【自报，博客】
- 两层：Gemini Robotics ER（具身推理模型，看画面、跟踪流程、规划多步）在上；Gemini Robotics 2.5（VLA）控制手和臂。Mercedes 试点就是这样配：ER 跟踪工作流程，VLA 抓取金属支架放进排序容器。
- 支持多种机器人：Apollo 2 人形（22 自由度 SharpaWave 五指手）、Franka Duo 双臂平行夹爪。

**2. 仿真生成 + 自我改进闭环：博客原文 vs X 帖**

| 环节 | X 线程 | 博客原文【自报】 | 判断 |
|---|---|---|---|
| 仿真从哪来 | 「from a single camera view」 | 「generate thousands of varied, simulated practice runs from a real-world camera scene and build a realistic digital twin」 | 博客没说「单个视角」；10 月 Argon 开发者博客有「单张 RGB 照片 → MuJoCo 孪生」的示例 |
| 仿真怎么用 | 「virtual practice spaces」 | 「Combined with real training demonstrations」 | 仿真数据**和真实演示混训**，不是只靠仿真 |
| 失败怎么改 | 「watches replays of its own mistakes to fix its technique」 | 「Argon can also help **researchers** hypothesize why task failures happen from video footage and test the best improvements both in simulation and directly on real robots」 | **主体不同**：是 Argon 帮研究员分析失败视频、验证改进；不是 VLA 自己看回放自我纠正 |
| 加速多少 | 「speeding up months of training」 | 「greatly accelerated our development」 | 博客没给具体月数 |

- 10 月开发者博客里 Argon 的两个可参考示例【自报，但属于 Argon 能力展示，没说就是 Robotics 2.5 的训练流程】：
  - 仿真增广：一张俯拍 RGB 照片 → Argon 自动建 MuJoCo 孪生（9 个派对道具，含软毛绒帽）、定义 77 个单/双臂任务、写闭环 IK 轨迹生成器、在仿真里验证 reward=1.0、导出 4,500+ 条随机化轨迹用于 VLA 微调。真机成功率 56% → 75%，完成时间 35 秒 → 24 秒。
  - 硬件自我改进：SO-101 小机械臂上，Argon 自己写控制代码、看日志和录像找失败原因、在 dry run 里验证修复再重试，三轮从 58.9 秒降到 17.4 秒。这是 **Argon 直接控制**，不是 VLA 在学。
- 【推断】Robotics 2.5 的「闭环」更像：真实场景 → Argon 建孪生 → 生成大量仿真轨迹 → 与真实演示混训 VLA → 真机失败录像 → Argon 帮研究员归因 → 在仿真或真机验证改进 → 下一轮。人仍在环里，没有披露 RL 算法、数据量、仿真/真实配比。

**3. 能力与可靠性数字**【自报，博客】
- 200 个任务（系蝴蝶结、移液、夹子夹食物等）。比「之前的基线」成功率高 30%–100%，快 20%–30%。**没写基线是谁**，也没写是相对提升还是百分点。
- Mercedes 试点：匈牙利 Kecskemét 和德国 Sindelfingen 产线，Apollo 2 从散料箱取零件按车序放进托盘（kitting，配料）。博客写的是「pick and pack… 96% success rate」，**没给样本量和统计周期**，性质是概念验证（proof of concept）。
- Apptronik CEO 引语：「几周后训练就大幅提升，迁移到产线几乎不掉点」【自报，合作方】。

**4. 安全（防御侧）**【自报，博客】
- 推理时的安全引导：类似给回答加安全分类器，在执行中避开危险。障碍物附近安全完成率提升 33%，人附近提升 43%（没说是相对还是百分点）。
- 越狱测试：发布开源基准 **ASIMOV-Jailbreak**（几百条把危险请求伪装起来的提示，几十个场景）。**99.5% 越狱抵抗率是 Gemini 4 Argon 的**，上一代基线 Gemini Robotics ER 2 是 82%。博客没给 Robotics 2.5 本身的越狱数字。
- 第三方出入：Ars Technica 报道写的是「Argon 在环 98.8%、ER 2 单独 73.5%」，与博客现文的 99.5% / 82% 不一致【第三方】。以博客为准；可能是博客更新过或口径不同【推断】。

### 与 GR00T 2 X-Adapt 对比表

| 维度 | GR00T 2 X-Adapt（NVIDIA） | Gemini Robotics 2.5 仿真加速（DeepMind） |
|---|---|---|
| 模型类型 | 世界-动作模型（同时预测画面和动作），2B | VLA（视觉-语言-动作），规模未披露 |
| 新任务数据从哪来 | 人戴手套/相机、手持 UMI、DexUMI 外骨骼、一段人类视频 | Argon 从真实相机画面建数字孪生、批量生成仿真轨迹 + 真实演示 |
| 「身体差异」怎么补 | 目标机器人与任务无关的 play 数据 + 跨身体预训练；模型「想象」自己的手完成任务 | 显式物理仿真（MuJoCo 类）里直接用目标机器人模型 |
| 是否需要该任务的遥操作 | 不需要（DexUMI 连 play 数据都不需要） | 博客说仍与真实演示混训，量未披露 |
| 自我改进 | 真机 RL（CPS 探索 + GRPO 风格 + 自我模仿 / 残差 RL）；世界模型 RL；RL 配方由 AutoRL agent 35 天找到 | Argon 分析失败视频、提出并验证改进；人在环里；未披露 RL |
| 上层 agent | 任意前沿 agent（实验用 GPT-6 Astra）经 MCP / WAM API 调用，可在画面上指点 | Gemini Robotics ER 跟踪流程，Argon 负责研究和安全评测 |
| 公开量化 | 零样本 40%、5 条演示 95%；X-Adapt 各任务 50%–86%；每任务多为 20 次试验 | 比未具名基线高 30%–100%；产线试点 96%（无样本量）；Argon 示例 56% → 75% |
| 公开程度 | 135 页白皮书；10 万小时数据 CC BY 4.0；权重和代码 12 月 | 只有博客；只对合作伙伴开放；越狱基准开源 |
| 技术报告 | 有（白皮书） | 暂无 |

- 【推断】两家思路互补：NVIDIA 赌「用视频预测把人类经验变成机器人技能」，几乎不用仿真生成新任务（仿真主要用于评测和 RL）；DeepMind 赌「用最强通用模型自动搭仿真、批量造数据」。前者的可复现性目前远高于后者。
