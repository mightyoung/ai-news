## 1. AlphaGenome 2：按细胞类型预测 DNA 变异效应（其他 · AI for Science）

**一句话结论**：AlphaGenome 2 是一个条件式「序列到功能」模型：输入最长约 100 万碱基的 DNA，再加上一个「条件」（组织、细胞类型或细胞状态），预测该条件下的基因表达、染色质可及性、组蛋白修饰、DNA 甲基化等。它在 TenK10K 上、90% 精确率时找回的因果单细胞 eQTL 大约是微调版上一代模型的两倍（30% vs 16%），并能把研究者自己的单细胞 RNA-seq 压成条件、无需微调。预印本和 API 已公开，**权重尚未开放**；直接 API 只给非商业主体，且仅限研究、不能用于临床。【自报】

### 机制拆解

1. **为什么要改架构。** 上一代 AlphaGenome 1 用约 100 万碱基的 DNA，一次并行预测许多组织和细胞系的实验读数，容量被摊薄，不容易分开近缘细胞类型（博客；论文第 1–2 页）。【自报】
2. **条件模型。** AlphaGenome 2 一次只针对一个条件做预测。条件是组织、细胞类型或细胞状态的嵌入向量，从网络最早的层开始，用 FiLM 去调制序列表征，经过 U-Net 编码器、中央 Transformer 塔（11 层，128 碱基一个 token，通道数 1536，1 Mb 对应 8192 个 token）和解码器（第 2 页及方法）。【自报】官方预印本**没有给出总参数量**。
3. **两种指定条件的方式。** 一是从参考目录里选一个已有条件；二是「表达量条件化」：把研究者自己的人类 scRNA-seq 表达谱送进细胞编码器（每次最多 256 个细胞，见 API 文档），得到条件嵌入，不必微调序列模型（博客；FAQs；`MAX_CONDITIONING_CELLS=256`）。【自报】
4. **训练分四段。** 预训练 → 只优化条件嵌入和调制层的 refinement → 把 8 个教师模型蒸馏成一个学生模型 → 冻结学生模型，把在超过 1 亿条人类 scRNA-seq 上训练的表达自编码器对齐到条件空间（第 2 页）。【自报】数据上，相对 AG1 新增 3977 条人类和小鼠单细胞 RNA/ATAC 伪批量轨迹（36 项研究）、覆盖 185 个人类参考条件的细胞类型分辨率 CpG 甲基化，并在 1.07 亿条人类 scRNA-seq 上进行后训练；后训练用的图谱来自 68 个组织（第 2 页，图 1d）。【自报】博客写「trained on more than 100 million individual cell profiles across 68 tissues」，与「超过 1.07 亿」一致，只是取了整数。【自报】
5. **输出。** 与 AG1 相同的核心读数（基因表达、组蛋白修饰、染色质可及性等），并新增 DNA 甲基化；还可做跨模态填补（例如只给单细胞基因表达，去预测未测的染色质可及性）。输入长度支持 16,384 / 131,072 / 524,288 / 1,048,576 bp，文档推荐 1 Mb 以获得最佳精度；梯度接口只支持 100 kb 和 1 Mb（API 文档、FAQs）。【自报】
6. **预计算资源。** 论文在数百个人类细胞类型上预计算了：640 个原代人类条件下的增强子–基因连接图谱，以及约 700 万个性状相关和常见变异在 510 个条件下的效应分数（摘要、图 1、第 53 页）。【自报】过滤后的版本入口写在 https://deepmind.google.com/science/alphagenome/downloads 。这些是 AlphaGenome 2 的预计算，不要和 2026-09 用 AlphaGenome 1 做的「90 亿单碱基变异」Atlas 混为一谈。【推断】

### 应用清单

**今天就能试**（需符合非商业主体资格，申请免费 API 密钥，密钥不得在组织内共享）：

**要有数据或机器再试**：

**暂时别碰**：
- 不要用于临床决策、诊断或任何医疗建议（条款与论文第 53 页明确禁止）。【自报】

### 机制拆解（复用 11-11 精读，不重复推导）

核心是把「证明」和「信任」分开：几百万行证明可以由不可信的 AI 写，因为 Lean 内核会检查；人真正要审的是规约和机器码语义（论文第 3 页）。【自报】

四个部件：人与智能体共同起草并锁定规约；用 Lean 写的用户态 AArch64 Linux 语义去解释编译产物；Gemini 4 Carbon 驱动的智能体团队写证明；守门员核对锁定规约、标准公理和内核通过，智能体自报「做完了」不算（第 4–6、25–26 页）。【自报】

验证对象：未修改的 libsignal v0.105.4 和 spqr v1.6.0，用标准 rustc 编成 AArch64 可执行文件；定理覆盖 init、send、recv。Rust 编译器不必被信任（第 9、24 页）。【自报】证明的是编译出来的机器码满足给定安全性质，不是 Signal 客户端应用的全部代码路径。【自报】

为避免把防御工作写成攻击说明：作者把两个**已经修复**的历史缺陷重新引入隔离版本，并由 Lean 证明相应安全定理不再成立，用来检验规约是否够强（第 24 页）。这里只记录「规约能区分有缺陷和无缺陷的已发布修复」，不展开缺陷机理。【自报】
