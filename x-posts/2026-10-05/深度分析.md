### 机制拆解

1. **「一次调用开浏览器」是会话创建形状，不是免审批。**  
   浏览器进程可以跟 session create 一起起来，但每个新 origin 仍要应用侧 `approve/deny/cancel`。产品承诺的是少一次「先开环境再挂工具」的编排，不是少一道人在环。

2. **环境复用复用的是策略，不是磁盘。**  
   模板把包、网络策略、技能配置做成可版本化对象；活文件仍死在该 session 的沙箱里，空闲约 1 小时可被回收。把它当成「Codex Cloud 机器镜像热迁移」会错。

3. **容器档是 CPU/内存旋钮，帖文的 light/beefy 没有官方美元对照。**  
   三档规格已公开；容器单价该页没写。账单模型必须把「容器分钟」和「模型 token」拆开记。

4. **BMA 是同一叙事下的另一控制面。**  
   Steve 的 “except AWS” 容易读成功能等价。AWS 自己写的是定制版，且 preview **明确不支持 subagent**、输入以文本为主。OpenAI dashboard 上配的 subagent **不能**假设在 BMA 里存在。

5. **可靠性数字没有测量合同。**  
   99.97% / −SSE / +20% 工具速度若没有窗口和分母，只能当方向性运营更新，不能写进 SLO。

### 工程落地（8 条）

1. **浏览器默认关。** 只有任务必须走 GUI 才设 `desktop.enabled` + `computer_use`；其余继续 `openai_hosted` 无桌面或 `self_hosted`。  
2. **Origin allowlist 做在应用里，不要自动 approve。** 文档写明公开站也要批；默认 deny，只放业务域名。  
3. **登录只走专用事件，凭证零日志。** 不支持 passkey/QR 的站点改走自有浏览器运行时，不要在 chat 里补密码。  
4. **后果动作不要依赖模型自觉确认。** 文档写 origin 批准不保证购买/破坏性操作前会再问；这类站点改用你控制的浏览器，或干脆禁止。  
5. **模板当策略包发布：** `environment_template_id` + 禁止放宽网络。工作区文件需要的，显式落到 `/workspace/outputs` 产物，不要指望下一 session 还在。  
6. **1 小时空闲写进运行手册。** 长等待的人在环任务要有 keep-alive 或接受重建；关 SSE 不等于停任务。  
7. **容器档按活选：** 依赖安装 / 浏览器走 `medium` 起评；`large` 仅在 OOM 复现后开。容器费与 token 费分账；美元单价未公开前用自测账单回填。  
8. **BMA 单独兼容矩阵：** 区域仅美东/美西三区；不要开 subagent、不要传非文本会话输入、不要假设和 OpenAI 托管 computer use 同日齐。preview 不另收费 ≠ 底层 AgentCore/模型免费。

### 风险

- 把 99.97% / 20% 写进对外 SLA：无官方定义。  
- 把模板复用当成工作区持久化：空闲 1 小时可删。  
- 在 BMA 上打开 OpenAI 侧的 subagent / computer-use 审批流：preview 限制写明不一致。  
- 截图进日志：文档明确可含账号与页面敏感数据。  
- Sol 是否已是 Agents 默认可选模型：帖文有、changelog 无单独行，上线前用一次 `sessions.create` 探活，不要凭帖文改路由。

### 机制拆解

1. **Dot 是协调层，Codex 是执行层。**  
   OpenAIDevs 的动词是 learns / keeps context / coordinates / flags，不是「dot 自己写完仓库」。Kundel 的结论是一起用，不是替换。

2. **上下文在「应用之间」而不在「线程之间」。**  
   官方句是 across apps。Simon 的反例是：他要的是多 thread 分上下文，dot 目前像单会话。两条都成立时，dot 适合「同一个人的连续工作记忆」，不适合「并行、隔离的任务账本」。

3. **主动推送是产品面，不是 API 合同。**  
   「flags what needs your attention」和 Kundel 的 proactiveness 都是行为描述，没有事件 schema、没有哪些信号算「需要你看」。工程上不能假设有稳定 webhook。

4. **sama 的帖是使用体感。**  
   「每天明显更好」不能外推成记忆算法或学习率。

### 工程落地（7 条）

1. **分工写进团队约定：** 跨应用提醒、代办、把任务派给 Codex → dot；要隔离上下文、要 diff/PR 级控制 → Codex 自己的线程。不要用一条 dot 对话承载多个互不相关的仓库。  
2. **单会话限制当成容量规划：** 一个主题一条外部记录（工单/文档），dot 只做指针。需要分叉时开新的 Codex 任务，而不是在同一条 dot 里堆历史。  
3. **人仍是验收器。** 「flags」之后的合并、发布、付款不自动放行。  
4. **敏感仓库默认不让 dot 协调。** 在连接器范围公开页取回之前，把密钥、客户数据、生产变更列在禁止清单。

### 机制拆解

1. **硬上限的语义是失败关闭，不是通知。**  
   到额必须让新请求变成错误（或 AWS 那种暂停项目）。邮件告警在人睡着时等于没有上限。

2. **默认封顶、显式开封，是把举证责任反过来。**  
   现在常见的是默认能无限烧、用户自己去找开关。Simon 要的勾选文案是法律和产品一起写的 opt-out。

3. **OpenAI 的硬上限已经存在，但不符合「默认」。**  
   Enforce 是人打开的；而且传播有延迟，所以不是数学意义上的硬墙。Agent 循环在延迟窗口里仍能多烧一小截。

4. **粒度和 9/30 的「每会话」不是一回事。**  
   平台开关是组织/项目的**月**额度。一个失控 session 可以在月额度内先烧完你能接受的单次预算。会话帽仍要做在应用网关，不能等 429。

5. **AWS/GCP 也还不是「所有东西默认有帽」。**  
   AWS 引文是付费计划上的项目月限额，且花费限额页写有限客户；GCP 是项目内指定服务。都不能当成账号级、默认、瞬时的全产品帽。

### 工程落地（8 条）

1. **组织级先打开 OpenAI Enforce a hard limit**，阈值低于财务能接受的月度；alert 设在硬帽之前，但不要只留 alert。  
2. **项目再拆一档**，agent 流量和人用 playground 分开，避免一条 dot/Codex 循环打满全组织。

### 机制拆解

1. **后端从「编进核心」变成「附加库」。**  
   主包不必为每个硬件后端发版；MLX（Apple 侧）和 Paddle 可以独立安装、独立版本。代价是用户环境里多一个必须对齐的包。

2. **移植面收成「主 op」。**  
   次要 op 用后端无关实现垫上，新后端只实现更小的核心集。正确性取决于这层降级是否在数值上可接受，所以才需要统一测试。

3. **一个 harness 测 casting 等不变量。**  
   跨后端最容易碎的是 dtype/shape 约定。统一套件是后端插件化的准入门，不是性能榜。

4. **KerasHub 去掉 tf-text 依赖。**  
   预处理改 PyGrain，意思是数据管线不再绑在 TensorFlow 文本栈上，和「后端可换」同一方向。迁移期旧代码会断。

### 工程落地（6 条）

1. **现在不要把 MLX / Paddle 写成生产依赖。** 帖文是 upcoming，无版本号。  
2. **跟踪附加库的安装面：** 以后 `pip install keras` 不够，后端是额外包；锁文件要把 keras 与 backend extra 钉在一起。  
3. **自有模型先跑官方统一 op 测试里的 casting 类检查**，再谈数值对齐；不要只用一个 loss 曲线判断后端可换。  
4. **KerasHub 预处理做一次导入审计：** 找到 `tf_text` / tensorflow-text，标成要迁到 PyGrain 的清单。迁移指南 **帖内未给**。  
5. **新模型数量不要写进汇报。** 「lots」没有名单。  
6. **纪要以 Chollet 帖为准**，直到 Google Group / keras.io 放出全文；不要用二手中文稿补数字。

### 风险

- 把 upcoming 后端当成已可 `import`。  
- 次要 op 的后端无关实现在速度或数值上和原生实现不一致，统一测试若只覆盖 casting，覆盖不到。  
- tf-text 一切换，旧 Hub 预处理脚本直接 ImportError。
