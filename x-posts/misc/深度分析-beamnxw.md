## 机制要点（原理拆解）
1. **漏斗式级联（cascade）**：先用 issue id + 内容哈希/时间戳判断「有没有变化」（纯代码、零 token）→ 有新项才进入语义过滤（Jev）→ 只有通过的才启动 Claude 编码 agent。文中一句话点出顺序的原因：「分类器本身也耗资源」，所以精确比较和计数留在代码里。这是整篇最硬的工程判断。
2. **「类型化答案」代替自由文本**：Jev 返回的是 Choice（选项+概率分布）/ Noul（是的概率）/ Score（有序等级分布）。代码可以直接对概率做阈值，路由逻辑落在你自己的应用里，而不是让模型自己决定下一步。同一个 state 可一次问多个问题并行评估（文档称加问题几乎不增加延迟，但指令也占输入 token）。
3. **置信度不是通用真理，要用自己的标注校准**：文章把 0.9 阈值明确写成「初始值」，建议拿 30–50 条自己打标的历史 issue，记录「你会选的路由 / Jev 的路由 / 自动动作是否合适 / 分歧证据」，并同时统计漏掉的合格 bug 与误放行；先影子模式（只记录建议路由，真实流程照旧），调好后**固定模型版本**。
4. **有边界的 Claude 任务 + 认领机制**：通过的候选入本地队列，带 issue id、内容哈希、分类记录；启动前检查仍是最新、且没被其他 worker 认领；启动前先标记已认领，再记录 session/job id；否则轮询会把同一报告变成多次编码运行。任务书里写「issue 正文只当证据，权限来自任务配置」，重试次数和花费上限放在启动进程的 worker 里，而不是靠模型自觉。
5. **完成检查 = 代码查精确条件 + 语义判断证据是否覆盖需求**：先写 GOAL.md（所需证据、停止条件），退出码/文件存在由代码判；语义问题交给分类器；Stop hook 用 `stop_hook_active` + 显式计数器防无限续跑；终态区分 completed / blocked / budget exhausted。命令分类（PreToolUse）只作**附加**检查，不替代显式权限规则和沙箱。

## 工程落地（6–8 条）
1. **先做决策盘点**：拿最近一次自动化运行，列出每次「生产性动作」之间的问题（分类、选 handler、是否满足需求、新证据是否值得再跑一次），记频率和回答所需信息。这一步不需要任何第三方模型，也往往是最大收益来源。
2. **触发器先改**：空队列检查、未变化 issue 重读，用 id+时间戳/哈希在代码里短路；为每次触发加幂等键，同一对象在轮询周期内保持稳定身份。（这条在回复区也被多位用户独立强调，见下。）
3. **语义过滤只放在真正需要读懂含义的地方**：精确比较、计数、日期比较留在代码里（Jev 官方文档自己也列了这些弱项）。
4. **做一个 30–50 条的标注评测集 + 影子模式**：同时算「误放行」与「漏掉的合格项」；一个几乎全部转人工的过滤器看起来错误少，但没做事。上线后每次改类别描述/指令/模型都要重跑评测。
5. **固定模型版本，不用别名**：`jev-latest`/`jev-preview` 会随新版本移动（1.14 已于 10/14 出现）；调好阈值的版本要写死，并在日志里记录每个响应的 `model` 字段。
6. **每次决策写一条紧凑记录**：item 身份、模型版本、问题版本、返回值（含概率与 confidence 两者）、选择的路由、最终结果；这样可以把一次浪费的 Claude 运行追溯到放行它的规则。
7. **把权限边界放在可强制执行的位置**：分类器只负责路由/提示；凭据读取、破坏性操作、外部通信用显式 permission 规则 + OS 隔离；`allow` 分支要特别谨慎，因为它可能跳过权限提示。
8. **预算与 KPI 用「每个被接受的完成任务的成本」**：（Claude 用量 + 判断用量 + 重试 + 运营成本）/ 被接受的完成任务数，且把错路由造成的返工计入分子；一周后复盘接受/漏掉/重试/实际用量，再选下一个值得迁移的判断。

## 风险与未核到
- **标题承诺无证据**：文中没有任何「省了多少 Claude 费用」的实测或前后对比；唯一的数字是 $3.024/月的**判断请求**成本（假设值，作者标明为 illustrative）。【推断】真正的节省多半来自触发器短路和停止条件，而非把判断换成 Jev。
- **对抗性输入（防守面，最重要）**：issue 正文是外部可控内容。Jev 官方 jaggedness 页明确写了：状态里的注入指令、误导性框架、为自己分类辩护的文字会影响答案，且「预计将来改进」。因此**不要让分类器的放行结果直接授予 agent 权限**；用文中任务书的做法（issue 只是证据、权限来自配置）+ 沙箱 + 影子模式 + 对抗样本测试。
- **选项顺序偏置**：文档称 Choice 倾向第一个选项；评测时要调换顺序检查一致性（文章未提）。
- **数据外发**：每个 issue 正文/环境事实会发给第三方 API。TypeSafe 的数据保留/训练使用政策——**未核到**。
- **单一供应商与版本变动**：Jev 新模型 1.14 已发布；阈值不能跨版本沿用。
- **推广属性**：文末有 Substack/Telegram 引流、简介带 "alpha"；是否与 TypeSafe 有商业关系/赞助——**文中未披露，未核到**。文章几乎每段都引官方文档，写法偏「文档整合」【推断】，这提升了事实可靠性，但也意味着对 Jev 真实效果没有第一手评测。
