### 机制要点（3–5 条）

1. **缩放阶梯 + 「source scaling」**。每一档只由层数 L 决定整个结构（hidden = 256/3·L，query 头数 = L 取整到 16 的倍数），固定「每激活参数训练 token 数」（TPP）。小档位训练时人为缩小唯一样本集，让数据重复次数和全量跑一致，避免小规模实验偏向「欠正则、放大后过拟合」的结构和超参。图 2 里，L18–L42 拟合外推预测的最终性能和实际终点基本重合。
2. **超参缩放律**。LR 和 WD 联合扫，且在 (log LR, log(LR×WD)) 上做网格（好配置落在窄对角带上）；二次曲面拟合取最小值，再对步数、TPP 回归。结论：LR×WD ≈ 17.04/steps（对步数指数约 −1，对应「解耦权重衰减的时间尺度占训练固定比例」）；log LR = −1.51 + 0.175·log TPP − 0.573·log steps；dropout 用激活参数量的 sigmoid 公式。在小实验上估计，中等规模上验证过。
3. **模型与基础设施协同**。用「效率增益 EG」（达到同样评测损失所需算力之比）做决策，主要看 EG time（墙钟）而不是 EG FLOPs。MoE 层 MFU 从 24% 提到 35%，才敢每层都用 MoE：无丢 token 的多轮 dropless MoE（固定显存、超载专家分多轮处理）、按专家组分组通信、从 GPU 直接发起 all-to-all、批量化负载均衡损失。
4. **Muon 取代 AdamW**。博客称更稳定、效率增益大。工程难点是 Newton–Schulz 需要完整矩阵，和 ZeRO 分片冲突：把动量重分片、按形状批量 all-to-all、对称感知核、路由权重复制。优化后 Muon 占单步时间 **2.1%（165 ms）**，理论下限约 55 ms。
5. **激活梯度裁剪**（对选定位置的激活梯度裁剪，而不是对整批权重梯度做全局裁剪）。与 Muon 一起把梯度范数压到更窄区间，收益随规模增大；还被当成**数据诊断工具**：它抓到一条被截断的 license 头的代码样本，由此定位到预处理 bug。

### 算力口径：我能复算的部分（均为【推断】，博客未给总 FLOPs）

- 16k GPU × 38 天 ≈ **1459 万 GPU 小时**。
- 按 MFU 反推：2.5e15 × 21% × 16000 × 38 天 ≈ **2.8e25 FLOP**；按 6·N激活·D = 6×80e9×50e12 ≈ **2.4e25**。两者同量级，Fig.2 横轴终点也在 2–3e25 附近。
- TPP ≈ 50T/80B ≈ 625 token/激活参数；终点层数按图上标签读为 L102（读图），对应 hidden ≈ 8704。专家数、专家粒度、上下文长度、batch 大小、学习率绝对值：**未公开**。
- 单步时间 ≈ 165 ms ÷ 2.1% ≈ 7.9 s（由两个自报数反推）。
- DeepSeek-V4-Pro-Base 的训练算力：博客只说「显著少于 MAI-Base-2」，具体值与估算依据**未公开**（读图在 1e25 量级）。

### 工程落地（8 条，中小团队可迁移的部分）

1. **先搭「缩放阶梯」再烧大模型**：同一配方跑 4–5 档小模型，固定 TPP，拟合外推预测大模型终点；预测和实测对不上就别放大。小团队用 100M–1B 档就能做。
2. **小规模实验固定「唯一数据/参数比」**：小档位用 source scaling 的思路限制唯一样本、让重复次数与大档一致，避免被「小数据+过拟合」误导选结构。
3. **LR 与 WD 联合扫，坐标换成 (log LR, log LR×WD)**，把乘积当成主轴；网格点数省一大截。步数变了就按「LR×WD ∝ 1/步数」重估。绝对系数（17.04、−1.51…）不要照抄，博客没给单位定义和适用的 batch/架构范围。
4. **每次改动同时记 EG FLOPs 和 EG time**：只赢 FLOPs 不赢墙钟的改动说明该投资基础设施；只看 FLOPs 会误导。
5. **用 BPB 做预训练期的快速评测，并做一套你自己的 held-out**：用自己业务的代码/文档做 held-out，STEM/QA 这类可向外部定制，全部对训练集去污染；报告时同时给出各分项，而不是只报最好那项。
6. **把激活梯度异常当数据质检信号**：对被裁剪最多的样本反查来源，定位预处理 bug（博客里的 license 头截断就是一例）。成本低，小团队也能做。
7. **数据管线上抄作业**：质量分类、主题分桶、去重、去污染、基于嵌入的多样性采样（优先新颖样本）；多模态时单独记 VLM 语料占比。
8. **不适合小团队直接迁移的**：16k GB200 级别的 dropless MoE 多轮调度、symmetric memory all-to-all、Muon 的跨 GPU 重分片核。小团队可只借「Muon 可能优于 AdamW」这个方向，在自己规模上做 A/B，别预设 2.8T 的结论成立。

### 风险与未核到

- **「SOTA」只在被测的开放权重模型里成立**；没有和 GPT/Claude/Gemini 等闭源模型比，也没有下游基准、没有后训练结果。Suleyman 帖里写的是 SOTA 的「base models」（复数），博客只有一个模型 MAI-Base-2。【推断】
- 12.3× 对应的是 MAI 自己的代码库，最有可能与其训练分布最接近；「去污染」的方法和阈值未公开。【推断】
- 倍数是 MAI 自己拟合的缩放律，误差范围（拟合不确定性、DS 算力估计误差）**未公开**。
- 「有机数据，不蒸馏」是自报；数据来源清单、许可处理、webcrawl 之外的数据（如 vendor 数据）**未公开**。对照 Anthropic 的反蒸馏立场见 10/13 稿 §1。
- 三个对手 Kimi K3、Qwen3.8、MiMo 的参数量来自 MAI 图中标注；二手媒体（pasqualepillitteri.it）列了 DS-V4-Pro 1.6T/49B/32T+ token，这是【第三方、二手】，我没核到 DeepSeek 官方卡，不要直接引用。
- 没有第三方复现；权重不发布，短期内也无法复现。

### 三个领域逐项拆

**B. 聚变（磁约束）——有论文，可核**

- 论文：arXiv 2610.07304《Analytic non-axisymmetric 3D MHD equilibria without stellarator symmetry》。作者：Opal Issan（DeepMind，兼 UCSD）、Jonathan Citrin、Brendan Tracey（DeepMind）、Matt Landreman（马里兰大学）。正文日期写 October 5, 2026（arXiv 提交日**未核到**）；未见期刊信息，按预印本对待。
- 内容：在 Landreman 此前发现的两族 Grad 猜想反例（本身已是反例；另有 Gómez-Serrano 等人的存在性证明）基础上，**加入一个破缺「恒星器对称性」的参数**，得到两族新的**解析解**（闭式、满足 Hamada 条件）。用途写得很明确：给 VMEC、SPEC、DESC 这类三维平衡求解器当**基准测试**。
- Argon 的角色（论文第 5 节「Use of AI tools」，一手来源）：Gemini 4 以小型 agent 团队跑在 Antigravity 里；给定 Landreman 的论文和它列出的开放问题，agent 提出推广解，**数小时内出现候选**；Argon 还起草了部分稿件、写了符号和数值验证代码。作者负责选题、引导、多轮对抗式审查，**每个推导都由作者独立重推并做符号验算**，并对内容负全责。
- 验证闭环：人工重推 + 符号验算。这类结果是解析式，可以代回方程检验，**可检查性强**【推断】。

**C. 酶/蛋白设计——有湿实验，细节少**

- 来源：Ryan Krueger 的线程（10/14 00:35 CST）+ 官方博客。目标反应：切 **4MU-acetate** 的酯键（荧光检测，博客称它为基准分子）。
- Argon 做的：**组装训练数据；微调一个多家族蛋白语言模型；构造序列和几何两类活性位点过滤器**，从该模型输出里筛选，得到 **5 个新颖候选**，与天然酶序列一致性 **59–81%**。
- 验证：「初步一轮湿实验」，在这些设计上看到所需催化活性（博客：robust catalytic activity）。作者原话称这是「initial (zero shot!) results」。
- 注意：生成序列的是**另一个蛋白语言模型**，Argon 是编排数据、微调、写筛选器的 agent；「数小时」指 Argon 完成数据组装、调参和筛选，**不含湿实验周期**【推断，博客措辞「Argon assembled… performed model tuning and identified filters」】。

### 机制要点（3–5 条）

1. **模型当「工程师」，不是「预言家」**：三个案例里 Argon 都在写代码/脚本（内核、电路、符号验证、数据管线与筛选器），真正的科学判断仍由外部验证决定。
2. **验证强度很不一样**：Lean（形式化，强但只证正确性）> 解析解代回方程 + 人工重推（强）> 单轮湿实验（弱，样本小）。这决定了你该信哪一条多少。
3. **「搜索 + 廉价验证」模式**：聚变那篇是 agent 在已知结构（Landreman 的两族解）上做参数化推广，几小时出候选，人再验；蛋白那篇是生成 + 过滤。两者都靠验证成本远低于生成成本。【推断】
4. **提速主要在「搬运」环节**：AlphaQubit 转内核、数据整理、论文起草，都是把已有思路落到可执行物上，量化提速（≈2×、>100×、「数小时」）属于工程效率，不是新原理。【推断】
5. **可核查性分层**：聚变有 arXiv；量子子程序没找到论文；AlphaQubit 是内部版本；酶的实验数据未公开。

### 工程落地（7 条）

1. **把「验证器」和「提案者」拆开建**：先决定你的验证手段（形式化、符号、仿真、实验），再让模型批量提案；验证成本比生成成本低的任务最适合。
2. **形式化验证只覆盖「它证明的那条性质」**：如 Lean 证正确性，不证成本；评审时问清「被证的命题是什么」。
3. **agent 写高性能内核时**：保留逐步回归测试（数值等价、吞吐、边界条件）；吞吐翻倍必须配精度不变的证据。
4. **做科研 agent 的流程模板**：给定论文 + 开放问题清单 → 多 agent 提候选 → 人工独立重推 → 符号/数值验算 → 对抗式审查。论文第 5 节可以直接当披露模板，写清 AI 用在哪、人做了什么。
5. **蛋白/酶类**：过滤器分序列层和几何层；报告时给出测试总数、命中率、与天然序列一致性、对照；只报「5 个成功」不够。
6. **用「基准分子」先验证流程，再换真实目标**：4MU-acetate 这类荧光底物便于快速验证流程；换成真实底物前不要外推。【推断】
7. **评估这笔「10,000 名科学家免费 6 个月」**：属于 Antigravity 最高档额度，滚动开通；是否符合资格要自己去申请页看，未核到具体资格条件。

### 风险与未核到

- 「breakthroughs」是营销措辞：聚变那篇是**推广已有反例**得到的基准解，不是反应堆设计；说「novel 3D magnetic field designs」容易被读成可建造的磁场设计，论文里是**解析平衡解**，用途是测代码。

### 机制要点（3–5 条）

1. **银行驻点检查官类比**：评估者人在内部、看到过程，而不只是拿到一份报告；Anthropic 自己说目标是缩小「评估者知道的」和「公司自己知道的」之间的差距。
2. **权限和发表权绑定成梯度**：越深入越能自主发表；一档发表要批准，二、三档不能否决、只能涂黑。信任是逐步建立的。
3. **「可涂黑，但不可否决」**：涂黑类别要**预先界定**，被评估方不能随意扩张；评估方还能公开评论涂黑是否合理，这是对涂黑权的制衡。
4. **隔离防泄露**：小团队 + 有执行力的协议 + 其他同事隔离 + 架构类信息默认不给。承认评估者可能同时服务别家，所以谨慎。

### 工程落地（7 条，给要做外部评测/红队的中小团队；防守面）

1. **先写评估者资格清单**：专业、独立（无股权、无财务依赖）、访问、发表自由，逐项打勾；不满足的作为「顾问」而非「独立评估」。
2. **分档接入**：第一档只给窄范围、指定数据，发表前过你审；确认对方能守密、有能力后再升档。每次升档留书面记录。
3. **预先写死涂黑类别**：客户数据、特权文件、凭证、与安全无关的商业机密；约定「不能否决发表，但可涂黑，对方可公开评论涂黑」。
4. **隔离**：指定小团队、配专用设备或受控环境、日志留痕；团队外同事不得接触其工作。
5. **给「和自己评估团队相当」的内部可见性**：包括事故记录、监控与安全措施说明、训练过程信息，这才能看到「系统怎么运作」，而不只是对一个模型做黑盒测试。
6. **红队只做防守向、授权范围内**：范围、时间窗、报告格式（含修复建议）、漏洞披露流程写进合同；可参考 METR 对 Anthropic 监控系统做 3 周红队并发现漏洞的做法（仅作形式参考）。
7. **预留费用与资金安排**：独立评估有成本；若由你出资，评估者独立性要在披露里说明；有条件可探索共同出资池。
