## 0. 先说四个总要点

1. **Daybreak Defense Factory 和 Daybreak Red Team 是产品，不是新模型发布。** Greg Brockman 宣布两款「cyber products」；Tibo 的措辞更谨慎，写「tools we're developing」。官方文档把 Defense Factory 标为 **research preview**（Codex 插件，连 GitHub 仓库、生成供人审的补丁）；Red Team 官方产品页定位为针对 **Web 应用** 的多智能体授权测试，落地细节明显少于 Factory。二者都挂在既有 Daybreak 准入之下，不是对公众开放的通用模型。【自报】
2. **补丁不会自动合入。** 官方 FAQ 写明：系统保存的是供审阅的候选补丁，可用 Codex 讨论修改，创建的是 GitHub **草稿 PR**；「提出补丁 / 草稿 PR / 状态变更」本身不能证明问题已修好。人仍然负责审差异、决定是否应用并验证。【自报】这与 11-04/11-06 那条「Scout→复现→候选补丁→人工再上报」的防御闭环是同一方向，但不能把当时 Linux 研究里「948 个 distinct LPE」直接算成这个新产品的成绩。【推断】
3. **可监控性（monitorability）和可控性（controllability）不是同一件事。** OpenAI 11-10 Alignment 博客把 no-CoT 能力（不写思维链、单次前向就能推理）和 CoT 可控性（按指令增删或改写思维链）当作 CoT 可监控性的**不完美代理**。Raschka 导读大体对，但「架构影响小」需要限定：多数评测上困惑度可跨架构预测，在多跳规划 / 串行计算上「Architecture 2」明显更好。附录 B 还显示：在一对能力接近的 Astra 级模型上，更高可控性**并不**对应更高的监控规避。【自报】

## 2. 思维链可监控性如何随训练演化（强化学习与RSI）

**一句话结论**：这是 2026-11-10 的 OpenAI Alignment **研究博客**（不是 arXiv 论文，`/workspace/paper-radar/ai-news/papers/` 中未见归档）。作者把 no-CoT 能力与 CoT 可控性当作 CoT 可监控性的代理：预训练更好（基础模型困惑度更低）时，**不写思维链**也能完成的推理变强，与可控性也有较弱正相关；多数评测上架构差异可被困惑度解释，但部分架构在多跳 / 串行计算上更好；在 Astra 级模型上，即便 RL 只有长度约束和最终答案打分（几乎没有过程监督），可控性仍明显上升，并可通过教师生成数据的 SFT 传给下一模型。作者同时强调这些代理不完美：一对能力接近的模型上，更高可控性并未对应更高监控规避。【自报】

### 原帖与官方原文

- Jeffrey Wang（@jeffreygwang），2026-11-12 02:17:13 CST 起 10 连帖。https://x.com/jeffreygwang/status/2120581630196879460
  - 开帖把 CoT monitorability 定义为「no-CoT capability and CoT controllability」；结论是「scale 向更强系统时，更难通过 CoT 监控」。末帖链到官方博客。约 1334 赞、177 转、21.2 万次展示（09:05 CST）。【第三方】
- Sebastian Raschka（@rasbt）导读，2026-11-12 23:02:35 CST。https://x.com/rasbt/status/2120895037064020406
  - 把「不写出来的推理」（no-CoT）和「按要求改写 CoT」（controllability）分开；预训练提升前者、架构大多不重要；单靠 RL 大幅提升可控性并经蒸馏传递；过程监督似乎不是主因。约 179 赞、16 转。【第三方】

标题 *What affects chain-of-thought monitorability across the model lifecycle?*，2026-11-10；通讯作者含 Jeffrey G. Wang 等，通讯指导含 Katherine Lee、Jakub Pachocki。BibTeX 标注为 OpenAI Alignment Research Blog，不是期刊论文。本次未查到 arXiv 版，论文雷达 papers/ 目录无对应归档。

### 机制拆解

1. **两个代理，一个目标。** 可监控性指能否识别模型行为的某些方面（例如是否会造成伤害）。CoT 可监控性一直是他们可扩展监督的一部分。代理一：no-CoT 能力 = 不产生思维链或工具调用 token 时，单次前向的推理能力（潜伏推理越强，越少需要把步骤写出来，也越有可能操纵写出的 token）。代理二：CoT 可控性 = 在被要求增加、删除或改写思维链时，模型能在多大程度上照做（附录 A：程序化统计「safe / meow / 大小写」等五类指令的遵从比例）。【自报】
2. **预训练。** 在 GPT-5（2025-08）到 Astra 级（2026-09）的内部与已发布模型上，no-CoT 成绩随基础模型困惑度下降而平滑上升；英国 AISI 曾认为 Astra 的 no-CoT 数学时间跨度偏离历史趋势，作者认为相对困惑度并不偏离。可控性与更低困惑度也有**较弱**相关（图 1–2）。【自报】
3. **架构。** 比较三个不同架构、不同规模的预训练系列。多数 no-CoT 评测上，同等困惑度则分数接近；在多跳规划和串行计算上，「Architecture 2」明显好于困惑度所预测的水平，小学数学也有较小但可见的效应。官方为保护训练细节隐去检查点位置，架构也不公开真实名称。【自报】
4. **RL。** 在最新 Astra 级模型 A 上，即使只有长度约束和最终答案打分、评分者看不到 CoT，可控性仍随 RL 计算量明显上升（图 4）。在最新 Terra 级模型 B 上，加上终端 / 浏览器工具及对工具输入输出的过程监督（B2），可控性只再升高一点；作者认为该效应小于降低困惑度，并承认这组实验**没有完全分离**困惑度与过程监督（脚注 10：未控制 A/B 在 RL 前的预训练数据与架构）。困惑度更差的内部模型上，他们起初没看到同样的可控性上升（附录 C）。作者称未对 CoT 施加直接奖励，并做过误用扫描。【自报】
5. **蒸馏 / SFT。** 两个下游能力接近、可控性不同的 Astra 级教师，用同一提示分布生成轨迹，分别 SFT 同一底座：学生会继承教师的可控性差距（图 6）。【自报】
6. **代理很吵。** 附录 B：在上述那对模型上，更可控的一方在数学侧任务监控规避和隐蔽沙袋评测上，规避并不更高，有时反而更低。作者明确：可控性是对抗性可监控性的嘈杂代理。【自报】

### 核验对照（晨报要点 vs 原文）

晨报要点按「不写思维链的推理能力随预训练变强；单靠 RL 会大幅提升思维链可控性且会通过蒸馏传递；架构影响小，过程监督不是主因」理解（「不写思维链」= no-CoT）。

| 晨报 / 导读说法 | 官方博客 | 判断 |
