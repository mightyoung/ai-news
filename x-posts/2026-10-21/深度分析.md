### 评测口径
- 公开基准：WGO-Bench（100 段视频，743 个金标分段）、RoboReward、Robometer。
- 自建基准：DenseCaptionBench（300 段）、DenseRewardBench（40 段 / 4861 步）、RubricBench（**in-house**）。论文里**没有写这三个会不会公开**；回复区也有人问「benchmarks 是否公开」，作者只回了一句「Should be!」。
- 和 API 对比时，各家推理强度没有做算力对齐（论文明说「not compute matched」）。

### 机制要点
1. 三个模型拆成流水线：9B 分段器按窗口预测局部区间和「是否延续」标志，再拼回整段时间轴；27B 描述器给每个区间写动作指令；27B 奖励器输出整段成功分、短时间步动作质量分和 rubric 分。
2. 分段器在 SFT 之后又用 GRPO 训练，奖励可验证：0.45·F1@0.5 + 0.15·F1@0.75 + 0.25·P@0.5 + 0.15·端点与延续标志。
3. 奖励器把 1–5 分 token 的概率分布取期望再缩放到 [0,1]，得到连续的奖励值。
4. 训练数据是开源数据、授权的私有数据和自采人工标注混合，模型卡写的规模是少于 1 万小时视频。

### 落地
- **标注流水线**：先用分段器 + 描述器批量出时间戳指令，用于筛选和配平预训练数据；奖励器的 outcome 分用来做质检和监控。对 DenseCaptionBench 那类多视角、灵巧手数据，要在自己的数据上抽检，因为 Robot200 子集上 Flora 不如 Astra。
- **机器人 RL**：process reward 可以当稠密奖励。上线前先在自己的失败样本上测 failure recall；论文提到 Flora-Rewarder 召回高，但约 11% 的正常步会被误标为失败。奖励模型被策略钻空子的风险需要另外加护栏【推断】。
- **成本**：用自己的 GPU 价格和实测吞吐重新算一遍，不要直接拿 125× 当结论。
- **合规**：非商用许可，商用产品不能直接用。

### 风险
非商用许可；关键基准是自建的且尚未公开；125× 是建模估算，而且只基于 50 段视频；输给 Astra 的那几行帖子没提。

### 数字对照
| 帖子 | 原文 | 结论 |
|---|---|---|
| 「+18% reasoning consistency over standard baselines」 | 摘要：「faithfulness 比 SoTA 对齐基线高 4%、比轨迹误差基线高 18%」。Table 3（德国数据，2 万条）Overall 一致性：Ours 61.4、ADE 43.4（+18.0）、VLM-Judge 57.5（+3.9）。Table 4（美国数据，1.5 万条）：64.8 vs 47.4（+17.4）、vs 62.4（+2.4） | **帖子漏了「对最强基线只有 +4」**；而且是百分点，不是相对 18% |
| 一致性怎么测 | 由 Gemini 3.1 Pro 判定，**只看第 1 次 trial**；ADE 指标取 3 次平均。在需要视觉落地的 E1、E2 两条边上，VLM-Judge 基线比 Ours 高 | 单次评判；裁判是一个 LLM |
| 代价 | ADE 从 4.169 升到 4.324，论文称约 5% 的轨迹性能损失 | 帖子没提 |
| 「1.6× more responsive to rare OOD scenarios」 | Table 5：从德国评测集均匀抽 **66 个场景**，用 Gemini 修图注入危险物（火、逆行车、摔倒的骑车人）。Overall 因果对齐：Ours 7.6%、Alpamayo-1.5-10B 4.6%、ADE 4.5%、LLM-Judge 4.5%。7.6/4.6≈1.65 | 66×7.6%≈5 个场景，66×4.6%≈3 个场景【推断】；绝对值很低，论文自己也说只能看作「方向性信号」 |
| 「critic 识别不忠实」 | Pinocchio 是在 Qwen3-VL-4B 上微调的，标签来自 Gemini（100 条人工核验，κ 0.385–0.720）。在 250 条留出集上平衡准确率 0.87，最弱的 E2 只有 0.78 | — |

### 机制要点
1. 把推理链拆成一个图：观测 → 场景描述 → 理由 → 元动作 → 路点，共 5 条边，每条边做「语义一致」的二分类。
2. 奖励 r_faith = Σ_e log P_e(CONSISTENT)，效果类似逻辑与：任何一条边不一致，整体奖励就被拉低。
3. GRPO 的总奖励 = −ADE + r_faith + 格式奖励（三项等权）；每个 prompt 16 个 rollout，lr 1e-6，β=0，用 4 块 H200。
4. 论文自己承认：成对语义一致只是忠实度的必要条件，不是充分条件；策略仍然可以绕过推理链来决定动作（事后合理化）。

### 落地
- 有思维链的 VLA 或驾驶模型，可以先用「图边一致性」做离线审计：抽样请 LLM 判定，同时安排人工复核，κ 值要单独报告。
- 如果把这类信号当奖励，至少要同时报告对最强基线的增益、任务指标的损失，以及在 grounding 边上会不会退化。
- OOD 评测要把样本量做到数百个以上，并且附上置信区间。

### 风险
只有驾驶这一个领域；裁判是 Gemini，学生 critic 又是在 Gemini 标签上学出来的，存在同源偏差；1.6× 的样本太小；代码还没放出。

## 3）后训练前预测编码 agent 潜力（NVIDIA，arXiv 2610.10478）

### 事实表
| 项 | 内容 | 来源 |
|---|---|---|
| 原帖 | @hyunw_kim https://x.com/i/status/2112252347665793461 ，10/20 02:39 CST，约 1.7 万次浏览。@soumyesinghal 的引用转发 https://x.com/i/status/2112255262233096604 ，10/20 02:51 CST | X API |
| 论文 | *Before They Can Solve*，arXiv 2610.10478 v1，提交于 10/8 01:37 CST。Tan Yu 等 22 人，通讯作者 Jiantao Jiao；**两位发帖人 Hyunwoo Kim、Soumye Singhal 都在作者名单里** | arXiv |
| 代码 | 论文全文没有代码或数据的发布链接 | 全文检索 |

### ρ=0.964 的口径
- **统计量**：Spearman ρ。同一张图里 Pearson r=0.965。
- **样本**：**10 个公开 base checkpoint**：Nemotron-3 Nano/Super/Ultra、Qwen-3.5-35B-A3B、DeepSeek-V4 Flash/Pro、Kimi-K2、GLM-4.5-Air、Hy3-Preview、Gemma-4-26B-A4B。
- **探针**：Decisive-Action BPB。做法是回放已经解出题目的 agent 轨迹，找到「第一次让测试由红转绿」的那一步，计算 base 模型对这一步动作的 bits-per-byte。轨迹来自 **DeepSWE**，与目标基准不同，算跨基准证据；生成轨迹的模型是 GPT-5.6-Sol、Opus-5、Kimi-K3，用 mini-swe-agent 跑。
- **目标**：对应后训练模型在 **SWE-bench Verified 上的 pass@1**。分数优先取各家公开报告值，没有的才自己测。所以各家后训练配方不同、评测框架也不同。
- **不确定性**：论文原话是「no bootstrap intervals」「indicative rather than calibrated」。n=10 时，一对排名对调 ρ 就会变化约 0.012【推断：1−6·2/990】。
- **其他数字**：同一探针改用 SWE-V 自身轨迹时 ρ=0.915。Patch MCQ 为 0.867（DeepSWE 轨迹）和 0.903（SWE-V 轨迹）。前缀条件 pass@K 用 SWE-V 前缀、K=8 或 16 时 ρ=0.988，K=32 时降到 0.906；用 DeepSWE 前缀时在 0.915–0.952 之间。对照组里，传统代码基准最高的是 RepoBench XFirst，ρ=0.830；HumanEval 为 −0.394。
- **受控实验**：同一套 SFT（1000 步、16.8B token）只训了 3 个底座，n=3，论文自己说只能作为描述性结果。

### 「已用于 Nemotron」的出处
- 唯一来源是 @soumyesinghal 的帖子：「We use it in Nemotron midtraining too, see our paper behind Super 3.5」，链接 2610.22019。他同时是这两篇论文的作者，算【自报】。
- 2610.22019 正文 §4.1 的说法：他们在中训练过程中**跟踪了**按 Yu et al. (2026) 方法算的 DeepSWE 决策轮 trace BPB，称它「与后训练结果相关性最好」；但紧接着写这些 base 指标「**did not track post-training results closely enough to guide recipe decisions**」，而且是单次运行。Table 4 里 BPB 从 0.171 降到 0.140。
- 结论：说「用于 Nemotron 中训练的**监控**」可以成立；说「用它来选 checkpoint 或定配方」**与原文不符**。该论文的其他核验见旧稿指针。

### 落地
- 有一批成功的 agent 轨迹和一个验证器，就能给候选底座打分：回放轨迹，定位决策步，再算 BPB。成本只是一次前向，适合在中训练过程中做低成本筛查。
- 先在自己的历史底座上跑一遍，看排名和后训练结果是否一致，再决定是否用它挡掉候选；分差很小时仍然要做真正的后训练小实验。
- 计算 BPB 时要把工具调用的格式 token 屏蔽掉，否则格式会主导分数，两篇论文都这么做。

### 风险
n=10 且没有置信区间；下游分数来自不同实验室、不同框架；轨迹由前沿闭源模型生成，可能偏向某种动作风格；代码未开源。

### 抗注入做法（只写防守面）
1. 训练数据：用教师模型在有宪章约束下做拒绝采样，**丢弃三类轨迹**：被注入指令带偏的、过度拒绝合法任务的、没完成正常目标的。数据覆盖单轮和多轮工具场景。
2. RL：只要执行了攻击者植入的动作就**确定性惩罚**，同时奖励正常任务完成，以及在推理中**明确识别出不可信内容**。
3. 策略层面：遵循指令优先级层级（principal hierarchy）；不可逆操作需要确认；数据最小化；不越出脚手架边界。
4. 对本地 agent 的启示：即使这样，ASR 仍有约 28%，所以**模型层的防护必须叠加系统层的防护**：工具返回内容标记为不可信、写操作和外发操作前要求人工确认、最小权限、出站白名单【推断】。

### 本地部署落地
- 24GB 显存用 Q4KM，32GB 用 EvoPress 混合精度（Q4_K/Q5_K/Q6_K）。配合 DFlash 投机解码，草稿模型是 5 层块扩散。
- 默认用 high 推理档；xhigh 在部分基准上反而下降（SciCode 43.6 → 39.2），选档要按任务测。
- 编码或终端类 agent 先和 Qwen3.6-27B 对比再选型。

### 风险
所有分数都是 Meta 自己评的（附录 A 有说明哪些跑在内部、哪些跑在外部）；没有速度数据；抗注入 ASR 不低；知识截止 2026-01-04。

【Pinocchio：给具身思维链训「忠实度」critic 做 RL 奖励（Stanford / NVIDIA）】
帖子 https://x.com/i/status/2112636599226060925 ｜论文 https://arxiv.org/abs/2607.04681 ｜项目页 https://mjf-su.github.io/pinocchio/

机制：把推理链拆成「观测 → 场景 → 理由 → 元动作 → 路点」5 条边，在 Qwen3-VL-4B 上微调一个 critic 判断每条边是否一致，标签由 Gemini 3.1 Pro 生成（100 条人工核验，κ 0.39–0.72）。用 Σ log P(一致) 作为奖励，和 −ADE、格式奖励等权，一起放进 GRPO。

### 3
【NVIDIA：后训练之前预测哪个底座能成为好的编码 agent】
帖子 https://x.com/i/status/2112252347665793461 ｜转述 https://x.com/i/status/2112255262233096604 ｜论文 https://arxiv.org/abs/2610.10478

结论：方法很实用，但 ρ=0.964 的口径很窄。它是 Spearman，只有 10 个公开 base checkpoint（Nemotron-3 三个、Qwen-3.5、DeepSeek-V4 两个、Kimi-K2、GLM-4.5-Air、Hy3、Gemma-4），比的是各家公开报告的 SWE-bench Verified pass@1，配方和框架各不相同，论文明说没有置信区间。

机制：回放已解题的 agent 轨迹，找到第一次让测试由红转绿的「决策步」，然后做三种探针：①base 模型对这一步动作的 BPB；②在正确补丁和被验证器否掉的补丁之间做选择题；③从决策步续写 K 次，用测试验证。0.964 是用 DeepSWE 轨迹算的 BPB，属于跨基准；改用 SWE-V 自身轨迹时为 0.915；前缀 pass@K 在 K=8/16 时最高到 0.988。传统基准最好的是 RepoBench，0.830；HumanEval 为 −0.394。同一套 SFT 的受控实验只有 3 个底座。

「已用于 Nemotron」：唯一出处是合作者自己的帖子。中训练论文 2610.22019 里写的是跟踪了这个 BPB 指标，但「不足以指导配方决策」。所以只能说用于监控，不能说用来选模型。

落地：手上有成功轨迹和验证器，就能低成本给候选底座排序，适合中训练过程中的筛查。先在自家历史底座上验证排名一致，再拿来做决策；分差小的时候仍要跑小规模后训练。

风险：样本量小，下游分数异源，代码未开源。
