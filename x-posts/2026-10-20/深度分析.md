### MultiLangBench 的评测口径（README，可核）
- 目标是实现 SQLite 3.40.1。模型可以查官方文档，禁止联网，环境里的 SQLite 痕迹要全部清掉。
- 测试由 SQLite TCL Tests 转换而来：51k 条里转出 24k 条，每条包含 initial_database、user_query、validation_query 三部分，用真实的 SQLite 3.40.1 执行 validation_query 比对输出串。
- **官方只要求跑 hash 以 00/01/02 开头的 272 条**（全量太贵）。所以博客的「通过率」大概率是在这 272 条上算的【推断】。
- 实现没用指定语言或混用语言，直接记 0 分，允许用另一个 LM 判定语言。单条超时 60 秒。
- 评分是二元组（api_cost, test_pass_rate），也就是说这是在比「花多少钱换多少功能」。

### 机制要点
1. **能力怎么来的，博客没说**。博客只写了「根据开发者和企业客户反馈改进」，没有任何训练数据、合成或 RL 方面的细节。晨报看点里的「数据合成」在原文中找不到答案；业内常见做法是跨语言转写合成、用编译器和测试做可验证奖励、长时程 agent RL【推断】。
2. **把数据库文件当跨语言接口**：输入是 db 加 SQL，输出是 db，再用参考实现校验。这样同一套测试可以用在任何语言上，而不需要每种语言写一套单测。这是这套评测最值得借鉴的设计。
3. **迁移评测只认可观测输出逐字节一致**，并且要求全部通过。博客专门举了 COBOL 定点运算默认截断（没写 ROUNDED 就不舍入）的例子：改写后「能跑但金额不对」。
4. 两个评测分别对应「从零构建」和「保持行为」两种能力，都按「成本 × 准确率」报告，背后的叙事是低推理强度也能做迁移。

### 工程落地：遗留系统迁移路径
1. **先做特征化测试（characterization tests）**：把生产环境的输入输出录下来（批处理文件、报表、交易流水），bug 也一起固化，作为等价性的基准。
2. **差分测试**：老系统和新系统吃同一批输入，对输出逐字节或逐字段比对。重点覆盖 COMP-3/定点小数、ROUNDED、截断、EBCDIC 排序、空记录和缺记录分支、日期边界。
3. **用 COBOL 语义的属性测试或模糊测试补足边界**：生成会触发精度截断、溢出（ON SIZE ERROR）、REDEFINES 的输入。
4. **按单元分批迁移**：按 copybook/程序/作业链切块，每块独立做差分；跨程序共享的数据布局先统一成 schema。
5. **影子运行再逐步切换**：新系统先并行跑但不生效，差异率降到阈值以下再按业务线或流量灰度切换，保留回滚通道。
6. **人审放在规则层**：模型生成代码，同时抽取业务规则说明，由领域专家审规则而不是逐行审代码（回复区也有人指出，瓶颈一直在审查改写）。
7. **自建小规模评测**：照 MultiLangBench 的思路，用参考实现做裁判，在自己的代码库上测「通过率 × 成本」，不要直接套用 OpenAI 的分数。
8. 评测时把推理强度和成本一起记录：86.6%（低强度）和 97.9%（高强度）之间的成本差，博客没有给出。

### 风险 / 未核实
- 所有数字都是自建评测上的自报值；COBOL 迁移集没有公开，题量和来源未知，「接近饱和」可能只是说明题目偏简单。
- 「每种语言的结果」宣称已发布，但仓库里还看不到。
- 隐藏测试只覆盖可观测输出，不覆盖性能、并发、事务语义、JCL/CICS/DB2 环境，以及未被测试到的业务规则。
- 回复区有账号称「评测已在 GitHub 公开」，实际只有 MultiLangBench 公开，COBOL 迁移集没有【第三方误传】。

### 算法拆解
设定：prompt x，二值或稀疏终局奖励 R∈[0,1]，β_KL=0。
1. **建树（initialize-then-expand）**：先用 π_old 采 M 条完整轨迹，每条随机选 N 个分支点各续写一个后缀，共 K=M(N+1) 个叶子。续写的期望成本约为整条的一半，所以 M(1+N/2)≈G。默认 (M,N)=(4,2)，K=12，对标 GRPO 的 G=8。
2. **回传信用**：A_k=(R_k−mean)/std；叶子 V=A_k，内部节点 V_i=Σ_c ω_{i,c} V_c，其中 ω 是 π_old 下子节点 span 似然的归一化权重。在行为策略处的树策略梯度是 g_tree=(1/L_x)Σ_i Σ_j V_i ∇log π(a_ij|h_ij)。
3. **回合级后验**：s_θ,i=(1/L_i)Σ_j log(π_θ/π_old)，即长度归一化的对数似然比，等价于几何平均比值，与 GSPO 相同；p_θ,i=σ(s_θ,i)，在行为策略处等于 1/2。
4. **闭式教师**：最大化 J=V_i·logit(q)−τ·KL(Ber(½)‖Ber(q))，得到 q_i=½+V_i/τ，r★=(τ+2V_i)/(τ−2V_i)。取 τ=√(K−1)/(ρ√K)（由 Samuelson 不等式界住标准化优势），q 就落在 [½−ρ, ½+ρ] 内，默认 ρ=0.25。
5. **前向 KL 蒸馏**：L_x=(τ/L_x)Σ_i L_i·KL(Ber(q_i)‖Ber(p_θ,i))，对每个 token 的梯度权重是 τ(p−q)/L_x。在**第一个 mini-batch** 上 p=½，梯度恰好等于树策略梯度；之后策略越过目标时，梯度会变小直至反号。默认共 E=4 个优化块。
- Theorem 1：q 的仿射映射与树回传可交换，因此只匹配父节点目标，和聚合所有后代叶子的损失梯度相同。共享前缀因此只算一次，不损失信用。
- Theorem 2：有界的加性漂移修正，取代乘性重要性比率（方差可能指数爆炸）和 clip（只截断，没有终点）。

### 与 GRPO / 其他树状 RL 对照
| 方法 | 信用粒度 | 离策略处理 | 是否有更新终点 |
|---|---|---|---|
| GRPO | 整条轨迹广播同一个组内标准化优势 | token 级比率 + clip | 无（clip 只截断） |
| GSPO | 同上 | 序列级（几何平均）比率 + clip | 无 |
| TreeRL（Hou et al. 2025）、Tree search for agent RL（Ji et al. 2026）、AT²PO（Zong et al. 2026）、TRACE（Zou et al. 2026a，同组） | 树回传得到 turn/step 级信用 | 一般沿用 PPO/GRPO 式 | 无 |
| 论文自设的 TreePO 对照 | 与 TreeOPSD 相同的树和 V_i | 每块都用固定系数 V_i/L_x | 无。这是最干净的消融：两者只差「是否匹配有限目标」 |
| TreeOPSD | 树回传 + 每个 turn 独立的 Bernoulli 目标（pointwise） | 前向 KL 投影 + 加性修正 | **有**（q 冻结，越过后反号） |
- 线程第 5 条说明，这是把同组 LPO 的「目标投影」视角推广到多轮 agent，并且由 listwise 改成 pointwise。
- 注意：论文里的「TreePO」是**作者自设的对照名**，参考文献中没有同名论文，容易和外部同名工作混淆【推断】。

### 复现要点
1. 超参：AdamW，lr 1e-6，weight decay 0.01，β 在 Multi-Hop 用 (0.9,0.999)、DR 用 (0.9,0.98)；100 次策略更新；无 KL、无熵正则；采样 T=1.0、top-p=1.0；M=4，N=2，ρ=0.25，E=4。
2. 规模：单机 8 卡；30B 的 rollout 用 TP=4，跑在 96GB H20 上；SGLang + FSDP，DR 用 FSDP2。
3. 数据：Multi-Hop 用 HotpotQA 训练集 90,447 题，本地 E5 + Wikipedia 检索，最多 5 轮。DR 用 OpenResearcher 的 6,102 个独立问题，训练时上限 60 轮，BC+ 评测 80 轮，最终评测最多 200 轮、131k token 预算，开放网络部分用 Serper。
4. 奖励：Multi-Hop 训练用阈值化 token F1（≥0.3 才给分），DR 用 EM，答案格式规范额外加 0.1。表里报的是不含加分的 EM。
5. 必须记录行为策略的逐 token logprob，并在每个 mini-batch 重新计算 s_θ,i。树需要支持前缀合并（unique turn），分支点从已走过的历史中抽取。
6. checkpoint 是在评测窗口内选的（每次 run 报一个），复现时要固定选择规则，否则会混入选点偏差。开放网络评测有时间漂移，论文的做法是交错评测并存档原始搜索响应。
7. 没有代码，信用回传权重、unique-turn 重建、Γ 计算都需要自己实现。建议以 verl 或 Search-R1 的脚手架为基座【推断】。

### 风险 / 未核实
- 30B 主结果只跑了一次；4B 五种子的方差约 0.4，与 TreePO 的差（约 2.4）相比有余量，但 30B 的显著性无从判断。
- 默认 ρ 和 (M,N) 都是在同一组 4B 评测上扫出来的，存在调参泄露的风险。
- 回复区有人提问：多个分支撞上同一个失败工具时，回传会冤枉早期的正确决策。论文没有专门处理工具失败。
- 论文 C.4 承认：默认设置下 q−½ 的 RMS 只有约 0.075，教师信号偏弱，只有出现单个反对奖励时才能达到满半径。

评测设计：MultiLangBench 要求用目标语言从零实现 SQLite 3.40.1，把数据库文件当跨语言接口，用真 SQLite 校验结果；24k 条转换测试里官方只要求跑 272 条。迁移评测要求可观测输出逐字节一致，全部通过才算成功。博客举的典型陷阱：COBOL 定点运算默认截断，改写成四舍五入后能跑，但金额不对。

落地路径：先录生产输入输出做特征化测试，然后新旧系统差分比对（重点盯定点小数、ROUNDED、溢出、EBCDIC 排序、缺记录），按程序或作业链分批迁移，影子运行后再灰度切换并保留回滚。专家审的是抽取出来的业务规则，不逐行审代码。

风险：迁移集的题量和来源不明，「接近饱和」也可能只是题目偏易；博客说的分语言结果目前不在仓库里；不覆盖性能、事务、CICS/DB2。

### B
【TreeOPSD：长时程 Agent RL 的树感知后验蒸馏（清华 × 腾讯）】
帖子 https://x.com/i/status/2112012777154023855 ｜论文 https://arxiv.org/abs/2610.23181

结论：晨报数字和论文 Table 1 一致。Qwen3-30B-A3B-Thinking-2507 在 Deep Research 上 GRPO 16.23→21.20，提升 4.97。这个分数是 BrowseComp-Plus、BrowseComp、GAIA、xbench 四项 EM 的等权平均。但 30B 只跑了一次，五种子方差只在 4B 上做过；Multi-Hop 的增益只有约 1 分，个别子集还不如 GRPO。论文里没有代码，GitHub 上也搜不到。

作者与机构：通讯作者 Qi Wang 的邮箱前缀 cheemswang 与发帖人主页一致，同在清华 Ji 组，基本可以确定发帖人就是他（第二作者）。论文署名是清华大学和「腾讯基础模型部门」，全文没有出现「混元」，混元只是帖子里的 @。

机制：先建 rollout 树，4 条完整轨迹各分叉 2 个后缀，共 12 个叶子，成本约等于 GRPO 的 8 条。终局奖励先组内标准化，再按行为策略似然加权逐层回传，得到每个回合的信用 V。然后把 V 映射成闭式的有界教师 q=½+V/τ，τ 由组大小和半径 ρ=0.25 决定。最后用前向 KL 让当前策略的回合后验 σ(平均对数比) 去对齐 q。第一个 mini-batch 上这一步恰好等于树策略梯度，之后策略越过目标就自动刹车甚至反向。相比 GRPO：信用细到回合，用有限终点取代 clip。

复现：单机 8 卡 H20；lr 1e-6，100 步；无 KL、无熵正则；E=4 个优化块。需自实现前缀合并树、行为 logprob、每块重算后验。

风险：checkpoint 在评测窗口内挑选；超参是在同一组评测上扫的；GAIA 和 xbench 各约 100 题，多对一题平均分就动约 0.25；工具失败可能把早期正确决策一并惩罚。
