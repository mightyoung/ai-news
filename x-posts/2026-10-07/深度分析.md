### 机制拆解

1. **评估饱和 → 开放题仓库**  
   README 写明：既有数学评测饱和后，把评估扩到**开放研究问题**；部分输出建立在模型更早结果之上——这是「可验证域自举」而不是一次性竞赛刷分。

2. **产出单元是「族 + 手稿」而非「解题率」**  
   4,000 题输入 ≠ 372 族全对；公开的是显著性筛选后的目录。**禁止**用 372/4000 当解题率。

3. **双重验证梯度**  
   - Lean：机器可检逻辑（形式化覆盖「许多但非全部」）。  
   - 自然语言手稿：仍需人类阅读、引用核查与概念吸收（AGMAI 核心关切）。  
   两者缺一都会被共同体卡住。

4. **负责任发布 = 流程对齐，不是完全合规声明**  
   OpenAI：咨询 AGMAI + 用其公开建议「inform」本次发布；GitHub 协议、Lean、平均算力、尝试题数、workshop 资助计划与建议方向一致。  
   对照 AGMAI：逐题 prompt、逐题成本、**可获取的模型**仍缺口——公开渠道记「部分对齐 / 理想要求未完全满足」。

5. **对 AI 科研的结构性意义**  
   可验证奖励（证明正确 / Lean 通过）使 RLVR 类训练能在数学上「推任意远」（与第 2 条 Chollet 假说对照）；同时把「人类理解滞后」写成组织问题（资助 + 独立顾问），而不是纯模型问题。

### 工程落地（7 条）

1. **只消费仓库元数据与 Lean，不默认定理已「被数学界接受」**：以 `CONTENTS.md` 问题陈述 + Lean 状态为工作清单；自然语言证明当「待人类审阅草案」。  
2. **建内部「形式化优先」管道**：对业务相关的数论/优化/密码相关族，优先跑 Comparator / `formalization.yaml` 配置，再开人工研读。  
3. **算力口径翻译**：对外沟通用官方「≈3h Pro thinking / 结果」；**不要**换算成自家美元或 GPU 小时（总额、token、加速器小时：**未公开**）。  
4. **引用与版本钉死**：引用具体 preprint 目录中的 BibTeX + 版本号；跟踪仓库 revision 协议。  
5. **与产品选型切割**：内部模型未释放 → 不能把「会解开放数学题」写进对外 SLA；可写「关注 openai/math 形式化覆盖率与未来模型开放」。  
6. **科研协作**：若跟进某族，优先对接 OpenAI 承诺的 workshop/funding 通道（细则未出前先盯博客更新）。  
7. **对照 Chollet 假说做实验设计**：在自家领域区分「可自动验证任务」与「需人类标注任务」，分别设 RLVR 预算 vs 数据采购预算（见 §2）。

### 风险

- **手稿 ≠ 已证定理（共同体意义）**：未形式化部分 README 自承可能有问题；即使 Lean 通过，概念新颖性/文献归属仍待人审。

## 2）Chollet：RLVR 与锯齿前沿会不会只是数学+代码 ★

**标题 / 链接**  
- François Chollet（@fchollet）：What if the jagged frontier is mainly math + code (RLVR)… non-verifiable… human generated data?  
  https://x.com/fchollet/status/2107625225768858076  
- 可对照：§1 OpenAI math 发布（同日邻近时段）

**一句话结论**  
Chollet 提出可检验假说：锯齿前沿（jagged frontier）**主要**由 **RLVR 可任意推进的数学/代码**构成；不可自动验证领域的「稳增」到底是 **通用能力 G 外溢**，还是 **持续注入的大规模人类数据**——答案将决定训练预算与产品能力板该押哪边；§1 的 openai/math 是「可验证侧加速」的强旁证，但**不能单独裁决**非验证域归因。

| 互动量（抓取时） | ≈236 likes / 18 reposts / 37 replies / 11.6k impressions | user-X metrics |

### 机制拆解

1. **RLVR 的定义边界（工程视角）**  
   Reinforcement Learning from Verifiable Rewards：候选 → 自动判对错（单测、编译、证明检查、竞赛打分）→ 强化。数学/代码天然闭合；法律意见、创意写作、开放科学解释通常**不闭合**。

2. **锯齿 = 验证器密度地图**  
   能力凸起出现在「便宜、客观、可规模化验证」的坐标上；凹陷出现在「贵、主观、需人类」的坐标上——与 §1 大规模数学产出同构。

3. **两种对立归因（正反证据框架）**  

   | 归因 | 支持证据（公开可指） | 削弱证据 / 缺口 |
   |---|---|---|
   | **G 外溢** | 数学/代码 RLVR 提升推理深度后，邻近 STEM、工具使用偶发变好；前沿实验室持续报非验证基准「慢速上涨」 | 缺少**控制人类数据新增量**的消融公开；外溢幅度与方向未标准化 |
   | **人类数据注入** | 实验室公开仍在大规模采标注/偏好/专家轨迹；非验证域提升节奏更像数据管道吞吐 | 数据配方、混合比例、更新频率多数**未公开**；难做因果 |

4. **与 §1 的对照（各自成节，这里只交叉）**  
   openai/math：约 4,000 开放题 × 可检查证明/Lean → 典型 RLVR 友好域的「批量前沿推进」。它**增强**「锯齿在可验证侧可被推远」这一支，但**不回答**客服文案/医疗沟通等非验证域的归因。

5. **产品含义的分叉**  
   - 若 G 外溢成立：押旗舰推理 + 可验证后训练，非验证域「等等就来」。  
   - 若人类数据主导：非验证域必须单独立项买数据/专家反馈，否则平台期。  
   在因果未清前，工程上应**并行**两条预算线，并用对照实验裁决。

### 工程落地（8 条）

1. **能力地图按「验证器有无」着色**：内部基准分成 Verifiable / Semi-verifiable / Preference-only 三桶，分别报分与成本。  
2. **Verifiable 桶优先 RLVR**：单测、形式化、结构化评分；对齐 §1 的 Lean/自动检查思路。  
3. **Preference 桶强制数据账本**：每月新增人类标注量、专家小时、偏好对数量写入训练卡——用来日后回归 Chollet 问题。  
4. **做最小消融**：同底座上「冻结人类数据更新 vs 只加 RLVR」或反向；即使规模小，也能给产品叙事纠偏。  
5. **产品选型**：Coding agent / 形式化助手 → 押 RLVR 密集模型；品牌文案、合规叙事、开放诊断 → 默认「数据与流程」主导，模型只是放大器。  
6. **路由策略**：不可验证高风险输出加人类抽检与检索接地；可验证输出可提高自动合并阈值。  
7. **对标叙事纪律**：引用 OpenAI math 时只说「可验证域加速的公开案例」，不说「因此通用智能已外溢到 X」。  
8. **跟踪指标**：非验证域「单位人类数据的增益」vs 可验证域「单位 rollout 的增益」——二者斜率交叉时再调预算。

### 风险

- **假说被当成结论**：原文是疑问句；对外不要写成已证实定律。  
- **任务伪验证化**：把开放题硬改成可打分代理，可能优化到代理而损坏真实质量。  
- **数据保密**：人类数据归因实验常撞 NDA；公开论文级因果可能长期缺失。

### 机制拆解（增量）

1. **从「预告」到「可调 SDK」**  
   9/30 只有 Recap + 延迟口号；今日有正式指南、Playground、Python `decisions.create`——接口形态可写进设计文档。

2. **三种题型 = 分类器代数**  
   二值概率 / 无序多类 / 有序量表，覆盖路由与优先级；需要自由 JSON 或工具调用时仍走 Responses（指南明确分工）。

3. **Input-only 计费改变单位经济**  
   无 output token → 鼓励「短证据 + 多并行 questions」；长图像 base64 会主导账单（像素进 token）。

4. **「Realtime general classifier」产品位**  
   Tibo 用词把 Decisions 从 agent 内环扩展到**任意 App 实时分类**；与 Agents/Codex 发布周并存，但接入点是独立 `/v1/decisions`。

### 工程落地（8 条 · 增量）

1. **契约化 questions schema**：版本化 `name/type/instructions/choices|levels`；`other`/`fallback` 必留。  
2. **阈值用业务代价矩阵校准**：指南要求用标注样本定阈值；`confidence` 与 `probability` 分开监控。  
3. **图像管道预编码 base64**：禁止假设 URL/`file_id`；控制分辨率以防 input token 爆炸。  
4. **延迟 SLO 先自建**：对比「同题 Luna Responses + JSON schema」vs Decisions，验证「约 10×」在你区域是否成立；合同勿写死无官方分布的毫秒数。  
5. **成本模型改写**：按 input tokens / 决策计；预留区域溢价与长上下文倍率开关。  
6. **串并联**：独立标签一个请求多 questions；状态机依赖则链式 + 超时回退规则引擎（继承 9/30 建议）。  
7. **合规开关**：ZDR/HIPAA/驻留按租户配置；beta → GA 前功能旗标。  
8. **App 内接入样板**：客服路由、内容安全初筛、agent「下一步动作」枚举、视觉质检——与 Codex 周「会议纪要接上下文」无强耦合则不必单独成章。

### 机制拆解

1. **原生共享空间 vs 管道拼接**  
   单一模型吃 text/image/audio/video，避免「ASR→caption→text-embed」级联的误差与延迟——跨模态检索的工程主因。

2. **模块化编码器 = 部署旋钮**  
   按 modality 卸视觉/音频，把端侧 RAM 从全量压到文本 270M 档；与 QAT INT4/INT8、MRL 截断一起构成「体积三联」。

3. **任务前缀（text-only）**  
   SearchQuery / Document / CodeRetrieval 等 instruction prefix 把同一向量空间舵到非对称检索或对称分类；图音不加前缀。

4. **交织占位符**  
   `<|image|>` / `<|video|>` / `<|audio|>` 让商品卡、课件页等「文+多图+短视频」编成**一个**向量，直接对文本查询。

5. **与生成模型同族**  
   博客：与 Gemma 4 共享 text tokenizer 与 audio encoder，端侧「Embed + Generate」总内存更省——本地 RAG 的成套故事。

### 工程落地（8 条）

1. **本地 RAG 最小栈**：EmbeddingGemma 2（按需 modality）→ 本地向量库（官方点名 Qdrant 等）→ Gemma 4 生成；敏感数据不出端。  
2. **先选有效参数档**：纯文档 270M；相册/截图检索 440M；语音备忘录 570M；全开 740M。  
3. **默认 256d 或 512d 存库**：768d 建索引贵；128d 上线前用自家多模态集回归（官方警告多模态掉点）。  
4. **截断必 `normalize_embeddings=True`**：否则余弦分「看起来合理但排序坏」。  
5. **dtype：`bfloat16` 或 `float32`，禁用 `float16`**（激活范围溢出 → NaN/静默劣化）。  
6. **跨模态检索模式**：文本查图/视频帧；语音查视频时刻；图搜图——对齐 Gallery 两个 showcase。  
7. **MediaPipe 捷径**：Universal Embedder + Semantic Retriever（ANN，官方称单 digit ms 级检索）；需要控图时再下沉 LiteRT。  
8. **与云端 Decisions 分工**：端侧用嵌入做毫秒级意图/相似度初筛；需强语义枚举且可联网时再打 OpenAI Decisions（§3）——两者都叫「decision」但层不同。

### 风险

- **榜分为 Google 公开表，未独立复现。**  
- **嵌入模型无生成式对齐**：安全/偏见风险在下游检索与分类策略。  
- **128d / float16 / 漏前缀** 是三类静默质量坑。  
- **ML Kit 正式服务「coming weeks」**：生产 Android 若等官方托管需排期；眼前用 HF/LiteRT/MediaPipe。
